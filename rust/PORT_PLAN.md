# Claudius → Rust: port plan

Goal: **full parity** with the TypeScript app, ending in a pure-Rust Claudius.
This file is the source of truth for the port: strategy, module map, what is
done, what is missing, and the rules that keep the two implementations
interchangeable while they coexist.

## Strategy: backend first, library first, UI last

A big-bang rewrite would mean months with nothing to test against. Instead:

1. **Port the backend as libraries** (`claudius-agent`, `claudius-core`) with
   no HTTP or UI assumptions, so the same core can later power a native UI.
2. **Put a Rust HTTP server in front** (`claudius-server`). It serves the same
   HTTP/SSE API as `app/api/**` for every ported route and **reverse-proxies
   everything else** (pages, assets, the HMR websocket, unported API routes)
   to the existing Next.js server.
3. **Use the unchanged React UI and the Playwright suite as the parity
   oracle.** If the real UI works against the Rust backend, the port is right.
   Every route ported moves traffic from Next to Rust with no UI change.
4. When the API is fully ported, Next only serves the UI. Then **replace the
   UI with a native Rust one** (last phase, below).

```text
 browser ──► claudius (Rust, :3100) ──┬─► ported routes ─► claudius-core ─► claudius-agent ─► `claude` CLI
                                     │                     (sessions, SQLite,     (stream-json +
                                     │                      settings, JSONL)       control protocol)
                                     └─► everything else ─► Next.js (:3000) — pages, assets, HMR, unported API
```

## Running it

```sh
# terminal 1 — the existing app (UI + not-yet-ported routes)
bun run dev                                  # :3000

# terminal 2 — the Rust front door; open http://localhost:3100
cd rust && cargo run -p claudius-server -- --port 3100 --next http://127.0.0.1:3000
```

Flags and environment variables:
- `--host` / `CLAUDIUS_RS_HOST` (default `127.0.0.1`)
- `--port`, `-p` / `CLAUDIUS_RS_PORT` (default `3100`)
- `--next URL` / `CLAUDIUS_NEXT_URL` (default `http://127.0.0.1:3000`), or `--no-next` to run without a proxy
- `--claude-bin PATH` / `CLAUDIUS_CLAUDE_BIN`. Otherwise the binary is found the same way the SDK finds it: the bundled `node_modules/@anthropic-ai/claude-agent-sdk-<platform>/claude`, then `claude` on `PATH`.
- `CLAUDIUS_DEV=1|0` forces the dev-only `dev-*` test routes on or off. Without it they follow TS: off when `NODE_ENV=production`, otherwise on in debug builds and off in release builds. The parity e2e config sets `CLAUDIUS_DEV=1`.
- `CLAUDIUS_DEV_FETCH_BASE=URL` (only with the dev routes on): every outbound request of the server's HTTPS client (`claudius_core::fetch`) goes to `URL/<host>/<path>` instead, for a local fake of the Anthropic endpoints. Outbound requests use `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` only with `NODE_USE_ENV_PROXY=1`, as node 22's fetch does.
- `CLAUDIUS_STATE_HOME=DIR` moves Claudius's own state (`~/.claude/.claudius`, per-project DBs, workspaces) to `DIR` while the CLI keeps the real `$HOME` and login. Use it for an isolated test world that still talks to the real model.
- `--scheduler` / `CLAUDIUS_SCHEDULER=1|true|yes|on` also runs Claudius's scheduled jobs (`claudius_core::scheduler`) and makes Rust answer the schedule routes (`claudius_server::schedule`, G07b); without it they go to Next. It is off by default because Next boots its own scheduler on the same `jobs.json` (in `instrumentation.ts` and on every schedule route), so turn it on only where Next doesn't run one.

**Open the UI through the Rust port (:3100), not :3000.** Live sessions exist
only in the process that started them (see below).

### Logging

Logs go to stdout through `tracing`. The default filter is `claudius=info`, a target *prefix*, so it covers every crate (`claudius_core`, `claudius_agent`, …) and the TS-parity targets below. Set `RUST_LOG` to replace it; an invalid `RUST_LOG` falls back to the default. Colours appear only when stdout is a terminal.

| Target | TS equivalent | Level |
|---|---|---|
| `claudius::sess_load` | `[sess-load] …` (`sessLoadDebug()`) | debug |
| `claudius::session` | `[session] …`, `[session.*] …` | warn |
| `claudius::api` | `[api/*] …`, `[input] …` | warn / error |
| `claudius::scheduler` | `[scheduler] …` | error; `armed` / `disarmed` at debug (Rust-only) |
| `claudius_agent::query` | (SDK internals) spawn argv, control traffic | debug |

Messages keep the TS bracket prefix and field names, so the same grep works on both backends.

```sh
CLAUDIUS_DEBUG_SESSIONS=1 cargo run -p claudius-server   # the TS switch: adds claudius::sess_load=debug
RUST_LOG=claudius=info,claudius::sess_load=debug …        # same, explicitly
RUST_LOG=claudius=warn …                                  # quiet: only warnings / errors
RUST_LOG=claudius=info,claudius_agent=debug …             # + CLI spawn argv and control-request traces
```

## Coexistence rules

- **Live sessions live only in the Rust process.** Every `/api/sessions/:id/*`
  route is answered by Rust. Unported ones return **501**
  `{error, notPorted: true, sessionId}` rather than being proxied: if Next
  received them, it would resume a *second* CLI for the same session id.
- **The disk-only collection routes are Rust's too:** `/api/sessions/all` and
  `/api/sessions/{export,file,info,transcript}/**` (D19), `/api/sessions/fork` (D05).
  Nothing under `/api/sessions` reaches Next.
- **Routes outside `/api/sessions` that use `sessionManager` are proxied but
  degrade.** Next's in-memory session manager is empty while Rust owns the
  sessions, so these see no live sessions: `schedule` (session loops).
  Porting them is phase 3.
- **Scheduled jobs run in one process only.** The schedule routes (`schedule`, `[id]`, `run-now`, `runs`; G07b) are answered by whichever process runs the scheduler: Rust only with `--scheduler`; otherwise they are forwarded to Next unchanged, so a create, edit or run-now always reaches the running scheduler. `session-loops` (+ `cancel`) and the run stream (G07c) always go to Next. Next boots its scheduler unconditionally, so `--scheduler` with a Next upstream still runs two schedulers; handing over needs a TS-side switch first (Known gaps › Routes).
- **On-disk formats are shared and must stay byte-compatible:** the same
  SQLite schema (embedded migrations), the same settings files, the same CLI
  JSONL. Either backend can open what the other wrote.

## Known gaps (parity debt)

**Session engine (`session.rs`)**
- JSONL watcher (S01): turns another client writes to the transcript reach open streams live. Differences from TS:
  - Deliberate: it watches the directory the CLI writes the transcript to (`<config>/projects/<SDK name>`, where `resyncFromDisk` reads it). Seen in the TS app on 2026-10-26: the mid-turn reminder listed the last-created item several times.
- `fs/dirs` (D04):
  - Containment is lexical and `stat` / `readdir` / `mkdir` follow symlinks, so a symlink inside the root lists, and creates folders in, a directory outside it.
  - The TCC gate and the container 403 compare exact strings. On a case-insensitive disk (the APFS default), `?path=desktop` or `Library/containers` passes both and reads the folder without the heads-up.
  - POST has no TCC or container check: `{parent: "Desktop"}` creates there without `ack`.
  - With `CLAUDIUS_FS_ROOT=/`, nothing below `/` is reachable (`startsWith("//")`): every other listing and every create is a 403.
  - A folder named `..foo` inside the root can't be a POST parent (a 403 from the `relative(…).startsWith("..")` check).
- `fs/list` (D04): a directory never gets the basename bonus; its `relPath` ends in `/`, so its basename is empty.
- Memory and rules (G08):
  - Containment is lexical and reads, edits and listings follow symlinks. A symlink inside the memory or rules dir (or the dir itself being one) is read, written through by `PATCH`, and listed with its target's size and mtime. A create never goes through one (exclusive, 409) and a delete removes only the link.

  - A cwd whose encoded memory-dir name passes 255 bytes is an empty 500 (`ENAMETOOLONG`); TS never shortens or hashes it.
- Workspace relocation (G09):
  - A sidecar-merge or stamp failure leaves the transcript already renamed into the new folder but reports it in `failed` (the TS type says failed transcripts stay behind), so a retry hits "already exists".
  - The stamp is appended through a symlinked `<id>.jsonl` to wherever it points (the containment check is lexical).
  - `NOT LIKE 'sqlite_%'` also skips user tables like `sqliteXfoo` (neither merged nor re-keyed).
  - A dotless `ınteger` PK passes the JS `toUpperCase() === "INTEGER"` test but isn't a rowid alias, so the source rows land with NULL keys.
  - A source row missing a NOT NULL column the destination has is dropped silently (`INSERT OR IGNORE`).
- Git (D06):
  - The branch header regex fails on a name with `.` or JS whitespace (`v1.2`, NBSP), so the status reads as detached with a `head` sha. A trailing BOM is trimmed off the branch.
  - `getRepoRoot` trims a top level that ends in whitespace, so git then runs in another dir (`spawn git ENOENT`, or a trimmed twin repo).
  - Untracked (`--no-index`) diffs read any path, absolute or `../` outside the repo, and treat "Could not access" (exit 1) as an empty diff.
  - No `--no-ext-diff`: a repo's `diff.external` runs.
- Git branches (D07):
  - git 2.54 shortens `refs/remotes/<remote>/HEAD` to `<remote>`, so `listBranches`' `<remote>/HEAD` filter never fires: `origin` is listed as a remote branch, and checking it out is `unknown branch: origin`. `origin/HEAD` derives the local name `HEAD`, which git refuses.
  - Ambiguous short names (`heads/dup` for a branch named like a tag, `remotes/rem/main` next to a local `rem/main`) are listed that way and can't be checked out (`unknown branch`).
  - A branch whose name starts with `-` or holds JS whitespace (NBSP) is listed, but every route refuses it as `invalid branch name`. A NEL passes JS `\s` and reaches git.
  - `diff <branch>` has no `--`: a name that is only a path diffs that path, one that is both is git's ambiguity error. No `--no-ext-diff`, so `diff.external` runs.
  - Remote delete splits at the first `/`: a remote with a slash in its name is misparsed, and `./x` pushes to the repo itself and deletes its local `x`.
  - Checkout's `refExists` probes swallow every failure, so a probe killed at 15 s or a corrupt packed-refs reads as `unknown branch`.
- `sessions/search` (D20):
  - It reads `homedir()/.claude/projects`, not `$CLAUDE_CONFIG_DIR`, and encodes `dir` with `encodeProjectDir` only (not the SDK's hashed name for long paths), so a profile's transcripts and a long cwd's folder aren't searched (a 300-char dir is ENAMETOOLONG → `[]`).
  - The encoding collides: `/tmp/😀 x` and `/tmp/😁 x` share a folder, as do `../../etc` and `.:/.\-etc`.
  - Containment is lexical, so a symlinked `<id>.jsonl` is read wherever it points.
  - Matching runs on the untrimmed `q` over the raw JSONL, keys included (`"type":"user"` matches every file).
  - The snippet unescape runs in pass order, so a raw `\\n` prints as `\ `.
  - Invalid-name files take slots before the 600 cut.
  - A FIFO named `<id>.jsonl` blocks the request forever (in Rust, one blocking-pool thread).
- `sessions/peer-source` (G11):
  - It reads `homedir()/.claude`, not `$CLAUDE_CONFIG_DIR`, and never a profile's `projects/`: a sender whose CLI writes elsewhere is found only through a profile's registry record.
  - The raw `includes` prefilters run before the structural match: an uppercase msgId passes the UUID check but never matches, and an escaped `msg_id`, tool name or `cwd` key in a transcript line is missed.
  - The 200-unit snippet cut can end in a lone high surrogate, which then prefixes a different astral character's body.
  - An empty workspace `rootPath` matches every absolute cwd (`"" + "/"`).
  - A FIFO named `*.jsonl` in the window blocks the request forever (by inspection; in Rust, one blocking-pool thread).

## Parity rules (read before porting a route)

- **Same status codes, error strings and JSON shapes** as the TS handler. The UI and Playwright specs depend on them.
- **Dev-only routes** (TS: `if (NODE_ENV === "production") return …`) start with `tri!(dev_only(app.dev_routes, DevRefusal::…))`, before params, the session lookup or the body. Pick the refusal the TS handler uses (`NotFound` → 404 `dev-only endpoint`, `Forbidden` → 403 `dev only`).
- **Request bodies: copy how the TS line reads them.** Use `claudius_server::body`, and call it at the same point in the handler (TS checks the session and returns 404 *before* `req.json()` runs):
  - bare `await req.json()` → `tri!(JsonBody::strict(&body))`. An empty or malformed body gets Next's response to a thrown handler, an **empty** 500 with no content type, not a JSON error.
  - `.catch(() => ({}))` / `.catch(() => null)` / a `try/catch` that assigns a fallback → `JsonBody::lenient(&body, fallback)`.
  - the same, in a handler that only tells numbers apart with `Number.isFinite` → `JsonBody::lenient_overflow(&body, fallback, &stand_in)`: a literal past f64 (`1e400`, ±Infinity in JS) reads as the stand-in instead of failing the whole body.
  - a `try/catch` returning `400 {error}` → `tri!(JsonBody::or_bad_request(&body, "msg"))`.
  - a `try/catch` that uses the error's `message` (`rewind`'s 503, `settings/import`'s `invalid JSON: …`) → `JsonBody::parse_or_message(&body)`. Its `Err` is V8's `JSON.parse` message byte for byte (`claudius_agent::js::json_parse_error`). It strips two leading BOMs like `Body.json()`, and reads lone-surrogate escapes as U+FFFD.
  - Afterwards, `body?.x` is plain indexing (`b["x"]`; `Null` for missing / non-object). `body.x` without `?.` throws on a `null` body, so use `tri!(js_member(&b, "x"))`, whose `Ok(None)` means `undefined`.
  - Any JSON value is a valid body (`null`, arrays, strings), exactly like `JSON.parse`.
- **JS numbers.** `serde_json` uses `preserve_order` + `float_roundtrip`. Write integral `f64` values as integers with `claudius_core::js_num`, because JS prints `3`, not `3.0`.
- **Re-serialized JSON** (TS `JSON.stringify` of parsed or merged data) goes through `claudius_agent::js::stringify`, not `serde_json::to_string`. serde keeps the source number text (`1.0`, `1e2`) and insertion order. JS prints `1` and `100`, formats like `1e+21`, and enumerates array-index keys (`"2"`, `"10"`) first. `claudius_agent::js` also has JS `truthy`, `trim`, `entries`, `prop` (`?.`), `Set` dedupe, and `json_parse` / `json_parse_error` (`JSON.parse` and the exact wording of V8's `SyntaxError`, replayed against node 22 in `tests/json_parse_golden.rs`). With `preserve_order`, `Map::remove` is `swap_remove`: use `shift_remove` for JS `delete`.
- **JS string lengths are UTF-16 units.** Use `encode_utf16().count()` for caps and slicing, e.g. draft text caps and project dir encoding.
- **SQLite:** never add schema on the Rust side. Add `lib/server/db-migrations/NNN_*.sql`, which both backends pick up.
- **Settings:** never write over a malformed settings file. `read_settings` errors and callers skip the write, the same as TS.
- **Locking:** `Session` state sits behind one `std::sync::Mutex`, never held across `.await`. Broadcast runs under the lock so subscribe (replay + register) is atomic.
- **Security rules** (the Rust side of `CLAUDE.md`'s CodeQL rules, N11). `.github/workflows/codeql.yml` scans `rust/` as well (language `rust`, build mode `none`).
  - **Paths (`rust/path-injection`).** Request data reaches `std::fs` / `tokio::fs` only after two steps:
    - resolve it against a base with Node's `path.resolve` semantics (`claudius_core::node_path::resolve`, which normalizes `..` lexically as the TS does; not `Path::join`, which keeps `..` and lets an absolute segment replace the base);
    - a containment check right above the call: `if !target.starts_with(&format!("{base}/")) { … 403 … }`.
    - Keep the check at the sink, where the TS has it. `safe_path::assert_within` and `paths::within` are fine inside `claudius_core` when their result is what the fs call uses.
    - Check the resolved string, like the TS. Don't `canonicalize()` unless the TS calls `realpath`: it changes behaviour for symlinks and missing files.
  - **Regexes (`rust/regex-injection`).** Never build a `Regex` from request data.
    - Escape it with `regex::escape`, the Rust form of the MDN escape. Or, when the TS only escapes in order to find a substring, match it as a literal (`str::find`, or `session_search`'s UTF-16 matcher).
    - The `regex` crate runs in linear time, so a pattern can't wedge the server the way a backtracking engine can. A compiled user pattern would still change what matches, though. Don't add a backtracking engine (`fancy-regex`, `pcre2`) for user input.
    - Where JS regex semantics differ (UTF-16 indices, `\b`, case folding), use the existing translators: `claudius_agent::redact`'s `translate` for SDK patterns, `session_search` for queries.
  - **Randomness.**
    - Security values (OAuth `state`, PKCE verifiers, tokens, ids) come from the OS: `getrandom::fill`, `uuid::Uuid::new_v4()`. For a bounded integer, use rejection sampling, not `x % n`.
    - Cosmetic picks (spinner tips, the `/color` accent) mirror what the TS does and don't need a CSPRNG. Don't "harden" them.
  - **Processes.** Spawn with an argv: `claudius_core::exec_file`, or `tokio::process::Command` with `.arg()`. Never a shell string built from input; the TS uses `execFile` for the same reason.
  - **No `re2`.** It's a native Node addon that breaks the Electron 42 build (a verified dead end), and the Rust side has no use for it.
- **Regenerate spinner tips** with `rust/scripts/gen-default-tips.sh` after editing `lib/shared/tips.ts`.

## Testing

```sh
cd rust
cargo test --workspace           # unit + fake-CLI integration + HTTP end-to-end
cargo clippy --workspace --all-targets -- -D warnings
scripts/route-coverage.sh        # regenerate ROUTES.md after porting a route
```

CI: `.github/workflows/rust.yml` runs the same three commands on ubuntu + macOS whenever
`rust/**`, `lib/server/db-migrations/**` or `app/api/**` change. A new Next route therefore needs
`scripts/route-coverage.sh` re-run, or the `route_coverage` test goes red.

The fake CLI (`claudius-fake-claude`) is driven by the prompt text:
- `tool:X` → permission request
- `ask:` → AskUserQuestion
- `plan:` → ExitPlanMode
- `mcp:` → SDK MCP tool call
- `hook` → hook callback
- `exit:N` → crash with code N
- `script:<json>` → run that JSON as a turn (a step array or `{steps, result}`)
- anything else → `echo:<text>`

For anything richer, use **scripts** (`$FAKE_CLAUDE_SCRIPT`: inline JSON or a file path). The full format is in the header of `crates/claudius-agent/src/bin/fake_claude.rs`. In short:
- `turns[]`: arbitrary message sequences per prompt (`system/*`, `stream_event`, task lifecycle, `compact_boundary`, tool uses and results), chosen by `match` substring, consumed unless `repeat`.
- `result`: absent → success with the last assistant text; a string; a merge object; or `false` to leave the turn open.
- steps: `$text`, `$control` (a CLI→host request whose response becomes `$LAST` / `$LAST:/ptr`), `$send` (fire one without waiting), `$collect_ms` (wait until every `$send` is answered, or the time is up), `$mark` (log a label to `$FAKE_CLAUDE_EVENTS`), `$delay_ms`, `$wait_file` (block until a path, relative to the CLI's cwd, exists; at most 60 s; G07a), `$fs` (`["write"|"rm"|"mkdir"|"chmod", …]`: change a file mid-turn; S21), `$stderr`, `$exit`.
- placeholders: `$SESSION_ID`, `$MODEL`, `$PROMPT`, `$UUID`, `$N`.
- `init` / `initialize`: merged over the default `system/init` and initialize response. `on_init`: steps emitted after initialize.
- `control.<subtype>`: overrides a canned response with a literal, `{"$error": …}`, or `{"$response", "$emit", "$delay_ms"}` (e.g. an `interrupt` that emits the `error_during_execution` result). `"$no_reply": true` sends no response, so `$emit` can exit with the host still waiting.
- `$hold_stdout_ms`: a grandchild `sleep` keeps stdout open that long past the exit.

Without a script, control requests still get realistic canned answers:
- `get_settings` reflects `apply_flag_settings` / `set_model` (`applied.effort`, `applied.model`)
- `mcp_set_servers` returns `added` / `removed` diffs
- `reload_plugins`, `background_tasks`, `get_usage` and `rewind_files` return their typed shapes
- everything else is acked

`$FAKE_CLAUDE_CONTROL_LOG` records every host→CLI `control_request` / `control_cancel_request` as JSON lines. Raw-output steps: `$stdout_bytes` / `$stderr_bytes` (byte arrays, no newline added) and `$kill` (a signal name or number). Existing env hooks: `$FAKE_CLAUDE_ARGV`, `$FAKE_CLAUDE_LOG` (all stdin), `$FAKE_CLAUDE_PID`, `$FAKE_CLAUDE_EVENTS` (`$mark` labels and stdin EOF, in order) and `$FAKE_CLAUDE_FDS` (the descriptors it inherited). The Session layer passes these through, so `claudius --claude-bin <fake>` with `FAKE_CLAUDE_SCRIPT` set scripts UI e2e runs too.

bump `claudius_agent::SDK_VERSION` (the test refuses fixtures from another version) and port until green.

**Control-request parity:** `node rust/scripts/control-golden.mjs` records what the real SDK replies to every
CLI-initiated `control_request` (79 of them: each subtype the SDK handles or ignores, plus malformed shapes). The

`tests/control_golden.rs` replays the fixture through the Rust `Query` and compares each reply with `JSON.stringify`,
or checks it's absent where the SDK stays silent. `fixture_covers_every_sdk_subtype` ties it to the drift snapshot:
a subtype added in an SDK bump fails until the recorder sends it.

**Single-turn parity:** `node rust/scripts/run-end-golden.mjs` runs the real SDK's string-prompt `query()` against the
fake CLI with scripts that interleave `$mark`s, delays, results and `session_state_changed` messages. The fixture
pins where the SDK closed stdin among the marks, the user line it wrote, what it yielded, and its ceiling-env parser
over 52 raw values. `tests/run_end_golden.rs` replays it through `Query::spawn_prompt`.

**Reader parity:** `node rust/scripts/reader-golden.mjs` (macOS) runs the real SDK's string-prompt `query()` against
the fake CLI with one scripted turn per case, including raw stdout/stderr bytes (`$stdout_bytes`, `$stderr_bytes`) and
signals (`$kill`). The fixture pins what was yielded, the error the stream ended with, and `supportedCommands()` once
it was over. Cases tagged `os` only replay there. `tests/reader_golden.rs` replays them through `Query::spawn_prompt`.

**Cleanup parity:** `node rust/scripts/cleanup-golden.mjs` runs the real SDK's `query()` (streamed and single-turn)
against the fake CLI, or a shell-script CLI that closes its stdin. It walks each case's steps: requests, waits,
`initializationResult()`, reading one message or draining the stream, `abort()` and sleeps. It records how every request, `initialize` and
the stream settled. Each case runs 5 times and must agree, so a race fails the recorder, not the Rust test. Orderings wait on events, not timing margins: the shell CLI prints a line once its stdin is closed and `cli_closed_stdin` waits for it, and a `request` step has written before the next step runs (synchronous in the SDK; the replay polls the request in place up to its reply wait). Fake
directives: `control.<subtype>.$no_reply` (leave a request unanswered, then `$emit` an exit) and `$hold_stdout_ms`
(a grandchild keeps stdout open past the exit). `tests/cleanup_golden.rs` replays the steps through `Query`.

**Binary parity:** `node rust/scripts/binary-golden.mjs` (macOS) records the SDK's package lookup (`xZ`, run with a fake
resolver over platforms, arches, libc and install sets), its not-found template, real launch failures through `query()`,
JS entries run through `node`, and Node's errno names. `tests/binary_golden.rs` replays them; the macOS-only parts skip
elsewhere.

**Redaction parity:** `node rust/scripts/redact-golden.mjs` evaluates the SDK's private `up()` and its pattern list
(sliced out of sdk.mjs between checked anchors) and records 1610 inputs with their redacted output.
`tests/redact_golden.rs` fails if the pattern list differs from `redact::SDK_PATTERNS` (copy the new ones in) or if any
output differs.

**SDK drift:** `rust/scripts/sdk-diff.sh` diffs the installed SDK against `rust/scripts/sdk-snapshot.json`. It covers the
versions, control subtypes (declared, sent, handled, left unanswered), `SDKMessage` kinds, `Options` keys and the names `query()`
destructures, and the CLI env rules. It exits 1 on any difference. **After an SDK bump, run it first:** each
reported change is SDK behaviour to port or re-check. Then run `--update`, bump `SDK_VERSION`, re-record the
fixtures, and classify any new env rule in `crates/claudius-agent/tests/sdk_snapshot.rs`.

**Live smoke (real CLI, needs login, not CI):** `rust/scripts/live-smoke.sh` builds `claudius`, creates a
throwaway workspace under /tmp (`CLAUDIUS_STATE_HOME`), and drives the real `claude` CLI on haiku:
an API turn (PONG), a permission round trip, then the same through the React UI (`--api-only` skips
Next and the browser). It always cleans up its session dir in `~/.claude/projects`. Run it at phase ends.

**Shutdown contract:** on SIGINT or SIGTERM `claudius` ends every session concurrently. `Session::end()`
waits for each CLI to exit (SIGTERM, then SIGKILL after the kill grace), and only then stops HTTP,
force-exiting after 3 s because open SSE streams never finish. No CLI is orphaned, and its last JSONL
writes land before the process exits (`tests/shutdown.rs`).

**Parity e2e:** `bun run test:e2e:rust [-- tests/e2e/<spec>.ts]` runs the unchanged Playwright suite
against the Rust front door. `playwright.rust.config.ts` starts Next on :3178 and Rust on :3179 with
a shared isolated HOME. It shares `.next-e2e` with the normal e2e run, so don't run both at once.
`test:e2e:rust` runs Playwright through two wrappers. **Wrap any other e2e command the same way.**
- `rust/scripts/keep-tree.sh`: many specs write PNGs into `docs/` and `site/screenshots/` unconditionally. After the run, this restores every path there that was clean before it, and leaves already-dirty paths alone.
- `rust/scripts/clean-env.sh`: strips a parent Claude session's env (`CLAUDE_*`, `CLAUDECODE`, `__NEXT_PRIVATE_*`, `NODE_ENV`, `CLAUDIUS_PACKAGED/ELECTRON`) and sets `CLAUDIUS_UPDATER_DISABLED=1`. An inherited `CLAUDE_CONFIG_DIR` points the e2e servers' CLIs and SDK listing at the **real** `~/.claude`. That writes transcripts into the user's project dirs and breaks `workspace-move-sessions` on both backends (found by I12). `playwright.rust.config.ts` also pins `CLAUDE_CONFIG_DIR` to the e2e HOME.
Results live in `rust/parity/e2e-status.md`. To refresh them:

```sh
# env: node@22 + bun + node_modules/.bin on PATH (the wrappers clean the rest)
PLAYWRIGHT_JSON_OUTPUT_NAME=/tmp/p/rust.json bun run test:e2e:rust -- --reporter=list,json
# TS baseline over just the failing files; --output keeps the Rust traces in test-results/
rust/scripts/keep-tree.sh rust/scripts/clean-env.sh env NEXT_DIST_DIR=.next-e2e PLAYWRIGHT_JSON_OUTPUT_NAME=/tmp/p/ts.json \
  playwright test --project=chromium --reporter=list,json --output /tmp/p/ts-results $(cat rust/parity/failing-specs.txt)
python3 rust/scripts/parity-report.py /tmp/p/rust.json --baseline /tmp/p/ts.json
```

The report reads each failure's trace (`test-results/**/trace.zip`) to find the `/api` error behind it. It caches those errors in `rust/parity/e2e-status.json`, so a rerun after the traces are gone keeps the categories.

For a manual check against the real UI, run Next with a gitignored dist dir (`NEXT_DIST_DIR=.next-e2e`). Tailwind v4 scans every non-ignored file, and a non-ignored build dir floods it with garbage class candidates. Then point Playwright at the Rust port.
