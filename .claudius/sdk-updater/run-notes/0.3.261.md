## Summary

0.3.261 is a small point release: it adds an opt-in `pluginDelivery:
'initialize'` mode for large plugin counts (a Windows command-line-length
fix Claudius doesn't hit, since we never pass `options.plugins` to
`query()` at all — plugins are managed through the CLI's own
marketplace/settings files), an `opts.skipBehaviors` parameter on the
experimental `usage_EXPERIMENTAL_…` plan-usage call, a new
`reloadOutputStyles()` control method, an optional `no_response` cause on
the `api_retry` system message, two new `Settings` keys
(`bashOutputMaxChars` / `taskOutputMaxChars`), a doc-only deprecation of
`Settings.keybindingFlavor`, and a doc-only broadening of what counts as
an `ambient` background task. We shipped four of these: `skipBehaviors`
on the usage call (a free latency win — Claudius never reads the
`behaviors` field it would otherwise fill), dedicated spinner copy for
`no_response` retries, the two new Settings catalog rows, and a
deprecation-aware description update for `keybindingFlavor`. We also
refreshed three code comments whose "auto-started only" description of
`ambient` watchers is now stale. `pluginDelivery` and
`reloadOutputStyles` are genuinely unreachable/unbuilt surfaces for
Claudius today (see the skip reasoning below) — the headline risk to
flag for review is purely that judgment call on `reloadOutputStyles`,
since it's the one item where "we could build a small feature" and "we
chose not to" is a real trade-off, not a hard unreachability.

## SDK changelog highlights

- `pluginDelivery: 'initialize'` (send `plugins` over stdin instead of
  growing the argv) — `[skipped — unreachable]`. Verified via
  `rg -n "options.plugins|plugins:" lib/server/session.ts`: the `Options`
  object Claudius builds for `query()` never sets `plugins` (plugins are
  installed/enabled through `lib/server/plugins.ts` + the CLI's own
  marketplace/settings files, surfaced on `/plugins`, and reloaded live
  via the pre-existing `reloadPlugins()` control call — not passed as an
  SDK launch option). `pluginDelivery` only matters when `options.plugins`
  is non-empty, so there is no code path for it to affect.
- "Fixed `query()` throwing 'Object not disposable' in runtimes without a
  native `Symbol.dispose`" — `[skipped — doesn't affect us]`. This targets
  Jest's `node` environment and vitest's `vmThreads`/`vmForks` pools.
  Claudius's `vitest.config.ts` pins `environment: "node"` (no vm-context
  pool), so we never hit the broken path either before or after the fix.
- "Updated to parity with Claude Code v2.1.261" — no further detail in the
  upstream bullet; covered by the type-surface diff below instead.

**New declarations** (type-surface diff):

- `pluginDelivery` (`Options`) — `[skipped — unreachable]`, see above.
- `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET(opts?: { skipBehaviors? })`
  / `skipBehaviors` (inner) — `[shipped]`. `lib/server/session.ts`'s
  plan-usage fetch now passes `{ skipBehaviors: true }`: it reads only
  `usageData.rate_limits` (confirmed via
  `rg -n "\.behaviors\b" lib/server`, zero hits) and never the
  `behaviors` section this flag skips computing, so this is a pure
  latency win with no shape change.
- `reloadOutputStyles()` / `SDKControlReloadOutputStylesRequest` /
  `SDKControlReloadOutputStylesResponse` / `available_output_styles` /
  inner `subtype` — `[skipped — no UI surface to wire it to]`. Claudius
  does have an `outputStyle` setting (`lib/server/settings.ts`,
  free-form string) rendered as a `<select>` on `/settings`
  (`OUTPUT_STYLES = ["default", "explanatory", "concise", "developer"]`,
  a hardcoded constant, `app/settings/page.tsx`), but that page is
  cwd-scoped, not session-scoped — it has no live `Query` handle to call
  a control method on, unlike `/plugins` (which already threads a
  `sessionId` through for exactly this kind of live-reload call via
  `reloadPlugins()`). Wiring `reloadOutputStyles()` in would mean adding
  a session-scoping concept to a page that's deliberately files-only, a
  larger architectural change out of proportion to this point release.
  Flagged in Risks/follow-ups as a legitimate candidate for a dedicated
  pass.
- `no_response` / inner `waited_ms` / `retry_wait_ms` (on

  `skipBehaviors` bullet above) — `[shipped]`. `ApiRetryState` gained an
  optional `noResponse` field, `use-session.ts` parses it off the raw
  `api_retry` system message, and `describeApiRetry` now shows "Anthropic's
  API didn't respond in time — retrying…" instead of the generic/
  reason-named copy that would otherwise misleadingly imply an HTTP error
  occurred.
- `plugins` (on `SDKControlInitializeRequest`) / `plugins_applied` (on
  `SDKControlInitializeResponse`) — `[skipped — unreachable]`, same
  reasoning as `pluginDelivery`: both are only populated when
  `options.plugins` is set, which Claudius never does.
- `SDKControlRequestInner` — `[skipped — internal, non-exported type]`.
  Declared with `declare type` (no `export`), so it isn't part of the
  package's importable public surface; it only widened because
  `SDKControlReloadOutputStylesRequest` joined its union.
- `bashOutputMaxChars` / `taskOutputMaxChars` (`Settings`) — `[shipped]`.
  Added to the `ClaudeSettings` type and to `SDK_SETTINGS_CATALOG` on
  `/settings` (new "Shell" rows, `type: "number"`, defaults 30000/32000,
  clamp 4000-128000 noted in the description) — config-passthrough only,
  same treatment as the existing `defaultShell`/`keybindingFlavor` rows:
  both are read by the bundled `claude` binary directly from
  `~/.claude/settings.json` when it truncates a Bash/TaskOutput tool
  result, with no browser-side truncation logic to mirror.

**Raw `.d.ts` diff, doc-only changes** (no new declarations, but real
semantic content):

- `Settings.keybindingFlavor` JSDoc now reads "Deprecated: no longer has
  any effect. The prompt's word-editing keys always follow Bash
  (readline) conventions." — `[shipped]`. Updated both the
  `lib/server/settings.ts` field comment and the `SDK_SETTINGS_CATALOG`
  row's user-facing `desc` on `/settings` to say so, instead of
  continuing to promise Ctrl+W behavior the SDK no longer provides. Left
  the key itself in place (Claudius never strips unknown/stale keys from
  a hand-edited settings.json).
- `ambient` on `task_started`/`task_notification`/
  `background_tasks_changed`: "auto-started live-update watchers" →
  "every live-update watcher, requested or auto-started" — `[type-only]`.
  No new field and no behavior change on our side (`ambient` is still a
  plain boolean we pass through verbatim: `lib/server/session.ts`,
  `lib/client/use-session.ts`, `lib/server/session-tasks-db.ts`,
  `isActivityCountableTask()` all just read the flag), but three code
  comments described the old, narrower semantics — updated in
  `lib/client/task-status.ts` and twice in `lib/server/session.ts` so
  they no longer say "auto-started" when the SDK now also flags
  user-requested watchers ambient.
- `SDKControlInterruptResponse.still_queued` doc — `[type-only]`. Much
  longer JSDoc describing a "latched" interrupt case during the
  first-command prewait window, but the field shape is unchanged
  (`string[]`) and Claudius's `interrupt()` wrapper
  (`lib/server/session.ts`) already treats it as an opaque uuid list
  (`{ stillQueued: receipt?.still_queued ?? [] }`) — nothing to change.
- `SDKControlInterruptRequest.cancel_queued` doc — `[skipped — not called
  with this option]`. Claudius calls `this.query.interrupt()` with no
  arguments; `cancel_queued` isn't part of our call path either before or
  after this doc update.

## Risks / follow-ups

- `reloadOutputStyles()` is a judgment-call skip, not a hard
  unreachability like `pluginDelivery`/`plugins_applied`: Claudius does
  have an `outputStyle` setting, and the settings page's output-style
  `<select>` is currently a hardcoded 4-entry list
  (`OUTPUT_STYLES` in `app/settings/page.tsx`) that can't reflect a
  user's custom output styles at all, live-session-reload or not. A
  follow-up could either (a) thread a `sessionId` into `/settings` the
  way `/plugins` already does and wire `reloadOutputStyles()` to a
  "refresh" affordance next to the dropdown, or (b) more simply, read
  custom output styles off disk on the settings API route without
  touching the SDK's live-session control protocol at all. Neither was
  in scope for this point release.
- The `keybindingFlavor` settings-catalog row is now dead weight (the
  key has no effect upstream) but was kept rather than removed, since
  Claudius never strips unknown/stale settings.json keys and a user may
  still have it set from before the deprecation. Worth revisiting removal
  once enough time has passed that stale values are unlikely.
- None of the four gates (`lint`/`test`/`build`/`test:e2e`) surfaced any
  pre-existing failures unrelated to this bump; nothing else to flag.
