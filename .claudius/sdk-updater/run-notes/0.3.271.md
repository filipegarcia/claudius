## Summary

`package.json` was already at `^0.3.270` before this run's bump commit (not
`0.3.267` as the orchestrator prompt assumed — see "Risks / follow-ups"), so
the vast majority of the 0.3.268–0.3.270 changelog window (`defaultToNo`/
`suppressAlwaysAllowRule`, `reloadPlugins({ holdOnCacheImpact })`,
`SDKRateLimitInfo.limitScope`, the context-usage `kind` field,
`SDKAssistantMessageError`'s `verification_required`, `bashEditDiffEnabled`,
`prependPlugins`/`appendPlugins`/`gatewayInternalNetworks`) was already
implemented and merged to `main` by earlier `sdk-update/0.3.268`/`0.3.269`/
`0.3.270` cycles — this run only had to *verify* those, not re-ship them.
The real net-new surface for this window is 0.3.271 itself: one genuinely
actionable, reachable addition — `AgentDefinition.omitClaudeMd` — which this
PR ships end-to-end (DB-agent coercion + `.claude/agents/*.md` frontmatter
badge in the Agents editor, confirmed against the bundled `claude` binary
that the field is honored via frontmatter, not just the programmatic
`agents` option). Everything else in the 0.3.271 type-surface diff — the new
`get_hooks_listing`/`list_permission_rules` control-protocol types, the
`rename_session` `session_id`/`source` fields, the `sdk-tools.d.ts`
`staged`/`written`/`foreign`/`icon` additions, `resume_reason` — is audited
and either confirmed unreachable from the SDK's *exported* `Query` interface
(verified by enumerating it directly) or absorbed for free through
Claudius's existing generic `SDKMessage`-typed passthrough. Headline risk
for review: the stale local-`main` baseline above means a reviewer diffing
this PR against the *prompt's* stated 0.3.267 baseline will see far fewer
hunks than the changelog volume implies — that's expected, not a missed
item; see "Risks / follow-ups" for the verification trail.

  "^0.3.270"` immediately before this run's bump commit (`f5c604f`), not
  `^0.3.267` as the orchestrator prompt's changelog/type-surface diff
  assumed. `git log --oneline` on this branch shows merged
  `sdk-update/0.3.268`, `/0.3.269`, `/0.3.270` PRs (#243, #251, #253)

  earlier run (`7e6af43 docs(sdk-update): ... document stale local main
  ref`) — worth checking whether the orchestrator's "current version" probe
  is reading a stale `origin/main` ref (per the operator's own note that a
  scoped `git fetch` can leave `origin/<branch>` stale). Net effect here is
  cosmetic (this run correctly found almost everything already shipped),
  but on a window where something real had regressed on `main` between
  0.3.267 and 0.3.270, that regression could hide behind this same
  "already on main" reasoning — worth a periodic `git ls-remote` sanity
  check in the orchestrator itself.
- `Settings.managedSourcesBehavior` still has no row in
  `SDK_SETTINGS_CATALOG` (`lib/server/settings.ts` / `app/settings/page.tsx`)
  despite being a settings-file key since the 0.3.245 window. Not touched
  in this PR (predates this window's diff), but worth a follow-up settings
  catalog pass.
- The `omitClaudeMd` frontmatter behavior was verified by `strings`-grepping
  the compiled `claude` binary (`node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`)
  rather than a documented API, since the SDK's own `.d.ts`/`.mjs` bundle
  doesn't reference frontmatter parsing at all (that lives entirely in the
  separate platform-specific `claude` binary package). This is the most
  reliable verification available short of an end-to-end run against the
  real agent, but it's binary-inspection evidence, not a published
  contract — if a future CLI release changes the frontmatter key set, the
  new "no CLAUDE.md" badge would silently stop reflecting reality (it would
  just never show, since `fm.omitClaudeMd` would stay `undefined`) rather
  than erroring.
