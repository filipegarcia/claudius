# SDK update 0.3.218 → 0.3.220

This branch was continued by the orchestrator from PR #168
(`sdk-update/0.3.219`, opened for the 0.3.218 → 0.3.219 half) rather
than cut fresh, so it now covers the full 0.3.218 → 0.3.220 range in
one PR. This file is the combined, stand-alone story for that whole
range — the 0.3.219 half's own notes still live at
`.claudius/sdk-updater/run-notes/0.3.219.md` with more detail, but
everything a reviewer needs is condensed here too.

## Summary

Two releases landed on this branch. **0.3.219** (six changelog items)
shipped in commits `c603e1e`/`1c106c4`, before this run started: the new
`fast_mode_disabled_reason` field is now surfaced as specific copy on the
StatusLine's `⚡ cooldown` chip and the fast-mode cooldown toast, the new
`Settings.workflowSizeGuideline` got a Settings → Model & behavior catalog
row forwarded to the SDK's flag layer, and the new `DirectoryAdded` hook
event was added to the `/hooks` editor's event list. The other three
0.3.219 items (`cancel_queued` on interrupt, the `fast_mode_state` init
bugfix — handled as type-only, `sandbox.network.strictAllowlist`) were
audited and legitimately skipped/type-only; see the 0.3.219 notes for the
full reasoning. **0.3.220** itself is a pure parity bump ("Updated to
parity with Claude Code v2.1.220", vendored CLI 2.1.219 → 2.1.220) with
**zero public API surface change**: `diff -rq` between the unpacked
`@anthropic-ai/claude-agent-sdk` 0.3.219 and 0.3.220 npm tarballs shows
`sdk.d.ts`, `sdk-tools.d.ts`, `agentSdkTypes.d.ts`, and `browser-sdk.d.ts`
byte-identical; only the minified runtime bundles (`sdk.mjs`, `bridge.mjs`,
`browser-sdk.js`) and the vendored native-binary checksums in
`manifest.json`/`manifest.zst.json` changed. This run's only code change is
therefore the version bump itself (`package.json` + `bun.lock`, commit
`c2e2999`) — this run added no further Claudius code. Headline risk:
identical to the one already flagged in the 0.3.219 notes — the fast-mode
UI is only exercised via mocked SSE, not a live SDK session.

## SDK changelog highlights

**0.3.219** (shipped in `c603e1e`/`1c106c4`, before this run):

- `cancel_queued` on the interrupt control request (capability
  `interrupt_cancel_queued_v1`) — `[skipped — no public call site]`.
  `Query.interrupt()` takes zero parameters in `sdk.d.ts`; `cancel_queued`
  lives only on the non-exported `SDKControlInterruptRequest` type.
- `fast_mode_disabled_reason` on result/init messages — `[shipped]`.
  StatusLine chip tooltip + cooldown toast now show the specific reason
  via `lib/shared/fast-mode.ts`'s `fastModeDisabledReasonLabel()`.
- `DirectoryAdded` lifecycle hook event — `[shipped]`. Added to
  `lib/shared/hook-events.ts`'s `HOOK_EVENT_NAMES`/`HOOK_EVENTS`, rendered
  by the `/hooks` editor.
- Initialize response now reports `fast_mode_state` from the post-switch
  model (bugfix) — `[type-only]`. We began reading `fast_mode_state`/
  `fast_mode_disabled_reason` off `system:init` this release
  (`lib/shared/parse-init.ts`), which is what makes the bugfix trustworthy.
- `sandbox.network.strictAllowlist` in SDK settings types —
  `[skipped — nested object, no existing UI surface]`. Lives under
  `Settings.sandbox.network`; `app/settings/page.tsx`'s catalog explicitly
  excludes complex nested objects in favor of the raw-JSON "Other" editor,
  which already round-trips a hand-edited value via `ClaudeSettings`'s
  catch-all index signature.
- `workflowSizeGuideline` in SDK settings types — `[shipped]`. New enum
  row in the Settings → Model & behavior catalog, forwarded to the SDK's
  flag layer in `lib/server/session.ts` alongside `advisorModel`.
- None of the six 0.3.219 items touch model identity, an alias, a default
  model, a context-window default, an effort/thinking tier, or a pricing
  tier — the heightened audit bar doesn't apply to this release.

**0.3.220** (this run):

- "Updated to parity with Claude Code v2.1.220" — `[skipped — no public
  SDK surface changed]`. Confirmed by tarball diff (see Summary): all
  four `.d.ts` files are byte-identical between 0.3.219 and 0.3.220, so
  there is no new export, no changed shape, and nothing for Claudius to
  wire through. Ran the model-identity audit anyway since this is a
  version bump touching the vendored CLI: grepped
  `claudeCodeVersion|2\.1\.21[0-9]|2\.1\.22[0-9]` across `lib/`, `app/`,
  `components/`, `tests/` — the only hard-coded-looking hits are CC-parity
  changelog comments/screenshot paths for unrelated older releases
  (2.1.210–2.1.217) and a test fixture using an unrelated placeholder
  version (`"2.1.99"` in `tests/unit/parse-init.test.ts`). The one real
  runtime read, `app/api/doctor/route.ts`, pulls `claudeCodeVersion`
  dynamically from the installed SDK's `package.json` rather than
  hard-coding it, so it already reflects 2.1.220 with no edit needed.
  No model name, alias, default model, context-window default, effort
  tier, or pricing tier appears in either release's changelog text, so
  the "second failure mode" audit list in the run prompt (STATIC_FALLBACK,
  the probe list, the session-model picker, `ModelInfo`, the
  fable/1m-context gating in `session.ts`, the litellm pricing tiers, the
  model-picker UI) was checked against both changelogs and none of those
  surfaces reference anything either release touches.
