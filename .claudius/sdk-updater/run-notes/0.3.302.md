# SDK update 0.3.301 → 0.3.302

## Summary

0.3.302 is a small parity release (Claude Code v2.1.302). It fixes structured-output results for refused responses, changes the default `permissionMode` on third-party providers when `permissionMode` is omitted, turns fork subagents on by default in SDK sessions, and adds one JSDoc sentence to `AgentInput.effort` (ignored for `subagent_type: "fork"`). The `.d.ts` diff adds no new declarations. In Claudius the only code change is the Agent task card no longer showing an "<level> effort" chip for fork subagents, since the SDK ignores `effort` there. Headline risk: forks are now on by default, so `subagent_type: "fork"` cards will appear in transcripts. They render through the existing `TaskBlock` path.

## Code changes

- `components/chat/TaskBlock.tsx`: skip the "<level> effort" stat chip when `subagent_type` is `"fork"`, because the SDK ignores `effort` for forks and the chip would claim a level that never applied.
- `tests/e2e/cc-parity-2.1.292-agent-effort.spec.ts`: extended the existing effort spec with a fork spawn carrying `effort: "low"` and asserting no effort text on its card.

## New UI surfaces

- No new UI surfaces this release. The only visible change is the absence of an effort chip on fork subagent cards, covered by an assertion in the existing `tests/e2e/cc-parity-2.1.292-agent-effort.spec.ts`; there is no new element to screenshot.

## Risks / follow-ups

- Fork subagents are on by default; Claudius has no setting to toggle `CLAUDE_CODE_FORK_SUBAGENT`. Users can set it via env. Consider a settings toggle later.
- Decision: hid the effort chip for forks rather than showing the parent's effort; the alternative (showing the session's effort) was rejected as extra plumbing for a tiny label.
