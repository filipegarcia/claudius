## Summary

0.3.228 is a one-line changelog release: `AgentOutput.usage` (the
structured tool-result payload the SDK's built-in "Agent" tool — née
"Task" — returns when a subagent invocation completes) now carries
`output_tokens_details.thinking_tokens` through instead of dropping it.
Claudius does not deserialize `AgentOutput` anywhere in its own code —
we never `import` that type, and the token/duration/cost figures we
show for subagents (the `TaskBlock` stats line, the background-tasks
rail) are sourced from separate SDK system messages
(`task_progress`/`task_notification`, shape `{ total_tokens, tool_uses,
duration_ms }`) and from the top-level `assistant`/`result` message
`usage` blocks — none of which changed shape in this release. No
call-site exists to update, so no product code changed. Headline risk
for review: none — this is a version bump with an audited-empty diff.

## SDK changelog highlights

- Agent tool results (`AgentOutput`): `usage.output_tokens_details` is
  now carried through — `[skipped — no Claudius call-site]`. Audited
  every consumer of subagent/Task usage data in the repo
  (`rg -n "AgentOutput|totalToolUseCount|toolStats" lib components app`
  returns nothing beyond the SDK's own `.d.ts`, confirmed by re-running
  it in this session). Claudius's subagent stats
  (`components/chat/TaskBlock.tsx`'s `task.totalTokens` /
  `task.toolUses` / `task.durationMs`) are populated in
  `lib/client/use-session.ts` from the `task_progress` /
  `task_notification` **system messages** (`usage: { total_tokens,
  tool_uses, duration_ms }`), not from the Agent tool's tool-result
  JSON content (`AgentOutput`, defined in `sdk-tools.d.ts`) — those are
  two distinct usage shapes on the wire. The top-level per-turn token
  meters and `$` cost tile (`lib/client/use-session.ts` around the
  `assistant`/`result` message handlers, `lib/shared/cost-pricing.ts`)
  read `assistant.message.usage` / `result.usage`
  (`input_tokens`/`output_tokens`/`cache_*_tokens`), which is a
  different, unaffected type. This is not a model-identity item (no
  model name, alias, default model, context-window, capability tier,
  or pricing tier is touched), so the higher audit bar in the run
  prompt doesn't formally apply — but as a precaution I re-checked the
  model surfaces anyway: `app/api/models/route.ts`,
  `app/api/models/probe/route.ts`,
  `app/api/sessions/[id]/model/route.ts`, `lib/client/types.ts`
  (`ModelInfo`), `lib/server/session.ts` (fable-advisor /
  `enable1mContext` gating), `lib/server/litellm-pricing.ts` +
  `litellm-prices.json`, and `components/chat/ModelPicker.tsx` /
  `FableLaunchTipBanner` — none reference `output_tokens_details`,
  `thinking_tokens`, or any Agent-tool usage field, so there is nothing
  to update there either.
