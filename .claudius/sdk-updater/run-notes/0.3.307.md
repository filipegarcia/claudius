# SDK update 0.3.306 → 0.3.307

## Summary

0.3.307 is a small parity release (Claude Code v2.1.307). It adds two things to the wire/type surface: richer `command_lifecycle` `started` frames for scheduled wakeups/tasks (`wakeup_source`, `scheduled_for`), and a browser-SDK-only `supportedDialogKinds` query option. The `.d.ts` diff also adds one managed Settings key, `sshHostCommands`. None of these are reachable from, or consumed by, Claudius: we use the Node `query()` path, never the browser SDK; we deliberately don't consume `command_lifecycle` frames (they are not in the public `.d.ts` and are excluded from the replay buffer); and we don't surface the sibling Desktop-only SSH settings either. No product code changed — the diff is the version bump plus these notes. Headline risk: none; the only thing to watch is that `command_lifecycle` is still an undeclared (untyped) frame, so `wakeup_source`/`scheduled_for` are only visible as untyped fields on the raw `sdk` event.

## SDK changelog highlights

- `wakeup_source` / `scheduled_for` on the `command_lifecycle` `started` frame (capability `lifecycle_wakeup_source_v1`) — `[skipped — no consumer]`. Neither identifier appears in any shipped `.d.ts` (`rg` over `sdk.d.ts`/`browser-sdk.d.ts`), so there is no typed surface to absorb. `command_lifecycle` frames are deliberately not consumed: `shouldBufferEvent` in `lib/server/session.ts` excludes them from the replay buffer and Claudius's queue UI is driven by the server-side `queued_messages` table. Claudius's own scheduler (`lib/server/`) owns wakeup/loop reconstruction from `ScheduleWakeup` tool input, so it does not need the SDK's source tag. Nothing model-identity related.
- `supportedDialogKinds` on browser SDK `query()` (`browser-sdk.d.ts`, `supportedDialogKinds?: string[]`) — `[skipped — browser SDK only]`. Claudius imports the Node SDK only (`rg "browser-sdk"` finds only the updater script); we pass no `onUserDialog`, and a non-empty list without it throws, so adopting it would be wrong anyway.
- Updated to parity with Claude Code v2.1.307 — `[type-only]`; the full `.d.ts` diff was reviewed (the rest of it is whitespace and a reworded `allowNestedUserNamespaces` JSDoc that drops the "rootless podman or buildah" example — no behavioural change).
- New declaration `sshHostCommands` (`Settings`, `sshHostCommands?: unknown[]`) — `[skipped — Desktop-only managed setting]`. It configures Claude Desktop SSH connections whose host comes from a command. Claudius has no SSH-connection settings surface (no `sshConfigs`/`sshIdentityFile` anywhere in `app/`, `lib/`, `components/`), so a catalog row for the sibling would be inconsistent; the field is `unknown[]`, so there's no typed shape to build an editor on.
- New declaration `supportedDialogKinds` — see above, `[skipped — browser SDK only]`.
- Model-identity audit: nothing in this release touches model names, aliases, defaults, context windows, capability tiers or pricing, so the model surfaces (`app/api/models/route.ts`, `models/probe`, `sessions/[id]/model`, `lib/client/types.ts`, `lib/server/session.ts` 1M gating, `litellm-pricing.ts`, `ModelPicker`) are unaffected.

## Code changes

- No code changes required. The only SDK-visible additions are an undeclared lifecycle-frame field pair we don't consume, a browser-SDK-only option, and a Desktop-only managed setting.

Details: `package.json` / `bun.lock` carry the dependency bump (done by the orchestrator). Every new identifier was checked against Claudius's call sites: Claudius uses the Node SDK (not `browser-sdk`), ignores `command_lifecycle` by design, and has no SSH settings UI. Because none are reachable or useful, wiring them would only add dead code.

## New UI surfaces

- No new UI surfaces this release. All changes are protocol/type additions with no Claudius consumer, so there is nothing to screenshot.

## Tests

- No new tests required. Existing coverage (`tests/unit/should-buffer-event.test.ts`) already pins the `command_lifecycle` replay-buffer exclusion that governs the one frame type that changed. vitest: 0 new, 0 updated; playwright: 0 new, 0 updated.

## Risks / follow-ups

- `command_lifecycle` is still absent from the public `.d.ts`; if upstream types it later, revisit whether the `wakeup_source` tag is worth surfacing (e.g. labelling a turn as scheduled-wakeup-initiated in the transcript).
- If Claudius ever grows a browser-SDK / remote-session path, `supportedDialogKinds` must be set together with `onUserDialog` (non-empty list without the callback throws).
- Flake observed: `sdk-update-0.3.287-prompt-queue.spec.ts` "URL prompt with no elicitationId…" timed out once (58s) in one full-suite run but passes in isolation (14s) and in a second full run (411 passed, 7 skipped). It is load-sensitive and unrelated to this bump (no product code changed).
