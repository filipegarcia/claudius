## Summary

0.3.265 is a small release: five `user_message_uuid` stamping-timing/coverage
fixes on internal turn-tracking fields, a CLI-internal fix for shell `cwd`
persisting across turns, and a doc-only default flip on
`Options.systemPrompt`'s `snapshot` field (recording now defaults **on**
instead of off). The `.d.ts` diff also adds `sdkMcpServerManifests` to an
unexported internal control-protocol type, and two new `method` values
(`project_memory_list`/`project_memory_read`) to the `Projects` built-in
tool's input/output union. Of all of that, exactly one item needed code:
the `systemPrompt.snapshot` default flip is a real behavioural change for
Claudius specifically, because `combinedSystemPromptAppend` (workspace
`systemPromptAppend` + session goal) is recomputed from mutable state on
every `Session.start()` call, including a resume — under the new default a
workspace-append edit made between sessions would be silently frozen out
until the next compaction, with no other delivery path. We now pass
`snapshot: false` explicitly to keep the pre-0.3.265 "render fresh every
launch" behaviour. Everything else audited to a genuine no-op: the
`user_message_uuid` changes only improve an already-tolerant best-effort
consumer (`applyThinkingTokensEstimate` in `lib/client/idle-reconcile.ts`),
the cwd fix is CLI-internal with no field/event surface, `Projects`
already renders through the generic `ToolCall` fallback with zero
special-casing today, and `sdkMcpServerManifests` lives on a type Claudius
never touches (populated internally by the SDK's own in-process MCP
handshake optimisation). Headline risk to flag for review: the
`snapshot: false` call is a deliberate opt-out of the SDK's new
recommended default (which trades prompt-cache-prefix stability and
extended-thinking continuity for staying dynamic) — see "Risks /
follow-ups".

### Raw `.d.ts` diff — doc-only changes (no new declaration, but a real behaviour change)

- `Options.systemPrompt`'s `{ type: 'preset', ... }` and
  `{ type: 'custom', ... }` variants' existing `snapshot?: boolean` field
  (`sdk.d.ts:2242`, `2237`) flipped its **default** from "omitted ⇒ render
  the prompt fresh on every launch" to "omitted or `true` ⇒ record on the
  conversation's first request and replay verbatim on every later
  request/resume until compaction" — `[shipped]`. This is exactly the
  "doc-only semantic change with no new declaration" case the run prompt
  warns about (the `disableArtifact` precedent). Claudius builds
  `Options.systemPrompt` from `combinedSystemPromptAppend`
  (`lib/server/session.ts`), which merges the workspace-level
  `systemPromptAppend` (house-style steering, editable any time via
  workspace settings) with the session goal, and recomputes it fresh on
  every `Session.start()` call — including a resume after the idle-reap
  loop. Under the new default, a workspace-append edit made between
  sessions would be silently ignored on the next resume until the model
  happens to compact, with **no other delivery path** (unlike the
  session-goal half, which has a partial mid-session fallback via
  `takeGoalReminder()`'s one-shot conversation-content reminder — but that
  doesn't cover a goal picked up fresh on resume either). Shipped
  `snapshot: false` explicitly via a new `buildSystemPromptOption()` helper
  in `lib/shared/system-prompt-append.ts` to keep the pre-0.3.265 dynamic
  behaviour. See "## Code changes" and "## Risks / follow-ups" for the
  trade-off this opts out of.

## Code changes

- `package.json` / `bun.lock` — bump `@anthropic-ai/claude-agent-sdk` to
  `^0.3.265` (orchestrator step, already applied before this session).
- `lib/shared/system-prompt-append.ts` — added `buildSystemPromptOption()`,
  a small pure helper that turns a combined append string into the
  `Options.systemPrompt` preset object (or `undefined` when there's nothing
  to append), setting `snapshot: false` explicitly to opt out of the SDK
  0.3.265 default flip described above.
- `lib/server/session.ts` — `Session.start()` now calls
  `buildSystemPromptOption(combinedSystemPromptAppend)` once and spreads the
  result into `Options`, replacing the inline `systemPrompt: { type:
  "preset", preset: "claude_code", append: combinedSystemPromptAppend }`
  literal. Behaviourally identical to before 0.3.265 (fresh render every
  launch); without this change the SDK's new default would apply.
- `tests/unit/system-prompt-append.test.ts` — added a `describe("buildSystemPromptOption")`
  block covering the empty-append (`undefined`) and non-empty-append
  (`snapshot: false` present) cases.

## Risks / follow-ups

- **`snapshot: false` is a deliberate opt-out of the SDK's new recommended
  default, not a neutral no-op.** The rejected alternative was
  `snapshot: true` (or leaving it unset, which now means the same thing):
  per the SDK's own docs this keeps the API prompt-cache prefix stable and,
  with extended thinking, avoids discarding the model's earlier reasoning
  when the prompt changes mid-conversation. We chose `false` because
  Claudius's workspace `systemPromptAppend` is user-editable at any time
  with no other delivery path than a fresh render on the next launch/resume
  — but this does mean Claudius sessions don't get the cache-prefix/
  thinking-continuity benefit the SDK is steering hosts toward. Worth
  revisiting if a future release makes the two properties (dynamic append
  vs. recorded stability) less mutually exclusive (e.g. an explicit
  "re-render on next launch only if the append changed" mode), or if
  prompt-cache costs on long sessions become a measured problem.
- This PR lands on `cc-parity/skip-audit-fixes` rather than a fresh
  `sdk-update/0.3.265` branch — per established convention (this repo
  combines a same-window cc-parity release into the coincident sdk-update
  PR rather than opening a second one), the orchestrator's `state.json`
  shows this run's `inFlight.branch` as the combined branch. Expected, not
  a defect; noted here only so a reviewer isn't surprised the diff also
  contains cc-parity content (restricted-mode toggle, spinner tips, etc.)
  unrelated to this SDK bump.
- Local-environment-only note, not part of this diff: `bun run test` first
  failed 108 specs in this session with a `better-sqlite3` `NODE_MODULE_VERSION`
  mismatch (native module built against a stale Node ABI, most likely left
  over from a prior Electron packaging run in this tree). Fixed by
  rebuilding the native module for the active Node binary
  (`node-gyp rebuild` inside `node_modules/better-sqlite3` using a pyenv
  Python 3.11 interpreter, since the system default Python 3.14 lacks
  `distutils`). This touches only the gitignored `node_modules/` build
  output, nothing in the diff — flagging in case CI or another machine hits
  the same class of failure after an Electron build shares the tree.
