# SDK update 0.3.312 → 0.3.314


## Summary

SDK 0.3.312 → 0.3.314 is a small window: one new startup-failure reason (`sandbox_required_unavailable`), one new permission setting (`permissions.blockWritesOutsideWorkingDirectories`), an alpha `prewarm()` export on the `/core` entry point, a `settingSources` isolation fix, and two parity-only bumps. In Claudius we (1) added a plain-English label for the new startup-failure reason so the "Session failed to start" banner doesn't show the raw code, and (2) added a "Block writes outside working directories" per-scope toggle on `/permissions`, the write-side twin of the existing 2.1.257 reads toggle (type, hook, UI, unit test, Playwright spec + screenshot). Nothing in this window touches model identity, context window or pricing. Headline risk: the new toggle only writes the settings key; enforcement is entirely inside the SDK/CLI, so we rely on it reading the key from every scope.

## Risks / follow-ups

- Enforcement of `blockWritesOutsideWorkingDirectories` is entirely inside the SDK/CLI; we only persist the key, the same trade-off as the reads toggle. Per the SDK docs the CLI keeps plan files, scratchpad and auto-memory writable regardless.
- `prewarm()` could cut cold-start latency once it is stable; revisit when it leaves alpha.
- `backgroundWakesOwner` could drive an extra hint next to the "ends with agent" chip; deliberately not done.
- E2E gate: full `bun run test:e2e` run gave 443 passed, 1 failed, 7 skipped. The failure is `tests/e2e/chat-verbose.spec.ts:90` (`verbose-current` stayed "normal" after clicking the verbose button). Its import graph does not touch any file changed here, and it looks like a hydration-timing flake (click before React attaches handlers). It was not re-run in isolation because tool execution was blocked mid-run; the new 0.3.314 spec passed in the full run. Re-run it before merging.
- The full e2e run regenerates unrelated screenshots under `docs/` and `site/`; those were reverted and should not be committed.
