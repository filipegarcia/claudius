# SDK update 0.3.326 → 0.3.327

## Summary

0.3.327 is a small parity bump (Claude Code v2.1.327). Upstream tightened option validation in `query()` / `startup()` / `prewarm()` (un-serializable options and non-array hook values are now refused), reverted 0.3.326's SDK-MCP tool-result fix, deprecated `createSdkMcpServer()` servers inside an agent's `mcpServers`, and added one new startup-failure reason. Claudius changed in two places: the new `initialize_fields_not_delivered` startup-failure reason now has friendly copy in `STARTUP_FAILURE_REASON_LABELS`, and the per-model `autoCompactWindow` Settings rows no longer warn above 1,000,000 (the SDK now documents per-model windows as "at least 100000"). Everything else was audited against our call sites and needs no change. The gates also needed a Next.js patch bump (16.4.3 → 16.4.6): 16.4.3 triggers a security-advisory nudge that aborts `build` / the e2e dev server and whose dev overlay intercepts clicks. Headline risk: that framework bump rides along in this SDK PR (see follow-ups).

## SDK changelog highlights

- Breaking: `query()` / `startup()` / `prewarm()` refuse options that can't be serialized (circular, BigInt) — [skipped — audited in `sdk.mjs` (`$7`): the check JSON-serializes the initialize-request config entries (e.g. `agents`, `jsonSchema`) and only the *metadata* of each hook matcher (`matcher`, `timeout`, `onFailure`, `whenUnanswered`) — hook callback functions are never serialized, and SDK MCP server instances are not part of the serialized config. Our serialized inputs are DB-loaded agent definitions parsed from JSON (`loadDbAgentsForOptions`), plain strings/booleans, and literal hook matchers with no circular/BigInt fields. Not exercised against a real `query()` in the gates; see risks].
- Breaking: hook options must be arrays (event value and matcher `hooks`) — [skipped — audited: the only `hooks:` option in `lib/server/session.ts` (~L3393) uses literal arrays for every event and every matcher's `hooks`; no Set/generator/object is passed].
- Fixed `task_started` sending Claude Code's own text (task notification) as `prompt` when a background subagent is woken; such events now have no `prompt` — [skipped — Claudius reads no `prompt` field from `task_started` (neither `captureTaskState` in `lib/server/session.ts` nor the `task_started` reducer in `lib/client/use-session.ts`), so there is nothing to guard].
- Fixed background agent reported as still running after a ≥30s `canUseTool` wait — [skipped — engine-side fix, no host API].
- Reverted 0.3.326's SDK MCP tool-result fix for reconnects — [skipped — engine-side; our only in-process server is `claudius_goal` (`buildGoalMcpServer`), whose handler is a fire-and-forget broadcast not sensitive to result routing].
- JSON-RPC `id` of requests to an SDK MCP server back from string to number — [skipped — engine-internal transport detail; `lib/server/mcp-in-process.ts` / the goal server use `createSdkMcpServer()` and never see raw JSON-RPC ids].
- Background MCP retries for remote https hosts now run ~1 day — [skipped — engine behaviour, no option or type surface].
- Deprecated `createSdkMcpServer()` servers in an agent's `mcpServers` (ignored with warning) — [skipped — audited: we pass an SDK MCP server only in top-level `mcpServers` (`claudius_goal`, session.ts ~L3112), which is the recommended location; DB-backed agents (`loadDbAgentsForOptions`) carry only name / inline-config JSON, never a live server instance].
- Updated to parity with Claude Code v2.1.327 — [type-only].

## Code changes

- `lib/client/use-session.ts` — added `initialize_fields_not_delivered` to `STARTUP_FAILURE_REASON_LABELS` so the new SDK 0.3.327 startup-failure reason renders friendly copy.
- `tests/unit/startup-failure-reason-labels.test.ts` — added the new reason to the pinned `REASONS` list.
- `lib/shared/auto-compact-window.ts` — `autoCompactWindowInputWarning` / `isAutoCompactWindowOutOfRange` take a `perModel` option that drops the upper (1M) bound.
- `app/settings/page.tsx` — per-model and "add model" `autoCompactWindow` rows pass `perModel`; `AutoCompactWindowWarning` shows "Below 100,000" copy for them.
- `tests/unit/auto-compact-window.test.ts` — new per-model-floor-only / top-level-ceiling-kept cases.
- `tests/e2e/cc-parity-2.1.304-auto-compact-suffix.spec.ts` — updated for the new per-model copy; asserts 2M gives no warning and 50k still does.
- `package.json` / `bun.lock` — SDK bump to `^0.3.327` (done by the orchestrator, earlier commit); plus `next` 16.4.3 → 16.4.6 (patch release that clears the Next security-advisory nudge which otherwise killed `build` and the e2e dev server mid-run).
- `tests/e2e/app-functionality.spec.ts` — "workspace switcher opens on click of the rail toggle" retries the toggle click (only while `aria-expanded` is not `true`) via `toPass`, since a click before hydration was occasionally dropped on a cold dev server.
- `tests/e2e/whats-new.spec.ts` — "Got it closes the window" now waits for the chat's `?session=` bind before clicking the version label (same wait its sibling test already has); the click was being lost to that pre-existing race.

## Risks / follow-ups

- **Framework bump rides along:** `next` 16.4.3 → 16.4.6 (patch, `bun add next@16.4.6`). Reason: on 16.4.3 an agent-environment security-advisory nudge exits `next build` / `next dev` with `SecurityFatalError` (retry only allowed within a 5-minute receipt window) and, in dev, leaves a `<nextjs-portal>` overlay that intercepted the `claudius-version` click in `whats-new.spec.ts`. After the bump the nudge no longer appears and build + e2e are clean. `eslint-config-next` stays at 16.2.11 (unchanged). If reviewers prefer, land the Next bump separately on `main` and drop it from this PR.
- Observed e2e flakes under a full single-worker run (each passes in isolation): `sdk-update-0.3.287-prompt-queue.spec.ts` URL-elicitation test, `cc-parity-2.1.284-rate-limit-options.spec.ts`, `cc-parity-2.1.216-sandbox-filesystem-disabled.spec.ts`. Not touched by this PR.
- Running the e2e suite rewrites tracked PNGs under `docs/` and `site/screenshots/`; those regenerated images were reverted and are not part of this diff.
- The new "refuse un-serializable options" validation is not exercised by any gate (no gate runs a real `query()`); audit above says our options are compatible, but a live session start is the real proof.
- Per-model `autoCompactWindow` ceiling was removed on the strength of the SDK's JSDoc alone; if the engine still enforces 1M, the warning is advisory either way (save is never blocked).
