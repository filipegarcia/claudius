# SDK update 0.3.274 → 0.3.275

## Summary

0.3.275 is a small release: five internal bug fixes to deferred tool call
results and fork/session-message ordering (all transparent — Claudius
already uses well-formed UUIDs and doesn't hit the edge cases they fix),
plus a genuinely new `Options.projectConfigRoot` field, `version`/`registry`
additions to the npm marketplace-source schema, and a batch of fields on the
web-only `artifact` tool's input/output shapes. We shipped
`projectConfigRoot`: Claudius already spins up and lets users open sessions
directly inside git worktrees (`WorktreesOverlay`), and without this field
the SDK loads project settings/hooks/`.mcp.json` from *inside* the worktree
— i.e. from whatever the checked-out branch carries — which inverts the
trust model `lib/server/trusted-cwd.ts` exists to enforce. We now point
config loading back at the registered root whenever a session's cwd is a
worktree of one. Everything else in this window is either unreachable from
Claudius's code (the `artifact` tool is a claude.ai web feature; Claudius
never issues or renders it) or doesn't match how Claudius models its own
data (`extraKnownMarketplaces` is a flat `string[]` of refs, never a
structured `{source:'npm'}` object). Headline risk: `projectConfigRoot` is
new, security-adjacent code with no direct e2e coverage (unit-tested only) —
see Risks/follow-ups.

## Code changes

- `lib/server/trusted-cwd.ts` — added `projectConfigRootFor(cwd)`: given an
  already-trusted session cwd, returns the registered root it is a git
  worktree of, or `null` (cwd is a root itself, or unrecognized). Reuses the
  module's existing `trustedRoots()` / `cachedWorktrees()` so the common
  case (cwd is a registered root) costs zero subprocess spawns, and shares
  the worktree cache with `resolveTrustedCwd`. Best-effort — swallows any
  error and returns `null`, matching every other best-effort precompute in
  `session.ts#start()`.
- `lib/server/session.ts` — imports `projectConfigRootFor`; `start()` now
  resolves it for `this.cwd` and forwards it as `Options.projectConfigRoot`
  (conditional-spread, omitted when `null`), so a session opened directly
  inside a worktree (`WorktreesOverlay` → `createSessionAt`) loads project
  settings/hooks/`.mcp.json` from the trusted root instead of the worktree's
  own branch.

## Risks / follow-ups

- `projectConfigRoot` is new, security-adjacent code (it changes which
  directory's hooks/`.mcp.json`/permissions govern a session) with only
  unit coverage on the helper function, not an end-to-end assertion that
  the SDK actually honors it the way we expect. Low risk in practice — the
  option only kicks in for the already-narrow "open a session directly in a
  worktree" path, and the fallback on any resolution error is `null`
  (today's behavior) — but worth a human's eyes before merge.
- Design call, not obviously "correct": when a user opens a session inside
  a worktree, they might in principle want that worktree's own branch-
  carried `.claude` config (e.g. testing a PR that itself changes hooks).
  We chose "always trust the root, never the worktree's branch" because (a)
  `trusted-cwd.ts`'s whole threat model already takes that stance for path
  writes, and (b) the SDK's own `projectConfigRoot` doc frames
  branch-carried config as the thing to route around. Rejected alternative:
  make it opt-in via a per-worktree-session toggle — not built, since
  nothing in the changelog asks for it and it would add UI surface for a
  narrow, security-flavored default we don't think anyone wants overridden
  silently.
- `lib/server/claude-code-changelog.ts` is not updated for CC 2.1.275. It's
  a manually-curated snapshot (see its module doc) that no automated
  sdk-update or cc-parity run has ever touched (checked full git history:
  one commit, unrelated, introduced the file) — out of scope for this PR,
  flagged here rather than guessed at.
- The five upstream bug fixes (deferred-tool-result keys, fork/session-
  message ordering) are all SDK-internal correctness fixes Claudius gets
  for free on the version bump; audited and confirmed no workaround code
  exists on our side to remove (see SDK changelog highlights above).
