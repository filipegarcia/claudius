## Summary

0.3.247 is a small release: it adds an `ambient` flag to
`task_started` / `task_notification` / `background_tasks_changed` task
entries so hosts can exclude CLI housekeeping tasks (e.g. auto-started
live-update watchers) from activity indicators, and it fixes a
long-standing bug where a per-turn `system/init` frame's
`permissionMode` reported the mode at turn *start* instead of the live
mode. Claudius already tracks subagent/background-task state closely
(the "Idle · N running" StatusLine badge, the Activity rail's
attention count), so `ambient` is a real, plumbable feature here — we
now thread it from the wire through persistence to the two indicators
that summarize "how much is running" (server `getStatus()` /
`countActiveBackgroundTasks()` and the client Activity rail's
attention/running counts) without hiding the affected rows from the
Tasks/Running panel itself, matching the SDK's own distinction between
`skip_transcript` (hide from transcript) and `ambient` (exclude from
*indicators* only). The `permissionMode` fix and the `spinnerTipsOverride`
additions (`tips`/`tipsFile`/`label`) needed no code changes — see the
audit below. Headline risk: Claudius has no in-app way to *trigger* an
ambient task itself (it's the CLI's own housekeeping, e.g. live-update
watchers), so the new exclusion logic is covered by unit tests
synthesizing the flag, not by an end-to-end run against a real ambient
task.

## SDK changelog highlights

- Added an optional `ambient` flag to `task_started`, `task_notification`
  and `background_tasks_changed` task entries so hosts can exclude
  housekeeping tasks from activity indicators — **[shipped]**. Plumbed
  through `TaskSnapshotEntry` / `TaskInfo`, persisted in
  `session_tasks.ambient` (migration 017), captured server-side in
  `Session.captureTaskState`, and excluded from `hasActiveSubagents()` /
  `countActiveBackgroundTasks()` (server) and the Activity rail's
  attention/running counts (`BackgroundTasksPanel.tsx`). Rows for
  ambient tasks still render in the Tasks/Running panel — the SDK's own
  JSDoc distinguishes `ambient` (exclude from indicators) from
  `skip_transcript` (hide from transcript), so nothing new is hidden.
- Fixed the `permissionMode` on per-turn `system/init` frames reporting
  the mode at turn start instead of the live mode — **[skipped — pure
  upstream behavior fix, no Claudius call-site change]**. Audited
  `lib/client/use-session.ts:3501`
  (`if (init.permissionMode) setPermissionModeState(init.permissionMode);`)
  — Claudius unconditionally trusts whatever `permissionMode` a
  `system/init` frame reports and has no local staleness workaround to
  remove (no debounce, no "ignore turn-start echoes" logic). The fix
  lives entirely in the SDK binary's message construction; bumping the
  dependency is the entire adoption. It should, if anything, reduce a
  latent flicker where a stale per-turn init frame could clobber an
  optimistic `setPermissionModeState` right after a mode switch
  (`lib/client/use-session.ts:4863`).

## Code changes

- `lib/shared/events.ts` — added `ambient?: boolean` to
  `TaskSnapshotEntry` (the persisted/replayed subagent-task shape).
- `lib/client/types.ts` — added `ambient?: boolean` to `TaskInfo` (the
  client's live task shape).
- `lib/server/db-migrations/017_session_tasks_ambient.sql` — new
  migration adding `session_tasks.ambient` (nullable `INTEGER`,
  0/1/NULL — same convention as `is_backgrounded`), following the
  precedent set by migration 016.
- `lib/server/session-tasks-db.ts` — persist/read the new `ambient`
  column (`RawRow`, `rowToEntry`, `saveSessionTask`'s INSERT/ON
  CONFLICT, `listSessionTasks`'s SELECT).
- `lib/server/session.ts` — `captureTaskState()` now reads `msg.ambient`
  off `task_started` (seed) and `task_notification` (late update, same
  `!= null` pattern as `is_backgrounded`'s `task_updated` patch);
  `hasActiveSubagents()` and `countActiveBackgroundTasks()` now skip
  any task with `meta.ambient === true`, so a housekeeping task can no
  longer pin the StatusLine on "running" / inflate the "Idle · N
  running" count.
- `lib/client/use-session.ts` — `task_started` seeds `ambient` on the
  new `TaskInfo`; `task_notification` carries `ambient` through onto
  both the synthesized fallback task and the merged update;
  `background_tasks_changed` (a level/snapshot signal that, per its
  updated JSDoc, now also re-fires when "an entry's `ambient` flag
  flips") updates the `ambient` field on any already-known task whose
  snapshot value changed, in addition to its existing
  `liveBackgroundTaskIds` bookkeeping. The changed-check normalizes
  with `!!existing.ambient === ambient` rather than a bare `===` —
  caught in adversarial review: a freshly-`task_started` non-ambient
  task has `ambient: undefined`, not `false`, which would otherwise
  read as a spurious "flip" on the very first snapshot and trigger a
  no-op `setTasks`.
- `lib/client/task-status.ts` — new pure helper `isActivityCountableTask()`
  (`!t.ambient`), alongside the module's existing small task-list
  predicates (`isBackgroundTaskLive`, `collectStoppableTaskIds`, …), so
  the exclusion rule is unit-testable without rendering the panel.
- `components/panels/BackgroundTasksPanel.tsx` — the Activity rail's
  `attention` and `runningBg` counts, and the header cue's reveal
  target / title / icon (which section a click on "N running" jumps
  to, and whether it shows the Bot or Terminal icon), now derive from
  `isActivityCountableTask`-filtered `nonAmbientSubagents` /
  `nonAmbientProcessTasks` — while the underlying `subagents` /
  `runningProcessTasks` lists (and thus the rendered rows, the "Tasks
  (N)" section badge, and the Stop-all fan-out) are unchanged —
  matching the SDK's "exclude from indicators, not from panels"
  framing. (An adversarial review pass caught the header cue's
  reveal/title/icon initially still reading the raw, ambient-inclusive
  `subagents.length` — fixed to use the same filtered count `runningBg`
  is built from.)

## New UI surfaces

- No new UI surfaces this release. The `ambient` flag only refines the
  *counting* behind two existing indicators (the StatusLine "Idle · N
  running" badge and the Activity rail's attention/running counts); no
  new visual element, copy, or affordance was added, and the rows those
  counts summarize are still rendered exactly as before. Claudius also
  has no in-app way to make the CLI emit an ambient task (it's
  CLI-internal housekeeping — e.g. auto-started live-update watchers),
  so there's no real state to screenshot the *difference* in; the
  change is covered by unit tests that synthesize the flag instead (see
  Tests below).

## Risks / follow-ups

- The `ambient` flag is inferred to also matter for `hasActiveSubagents()`
  (not just `countActiveBackgroundTasks()`), i.e. a *foreground* ambient
  task no longer pins `getStatus()` to `"running"`. This is a
  conservative reading of "exclude them from activity indicators" (the
  StatusLine dot is exactly such an indicator) but the changelog/type
  diff doesn't explicitly say foreground ambient tasks exist in
  practice — worth confirming against a real CLI build if this ever
  looks wrong in the field.
- `background_tasks_changed` is a *level* signal carrying the full live
  set incl. `ambient` per entry; we only use it to refresh `ambient` on
  tasks Claudius already knows about (via `task_started`) rather than
  creating new task rows from it (consistent with its pre-existing
  ids-only usage). If the CLI ever emits `background_tasks_changed` for
  a task Claudius hasn't seen a `task_started` for yet, that task's
  `ambient` value is silently dropped until a matching `task_started`/
  `task_notification` arrives — low risk today since the panel already
  treats such a task as absent-until-`task_started` for every other
  field.
