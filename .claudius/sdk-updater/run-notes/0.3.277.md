# SDK update 0.3.274 → 0.3.277

## Summary

This branch rolls 0.3.274 → 0.3.277 in three legs (0.3.275, 0.3.276 — both
already landed on this branch with their own run-notes — and 0.3.277, this
run). 0.3.277's own delta is small in bullet count but contains one real
correctness bug for Claudius: the changelog's "Fixed a resumed or forked
session's `total_cost_usd`, `modelUsage` and `get_usage` totals starting at
zero instead of continuing from the earlier turns" directly invalidates the
premise of `foldResultIntoSessionUsage`'s accumulator model in
`lib/server/session.ts`, which was *built* to paper over that exact zero-start
bug by adding a separately-persisted `usageBaseline` on top of the SDK's
per-process running totals. Post-fix, a resumed session's first `result`
already carries its pre-resume cost/modelUsage, so adding our baseline on top
would double-count every dollar earned before the resume. We fixed this with
a reconciliation step that zeroes the cost/token/modelUsage components of the
baseline (but not `numTurns`/durations, which the changelog does not name as
fixed) the first time a post-resume result already reaches or exceeds them.
We also wired the new `updateSettings('userSettings', {effortLevel})` source
into `Session.setEffort` so an in-chat effort pick persists across a
reap→resume the same way `/effort` does in the CLI (previously documented as
a known gap), threaded the new `SlashCommand.builtin` field through the
slash-command picker as a small badge, and corrected a stale Settings-page
description for `taskOutputMaxChars` (the TaskOutput tool it describes was
removed upstream; the JSDoc was reworded to say the setting is a no-op).
Headline risk: the usage-baseline reconciliation is a judgment call on a
field split the changelog doesn't spell out explicitly (see Risks/follow-ups)
— it's conservative (only ever *removes* double-counted dollars, never
invents missing ones) but deserves a human's eyes on the accounting path.

## Code changes

- `lib/server/session.ts` — added `reconcileUsageBaselineOnFirstFold()`
  (pure, exported for testing) and wired it into `foldUsageFromResult()` via
  a new `hasFoldedResultSinceStart` flag: the first successful fold after
  session start probes the raw message's own running totals and, if they
  already reach the persisted/estimated `usageBaseline`'s cost, zeroes the
  baseline's cost/token/modelUsage components (not `numTurns`/durations,
  which the changelog doesn't name as fixed) before folding, so a resumed
  session's total no longer double-counts pre-resume cost.
- `lib/server/session.ts` — `Session.setEffort` now also calls
  `this.query.updateSettings("userSettings", { effortLevel: value })`
  (best-effort, skipped on `"auto"`/clear since the writer doesn't support
  deletion) alongside the existing `applyFlagSettings` live-apply call, so
  an effort pick from the chat's ModelPicker chips persists to
  `~/.claude/settings.json` the same way `/effort` does in the CLI, instead
  of reverting to whatever Settings → Thinking & effort last saved after a
  reap→resume.
- `lib/shared/slash-commands.ts` — added `builtin?: boolean` to
  `SdkSlashCommandInfo` and `SlashSuggestion`; `mergeSuggestions` carries it
  through for SDK-sourced rows.
- `components/chat/SlashCommandPicker.tsx` — renders a small "built-in"
  badge next to a command name when `builtin` is true.
- `app/settings/page.tsx` + `lib/server/settings.ts` — updated the
  `taskOutputMaxChars` description/comment to reflect the upstream
  deprecation instead of describing a tool that no longer exists.

## Risks / follow-ups

- **Usage-accounting reconciliation is a judgment call.** The changelog
  names `total_cost_usd`, `modelUsage`, and `get_usage` as fixed but not
  `num_turns` or the duration fields, so `reconcileUsageBaselineOnFirstFold`
  only zeroes the cost/token/modelUsage components of `usageBaseline` and
  leaves `numTurns`/`durationMs`/`durationApiMs` in the baseline exactly as
  before. If a future SDK release also fixes turn/duration continuity, this
  function's field split needs to grow with it — otherwise turns/duration
  will *undercount* (baseline no longer needed but still added) the same way
  the old code *overcounted* cost. The trigger condition (first fold's
  reported cost ≥ baseline's persisted cost) is a proxy, not a field the SDK
  exposes directly — it can't be verified against a live resumed session in
  this environment (no real Anthropic-backed session available in
  the harness), only against the documented JSDoc semantics and the
  existing unit-test suite's synthetic fixtures. Recommend a human spot-check
  the `/cost` dialog immediately after a real reap→resume on this build.
- `pasted_content` (SDKUserMessage) is deliberately unshipped — see SDK
  changelog highlights. If Claudius later builds "pasted text" collapsing in
  the composer (mirroring the existing `[Image #N]` pattern for images),
  wiring this field is the natural place to plug it in.
- `lib/server/claude-code-changelog.ts` remains a manually-curated snapshot,
  now three CC versions stale (carried forward from the 0.3.275/0.3.276
  notes; still true, still out of scope for an sdk-update run per its module
  doc).
- None of the three legs' work has an associated cc-parity run yet beyond
  2.1.275 (already combined onto this branch per
  `.claudius/cc-parity/run-notes/2.1.275.md`); 2.1.276/2.1.277 cc-parity is
  tracked separately.
