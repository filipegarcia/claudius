# SDK update 0.3.311 → 0.3.312

## Summary

0.3.312 is a small, parity-with-CC-2.1.312 release. Its public type surface gains auto-mode settings (`autoMode.classifyAllShell`, `skipAutoPermissionPrompt`, `useAutoModeDuringPlan`, and the nested `permissions.disableAutoMode`), a per-question `unanswered` annotation on AskUserQuestion answers (gated on a new `ask_user_question_unanswered_v1` init capability), and one more entry in the `@alpha` `USAGE_TRANSITION_PREFIXES` list. A `resolveSettings()` fix for mistyped managed auto-mode values is also included. In Claudius we wired the four auto-mode settings keys through end to end: types, a shared `isAutoModeDisabled()` predicate used by both the server-side Auto-mode gate and the client picker (so `permissions.disableAutoMode` is honoured), two new Settings-page catalog rows, and a "Classify all shell commands" toggle on the `/permissions` → Auto mode tab. The AskUserQuestion `unanswered` annotation and the usage-transition prefix were deliberately not adopted because Claudius has no producer or consumer for them (see below). Headline risk: `permissions.disableAutoMode` is now read from user scope only, matching the existing top-level key, so a managed-scope value is enforced by the SDK/CLI, not by our picker.

## SDK changelog highlights

- Added `autoMode` to `Settings` (inner fields `allow`, `soft_deny`, `hard_deny`, `environment`, `classifyAllShell`) — `[shipped]`. `AutoModeConfig` gains `classifyAllShell`; the /permissions Auto mode tab has a new checkbox that saves it via the existing `/api/settings/auto-mode` patch route. `allow` / `soft_deny` / `hard_deny` / `environment` were already shipped in 2.1.246 (`[type-only]` for this release, no change).
- Added `skipAutoPermissionPrompt` to `Settings` — `[shipped]`: `ClaudeSettings` type + Settings-page catalog row (Permissions section, boolean).
- Added `useAutoModeDuringPlan` to `Settings` — `[shipped]`: `ClaudeSettings` type + Settings-page catalog row (Permissions section, boolean).
- Added `permissions.disableAutoMode` (`disableAutoMode` under `Settings.permissions`) — `[shipped]`: `PermissionRules.disableAutoMode` type; new `lib/shared/auto-mode-disabled.ts` `isAutoModeDisabled()` now backs `Session.setPermissionMode` (server gate) and `useDisableAutoMode` (client picker), so both the top-level and nested spellings disable Auto mode. Mistyped values (e.g. `true`) are ignored, matching the CLI.
- Added `unanswered` (`skipped` | `replied_in_chat` | `dismissed`) to AskUserQuestion per-question `annotations` (`sdk-tools.d.ts`), only to be sent when `system/init` lists `ask_user_question_unanswered_v1` — `[skipped — deferred: adopting it changes behaviour]`. A producer does exist: `AskUserQuestionPrompt`'s Cancel/Esc whole-form dismissal maps to `dismissed`. But today that path resolves the tool call as `behavior: "deny"` (`Session.submitAskAnswer`), and annotating it means turning that deny into an `allow` with `unanswered` annotations — a model-visible behaviour change we did not want to ship unreviewed in a parity bump. It would also need `capabilities` parsed out of `system/init` (`lib/shared/parse-init.ts`, not parsed today) so the annotation is only sent to a session that advertises `ask_user_question_unanswered_v1` (older CLIs on a strict host refuse the whole answer). `submit()` itself requires every question answered, so per-question `skipped` has no producer. I did not verify whether a composer message sent while an Ask is pending settles it (`replied_in_chat`).
- Fixed `resolveSettings()` returning mistyped managed auto-mode settings as written; invalid user/project auto-mode keys are now skipped — `[skipped — behaviour fix, no call-site impact]`. Our only `resolveSettings` callers (`lib/server/model-pricing-override.ts`, `lib/server/cost-aggregate.ts`) read `modelPricing`, not auto-mode keys.
- `USAGE_TRANSITION_PREFIXES` (new entry `'Now using credits'`, `@alpha` runtime const in `sdk.d.ts`) — `[skipped — no consumer]`. `lib/shared/rate-limit-prefixes.ts` deliberately mirrors only `USAGE_LIMIT_ERROR_PREFIXES` (transition prefixes are toast/footer-only upstream and we have no detector for them); the sync test covers only the limit list, which is unchanged.
- `disableAutoMode` / `skipAutoPermissionPrompt` / `useAutoModeDuringPlan` / `autoMode` / `unanswered` / `USAGE_TRANSITION_PREFIXES` — all new-declaration identifiers are positioned above.
- `ClaimOptions.settings` / `SpareProcess` doc rewording (overlay applies ahead of the claim; `settings_not_applied` now carries `.claim` in some cases) — `[skipped — Claudius does not use prewarm()/claim()]`.
- `SDKSystemMessage.capabilities` / `effort` JSDoc rewording (adds `ask_user_question_unanswered_v1`) — `[type-only]`, doc-only, no behaviour change.
- Updated to parity with Claude Code v2.1.312 — `[skipped — engine-side parity; no host-visible surface beyond the items above]`.
- Model-identity audit: nothing in this window touches a model name, alias, default model, context window, capability tier, or pricing tier; no `modelPicker` / `modelPricing` / `[1m]` change in the `.d.ts` diff, so none of the `/api/models` routes, `ModelPicker`, or the pricing tables needed changes.

## Risks / follow-ups

- Environment: the gates only ran green with Node v22.22.0 first on `PATH` (`~/.nvm/versions/node/v22.22.0/bin`). The default `/opt/homebrew/bin/node` is v26 (ABI 147) while `better-sqlite3` in `node_modules` was built for ABI 127, so under the default `PATH` `bun run test` fails ~176 SQLite-backed tests with `NODE_MODULE_VERSION` mismatch — unrelated to this diff. I did not rebuild `node_modules`.
- `permissions.disableAutoMode` is read from user scope only (same as the top-level key, per the 2.1.207 scope restriction). A value set in managed settings is enforced by the CLI/SDK but our picker won't hide "Auto" for it; revisit if we start surfacing managed settings.
- `unanswered` AskUserQuestion annotation is not wired: no per-question skip/reply-in-chat/dismiss path exists. If a "skip question" affordance is added, parse `capabilities` from `system/init` (`lib/shared/parse-init.ts`) and send `annotations[q].unanswered` only when `ask_user_question_unanswered_v1` is advertised.
- `skipAutoPermissionPrompt` / `useAutoModeDuringPlan` are plain settings toggles; Claudius has no Auto-mode opt-in dialog of its own, so they only edit the value the CLI reads.
