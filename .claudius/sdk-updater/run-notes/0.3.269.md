## Summary

0.3.269 is a small, mostly-internal release: five bug fixes (assistant-message
UUID stamping timing, a `permission_denials` omission, an OAuth-sign-in
interrupt delay, a missing `tool_use_id` on auto-resumed background subagents,
and plan mode now always routing writes through `canUseTool`) plus a CC
2.1.269 parity bump, and one new `Settings` field (`bashEditDiffEnabled`). The
type-surface diff adds two new CLI-menu-parity control requests
(`get_hooks_listing`, `list_permission_rules`) and a "staged tool write" /
artifact-provenance vocabulary (`FileEditOutput.staged`, `FileWriteOutput.staged`,
`ArtifactOutput.written`/`foreign`) — but every one of those, plus all five
changelog bug fixes, verified out as unreachable or already-handled for
Claudius (see below; each line names the exact grep/read that closed it). The
one real, actionable change is the `bashEditDiffEnabled` settings-catalog row,
which is shipped. Headline risk for review: this is a thin diff by design —
the audit trail below is the evidence that the thinness is earned, not
skipped-for-convenience; a reviewer should spot-check the two "no Query
method" claims (`get_hooks_listing`, `list_permission_rules`) against
`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`'s `declare interface Query`
block if they want independent confirmation.

## SDK changelog highlights

- `user_message_uuid`/`user_message_uuids`/`resume_reason` now also stamped
  on a turn's first complete assistant message, not just its first stream
  event — `[skipped — not consumed]`. `session.ts` never reads any of these
  three fields off `SDKAssistantMessage` (grepped the full 8266-line file:
  zero hits). The only place Claudius reads a `user_message_uuid` at all is
  client-side, off the unrelated `SDKThinkingTokensMessage` subtype
  (`lib/client/use-session.ts:3883-3894` → `lib/client/idle-reconcile.ts`'s
  `applyThinkingTokensEstimate`), whose stamping rule is untouched by this
  release. No dedup/first-message-of-turn logic exists to be affected.
- Fixed `result.permission_denials` omitting Read/Edit/Write calls blocked by
  a path-scoped deny rule — `[skipped — not consumed]`. Claudius's "Recent
  Denials" UI (`/permissions`, `useRecentDenials`) is fed entirely by
  watching `system` messages with `subtype === "permission_denied"` as they
  stream through `broadcast()` (`session.ts:7027-7038`,
  `getRecentDenials()` at `session.ts:5914`) — never by the `result`
  message's `permission_denials` array, which has zero references anywhere
  in `session.ts`.
- Fixed interrupts/permission responses delayed by a slow host-started MCP
  OAuth sign-in — `[skipped — internal timing fix]`. This is scheduling
  behavior inside the CLI's control-channel handling; Claudius doesn't
  manage OAuth sign-in timing itself and has no call site that could be
  affected either way.
- Fixed missing `tool_use_id` on `task_started`/`task_notification` when the
  CLI auto-resumes a background subagent — `[skipped — already defensive]`.
  Both the server (`captureTaskState()`, `session.ts:7645-7803`, stores
  `msg.tool_use_id` into an already-optional `toolUseId` field) and the
  client (`lib/client/use-session.ts:3688-3737`, guards every lookup with
  `t.tool_use_id ? … : null`) already treat this field as optional and
  degrade gracefully (task row created, just not back-linked) rather than
  assuming presence. The upstream fix means that graceful-degradation path
  fires less often; no Claudius code needs to change.
- Changed plan mode to always route writes through `canUseTool` even when
  `allowDangerouslySkipPermissions` is set — `[skipped — verified no-op]`.
  Repo-wide `rg -n "allowDangerouslySkipPermissions"` (excluding
  `node_modules`) turns up exactly two hits, both in
  `scripts/sdk-update/` (this run's own off-limits harness, per the prompt's
  "updater's own harness is off the migration surface" rule) — zero hits in
  any app code (`app/`, `lib/`, `components/`). Claudius never sets this
  flag, so this behavior change cannot affect us.
- Updated to parity with Claude Code v2.1.269 — `[skipped — tracked by the
  separate cc-parity pipeline]`, out of scope for this SDK-version bump.

**New declarations** (type-surface diff):

- `SDKControlGetHooksListingRequest` / `SDKControlGetHooksListingResponse`
  (and every inner field: `events`, `hooks`, `eventCatalog`, `policy`,
  `safeMode`, `bareMode`, `errors`) — `[skipped — unreachable]`. `subtype:
  'get_hooks_listing'` is a member of the internal `SDKControlRequestInner`
  union, but the exported `Query` interface (verified by listing every
  method name declared on `declare interface Query` in `sdk.d.ts`:
  `accountInfo`, `applyFlagSettings`, `backgroundTasks`, `close`,
  `getContextUsage`, `initializationResult`, `interrupt`, `mcpServerStatus`,
  `readFile`, `reconnectMcpServer`, `reinitialize`, `reloadOutputStyles`,
  `reloadPlugins`, `reloadSkills`, `rewindFiles`, `seedReadState`,
  `setMaxThinkingTokens`, `setMcpPermissionModeOverride`, `setMcpServers`,
  `setModel`, `setPermissionMode`, `stopTask`, `streamInput`,
  `supportedAgents`, `supportedCommands`, `supportedModels`,
  `toggleMcpServer`, `updateSettings`,
  `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`) has **no**
  method that issues this request. It powers the CLI's own `/hooks` menu
  internally; Claudius's `/hooks` page is a separate, file-based UI
  (`app/api/hooks/route.ts` reads/writes settings files directly via
  `lib/server/hooks.ts`) that never goes through the SDK's control channel
  for this. There is no supported way to request this data.
- `SDKControlListPermissionRulesRequest` / `SDKControlListPermissionRulesResponse`
  / `SDKControlPermissionRulesState` / `SDKPermissionRuleEntry` /
  `SDKPermissionRuleDescription` / `SDKPermissionWorkspaceDirectory` —
  `[skipped — unreachable]`, same reasoning as above: `subtype:
  'list_permission_rules'` has no corresponding `Query` method in the list
  verified above. Claudius's `/permissions` page (`useRecentDenials`,
  `usePermissions`) reads/writes settings-file rule arrays directly and has
  no live-session-state view to extend with this payload even if it were
  reachable.
- `SDKControlRequestInner` (union gains the two subtypes above) —
  `[type-only]`. Internal type, not referenced by Claudius code; noted for
  completeness since it's the type that actually changed shape in this
  release (the two request/response pairs above are new members of it).
- `session_id` (new optional field on `SDKControlRenameSessionRequest`) and
  its sibling `source?: 'remote' | 'host'` — `[skipped — different rename
  path]`. Claudius's `Session.rename()` (`session.ts:3033-3057`) never
  issues `SDKControlRenameSessionRequest` at all — it writes its own DB
  (`setSessionTitle`, authoritative) and then best-effort calls the SDK's
  separate top-level exported `renameSession(sessionId, title,
  SessionMutationOptions)` function (an offline JSONL-header mutation
  helper, `sdk.d.ts:2985`), which takes `SessionMutationOptions` (just
  `dir`) and has no relationship to the control-channel rename request used
  internally by the CLI's own live `/rename`. Verified by reading both type
  definitions side by side — there is no overlapping field to add.
- `bashEditDiffEnabled` (new `Settings` field) — `[shipped]`. Added as a
  boolean row to `SDK_SETTINGS_CATALOG` in `app/settings/page.tsx`, next to
  the existing `defaultShell` entry it's grouped with upstream.
- `sdk-tools.d.ts`: `ArtifactOutput.written` (`{url: string}`),
  `ArtifactOutput`'s `asset_upload`/`asset_delete` variants' `foreign?:
  true`, `FileEditOutput.staged?: boolean`, `FileWriteOutput.staged?:
  boolean` — `[skipped — unreachable / nothing to extend]`. Verified: (a)
  `grep -rn "Artifact|asset_upload|asset_delete|cowritten"` across `lib/`,
  `components/`, `app/` returns zero matches — Claudius has no Artifact-tool
  integration of any kind. (b) The only place Claudius touches a tool
  result's content is `session.ts:4549-4554`'s generic `ToolResultBlock`
  type, which types `content: unknown` — there is no per-tool `FileEditOutput`
  /`FileWriteOutput` parsing to extend (`structuredPatch`/`oldString` never
  appear outside `node_modules`); Claudius's diff previews are built
  independently from git (`lib/server/git.ts`, `lib/shared/diff-overlay.ts`),
  not from tool-result content. (c) There is no "staged / held for
  machine-owner review" tool-call concept anywhere in Claudius's permission
  system (`canUseTool` only ever resolves `allow`/`deny`) to attach these
  fields to.

## Risks / follow-ups

- `get_hooks_listing` and `list_permission_rules` are genuinely useful data
  (live, merged, per-source permission/hook state including session-only
  grants and policy-disabled entries) that Claudius's file-based `/hooks`
  and `/permissions` pages don't currently show. They are unreachable today
  only because the SDK hasn't exported a `Query` method for them yet — if a
  future SDK release promotes either to a public method (watch for
  `getHooksListing()` / `listPermissionRules()` appearing in `declare
  interface Query`), that's a strong candidate for a real live-state panel
  on those two pages. Nothing to do now; flagged for the next upgrade
  cycle's audit.
- Same watch-list note for `FileEditOutput.staged` / `FileWriteOutput.staged`
  / `ArtifactOutput.written` / `foreign`: they describe a "held for machine-
  owner review" tool-call workflow Claudius has no equivalent of yet. If a
  future release adds a corresponding `PermissionResult` outcome (a third
  "staged" behavior alongside `allow`/`deny`), this is the type surface that
  would carry its result — worth re-checking then.
- None of the five changelog bug fixes required verification beyond static
  code review (no repro harness was built) since each was confirmed
  unreachable by grep/read rather than by exercising the bug; if any of
  these reasoning chains turn out wrong on a future audit, that audit should
  start from the file:line citations above rather than re-deriving them.
