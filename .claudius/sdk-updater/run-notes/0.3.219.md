# SDK update 0.3.218 → 0.3.219

## Summary

SDK 0.3.219 is a small release: six changelog items, none touching model
identity/pricing/context-window defaults. We shipped two of them end-to-end
—`fast_mode_disabled_reason` on the `result`/init messages (now surfaced as
specific copy on the StatusLine's `⚡ cooldown` chip and the fast-mode
cooldown toast, replacing the generic "temporarily unavailable" wording a
code comment explicitly flagged as a gap) and `Settings.workflowSizeGuideline`
(a new enum row in the Settings → Model & behavior catalog, forwarded to the
SDK's flag layer at session start alongside `advisorModel`) — plus the
`DirectoryAdded` hook event, added to the `/hooks` editor's mirror of the
SDK's `HOOK_EVENTS` list. The other three items (`cancel_queued` on
interrupt, the `fast_mode_state` init bugfix, `sandbox.network.strictAllowlist`)
are legitimate skips, audited below. Headline risk: the fast-mode-reason
screenshot spec is the only e2e coverage exercising the new field end-to-end
(mocked SSE, not a live SDK) — see Risks.

## SDK changelog highlights

- **`cancel_queued` on the interrupt control request** (capability
  `interrupt_cancel_queued_v1`) — `[skipped — no public call site]`. Audited
  `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`: the public
  `Query.interrupt()` method is declared `interrupt(): Promise<SDKControlInterruptResponse
  | undefined>` — zero parameters. `cancel_queued` lives only on
  `SDKControlInterruptRequest`, a `declare type` with **no `export`** —
  unreachable from consumer code. `SDKControlInterruptResponse.cancelled` is
  exported, but nothing populates it without a way to set the request field.
  Claudius's `Session.interrupt()` (`lib/server/session.ts`) already forwards
  the `still_queued` receipt end-to-end (0.3.205); there's nothing more to
  wire until the SDK exposes the flag on the public `Query` interface. We
  also don't read any `capabilities` array today, so there's no
  feature-detection gap either.
- **`fast_mode_disabled_reason` on result/init messages** — `[shipped]`. See
  Code changes / New UI surfaces below.
- **`DirectoryAdded` lifecycle hook event** — `[shipped]`. Added to
  `lib/shared/hook-events.ts` (`HOOK_EVENT_NAMES` + a `HOOK_EVENTS` display
  row, category `fs`, matcher hint `slash_command | register_repo_root`
  matching `DirectoryAddedHookInput.source`), which the `/hooks` editor
  renders directly — a genuine UI surface, not just a type mirror.
- **Initialize response now reports `fast_mode_state` from the
  post-switch model** (bugfix, not a new field) — `[type-only]`, not
  skipped. We began reading `fast_mode_state` (and `fast_mode_disabled_reason`)
  off the `system:init` message this release (`lib/shared/parse-init.ts`),
  seeding the StatusLine chip before the first `result` arrives. The bugfix
  is exactly what makes that newly-read value trustworthy right after a
  `/model` switch — noted here so it doesn't read as a contradiction next to
  the init-parsing diff.
- **`sandbox.network.strictAllowlist` in SDK settings types** —
  `[skipped — nested object, no existing UI surface]`. Lives under the
  nested `Settings.sandbox.network` object. `app/settings/page.tsx`'s
  `SDK_SETTINGS_CATALOG` explicitly documents excluding "complex nested
  objects (worktree, attribution, hooks…)" — same category as this field —
  in favor of the generic "Other" raw-JSON editor. Grepped
  `allowedDomains|deniedDomains|allowManagedDomainsOnly|network:` across
  `lib/`, `app/`, `components/`: zero hits — Claudius has **no** sandbox-network
  UI today (the existing `sandboxEnabled`/`sandboxFilesystemDisabled` toggles
  in `WorkspaceForm.tsx` are a different, top-level `Options.sandbox` knob,
  unrelated to this nested `Settings.sandbox.network.strictAllowlist`). The
  field is also scoped to user/managed/CLI settings only — project settings
  are ignored — making it a poor fit for a per-workspace toggle even if we
  built one. A hand-edited value still round-trips untouched through
  `ClaudeSettings`'s catch-all (`[key: string]: unknown`) and the "Other"
  editor. Not a model-identity item, so the higher audit bar doesn't apply;
  building a sandbox-network editor is scope creep past what this release
  requires.
- **`workflowSizeGuideline` in SDK settings types** — `[shipped]`. See Code
  changes below.
- No item in this release touches model identity, an alias, a default
  model, a context-window default, an effort/thinking tier, or a pricing
  tier — the heightened audit bar in the run prompt's "second failure mode"
  section doesn't apply to any of the six items above.

## Code changes

- `lib/shared/fast-mode.ts` (new) — `FastModeDisabledReason` type mirror +
  `fastModeDisabledReasonLabel()`, mapping the ten known SDK reason values to
  human copy, falling back to neutral wording for anything unrecognized (the
  SDK's reason list is an open set).
- `lib/shared/parse-init.ts` — `InitInfo` gains `fastModeState` /
  `fastModeDisabledReason`, tolerantly parsed off the `system:init` message
  (unknown `fast_mode_state` values collapse to `undefined`; the reason
  string passes through raw, per this file's existing schema-drift
  contract).
- `lib/client/use-session.ts` — seeds `fastModeState`/`fastModeDisabledReason`
  from init; the `result`-message handler now also reads
  `fast_mode_disabled_reason` and threads it into the `fastModeNotice` at
  the moment of the cooldown edge. Adversarial review (see Risks) caught
  the reason being write-only-on-presence — a recovery result with no
  reason field left the StatusLine tooltip showing a stale reason from an
  earlier cooldown. Fixed: the reason is now mirrored on every
  `fast_mode_state` observation (cleared on `"on"`, mirrored — including to
  `null` — on `"off"`/`"cooldown"`), and `resetState()` clears it on
  session/tab switch alongside `fastModeState`/`fastModeNotice`.
- `lib/client/types.ts` — `ChatState.fastModeDisabledReason` field;
  `fastModeNotice`'s type gains an optional `reason`.
- `components/chat/FastModeNoticePanel.tsx` — cooldown detail text now
  calls `fastModeDisabledReasonLabel(notice.reason)` instead of a fixed
  string; rewrote the stale "SDK exposes neither a fast-mode reason nor..."
  scope-note (that's exactly the gap 0.3.219 closes) while keeping the
  still-true part (no reset-timestamp countdown).
- `components/chat/StatusLine.tsx` — the `⚡ cooldown`/`⚡ off` chip's
  tooltip now shows the specific reason via the same label helper.
- `components/chat/ChatSurface.tsx` — threads `session.fastModeDisabledReason`
  into `StatusLine`.
- `lib/shared/hook-events.ts` — `DirectoryAdded` added to
  `HOOK_EVENT_NAMES` and `HOOK_EVENTS` (category `fs`).
- `lib/server/settings.ts` — `ClaudeSettings.workflowSizeGuideline` typed
  field + `WorkflowSizeGuideline` type + `WORKFLOW_SIZE_GUIDELINE_VALUES` /
  `isWorkflowSizeGuideline()` guard, used to validate a hand-edited
  settings.json value before forwarding it to the SDK.
- `lib/server/session.ts` — the session-start `settings` flag-layer spread
  (previously gated on `includeCoAuthoredBy`/`advisorModel` alone) now also
  triggers on, and forwards, a valid `workflowSizeGuideline`. The outer
  ternary condition was extended (not just the inner spread) — a value-only
  addition to the inner object would have been silently dropped whenever
  `workflowSizeGuideline` was the *only* Settings-level flag set.
- `app/settings/page.tsx` — `workflowSizeGuideline` added to
  `SDK_SETTINGS_CATALOG` as an `enum` row (Model & behavior section,
  options `unrestricted`/`small`/`medium`/`large`) — renders via the
  existing generic catalog UI, no new component needed.

## Risks / follow-ups

- The fast-mode-disabled-reason wiring is verified against a mocked SSE
  stream, not a real SDK session in cooldown — the reason-string contract
  (`FastModeDisabledReason` literals) is trusted from `sdk.d.ts` rather than
  observed live. If the SDK ever sends a differently-cased or
  differently-spelled reason token than the `.d.ts` documents, it will
  silently fall through to the neutral "temporarily unavailable" copy
  (safe failure mode, but worth knowing).
- `cancel_queued` (interrupt) has no public SDK entry point yet — revisit
  next release; if `Query.interrupt()` grows a parameter, Claudius's Stop
  button is the natural place to offer a "stop and drop everything queued"
  variant (mirroring the existing per-uuid `cancelQueued` already wired for
  `cancel_async_message`).
- `sandbox.network.strictAllowlist` remains reachable only via the
  Settings page's raw-JSON "Other" editor (hand-edit `sandbox.network.strictAllowlist`
  nested under the raw key) — no dedicated UI. Fine for now; flag if a
  future release adds more `sandbox.network.*` settings and a dedicated
  editor becomes worth building.
- All three new Playwright specs — and the pre-existing marketing/dev
  screenshot pages in general — show a "1 Issue" dev-mode overlay badge in
  the bottom-left corner in the captured screenshots. This is a
  pre-existing hydration mismatch in `components/settings/ShortcutsSection.tsx`
  (Mac `⌘⌥` glyphs vs. `Ctrl+Alt+` text — almost certainly an
  SSR-vs-client platform-detection difference, dev-mode only), unrelated to
  this SDK bump and out of scope per the harness/off-migration-surface
  rule; not fixed here.
