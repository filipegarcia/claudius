# SDK update 0.3.220 → 0.3.222

## Summary

0.3.221 and 0.3.222 are both small, internal-facing releases: 0.3.221 tightens
server-side validation of the `skills` option (malformed/wildcard names now
hard-error instead of being tolerated) and fixes external `mcpServers` not
being connected before the first turn; 0.3.222 fixes `sessionStore` +
`resume` combinations not carrying user `settings.json` into the resumed
subprocess. None of these are new public API surface — they're bug fixes and
stricter validation on existing options. Auditing our call sites found one
real regression risk: `lib/server/db-agents.ts` builds `Options.agents` from
user-supplied DB rows (via `PUT /api/agents/db`) and was passing
`definition.skills` straight through to the SDK with no name validation
beyond "is a string." Under the new strict validation, a single malformed
skill name in any one stored agent would throw out of `query()` and break
session start for *every* session in the project (`loadDbAgentsForOptions`
merges every row unconditionally). We now validate/filter skill names on
both the write and read paths so a bad entry is dropped, not fatal. The
other two changelog items don't touch a Claudius call site (we don't
provide a custom `sessionStore`, and our only `mcpServers` user —
`claudius_goal` — benefits automatically with no code change). Headline
risk for review: the skill-name regex (`^[\w][\w.-]*(?::[\w][\w.-]*)?$`) is
our best-effort match for the SDK's undocumented internal validation rule
(the exact charset isn't published); see Risks below.

## SDK changelog highlights

- **0.3.222** — Fixed `query({ sessionStore, resume })` not carrying user
  `settings.json` (`apiKeyHelper`, `env`, `hooks`, `permissions`) into the
  resumed subprocess.
  `[skipped — audited]`. Claudius never passes a custom `sessionStore` to
  `query()` (confirmed via `rg -n "sessionStore"` across the whole repo,
  excluding `node_modules` and the vendored `sdk.d.ts` — zero hits). We rely
  entirely on the SDK's default file-based session store, so the buggy code
  path (custom store + `resume` combined) never executes for us. `resume`
  itself is used (`lib/server/session.ts:2412`), but without a custom store
  this fix is a pure behind-the-scenes correctness improvement with nothing
  for Claudius to wire up.
- **0.3.221** — Improved `skills` option validation: malformed names
  (delimiters or control characters) and wildcard-form names are rejected
  with a clear error; use `skills: 'all'` to enable every skill.
  `[shipped]`. Claudius never passes the top-level `Options.skills` (grep
  across `lib/`, `app/`, `components/` for `skills` confirms every
  `session.skills` / `SkillsOverlay` / `StatusOverlay` reference is a
  *read* of the SDK's discovered-skill list from the init message
  (`lib/shared/parse-init.ts`), never a write into `query()` options). But
  `AgentDefinition.skills` (a sibling field with the same name-validation
  rule) **is** a real call site: `lib/server/db-agents.ts` builds
  `Options.agents` from DB-stored agent rows and was forwarding
  `definition.skills` with only a `typeof === "string"` check — no name-shape
  validation. `Options.agents` is populated from *every* stored row
  unconditionally (`loadDbAgentsForOptions`), so one malformed skill name in
  one row would take down session start for the whole project under the new
  strict validation. Fixed by filtering skill names through
  `SKILL_NAME_RE` on both the write path (`upsertDbAgent` →
  `coerceAgentDefinition`) and the read path (`listDbAgents` →
  `coerceAgentDefinition`, so a legacy bad row already on disk before this
  fix also degrades gracefully instead of crashing startup).
- **0.3.221** — Fixed external MCP servers passed via the `mcpServers`
  option not being connected before the first turn, which caused the model
  to emit tool calls as literal text.
  `[skipped — pure SDK-side timing fix, no Claudius code to change]`.
  Claudius's only `mcpServers` call site is the in-process `claudius_goal`
  server registered unconditionally every session
  (`lib/server/session.ts:2091`, `buildGoalMcpServer()`). This is exactly
  the class of server the bug affected — a user setting a `/goal` on turn
  one could previously have seen the agent emit a literal-text tool call
  instead of actually invoking `report_goal_achieved`. The fix ships
  entirely inside the SDK subprocess; there's no shape change and nothing
  for Claudius to call differently. Noted under Risks as a reliability
  improvement worth spot-checking.

## Code changes

- `lib/server/db-agents.ts` — added `SKILL_NAME_RE` and applied it when
  coercing `definition.skills` in `coerceAgentDefinition`, so a
  malformed/wildcard skill name from a DB-stored agent (`PUT
  /api/agents/db`) is dropped instead of reaching `Options.agents` and
  throwing `query()`'s new strict validation for every session in the
  project. Applies on both the write path (`upsertDbAgent`) and the read
  path (`listDbAgents`), matching the file's existing "malformed row can
  never crash session start" contract.
- `tests/unit/db-agents-coerce.test.ts` — two new specs pinning the
  filtering behaviour (well-formed names incl. `plugin:skill` kept;
  wildcards/delimiters/control chars/empty strings dropped).
- `package.json` / `bun.lock` — SDK bump to `^0.3.222` (done by the
  orchestrator before this run started).

## New UI surfaces

- No new UI surfaces this release. Both 0.3.221 changelog items that touch
  Claudius (`skills` validation, `mcpServers` first-turn fix) are
  server-side robustness fixes with no new user-facing control, toggle, or
  affordance — the `skills` validation fix only prevents a latent crash
  that had no UI representation to begin with (it would have surfaced as a
  session failing to start), and the `mcpServers` fix is invisible plumbing
  behind the existing `/goal` feature.

- playwright: 0 new, 0 updated. No new/changed UI surface to exercise (see

  mcpServers first-turn timing) are both about the SDK subprocess/session
  layer, which the existing e2e suite already exercises indirectly through
  every session-bound spec. Not covered directly: an e2e regression test
  that actually saves a malformed-skill DB agent through `PUT

  pure function through an HTTP + SQLite layer for no new signal.

## Risks / follow-ups

- The `SKILL_NAME_RE` regex (`^[\w][\w.-]*(?::[\w][\w.-]*)?$`) is a
  best-effort reconstruction of the SDK's internal skill-name validation
  rule from the changelog's prose ("delimiters or control characters" and
  "wildcard-form names" are rejected) — the exact accepted charset isn't
  published in `sdk.d.ts` or the changelog. It's deliberately conservative
  (word chars, dot, hyphen, optional single `plugin:skill` colon
  qualifier), so it may reject a small number of legitimate skill names the
  SDK would actually accept. If a real-world skill name gets dropped by
  this filter, loosen the regex rather than removing the guard — the
  failure mode without it (one bad row breaks every session in the
  project) is worse than the failure mode with it (one skill preload
  silently ignored).
- The `mcpServers`-first-turn fix (0.3.221) should make `/goal` completion
  detection on the very first turn of a session more reliable than before
  (previously the model could emit a literal-text tool call instead of
  actually invoking `report_goal_achieved` if the goal was completable
  immediately). This is an SDK-internal behavior change with no Claudius
  code path to test directly; `tests/e2e/goal.spec.ts` is intentionally
  SDK-free (goal achievement is simulated via the dev-broadcast endpoint)
  per its own docstring, so this improvement isn't exercised by an
  automated test. Worth a manual spot-check on the next `/goal` session if
  first-turn goal completion has ever looked flaky.
- `PUT /api/agents/db` has no web UI caller today (grepped — the only
  writer found is the route handler itself; `app/[workspaceId]/agents/`
  only reads/displays file-based `.claude/agents/*.md` agents). It's a
  programmatic API surface (external tooling / MCP-driven agent
  management). That doesn't change the risk calculus — `req.json()` is
  still untrusted input reaching `Options.agents` — but flagging it in
  case a reviewer expected a UI screenshot for this fix.
