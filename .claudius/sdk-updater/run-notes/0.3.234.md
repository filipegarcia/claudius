## Summary

0.3.228 → 0.3.234 spans six point releases (0.3.229–0.3.234). The one item
with real, silent-breakage potential for Claudius is 0.3.233's change to the
*default* tool surface: `TodoWrite`/`TaskCreate`/`TaskGet`/`TaskUpdate`/
`TaskList` are no longer auto-included for Opus 4.8, Sonnet 5, Fable 5,
Mythos 5, and newer models unless a consumer explicitly asks for them.
Claudius never set `tools`/`allowedTools`/`disallowedTools` anywhere — it
relied entirely on the SDK's default preset — and the entire todos rail
(`TodosBanner`, `BackgroundTasksPanel`, the `TaskCreate`/`TaskList`/
`TaskUpdate` bookkeeping in `lib/server/session.ts`) is built assuming those
five tools exist. Left unfixed, every session on a newer model would have
silently lost the todos feature with no error surfaced anywhere. Fixed by
forwarding them through `Options.allowedTools`. Separately, 0.3.234 adds an
`effort` field to the `system:init` message — the session's authoritative
*applied* effort after every downgrade step — which directly fills a gap
`use-session.ts` had documented in its own comments ("the SDK doesn't expose
the *current* effort on any event we replay"); wired that through to correct
the effort picker's optimistic mirror on session start/reconnect. Everything
else in this range (`ExitReason` cleanup, `ApiKeySource` value additions,
`vcs_state_changed` directory/branch reporting, peer `fromMode`, the `/context`
message's structured `context_usage` twin, subagent MCP `_meta` shape, the
32MB message-limit terminal-reason rename, `terminal_slash_commands`, and the
two bare "parity" releases) has no live call site in Claudius — see the
per-item audit below. Headline risk for review: the `allowedTools` fix is the
first time this options object grants an explicit auto-allow list, and while
the five tools have no special-cased `canUseTool` handling today, a reviewer
should double check that doesn't quietly change permission-prompt behavior
for a future `canUseTool` branch that starts checking `toolName` against
these names.

## Code changes

- `lib/server/session.ts` — added the exported `TODO_TASK_TOOL_NAMES`
  constant (`TodoWrite`, `TaskCreate`, `TaskGet`, `TaskUpdate`,
  `TaskList`) and forwarded it as `allowedTools` in the `query()` options
  builder, so these tools stay in the default surface on newer models
  (SDK 0.3.233).
- `lib/shared/parse-init.ts` — added `InitInfo.effort`, parsed from the
  `system:init` message's new `effort` field (SDK 0.3.234), tolerant of
  the three states (a literal level, explicit `null`, or the field being
  absent entirely).
- `lib/client/use-session.ts` — on `system:init`, corrects the previously
  purely-optimistic `effort` mirror from `init.effort` when it carries a
  literal level; updated the stale comment that claimed the SDK exposed no
  current-effort signal at all.

## Risks / follow-ups

- The `allowedTools` fix is additive-only today (these five tools have no
  special-cased `canUseTool` branch), but if a future change adds
  tool-specific permission logic keyed on `toolName`, a reviewer should
  confirm it doesn't assume "not in `allowedTools`" as a signal — these
  five are now unconditionally in that list.
- The `effort` init-mirror correction only fires on `system:init` (session
  start / reconnect), matching the existing comment's documented
  limitation: a live mid-session `/effort` typed directly into the composer
  still bypasses the mirror until the next picker interaction or a fresh
  init. This was already true before this change; 0.3.234 narrows but
  doesn't close that gap.
- Several changelog items in this range (`vcs_state_changed`, subagent
  `_meta` tool-result shape, `/context`'s `context_usage` sibling,
  `terminal_slash_commands`) are marked skipped because Claudius has no
  current call site — if a future feature starts consuming any of these
  (e.g. a VCS-state status chip, or a "why did this session end" banner
  keyed on `terminal_reason`), the audit trail above is the starting point.
