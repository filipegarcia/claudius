# SDK update 0.3.294 → 0.3.296

## Summary

The 0.3.294 → 0.3.296 window spans two SDK releases (0.3.295 and 0.3.296), both tracking Claude Code parity. The 0.3.295 half (`overageEnabled`, hook `onFailure`) was already absorbed on this branch by the earlier 0.3.295 work merged from main. The one new public field in 0.3.296 that maps to something a Claudius user does is `AgentDefinition.autoCompactWindow`, which lets a subagent auto-compact earlier than the main conversation. It is now accepted by the DB-agent coercion (so it reaches `Options.agents`) and shown as a `compact@<n>k` badge, with a commented template line, in the Agents page for file-based agents (the bundled CLI lists `autoCompactWindow` in its agent frontmatter keys). Everything else is SDK/CLI-internal. Headline risk: the badge format and the `> 0` validation for the DB path are my own choices.

## Risks / follow-ups

- Assumption: the DB-agent path accepts only positive finite numbers for `autoCompactWindow`; anything else is dropped rather than forwarded. The alternative (forwarding any number) was rejected as less conservative.
- The badge abbreviates values ≥1000 to `<n>k` (rounded), so e.g. 123456 shows as `compact@123k`.
- There is no DB-agent editor field for `autoCompactWindow`; it is reachable via the agents API payload and file-agent frontmatter only.
