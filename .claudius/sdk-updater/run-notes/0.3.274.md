## Summary

0.3.274's headline change is MCP provenance: `canUseTool` options,
every tool-use hook input, and `mcp_servers` status rows now carry a
`{name, source}` pair (`McpServerProvenance`) saying which MCP server
served a tool and whether it's one Claudius itself registered
(`source: "sdk"`) versus one from user/project/plugin/managed
configuration. We wired this end-to-end: the permission-prompt modal
now shows an "MCP · name (source)" badge, and the `/mcp` status page
shows a source badge next to each server's scope. We also shipped
`startup_failure_reason` — Claudius's session process is a stream-json
`query()` run, exactly the surface this field targets, so a known
startup failure (org policy conflict, unusable temp dir, missing shell
tool, etc.) now surfaces a specific, actionable message instead of a
bare failure. Separately, we hardened `foldResultIntoSessionUsage`
against the changelog's "queued background-task completions now share
one model call, all but the last empty with `num_turns: 0`" change:
the existing zero-frame guard required `duration_ms === 0` too, which
an empty queued-completion frame isn't guaranteed to have, and would
otherwise be misread as a `/clear` reset and double-count cost. The
headline risk to flag for review: the `num_turns` fix is defensive
(we could not exercise the real multi-queued-task-completion shape
against a live agent this run), and the `startup_failure_reason` UI
is exercised in a unit test but not by a live-agent e2e run (it can
only be triggered by a genuine startup failure, which isn't
reproducible in Playwright's fixture flow).

## SDK changelog highlights

- `startup_failure_reason` on the error result — **[shipped]**.
  Confirmed Claudius's session process is a CLI stream-json `query()`
  run (`lib/server/session.ts`, `query({ prompt, options })` with no
  custom transport), so this field is reachable, not dead. Added
  `CLAUDE_CODE_STARTUP_FAILURE_RESULTS=1` to `buildQueryEnv()` so the
  stderr-only failure class also populates it, mapped every documented
  reason code to a friendly message in `STARTUP_FAILURE_REASON_LABELS`
  (`lib/client/use-session.ts`), and surface it as a session error
  banner.
- `mcpServer` on `canUseTool` options, `mcp_server` on tool hook
  inputs, `source` on MCP server status rows — **[shipped]**.
  `canUseTool` (`lib/server/session.ts`) now forwards `ctx.mcpServer`
  onto the `permission_request` SSE event; `PermissionPrompt.tsx`
  renders it as a badge next to the existing subagent badge. The
  `/mcp` page's live-status badge renders the new `source` field
  (already passed through raw by `app/api/mcp/route.ts`, since it
  calls `session.mcpServerStatus()` and forwards `data` untouched —
  only the hand-typed client `LiveStatus` shape needed the new field
  added). Hook input types (`PreToolUseHookInput` etc.) are imported
  directly from the SDK and cast at the two call sites in
  `session.ts` — the new `mcp_server` field is available there for
  free with no type-sync work, but Claudius doesn't currently branch
  on hook-input MCP provenance (only on `canUseTool`'s), so no
  additional wiring was added there.
- `McpServerProvenance` (the shared `{name, source}` type) — **[type-only]**,
  covered by naming its two call sites above; Claudius doesn't
  re-export or alias the SDK type itself, it just reads the fields.
- `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` — **[skipped — CLI env-var knob,
  no Claudius-side wait/timeout logic to bound]**. Claudius doesn't
  implement its own MCP-connect timeout that this would replace or
  interact with.
- `CLAUDE_CODE_EMIT_STARTUP_TIMING=1` — **[skipped — opt-in perf
  debug feature]**. Claudius doesn't currently surface a startup
  timing breakdown in any UI; there's no `system/init` consumer this
  would feed today (`lib/shared/parse-init.ts`'s `InitInfo` has no
  timing field). Worth revisiting if a future release wants a "why did
  this session take N seconds to start" panel.
- Fixed `getSessionMessages()` omitting a mid-tool-run user message —
  **[skipped — internal SDK bugfix, no type/behavior surface Claudius
  code branches on]**. This changes what messages `getSessionMessages()`
  returns; Claudius doesn't call that API directly (it consumes the
  live stream via `query()`'s async generator), so nothing to wire up.
- Fixed missing `origin: {kind: 'task-notification'}` on replayed user
  messages — **[skipped — internal SDK bugfix]**. This is a
  `--replay-user-messages` CLI-flag concern; Claudius doesn't pass
  that flag or read `origin.kind` off replayed messages.
- Improved startup MCP-wait behavior (skip the 2s wait for
  settings/plugin servers) — **[skipped — internal timing
  improvement, no new public field, verified no Claudius code depends
  on the old wait duration]**.
- Queued background-task completions sharing one model call, with
  `num_turns: 0` on all-but-last — **[shipped]**. See Summary; fixed
  `foldResultIntoSessionUsage`'s zero-frame guard in
  `lib/server/session.ts` and added a regression test in

- "Updated to parity with Claude Code v2.1.274" — **[skipped —

## Code changes

- `lib/shared/events.ts` — `PermissionRequestEvent` gains
  `mcpServer?: {name, source}`, forwarded from `canUseTool`.
- `lib/server/session.ts` — `canUseTool` now includes `ctx.mcpServer`
  in the `permission_request` event; `buildQueryEnv()` sets
  `CLAUDE_CODE_STARTUP_FAILURE_RESULTS=1`; `foldResultIntoSessionUsage`'s
  zero-frame guard no longer requires `duration_ms === 0`, to avoid a
  double-count when an empty queued-completion frame carries nonzero
  duration (see Summary).

  map and a "Session failed to start: …" error banner when a result
  carries `startup_failure_reason`.

- `components/chat/PermissionPrompt.tsx` — renders an "MCP · name
  (source)" badge when the request names an MCP server; imports `cn`.
- `app/[workspaceId]/mcp/page.tsx` — `ServerRow` renders a source
  badge next to the scope label.
- `tests/unit/session-usage-fold.test.ts` — new case for the
  empty-queued-completion-frame fix.
- `tests/unit/startup-failure-reason-labels.test.ts` — new file
  pinning the full `STARTUP_FAILURE_REASON_LABELS` catalog.
- `tests/unit/session-options.test.ts` — new case for

## Risks / follow-ups

- The `PermissionPrompt.tsx` MCP-provenance badge has no e2e
  coverage — Claudius's permission-prompt Playwright specs inject
  synthetic non-MCP tool requests. If Claudius later wires up an MCP
  server whose tools flow through the standard permission prompt in
  an e2e fixture, add a screenshot then.
- The `foldResultIntoSessionUsage` fix for the queued-background-task
  `num_turns: 0` change is defensive, not verified against a live
  multi-queued-completion turn (that shape needs a real agent session
  with several background tasks completing together, which we
  couldn't reproduce this run). The change is a strict broadening of
  an existing "ignore this frame" guard (removing one of three
  zero-checks), so it can only make more frames get ignored, never
  fewer — worst case if the assumption is wrong is a small duration
  undercount on an already-non-authoritative frame, not a cost
  double-count.
- `startup_failure_reason` is now surfaced as a plain error-banner
  string; a follow-up could add per-reason "fix it" actions (e.g. a
  link to account settings for `org_pin_api_key_conflict`) rather
  than just prose.
- `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` and
  `CLAUDE_CODE_EMIT_STARTUP_TIMING` were left unimplemented (see
  changelog highlights) — revisit if a future release wants
  configurable MCP-connect timeouts or a startup-timing UI.
