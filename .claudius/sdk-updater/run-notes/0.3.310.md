# SDK update 0.3.306 → 0.3.310

## Summary

The window 0.3.306 → 0.3.310 is small: four patch releases, three of which are bare "parity with Claude Code v2.1.30x" lines. The substantive items are a `managedSettings` fix (0.3.309), a change to where `extractFromBunfs()` unpacks the embedded CLI (0.3.309), `wakeup_source` / `scheduled_for` on the `command_lifecycle` `started` frame (0.3.307), and a browser-SDK-only `supportedDialogKinds` option. The `.d.ts` diff adds three public fields (`liveReply`, `sshHostCommands`, `supportedDialogKinds`). Auditing every importer of the SDK showed none of these touch a path Claudius uses, so the PR is the version bump plus these notes and no product code changed. The headline risk is low: the `command_lifecycle` frames are still deliberately not buffered or consumed, and the `managedSettings` fix only affects hosts that pass that option, which Claudius does not.

## SDK changelog highlights

- 0.3.310 "parity with Claude Code v2.1.310" — [type-only] no public surface change beyond the declarations listed below; the bump is absorbed by the dependency update.
- 0.3.309 host-supplied `managedSettings` no longer drops `disableAllHooks`, `disableSkillShellExecution`, empty `allowedHttpHookUrls` / `httpHookAllowedEnvVars` — [skipped — Claudius never passes the `managedSettings` query option (`rg managedSettings lib app` is empty). Its own `disableAllHooks` handling in `lib/server/hooks.ts` and the Hooks page edits user/project settings.json files directly and is unrelated to the SDK option.]
- 0.3.309 `extractFromBunfs()` extracts into a per-user temp dir (`claude-agent-sdk-<uid>`) and reuses the file only if bytes match — [skipped — only runs when the SDK is compiled into a Bun single-file binary. Claudius runs under Node/Next and Electron and resolves the CLI from `node_modules`; no call-site.]
- 0.3.309 / 0.3.308 "parity with Claude Code v2.1.309 / v2.1.308" — [type-only] no new public declarations in those releases.
- 0.3.307 `wakeup_source` / `scheduled_for` on `command_lifecycle` `started` frame (capability `lifecycle_wakeup_source_v1`) — [skipped — `command_lifecycle` frames are not in the public `.d.ts` and Claudius intentionally has no consumer: `shouldBufferEvent` in `lib/server/session.ts` drops them from the replay buffer and the queue UI is driven by the server-side `queued_messages` table. Claudius reconstructs scheduled wakeups from the `ScheduleWakeup` tool input, not lifecycle frames. Adopting would need a new consumer with no UI that needs it.]
- 0.3.307 `supportedDialogKinds` in browser SDK `query()` — [skipped — browser-SDK-only (`browser-sdk.d.ts`) option for remote-CLI `request_user_dialog`; Claudius uses the Node `query()` from `sdk.d.ts` and has no `onUserDialog`.]
- 0.3.307 parity with Claude Code v2.1.307 — [type-only].

New declarations from the type-surface diff:

- `liveReply` (`sdk.d.ts`, on the internal `mcp_status` control request: `liveReply?: boolean`) — [skipped — only affects control requests when the CLI writes via CCR (cloud / Remote Control worker). The public `Query.mcpServerStatus()` takes no arguments (verified in sdk.d.ts line ~3094), so there is no supported way to set it, and Claudius's local CLI does not write through CCR.]
- `sshHostCommands` (`sdk.d.ts`, `Settings.sshHostCommands?: unknown[]`) — [skipped — Claude Desktop (macOS/Linux) SSH-connection setting whose host comes from a command. Claudius has no SSH connection feature (`rg sshConfigs` is empty), the type is `unknown[]` of nested objects, and the Settings page deliberately omits complex nested objects from `SDK_SETTINGS_CATALOG`; an existing value falls through to the generic "Other" editor.]
- `supportedDialogKinds` (`browser-sdk.d.ts`, `supportedDialogKinds?: string[]`) — [skipped — see above; browser-SDK-only.]

Doc-only changes in the raw `.d.ts` diff: the `Options.managedSettings` JSDoc now documents that `disableAllHooks` binds as `allowManagedHooksOnly` and that the HTTP hook allow-lists bind only as empty lists (the 0.3.309 fix; Claudius does not pass the option). `bridge.d.ts` `reconnectTransport` / `onClose` doc updates concern the Remote Control bridge, which Claudius does not use. Other JSDoc rewording (`can_use_tool` `requires_user_interaction`, `setMaxThinkingTokens`, sandbox `allowNestedUserNamespaces`, `sdkMcpServerConfigs` `connectorId`) is clarification only with no signature change.

Model-identity items: none in this window. No changelog line or declaration touches a model name, alias, default model, context window, capability tier, or pricing tier, so no model-surface skip justification is needed. (Cross-checked: the raw diff has no change to `Settings.modelPicker` / `modelPricing`, `ModelInfo`, or effort levels.)

## Code changes

- No code changes required. The SDK delta in this window consists of fields and options that Claudius does not reach.

The version bump of `@anthropic-ai/claude-agent-sdk` to `^0.3.310` in `package.json` / `bun.lock` was made by the orchestrator; the only other addition is this run-notes file. Every changelog item and new declaration was checked against its actual call path (see highlights): `managedSettings` is never passed, `extractFromBunfs()` never runs outside a Bun binary, `command_lifecycle` frames are intentionally ignored, `mcpServerStatus()` cannot set `liveReply`, and `supportedDialogKinds` exists only on the browser SDK.

## Risks / follow-ups

- If a future release makes `command_lifecycle` public and a UI wants to show which scheduled wakeup or task fired, `wakeup_source` / `scheduled_for` (`lifecycle_wakeup_source_v1`) would be the data source; for now `shouldBufferEvent` still excludes these frames from replay.
- If Claudius ever passes `managedSettings` to `query()`, re-read the new `Options.managedSettings` JSDoc: `disableAllHooks: true` binds as `allowManagedHooksOnly`, and the HTTP hook allow-lists bind only as empty lists.
