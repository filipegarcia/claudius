## Summary

Note on the base version: `origin/main`'s `package.json` was already on
`@anthropic-ai/claude-agent-sdk@^0.3.252` (the 0.3.251 and 0.3.252 PRs had
already merged — see `.claudius/sdk-updater/run-notes/0.3.251.md` /
`0.3.252.md`), so the type-surface diff this prompt was generated against
(0.3.250 → 0.3.257) is wider than the actual gap this PR closes
(0.3.252 → 0.3.257). Every item below is audited against that actual gap;
`PreModelSwitch`/`PostModelSwitch` and related hook plumbing are already
shipped from the 0.3.251 run and are simply reconfirmed, not re-implemented,
here.

The real 0.3.257 changelog is thin in prose (mostly "Updated to parity")
but the `.d.ts` diff carries three genuinely actionable items for Claudius:
(1) `ModelUsage.thinkingTokens` — now accumulated correctly in per-model
usage merges (`ADDITIVE_MODEL_USAGE_FIELDS`); (2) `task_notification` /
`tool_use_result` can carry `resource_links` for an auto-backgrounded MCP
tool call's returned files — this was previously silently dropped, and is
now captured server-side (SQLite migration 020), streamed to the client,
and rendered on the transcript's tool-call card (with the card's own
completion status now sourced from the joined task instead of getting
stuck on "running" — the SDK's own doc notes a backgrounded MCP call's
`tool_use_result` is only ever the launch placeholder); and (3)
`Query.getContextUsage({ detail })` — the idle-polling context watcher now
requests the cheap `'summary'` tier instead of the default `'full'`
per-category breakdown it never used, cutting a repeated expensive SDK
call on a hot polling path. Two small settings catalog rows
(`timeFormat`/`timeZone`) were also added as config-passthrough, mirroring
the existing `keybindingFlavor` treatment.

**Headline risk for review:** the new `taskStatus` prop on the generic
`ToolCall` component (gated strictly to `taskType === "mcp_task"`) is a
small, deliberately narrow behavior change to make the resource-links
feature coherent — verified with a unit + e2e test, but not exercised
against a real backgrounded MCP server locally (mocked SSE only, per the
run's headless constraints). See "## Risks / follow-ups".

## Code changes

- `lib/server/session.ts` — (1) added `"thinkingTokens"` to
  `ADDITIVE_MODEL_USAGE_FIELDS` so it accumulates across SDK-process
  merges instead of last-write-wins; (2) `getContextUsage()` now accepts
  an optional `{ detail }` and passes it through to `Query.getContextUsage`;
  (3) `captureTaskState`'s `task_notification` handler captures
  `msg.resource_links` onto the persisted `TaskSnapshotEntry`.
- `app/api/sessions/[id]/context/route.ts` — reads an optional
  `?detail=summary` query param and forwards it; omitted (default) still
  requests `'full'`, unchanged for the `/context` overlay's category
  breakdown.
- `lib/client/useContextWatcher.ts` — the idle-polling watcher now
  requests `?detail=summary` (it only ever read `totalTokens`/`maxTokens`/
  `percentage`, never the per-category breakdown).
- `lib/shared/events.ts` — new `TaskResourceLink` type (mirrors
  `SDKMcpResourceLink` minus `annotations`); `resourceLinks?` added to
  `TaskSnapshotEntry`.
- `lib/client/types.ts` — `resourceLinks?: TaskResourceLink[]` added to
  `TaskInfo`.
- `lib/client/use-session.ts` — `task_notification` handling captures
  `resource_links` into `TaskInfo.resourceLinks`; the `task_snapshot`
  replay path (disk-rebuilt sessions) carries it through too.
- `lib/server/session-tasks-db.ts` + `lib/server/db-migrations/020_session_tasks_resource_links.sql`
  — new nullable `resource_links` TEXT (JSON) column so a completed MCP
  task's returned files survive an idle-reap/server-restart reload, same
  treatment as `ambient` (migration 018).
- `components/chat/ToolCall.tsx` — new `resourceLinks`/`taskStatus` props:
  a collapsed "N files" badge + expanded "files returned" list when
  present; `taskStatus` (gated to a joined `mcp_task`) overrides the
  `!result`-only status derivation so the card correctly reads "completed"
  instead of getting stuck on "running" for a backgrounded MCP call whose
  `tool_use_result` is only ever a launch placeholder.
- `components/chat/AssistantMessage.tsx` — joins `taskByToolUseId` (already
  built for `TaskBlock`/`WorkflowBlock`) to the generic `ToolCall` too,
  passing `resourceLinks`/`taskStatus` only when `taskType === "mcp_task"`
  so every other tool (Bash, etc.) is unaffected.
- `app/settings/page.tsx` + `lib/server/settings.ts` — two new
  `SDK_SETTINGS_CATALOG` rows (`timeFormat`, `timeZone`, new "Display"
  section) plus the matching `ClaudeSettings` type fields.
  Config-passthrough only (same treatment as `keybindingFlavor`): these
  format times in the CLI's own TUI, not Claudius's browser UI.
- `tests/e2e/cc-parity-2.1.216-context-and-compact.spec.ts` — widened its
  `/context` route mock glob to `/context*` so it still matches now that
  the watcher appends `?detail=summary` (existing test, fixed as a direct
  consequence of the `getContextUsage` change above).

## Risks / follow-ups

- **`modelPicker` shape mismatch (pre-existing, not caused by 0.3.257,
  but surfaced during this release's `behavesAs` audit)**: Claudius's
  `ModelPickerSettings` type (`lib/server/settings.ts`) models
  `{mode, entries: {id,label}[]}`, but the SDK's real `Settings.modelPicker`
  shape is `{options: {model,label,description,behavesAs}[],
  replaceBuiltInOptions}`. Claudius's own settings UI round-trips its own
  shape correctly, but a `modelPicker` block written by the actual `claude`
  CLI (or another host) against the same settings file would not be read
  or forwarded correctly, and `behavesAs` has no way to reach Claudius at
  all under the current shape. This needs a dedicated migration of the
  `ModelPickerSettings` type + `ModelPickerCatalogField` UI +
  `model-picker-curation.ts`'s mapper — out of scope for this point
  release; scheduled as its own follow-up.
- **`blockReadsOutsideWorkingDirectories`**: deliberately not wired (see
  changelog highlights) — Claudius has no generic UI for the SDK's broader
  `permissions.*` surface today. Worth a dedicated toggle in the
  Permissions settings surface in a future pass if there's demand for it.
- **The `taskStatus` override on `ToolCall`** (gated to `taskType ===
  "mcp_task"`) is a new, narrow behavior change verified only against
  mocked SSE fixtures (unit + e2e), not a real MCP server that actually
  gets auto-backgrounded — flag for a sanity check against a live session
  the next time an MCP server with a long-running tool is available.
- **`thinkingTokens` is captured and correctly accumulated but not yet
  surfaced in the Cost UI** — there was no existing "thinking tokens" cost
  line to extend (checked `CostOverlay.tsx`, `StatusLine.tsx`,
  `litellm-pricing.ts`); a follow-up could add a breakdown line once
  there's a clear design for it (thinking tokens are already billed as
  part of `outputTokens`, so this is purely a transparency/analytics
  feature, not a pricing correctness one).
- **`tests/unit/hook-events.test.ts` has no actual SDK-parity check** —
  it only asserts Claudius's own two mirrors of the hook-event list agree
  with each other, not that they match the installed SDK's `HOOK_EVENTS`.
  A stale local list would still pass green. Worth adding a direct import
  + diff against the SDK export in a future pass (noted originally in the
  0.3.251 run, still open).
- The synchronous `tool_use_result.resourceLinks` path (a non-backgrounded
  MCP tool's immediate result carrying resource links) is not yet
  surfaced anywhere — see changelog highlights above.
