## Summary

SDK 0.3.317 → 0.3.319 is a small parity release: MCP task support (`task_type: "mcp_task"`), OTel/`session_writes_lost`/`deleteSession` fixes inside the bundled CLI, plus a handful of additive types (`config_file_invalid` startup failure reason, `credential_expires_at` on results, three new `Settings` booleans, an optional `PushNotificationInput.status`). In Claudius we shipped the pieces that have a real surface: a friendly label for the new `config_file_invalid` startup-failure reason, and two new flat boolean rows in the `/settings` catalog (`disableWindowsBashCommandSplit`, `disableReplyCheck`), with a unit test and a Playwright spec + screenshot. Everything else is type-only or a deliberately skipped CLI-internal change. Headline risk: low — no model-identity surfaces changed.

## SDK changelog highlights

- MCP task support, `task_type: "mcp_task"` (needs `CLAUDE_AUTO_BACKGROUND_TASKS=1` + streaming input) — [type-only]: `taskType` is already passed through as an opaque string (`lib/client/use-session.ts`, `BackgroundTasksPanel.tsx` falls back to a generic icon/label and `ToolCall.tsx` already documents `mcp_task`); we do not set the env var, so nothing to enable.
- OTel `claude_code.session.count` no longer counts unclaimed `prewarm()` processes — [skipped — CLI-internal telemetry fix; Claudius does not call `prewarm()`/`SpareProcess.claim()` and does not consume that metric].
- `session_writes_lost` lists the right session in `transcript_session_ids` after `/clear` on an out-of-projects-folder resume — [skipped — CLI-side fix; our handler (`lib/shared/session-writes-lost.ts`) just reads the field and needs no change].
- `deleteSession()` rejects with `ENOTEMPTY` if the session folder could not be fully deleted — [skipped — `sessions-store.remove` already propagates rejections to `DELETE /api/sessions/file/[id]`, which surfaces them as an error response; the transcript is already gone when this fires, which is acceptable for our delete flow].
- `session_writes_lost` is sent only when the CLI exits 0 — [skipped — narrowing of when the message fires; the existing handler is unchanged and still correct].
- Parity with Claude Code v2.1.319 / v2.1.318 — [skipped — no host-facing API beyond the items listed here].
- `credential_expires_at` on result messages (also the `credential_expires_at` field in the type diff) — [type-only]: optional ISO timestamp on `SDKResultSuccess`/`SDKResultError`; no UI for sign-in expiry exists today and a build going green is not the reason — we considered a banner but chose not to invent a new surface this release (see Risks).
- `config_file_invalid` startup failure reason / `SDKStartupFailureReason` — [shipped]: new entry in `STARTUP_FAILURE_REASON_LABELS` (`lib/client/use-session.ts`) so the "Session failed to start" banner shows a specific fix; pinned in `tests/unit/startup-failure-reason-labels.test.ts`.
- Interrupt response now lists a message held behind a model change (`SDKControlInterruptResponse` JSDoc) — [skipped — doc-only semantics change in the CLI's `still_queued`/`cancelled` handling; we consume those arrays generically].
- `agentProgressSummaries` may be delayed up to 5 minutes on a cold cache (`Options` JSDoc) — [skipped — behaviour-only; we do not depend on summary timing].
- `PushNotificationInput.status` now optional (`PushNotification` / `status` in `sdk-tools.d.ts`) — [type-only]: `rg PushNotification` finds no consumers in app/lib/components.
- `check_permissions` on `SDKControlMcpCallRequest` — [skipped — control-protocol request field for the MCP call-without-model-turn path; Claudius does not issue `mcp_call` control requests].
- `SDKControlRequestInner` (now a union that includes `SDKControlSetHasSubscribersRequest`) and `SDKControlSetHasSubscribersRequest` (`subtype: 'set_has_subscribers'`, `has_subscribers`) — [skipped — internal control-protocol type (the declaration is not exported); only matters for a CLI started with `CLAUDE_CODE_STREAM_EVENT_HOLD_MS`, which Claudius never sets].
- `denyInsteadOfPrompting` (nested `Settings.permissions.denyInsteadOfPrompting`) — [skipped — `SDK_SETTINGS_CATALOG` only models top-level keys, there is no nested-key row mechanism; it is also a headless `-p` behaviour that would make Claudius' interactive permission prompts auto-deny, so exposing it as a one-click toggle is risky. Users can still set it by editing settings JSON].
- `disableReplyCheck` (`Settings`) — [shipped]: boolean row in "Dialogs & messaging" in `SDK_SETTINGS_CATALOG`.
- `disableWindowsBashCommandSplit` (`Settings`) — [shipped]: boolean row in "Shell" in `SDK_SETTINGS_CATALOG`.
- `bridge.d.ts` `CredentialsFailure` variant — `terminal: true`, `reason: 'session_security_tier_below_org_policy'`, `status: 403` — [skipped — Remote Control bridge credential fetch; Claudius does not use `bridge`].
- Doc-only JSDoc changes (`matched_ask_rule`/`CanUseTool` MCP alternate server names, `cleanupPeriodDays` local-only wording, `attributionProject` `chan_` IDs, `pluginSuggestionMarketplaces`, `sshHostCommands`, `SDKMessageOrigin.body`, `RemoteTrigger` cursor wording) — [skipped — wording only, no shape change].
- Model identity: no changelog or type-diff item in this window touches a model name/suffix/alias/default, context window, effort tier or pricing tier (no `modelPicker`/`modelPricing`-style additions; the new Settings keys are `denyInsteadOfPrompting`, `disableReplyCheck`, `disableWindowsBashCommandSplit` only), so the model-surface audit does not apply.

## Risks / follow-ups

- `credential_expires_at` is absorbed type-only. A "sign-in expires in N days" indicator could be built from it next cycle; deliberately not invented here.
- `permissions.denyInsteadOfPrompting` has no Settings-page row (the catalog has no nested-key support); revisit if nested keys are ever added.
- E2E flake: in one full-suite run `app-functionality.spec.ts:138` ("workspace switcher opens on click of the rail toggle") failed (`aria-expanded` stayed `false` after clicking the 768px hamburger — looks like a click-before-hydration race under load). It is outside this diff and passed on isolated rerun; consider waiting for hydration before the click.
- Running the full e2e suite regenerates ~200 tracked screenshots under `docs/` and `site/`; those were reverted and are not part of this PR.
- Environment note: the local `better-sqlite3` binary was built for Node ABI 127 while the shell runs Node v26; I ran `npm rebuild better-sqlite3` so vitest could load it. This is not part of the diff.
