# SDK update 0.3.323 → 0.3.325

## Summary

0.3.324 is a bare parity bump; 0.3.325 adds session archive helpers (`archiveSession` / `unarchiveSession` / `archived`), `reloadPlugins({ refuseIfBusy })`, `managed_lock` on `plugin_errors`, a `hook_no_verdict`-tagged `system/informational` warning, `invalid_config_file` on the `config_file_invalid` startup failure, deny-rule / `supportedEffortLevels` fixes, a sandbox auto-approve default change, and `ProposeSkillsInput.edits`. In Claudius we shipped two small end-to-end surfaces: (1) the Plugins page now explains a `managed_lock` (why a managed-settings `enabledPlugins` entry dropped a local plugin copy), and (2) the "Session failed to start" error for `config_file_invalid` now names the broken file and its backup from `invalid_config_file`. Everything else is either already handled by existing generic code or deliberately skipped with the reason below. Headline risk: the sandbox default change is a no-op for us only because `lib/server/session.ts` already sets `autoAllowBashIfSandboxed: true` explicitly — worth a reviewer's glance.

## Risks / follow-ups

- Sandbox default change relies on our explicit `autoAllowBashIfSandboxed: true` in `lib/server/session.ts`; if that line is ever refactored away, sandboxed Bash will start prompting.
- Decision to skip archive support: if the product wants an "Archived" section in the sessions list, `archiveSession`/`unarchiveSession`/`archived` are ready to wire (note they reject when `sessionStore` is passed and only mark local transcripts).
- Decision to skip `refuseIfBusy`: alternative considered was passing it in the plugin-toggle fan-out; rejected because busy sessions would silently miss the change.
- `applyFlagSettings` rejection semantics: every call in `session.ts` ends in `.catch(() => {})` while the effort/fast/ultracode/advisor UIs update optimistically; with 0.3.325 a rejected call applies nothing, so the UI could show a value the SDK never took. Not changed here (no known trigger from our inputs); worth surfacing the rejection if it ever shows up.
- `bun run lint` shows 6 pre-existing warnings (e.g. `react-hooks/set-state-in-effect` in `use-session.ts`), 0 errors.
