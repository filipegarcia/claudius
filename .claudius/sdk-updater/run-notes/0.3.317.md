# SDK update 0.3.306 → 0.3.317

## Summary

The 0.3.306 → 0.3.317 window is eleven point releases, almost all "parity with Claude Code v2.1.30x–31x" lines. The real surface is a handful of additive types: `onFailure` on hook matchers, a new `session_writes_lost` system message, the `initialize_not_first` startup-failure reason, `unanswered` on AskUserQuestion annotations, `lossy` on `readFile()`, and several `Settings` keys that only the host or managed tier can set. Main already absorbed several earlier items from this window (0.3.311 cache-split usage fields, 0.3.312 auto-mode settings, 0.3.314 `blockWritesOutsideWorkingDirectories` and `sandbox_required_unavailable`), so this PR ships the remaining ones that affect Claudius. It adds a warning pill for `session_writes_lost`, a label for `initialize_not_first`, and `annotations[q].unanswered` on skipped AskUserQuestion questions, sent only when `system/init` lists `ask_user_question_unanswered_v1`. It also refreshes the `bashEditDiffEnabled` catalog copy. Headline risk: the `unanswered` annotation is untested against a live CLI (see Risks).

**Re-run note (0.3.316 → 0.3.317 window):** this migration was already merged to `main` in PR #337, so the code, tests and screenshot described below are present on `main` and this branch adds no further product diff. The re-run re-audited the 0.3.316 → 0.3.317 `.d.ts` diff (`onFailure`, `hook_on_failure_supported`, `lossy`, `SDKSessionWritesLostMessage`, `SDKStartupFailureReason`, `workingDirectoriesAsGiven`, `next_page_token`, `page_token`, `timedOut`, `description`, the removed `file_unchanged` variant) against the entries below and found every item already positioned and implemented where marked `[shipped]`. It also reverted the orchestrator's bump commit, which had wrongly rewritten the app's own `version` (0.3.318 → 0.3.317) instead of the SDK dependency (already `^0.3.317`).

## Risks / follow-ups

- `unanswered: "skipped"` is wired defensively and does not fire from the current UI: the form's Submit button is disabled until every question is answered, and Cancel denies the whole call. Assumption: ship the plumbing (small, capability-gated, unit-tested) rather than add a per-question Skip control, which would be a UX change beyond this bump. Alternative rejected: omitting the field. Revisit if a Skip affordance is added; `replied_in_chat` / `dismissed` have no Claudius equivalent.
- `session_writes_lost` reaches the client: the consume loop in `lib/server/session.ts` broadcasts every SDK message unfiltered and it is buffered for replay. But the CLI sends it as the process exits (after the last result), so it only shows when a tab is attached at that moment or replays the buffer afterwards. The spec drives it through a mocked SSE stream, not a real disk-full condition.
- Six lint warnings in `lib/client/use-session.ts` (React-compiler `set-state-in-effect` / refs-in-render) are pre-existing and not on lines touched here; lint has zero errors.
- `onFailure: 'block'` for SDK callback hooks was deliberately not adopted; revisit if Claudius ever registers a hook that must fail closed.
