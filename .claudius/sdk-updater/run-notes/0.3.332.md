# SDK update 0.3.327 → 0.3.332

## Summary

A five-release catch-up, 0.3.328 through 0.3.332 (Claude Code 2.1.328–2.1.332). The hourly updater stalled at 0.3.327 because of #383 (runtime state tracked in git broke `git checkout`); that is fixed separately in #384. This PR also carries the 2.1.327 parity work that never reached main, and the Claude Code parity for 2.1.328–2.1.332 (see `.claudius/cc-parity/run-notes/2.1.332.md`).

Five SDK changes needed code in Claudius:
- **`sideload_flags_disabled` (0.3.331).** The new startup-failure reason gets friendly copy in the "session failed to start" banner: the organization's `disableSideloadFlags` refused a session that names its own plugins, agents or MCP servers.
- **`setPermissionMode()` answers with the mode in effect (0.3.332).** Claudius used to record, broadcast and persist the mode it asked for. It now uses the engine's answer, and when the engine substituted another mode the pill says "Asked for X: the session switched to Y instead."
- **`PreSkillShellCommand` hook event (0.3.332).** `/hooks` can add and show it, `/api/hooks` accepts it, prompt and agent handlers are refused there as the engine requires, and a drift test pins Claudius's event list to the SDK's runtime `HOOK_EVENTS`.
- **`onFailure` on `mcp_tool` hooks (0.3.328).** This exposed a real bug: Claudius saved `mcp_tool` hooks as `{tool: "mcp__srv__tool", arguments}`, but the engine schema is `{server, tool, input}`, so every Claudius-authored `mcp_tool` hook failed to load. Hooks are now saved in the engine's shape, old entries are badged for re-creation, and `onFailure: "block"` is offered for `mcp_tool`.
- **`CronCreateOutput.maxAgeMs` (0.3.330).** Recurring loops now run up to 30 days. Claudius's keep-alive capped them at 7; it now follows each loop's own end, and the Activity rail says when a loop ends.

Everything else in the five releases is engine-side, browser-SDK only, or doc-only, and is classified below.

## Code changes

- `package.json` / `bun.lock`: `@anthropic-ai/claude-agent-sdk` `^0.3.327` → `^0.3.332`, and the Claudius version 0.3.327 → 0.3.332 (it tracks the SDK number).
- `lib/client/use-session.ts`: `sideload_flags_disabled` label in `STARTUP_FAILURE_REASON_LABELS` (now `satisfies Record<SDKStartupFailureReason, string>`, so a future reason without copy fails tsc).
- `lib/server/session.ts` `applyPermissionMode`, `lib/shared/permission-modes.ts`, `app/api/sessions/[id]/mode/route.ts`, `lib/client/use-session.ts`, `lib/client/types.ts`, `components/chat/ModeChangeRefusedNoticePanel.tsx`: the effective-mode answer is recorded and a substitution is reported (`substituted: { requested }`).
- `lib/shared/hook-events.ts`, `app/[workspaceId]/hooks/page.tsx`, `app/api/hooks/route.ts`: `PreSkillShellCommand`; `{server, tool, input}` `mcp_tool` shape, `isLegacyMcpToolHook`, `handlerSupportsOnFailure` includes `mcp_tool` (the engine ignores it on `Setup` and `SessionStart` as well as the events it ignores for command and HTTP hooks; the editor hints at those combinations); `handlerTypeAllowed` per event.
- `lib/server/loop-keepalive.ts`, `lib/shared/session-loops.ts`, `lib/server/session.ts`, `lib/client/use-session.ts`, `components/panels/widgets/ScheduledLoops.tsx`: per-loop end from `maxAgeMs` (else the result text, else 7 days), keep-alive to that end plus 30 minutes, "ends <date>" / "ended <date>" in the rail. ## Risks / follow-ups

- **Legacy `mcp_tool` hooks.** Entries saved by earlier Claudius builds are flagged ("won't run — no server" or "arguments ignored"), not migrated. Splitting the old `tool: "mcp__srv__tool"` back into server and tool is ambiguous when either name contains `__`, so the badge asks the user to remove and re-add the hook.
- **`PreSkillShellCommand` is new in Claude Code 2.1.332.** Older engines show a start-up dialog for a settings file that names it; the editor's description says so.
- **Loop end dates** come from `maxAgeMs` when the engine sends it, else from the result text, else a 7-day fallback. A `maxAgeMs` of 0 is treated as the 30-day engine cap.
- **`disableSideloadFlags` and Claudius's database agents.** Under that policy the engine silently drops agents Claudius passes inline; that isn't a startup refusal, so no banner appears. Candidate follow-up: say so on `/agents` when the managed tier sets it.
- **`fileCheckpointingEnabled: false` (managed).** "Restore files" still shows and fails with the SDK's message (both refusal shapes already reach the dialog). Candidate follow-up: hide it via `resolveSettings`, as `lib/server/managed-model-policy.ts` does for models.
