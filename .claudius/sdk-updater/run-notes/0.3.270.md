## Summary

The prompt's changelog/type-diff window is computed cumulatively against
0.3.267, but `main` (and this branch's base, `origin/main` @ `3df3c70`)
already carries the two intermediate releases as separate, already-merged
PRs: `sdk-update/0.3.268` (PR #246) and `sdk-update/0.3.269` (PR #251). I
cross-checked every changelog bullet and every identifier under "New
declarations" against `.claudius/sdk-updater/run-notes/0.3.268.md` and
`0.3.269.md`, then re-verified each claimed shipped surface is still
present and unmodified in the working tree (file:line citations below).
Every single one was already triaged — most `[shipped]` end-to-end,
several deliberately `[skipped]` with an audited "unreachable" reason —
by those two prior runs. The only line in the changelog block that is
actually new to this specific 0.3.269→0.3.270 bump is "Updated to parity
with Claude Code v2.1.270", a bare parity marker with no accompanying
type-surface change, which (per the established convention in
0.3.268.md/0.3.269.md) is tracked by the separate cc-parity pipeline, not
this SDK-version bump. One doc-only change (the `applyFlagSettings`
JSDoc clarifying that `effortLevel`/`model`/`agent`/`ultracode` reset to
session defaults rather than falling back to a `query()` option or
settings file) was not previously called out; I audited it against
`Session.setEffort`/`setUltracode`/`setAgent` and found the existing
code/doc comments already describe exactly that reset behavior — no
correction needed. **Net result: no product code changes were required
for this bump.** Headline risk to flag for review: this is a
version-bump-plus-notes PR by design, not by omission — the audit trail
below is the evidence; a reviewer who wants independent confirmation
should spot-check a couple of the "already shipped, still present" file:line
citations against `main`.

## Risks / follow-ups

- `local_command` (skipped again this window, originally flagged in
  0.3.268.md): a pure local slash command still renders as a bare
  `system/local_command_output` pill with no content. Still unaddressed;
  would need a new SSE event, client reducer, and pill UI — worth
  scheduling as dedicated UX work rather than folding into a future
  version-bump PR.
- `get_hooks_listing` / `list_permission_rules` (skipped again, 0.3.269.md):
  genuinely useful live permission/hook state that Claudius's file-based
  `/hooks` and `/permissions` pages don't surface. Still unreachable —
  no exported `Query` method issues either control request as of
  0.3.270. Re-check `declare interface Query` in `sdk.d.ts` on the next
  upgrade for a promoted method (e.g. `getHooksListing()` /
  `listPermissionRules()`).
- `ArtifactOutput.written`/`foreign`, `FileEditOutput.staged`,
  `FileWriteOutput.staged` (skipped again, 0.3.269.md): describe a "held
  for machine-owner review" tool-call workflow Claudius's `canUseTool`
  model (`allow`/`deny` only) has no equivalent of. Watch for a
  corresponding `PermissionResult` third outcome in a future release.
- None of this window's changelog bug fixes (permission_denials
  omission, OAuth sign-in interrupt delay, missing tool_use_id on
  auto-resumed subagents, plan-mode canUseTool routing) required new
  verification beyond the static reachability audits already on record
  in `0.3.269.md` — all four were confirmed unreachable by grep/read,
  not by exercising the underlying bug, carried forward unchanged.
