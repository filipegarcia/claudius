## Summary

0.3.235 is a parity-only bump (CLI parity with Claude Code v2.1.235; no
public SDK export changed) and 0.3.236 adds exactly one new hook
capability: `PostToolUse` hook results can now include
`hookSpecificOutput.classifierContext`, a short host-asserted note about a
tool call's result that the auto-mode permission classifier reads
alongside that result. Claudius doesn't construct that field itself (its
one programmatic `PostToolUse` hook in `lib/server/session.ts` only
snapshots on-disk hashes and always returns `{ continue: true }`) — the
field exists for *user-authored* `PostToolUse` hooks (command/http/prompt/
agent/mcp_tool, configured on `/hooks`) to set. The only place Claudius
owns that surface is the `/hooks` editor's per-event documentation in
`lib/shared/hook-events.ts`, which is what this PR updates so a user
composing a `PostToolUse` hook can discover the capability. Headline risk:
none — this is an additive, purely-documentary change with no behavior
change to Claudius's own hook handlers or permission logic.

## Code changes

- `lib/shared/hook-events.ts` — `PostToolUse`'s `description` now
  mentions that a hook result can assert `classifierContext` to
  inform the auto-mode permission classifier. This is the string
  rendered verbatim on each event row in `/hooks`, so it's the actual
  (only) Claudius-owned surface for this SDK capability.
- `tests/unit/hook-events.test.ts` — added a pinning test (mirrors the
  existing `DirectoryAdded` 0.3.219 pin) asserting the `PostToolUse`
  spec's description mentions `classifierContext`, so a future refactor
  can't silently drop the callout.

  — Playwright spec confirming the description is actually visible on
