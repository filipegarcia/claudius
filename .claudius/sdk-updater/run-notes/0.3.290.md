# SDK update 0.3.289 → 0.3.290

## Summary

0.3.290 is a small release: WebFetch gains an optional `offset`, a new `OfferChromeSetup` tool type appears, a new `idleCompaction` setting is added, and several CLI-side fixes (tool alias deny rules, replay of duplicate uuids, `message_stop` on cut streams, `resume_reason`/`user_message_uuid` on more resumed turns) land inside the SDK binary. Claudius now exposes `idleCompaction` in the settings catalog; everything else is type-only or not reachable. Headline risk: low.

## SDK changelog highlights

- WebFetch `offset` input (`offset`) [type-only — Claudius renders WebFetch tool calls generically from the input JSON; nothing to wire, the model supplies it].
- Chrome tool result `_meta` preserved in `tool_use_result` [skipped — SDK-internal result shape; Claudius shows tool results generically].
- Deny/ask rules matching `toolAliases` tools with wildcards [skipped — runtime permission-matching fix inside the SDK, no Claudius call-site].
- Duplicate-uuid user message replay fix [skipped — `--replay-user-messages` behaviour inside the CLI; Claudius does not rely on replay ordering].
- `includePartialMessages` streams always end with `message_stop` [skipped — fix only makes streams more complete; our stream reducer already tolerates a missing/duplicate stop].
- `user_message_uuid`, `user_message_uuids`, `resume_reason` set on more resumed turns [type-only — doc change only; fields unchanged in shape, Claudius does not key behaviour on them].
- Parity with Claude Code v2.1.290 [skipped — no separate SDK surface; cc-parity pipeline covers CLI behaviours].
- `idleCompaction` (Settings) [shipped — added to `SDK_SETTINGS_CATALOG` under "Context & compaction"].
- `offset` (sdk-tools.d.ts, WebFetchInput) [type-only — see above].
- `OfferChromeSetupInput` / `reason` and `OfferChromeSetupOutput` / `outcome` [type-only — new tool the CLI may call to offer Claude in Chrome setup; tool calls render via the generic ToolCall fallback, no bespoke UI].
- Doc-only: `disableClaudeAiConnectors` now also blocks explicitly passed claudeai-proxy servers [skipped — CLI behaviour; catalog description left as is]. `bridge.d.ts` `CreateSessionFailure.detail` doc [skipped — bridge API unused by Claudius].
- Model identity: no model names, aliases, defaults, context windows or pricing tiers changed in this release, so no model surfaces need updating.

## Code changes

- `app/settings/page.tsx`: added `idleCompaction` boolean entry to `SDK_SETTINGS_CATALOG` ("Context & compaction" section) so the setting is editable in the Settings page instead of falling through to the raw JSON editor.

## New UI surfaces

- No new UI surfaces this release. The only UI delta is one additional boolean row in the existing generated settings catalog, rendered by the same component as its neighbours.

## Tests

- No new tests required. The catalog row is data rendered by the existing generic settings control, already covered by existing settings e2e specs; full gates were run.

## Risks / follow-ups

- `idleCompaction` only has an effect when false; the UI toggle writes true/false literally, and true is a no-op per the SDK doc (noted in the description).
- Gates: lint, vitest (2541 passed) and build are green. Full e2e: 311 passed, 7 skipped, 5 failed (session-management, session-tabs-pin, site-marketing lightbox, 2x sticky-user-message). All fail with a 60s timeout; I re-ran site-marketing and session-tabs-pin on a clean `main` checkout and they fail identically there, so they are pre-existing local-environment failures unrelated to this bump (none touch the settings catalog). The other three were not re-run on `main`.
- Local note: vitest needed `better-sqlite3` rebuilt for the Node ABI (local toolchain artifact, not committed).
