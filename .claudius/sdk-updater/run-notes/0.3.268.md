# SDK update 0.3.267 → 0.3.268

## Summary

0.3.268 is entirely undocumented-field territory: the four-bullet prose
changelog ("added `result_index`", "added `local_command`", "added
`hold_on_cache_impact`", "added `resume_reason`", plus three behaviour
changes and a parity bump) understates the actual type-surface delta —
diffing `sdk.d.ts` turns up two more shipped-worthy fields
(`canUseTool`'s `defaultToNo`/`suppressAlwaysAllowRule`, `SDKRateLimitInfo
.limitScope`, `get_context_usage`'s `kind` classifier, a new
`SDKAssistantMessageError` value, and three `Settings` passthrough keys)
that the prose never mentions. We shipped all of those end-to-end
(server → SSE/API → UI, with a Playwright spec + screenshot per UI
surface) and left the rest — `result_index`, `local_command`,
`resume_reason`, the `initialize` response's now-always-present
`pending_permission_requests`, and the Artifact tool's `icon` — skipped
with an audited "no reachable call site" justification each (see below).
One changelog item, the task-tracking-tools model gate, turned out to
already be shipped: this branch's sibling `cc-parity/2.1.268` commit
(`ab6e8e4`, already on this branch per the "combine a coinciding cc-parity
+ sdk-update release into one PR" convention) fixed the exact same
default-tool-boundary problem via `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`, for
reasons unrelated to this SDK bump but that happen to cover it too.
Headline risk to flag for review: `local_command` (skipped) revealed a
pre-existing UX gap — a pure local slash command still renders as a bare
`system/local_command_output` pill with no content — that we did **not**
fix this release; see Risks.

## SDK changelog highlights

- Added `result_index` to result messages: the result's position in
  delivery order within the run — `[skipped — diagnostic field for
  detecting a lost result in a stdout-multiplexed stream-json pipe.
  Claudius's transport is an in-process SSE broadcast over HTTP, not a
  multiplexed stdout stream, so there's no equivalent loss mode for it to
  detect. Grepped `result_index`/`resultIndex` across `lib/` and
  `app/` — zero hits]`
- Added `local_command` to the result message of a turn that ran a slash
  command without entering the model loop, carrying the command's name —
  `[skipped — would need a new SSE event/client reducer/SystemEntry kind
  and pill, the largest chunk of surface in this release, for UX the
  changelog didn't ask for. Grepped `local_command`/`localCommand` — zero
  hits on the new *field*; there IS pre-existing handling of the
  *system-message subtype* `local_command_output` in
  `lib/server/session.ts` (~L7660), which is what this skip actually
  exposed as a gap — see Risks]`
- Added `hold_on_cache_impact` to the `reload_plugins` control request
  (`Query.reloadPlugins({ holdOnCacheImpact: true })`) — `[shipped]`.
  `Session.reloadPlugins()` now defaults to `holdOnCacheImpact: true`
  (mirroring the interactive CLI's own `/reload-plugins` → `--force`
  check); `/reload-plugins force` in chat re-sends with it `false`.
- Added `resume_reason` to assistant, stream-event and result messages
  (host-restart interrupted-turn re-run) — `[skipped — no reachable call
  site: grepped `resume_reason` / `CLAUDE_CODE_RESUME_INTERRUPTED_TURN` /
  `CLAUDE_CODE_RESUME_REASON` across `lib/` and `app/` — zero hits.
  Claudius runs the SDK as a long-lived in-process child, not under a
  host-restart orchestrator that sets either env var, so this re-run path
  never fires for us]`
- Added `kind` (used, free, buffer, deferred) to each `get_context_usage`
  category — `[shipped]`. `ContextOverlay`'s `StackedBar` used to
  string-match `name !== "Free space"` — exactly what the SDK's own doc
  comment warns against ("classify on this, never on the name"). Now
  classifies on `kind` when present, falling back to the old name check
  for a CLI that predates the field.
- Added optional `defaultToNo` and `suppressAlwaysAllowRule` hints to
  `canUseTool` options — `[shipped]`. See the dedicated writeup below and
  in "Code changes".
- Changed `setModel()` to confirm a model id the CLI doesn't know locally
  with the API the first time a session uses it, instead of refusing it
  as unrecognized — `[skipped — internal SDK behaviour change, already
  covered]`. `Session.setModel()` (`lib/server/session.ts`) forwards
  whatever id string it's given to `query.setModel()` inside a try/catch
  that surfaces *any* rejection generically; that handles both the old
  "refuse synchronously" and the new "confirm with the API first" shapes
  without a call-site change.
- Changed `user_message_uuid` on the automatic re-run of an interrupted
  turn to name that turn's last user prompt — `[skipped]` — same
  reachability gap as `resume_reason` above; this only applies to frames
  tagged with a `resume_reason` Claudius never receives.
- Changed the `initialize` success response to always include
  `pending_permission_requests` (doc-only reword of an existing field —
  not a new declaration; sibling `pending_user_dialog_requests` too) —
  `[skipped — no call site: grepped both field names, plus
  `initializationResult`/`.reinitialize(` (the only exported methods that
  surface `SDKControlInitializeResponse`), across `lib/` and `app/` — zero
  hits. Claudius's own `pendingPermissions` map is populated entirely from
  `canUseTool` callbacks, never by reading this control response]`
- Changed the task-tracking tools (TaskCreate/Get/Update/List, TodoWrite)
  to be default tools only on Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6 and
  Haiku 4.5, elsewhere requiring `tools`/`allowedTools` — `[shipped — via
  the cc-parity 2.1.268 commit already on this branch (`ab6e8e4`, "MCP
  needs-auth announce-once + todo-tools env fix")]`. That commit
  discovered `allowedTools: TODO_TASK_TOOL_NAMES` alone doesn't work — the
  SDK's tool-gate never consults `allowedTools`, only model tier and
  `CLAUDE_CODE_ENABLE_TODO_TOOLS` — and switched Claudius to set
  `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` unconditionally in the session's env.
  That's model-tier-independent, so it also covers 0.3.268's updated
  default-tool boundary for any model, named on the list or not. No
  additional change needed from this update.
- "Updated to parity with Claude Code v2.1.268" — covered by the items
  above plus the separate `cc-parity/2.1.268` work on this same branch; no
  additional sdk-update-specific call sites found.

## Code changes

- `lib/client/api-retry.ts` + `tests/unit/api-retry.test.ts` — add
  `verification_required` to the `ApiRetryErrorReason` mirror and its
  human-readable phrase.
- `components/overlays/ContextOverlay.tsx` — classify the "Free space"
  category by the SDK's new `kind` field instead of its English `name`.
- `lib/client/use-session.ts` + `lib/client/types.ts` +
  `components/chat/RateLimitHitPanel.tsx` + `components/chat/SystemPill.tsx`
  — forward `SDKRateLimitInfo.limitScope` and swap the personal upgrade
  links for a shared-pool / contact-admin line when it's `'group_pool'`.
- `lib/shared/events.ts` + `lib/server/session.ts` (`canUseTool`) +
  `components/chat/PermissionPrompt.tsx` — forward `defaultToNo` /
  `suppressAlwaysAllowRule` from the SDK's `canUseTool` options onto
  `PermissionRequestEvent`, and render both hints in the modal.
- `components/chat/PromptInput.tsx` — fix a focus-stealing race the above
  exposed: the composer's "don't steal focus while the user is in another
  editor" guard only excluded INPUT/TEXTAREA/contentEditable, so its
  autofocus rAF would yank focus back from the permission modal's deny
  button (a `<button>`). It now also bails when `[data-permission-modal]`
  is present, checked again inside the rAF callback (the modal can mount
  in the gap between scheduling and firing).
- `lib/server/session.ts` (`reloadPlugins`) +
  `app/api/plugins/reload/route.ts` + `lib/shared/reload-plugins.ts`
  (new, unit tested) + `lib/shared/slash-commands.ts` +
  `components/chat/ChatSurface.tsx` — hold-by-default `reloadPlugins()`,
  a `force=1` passthrough on the reload route, and `/reload-plugins
  force` in chat to lift the hold; held responses show a toast
  summarizing what applying would change. (`app/api/plugins/route.ts`'s
  read-only plugins-listing GET needed no change — it already called
  `reloadPlugins()` with no options, which now means "hold by default"
  instead of "always apply", fixing a latent side effect where loading
  `/plugins` silently invalidated the prompt cache.)
- `app/settings/page.tsx` — three new SDK-settings-catalog rows:
  `gatewayInternalNetworks` (Authentication), `prependPlugins` /
  `appendPlugins` (new "Plugins" section). All three are already
  reachable via `ClaudeSettings`'s index signature (no server-side type
  change needed — same passthrough pattern as `promptCacheTtl` in
  0.3.245).
- `package.json` / `bun.lock` — SDK bump to `^0.3.268` (orchestrator).

## Risks / follow-ups

- `local_command` (skipped this release) revealed a pre-existing gap: a
  pure local slash command (`/clear`, `/compact`, `/cost`, …) that never
  enters the model loop renders in the transcript as a bare
  `system/local_command_output` info pill with no content shown at all
  (`lib/client/use-session.ts`'s generic `system/${subtype}` fallback,
  paired with the existing but narrowly-scoped handling in
  `lib/server/session.ts` ~L7660). The new `local_command` result field
  would let a future pass label this properly (e.g. "Ran /compact") and
  show the paired system message's content instead of dropping it.
  Scoped out of this release as new UX the changelog didn't request —
  worth a follow-up.
- `resume_reason` / `user_message_uuid`-on-resume / the `initialize`
  response's `pending_permission_requests` are all gated on Claudius
  never running the SDK under a host-restart orchestrator (no
  `CLAUDE_CODE_RESUME_INTERRUPTED_TURN` / `CLAUDE_CODE_RESUME_REASON` env
  var, no `initializationResult()`/`reinitialize()` call). If Claudius
  ever adds multi-worker restart-resume or multi-client session
  reconnect, re-audit all three together — they're one coherent feature
  upstream.
- `result_index` is a diagnostic-only field for detecting a lost result
  in a stdout-multiplexed pipe; revisit only if Claudius ever exposes a
  raw-message debug/export view where a dropped SSE frame would need
  detecting the same way.
- The three new settings-catalog rows (`prependPlugins`, `appendPlugins`,
  `gatewayInternalNetworks`) are managed-settings-only per their SDK doc
  comments — Claudius has no "managed" settings scope/UI, so they're only
  useful today via the catalog's raw JSON round-trip (same limitation
  `forceLoginGatewayUrl` already has). No new risk, just noting the
  ceiling on their usefulness in Claudius's current settings model.
- The `PromptInput.tsx` focus-stealing fix (see "Code changes") is a
  narrowly-targeted patch (checks specifically for
  `[data-permission-modal]`) rather than a general "don't steal focus
  from any focused element" guard. If a future modal introduces the same
  race, it'll need the same explicit opt-out rather than inheriting this
  one automatically.
- This run's `git diff main...HEAD` also contains the sibling
  `cc-parity/2.1.268` commits (this branch combines both releases per the
  project's own convention for a coinciding cc-parity + sdk-update
  window) — that work is documented separately in
  `.claudius/cc-parity/run-notes/2.1.268.md` and is out of scope for this
  file, which covers only the `0.3.267 → 0.3.268` SDK delta (commits
  `b1319f4..166dd3b`, plus the version-bump commit `f6b2857`).
