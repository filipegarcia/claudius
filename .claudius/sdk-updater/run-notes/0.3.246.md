## Summary

0.3.246 is a small release: four new public fields, none of them a
model-identity or pricing-tier change we hard-code. Of the two that
are actual options Claudius' server passes to the SDK, one was a real
gap — `perTaskStopAffordance` — which we now declare in
`lib/server/session.ts`'s `Options` builder, since Claudius already
ships the exact per-task stop UI (`BackgroundTasksPanel` +
`Session.stopTask()` + `POST /api/sessions/[id]/stop-task`) that this
flag is designed to attach to; without it, the global Stop button was
silently killing every backgrounded agent/workflow on every interrupt,
even though the user has a dedicated way to stop them individually.
The other actionable item, `Settings.syncClaudeAiPlugins`, is a plain
settings-file toggle (mirrors the pre-existing `syncClaudeAiSkills`)
that we surface as a checkbox in the existing "Plugins" card on
`/settings`. `user_message_uuid` and `modelUsage[*].costBasis` both
ride through Claudius's existing untyped SDK-message/usage passthrough
with zero code required, and aren't hooked to any UI this release —
see the "type-only" entries below for why. Headline risk for review:
`perTaskStopAffordance` is a genuine behavior change to Stop's blast
radius and is only exercised by a vitest-free/e2e-free code path (see
"## Risks / follow-ups") — worth a manual smoke of "Stop while a
background Task is running" before merge.

## SDK changelog highlights

- `user_message_uuid` on `SDKResultError` / `SDKAssistantMessage` /
  `SDKPartialAssistantMessage` — **[type-only]**. `lib/server/session.ts`
  imports the SDK's own `SDKMessage` union directly (no locally mirrored
  message-shape types) and broadcasts every message wholesale
  (`this.broadcast({ type: "sdk", message })` in the `for await` consume
  loop) — new fields on message types the client already unwraps ride
  along automatically with no server or client type change. Claudius
  *does* already mint and pin a client-side `uuid` per user turn
  (`session.ts` ~L2954, reused for the inputQueue message, the JSONL
  write, and dedup/resume cursors), so the pieces exist to eventually
  build a "which reply answers which send" correlation — but there is
  no current UI concept that needs it (turns are rendered strictly in
  arrival order), so wiring it up this release would be new,
  un-requested surface. Flagged as a follow-up idea, not shipped.
- `modelUsage[*].costBasis` (`'list' | 'managed' | 'unknown'`) —
  **[type-only]**. `SessionUsage.modelUsage` is already
  `Record<string, unknown>` (`lib/client/types.ts:547`), populated
  opaquely from the raw `result` event (`use-session.ts`), so
  `costBasis` is already present in that blob today with zero code
  change. Not surfaced in UI: Claudius's own cost dashboard
  (`lib/server/cost-aggregate.ts`) doesn't read the live `modelUsage`
  blob at all — it re-derives cost from on-disk JSONL `costUSD` values
  priced against Claudius's own LiteLLM-based table
  (`lib/server/litellm-pricing.ts`), which has no "managed" pricing
  concept. Since Claudius never sets `managedSettings`/`modelPricing`
  (see next item), `costBasis` would only ever read `'list'` or
  `'unknown'` in Claudius's own sessions today, so there is no
  actionable "list vs managed" distinction to show yet.
- `modelPricing` support in the `managedSettings` option (for hosts
  that set `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`) — **[skipped —
  audited, unreachable]**. This is a pricing-tier item, so per the
  higher skip bar: confirmed via `rg -rn "managedSettings|modelPricing|CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST"`
  across `lib/` and `app/` that Claudius never sets `managedSettings`,
  `serverManagedSettings`, or the `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
  env var anywhere — it isn't a "managed" host in the SDK's sense.
  Audited the model-identity/pricing surfaces named in the prompt:
  `app/api/models/route.ts` (`STATIC_FALLBACK`), `app/api/models/probe/route.ts`,
  `app/api/sessions/[id]/model/route.ts`, `lib/client/types.ts`
  (`ModelInfo`), `lib/server/session.ts` (model-conditional logic —
  fable-advisor clearing, `enable1mContext`/`context-1m` gating), and
  `lib/server/litellm-pricing.ts` + `lib/server/litellm-prices.json` —
  none reference `modelPricing` or a managed-settings pricing tier;
  Claudius's cost figures are entirely self-computed from the LiteLLM
  snapshot, independent of this SDK mechanism. Genuinely unreachable.
- `perTaskStopAffordance` option — **[shipped]**. See "## Code changes".
- (sdk-tools.d.ts, doc-only) `ArtifactInput.action` JSDoc — `upload_asset`
  now also accepts CSV/Markdown/JSON/plain-text files, not just
  image/video/PDF/font — **[skipped — no call-site]**. `rg -i
  "upload_asset|ArtifactInput"` across `lib/`, `app/`, `components/`
  returns nothing; Claudius doesn't special-case the Artifact tool's
  input shape or restrict file types client-side, so the widened
  accepted-type list needs no code change.
- (sdk-tools.d.ts, doc-only) `FileWriteOutput.structuredPatch` /
  `originalFile` JSDoc — now documented as possibly empty/null on a
  timeout or an oversized previous file — **[skipped — no call-site]**.
  `rg "structuredPatch|originalFile"` across `lib/`, `app/`,
  `components/` returns nothing; Claudius renders `FileWrite`
  tool_result blocks generically and never reads these fields directly.

## Code changes

- `lib/server/session.ts` — added `perTaskStopAffordance: true` to the
  `Options` object passed to `query()`. Claudius already renders a
  full per-task stop affordance (`Session.stopTask()` →
  `query.stopTask(taskId)`, exposed via `POST /api/sessions/[id]/stop-task`,
  driven from `BackgroundTasksPanel`'s per-row Stop buttons and its
  "stop all" fan-out over `collectStoppableTaskIds`). Declaring the
  flag tells the SDK that an `interrupt()` (the composer's Stop
  button) should only abort the current turn and spare running
  background agents/workflows, instead of failing closed and killing
  them all — matching the UI's existing implied contract.
- `lib/server/settings.ts` — added `syncClaudeAiPlugins?: boolean` to
  `ClaudeSettings`, mirroring the SDK's key exactly (only `false` is
  honored; the CLI reads it straight from `~/.claude/settings.json`,
  so no per-session SDK forwarding is needed, same shape as the
  0.3.245 `promptCacheTtl` addition).
- `app/settings/page.tsx` — added a `syncClaudeAiPlugins` `ToggleRow`
  inside the existing (previously read-only) "Plugins" card, next to
  the `enabledPlugins` JSON dump, and extended that card's search
  keywords (`sPlugins`) so the toggle is discoverable via the settings
  search box.
- `tests/e2e/sdk-update-0.3.246-sync-claude-ai-plugins.spec.ts` — new
  Playwright spec (see "## New UI surfaces" / "## Tests").

## Tests

- vitest: 0 new specs. `perTaskStopAffordance: true` is a static
  literal in the `Options` object builder in `lib/server/session.ts`,
  the same category as neighboring literals like
  `includePartialMessages: true` / `enableFileCheckpointing: true`,
  none of which have a dedicated pinning test —
  `tests/unit/session-options.test.ts`'s own doc comment explains why:
  exercising the full `Session.start()` → `query()` options path
  requires mocking disk I/O, DB reads, and the notification sweep "for
  no extra signal" versus pinning the one exported constant a test
  actually needs (`TODO_TASK_TOOL_NAMES`). There is no equivalent
  single-point exported constant for this boolean, so no vitest was
  added; the e2e spec below is genuine (not literal-pinning) coverage.
- playwright: 1 new spec
  (`tests/e2e/sdk-update-0.3.246-sync-claude-ai-plugins.spec.ts`),
  0 updated. Not covered: the actual behavior change from
  `perTaskStopAffordance` (a Stop press sparing a running background
  Task) — that requires a real agent running a real backgroundable
  task and would need the `chromium-live` project; see "## Risks /
  follow-ups".

## Risks / follow-ups

- `perTaskStopAffordance: true` changes what the global Stop button
  does whenever a background agent/workflow is running: it now leaves
  those tasks running instead of killing them. This is the intended
  effect (Claudius already gives users a dedicated way to stop
  individual tasks) but it's a real behavior change with no automated
  coverage of the "press Stop mid-turn while a Task is backgrounded"
  path — that needs a live agent to exercise realistically. Recommend
  a manual smoke test before merge: start a long-running backgrounded
  Task, press the composer Stop button, and confirm the Task keeps
  running in `BackgroundTasksPanel` afterward (and that it can still be
  stopped individually via its own Stop button).
- `syncClaudeAiSkills` (the pre-existing sibling of the new
  `syncClaudeAiPlugins`) is still not surfaced anywhere in the Settings
  catalog — it currently falls through to the generic "Other" JSON
  editor. Out of scope for this bump (it isn't part of the 0.3.246
  diff), but worth adding alongside `syncClaudeAiPlugins` in a
  follow-up pass for consistency now that one of the pair has a proper
  toggle.
- `user_message_uuid` is a plausible foundation for a future
  "highlight which reply answers this send" UI, and Claudius already
  mints the matching client-side uuid per turn — but building that UI
  wasn't part of this release's scope and isn't started.
