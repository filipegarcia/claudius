# SDK update 0.3.294 → 0.3.295

## Summary

0.3.295 is a parity release with Claude Code v2.1.295. Most of its surface was already absorbed by earlier cc-parity work (the `extraUsageState` helper and pill line, and the hook `onFailure` field, both already in the tree). The only genuinely new public field Claudius could use was `SDKRateLimitInfo.overageEnabled`, the direct "is extra usage on?" flag. It is now wired into `extraUsageState`, which drives the rate-limit pill's "extra usage is on/off" line, and into the client mirror types. The rest is runtime or limit behaviour inside the SDK/CLI with no Claudius call-site. Headline risk: `overageEnabled` precedence, documented below.

- `lib/client/use-session.ts` — `rate_limit_event` payload typing gains `overageEnabled`.

## Risks / follow-ups

- Assumption: when `overageEnabled: true` conflicts with `overageStatus: 'rejected'` or an `overageDisabledReason`, the "off" signal wins. This is the same precedence the helper already used for `isUsingOverage`. The alternative, letting `overageEnabled` override everything, was rejected as less conservative.
- Behaviour change to eyeball: a warning with only `overageEnabled: false` now shows the "extra usage off" line, where before it showed nothing.
