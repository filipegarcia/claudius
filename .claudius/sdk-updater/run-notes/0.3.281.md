## Summary

This run's prompt frames the jump as 0.3.274 → 0.3.281, but `main` had
already absorbed 0.3.275 through 0.3.280 through prior, separate
`sdk-update/*` and `cc-parity/*` PRs (see `git log --oneline -- lib/server/
settings.ts` for the paper trail: `feat(sdk-update): implement 0.3.277
shipped items`, `feat(cc-parity): 2.1.277 — … deprecate taskOutputMaxChars`,
etc.) — `package.json` was at `^0.3.280` before this bump, not `^0.3.274`.
So the type-surface diff attached to this run (computed against the stale
0.3.274 tarball) lists a large number of fields that are already wired up
in the current tree; those are marked `[shipped — landed in an earlier PR]`
below with the grep that proves it, not re-implemented. The genuinely new
surface at 0.3.281 is one changelog item — optional `trigger` /
`user_message_uuid` / `timestamp` on the pre-existing `conversation_reset`
message — plus a `Settings.attribution` type widening. Claudius had **zero**
handling of `conversation_reset` anywhere in the tree (confirmed via
repo-wide grep) even before this bump, so this release's fields are what
make wiring it up worthwhile: the client now renders a "Conversation reset"
divider with the trigger reason and timestamp instead of silently dropping
the frame. `Settings.attribution` needed no change — nothing in Claudius
reads or writes that key. The headline risk: the new divider covers the
frame arriving, but doesn't yet remount the transcript under
`new_conversation_id` (a materially bigger change to session load/replay);
see Risks/follow-ups.

## Risks / follow-ups

- The divider surfaces that a reset happened but does **not** remount the
  transcript under the frame's `new_conversation_id` (a field that predates
  0.3.281, not new to it). The SDK's own JSDoc recommends mounting a fresh
  transcript on this frame; Claudius's session/transcript loading is built
  around a single persistent JSONL history per session id, so honoring
  `new_conversation_id` would mean either splitting the visible transcript
  at the reset point or reloading a distinct sub-history — a materially
  bigger change to `lib/server/session.ts`'s history-loading path than this
  release's scope. Chose the conservative option (surface the event,
  don't restructure history loading) since the divider still gives the
  user the "what/why/when" the changelog calls out, and a wrong transcript-
  remount implementation risks silently hiding real transcript content.
  Next step if this needs to go further: decide whether `new_conversation_id`
  should become the session's new resume pointer.
- `user_message_uuid` (dedup a `/clear` frame against the message that
  caused it) isn't used for de-duplication — Claudius's own `/clear` never
  produces this frame (see Summary), so there's currently no double-render
  case to guard against. If a future change ever routes `/clear` through
  the SDK instead of the new-session shortcut, revisit this.
- `view_mode` (`'focus' | 'default'`) is a plausible future enhancement to
  sync with Claudius's existing client-local Focus/Zen mode, but the two
  are conceptually distinct today (one's CLI/Remote-Control state, the
  other's pure browser UI) — deliberately left unreconciled rather than
  guessed at; see "New declarations" above.
- Scoped `bun run test:e2e` to the new spec plus a full-suite run for this
  session (see Definition-of-Done paste below) rather than re-running every
  pre-existing spec twice; no pre-existing spec touches `SystemEntry.kind`
  exhaustively apart from the one updated in `verbose-filter.test.ts`.
