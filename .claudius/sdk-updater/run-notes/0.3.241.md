## Summary

0.3.236 → 0.3.241 spans four SDK releases (0.3.237 parity-only, 0.3.238,
0.3.239, 0.3.240/0.3.241 parity-only) whose substantive changes are all
in 0.3.238–0.3.239: `task_started` gained public `is_backgrounded` and
`spawn_depth` fields, `total_cost_usd`/`modelUsage.costUSD` now fold in
the 1.1× US-data-residency multiplier server-side, a `command_lifecycle`
`refused` terminal state, a `background_tasks_changed` resend on repeated
`initialize`, a `UserPromptExpansion.suppressOriginalPrompt` hook output
field, a `hooks_applied` initialize-response flag, and a Bedrock/Vertex/
Foundry/gateway `systemPrompt` array-literal bug fix. Only the
`task_started` fields had a real Claudius call site: `is_backgrounded`
was previously seeded only from a later `task_updated` patch, which a
task backgrounded from birth (a resumed subagent, always backgrounded
per the SDK) never receives — leaving `hasActiveSubagents()` /
`countActiveBackgroundTasks()` permanently wrong for that task after a
reload. `spawn_depth` is wired through end-to-end as a new "L{n}"
nesting badge in the Tasks rail for depth-≥2 subagents. Both fields are
now also persisted to `session_tasks` (new migration 016 — they were
never written to disk even before this bump, so the bug would have
resurfaced on every idle-reap/restart reload). Everything else audited
as SDK/CLI-internal or already generically handled — see the
changelog section below for the audit trail. Headline risk: the new
`session_tasks` columns are additive-only (nullable `ALTER TABLE ADD
COLUMN`), so no backfill/rollback concern, but reviewers should confirm
the 0/1/null tri-state mapping in `session-tasks-db.ts` reads correctly.

### 0.3.239

- `[skipped — no Claudius-side call site]` `total_cost_usd` /
  `modelUsage.costUSD` now include the 1.1× US-only-inference
  multiplier when `inference_geo: "us"`. `inference_geo` is not
  exposed anywhere in `sdk.d.ts` — it's an Anthropic-API-internal
  field the CLI binary consumes to compute the cost fields *before*
  they ever reach `query()`. Claudius's primary cost path
  (`lib/server/cost-aggregate.ts:173`, `lib/server/scheduler.ts:178`)
  reads `costUSD`/`total_cost_usd` straight off live SDK results, so
  it already reflects the multiplier verbatim with zero code changes
  needed. The one place Claudius *independently* estimates cost is
  `lib/shared/cost-pricing.ts`'s `costFromTokens` — a back-compute
  fallback used only when replaying on-disk JSONL that has no
  `total_cost_usd` snapshot. That fallback doesn't (and structurally
  can't) know the account's data-residency setting, so it will
  under-estimate by ~10% for US-residency accounts. The file's own
  docstring already frames it as an "approximate" fallback whose
  source of truth is the live `total_cost_usd` field, so this drift
  stays inside its documented error bar — not shipping a fix here,
  flagged under Risks below instead.
- `[skipped — Claudius never runs one-shot/print mode]` A held-back
  background-subagent result in one-shot mode now reports
  `total_cost_usd`/`duration_api_ms`/`modelUsage` as of release, not
  turn-end. Claudius always opens a streaming-input session
  (`query({ prompt: this.inputQueue, options })`,
  `lib/server/session.ts:2457`, `inputQueue` is an `AsyncQueue`) — the
  one-shot/`-p` code path this fixes is never exercised.
- `[skipped — audited, no call site]` Fixed `SYSTEM_PROMPT_DYNAMIC_
  BOUNDARY` in an *array*-shaped `systemPrompt` being sent to the
  model as literal text on Bedrock/Vertex/Foundry/gateway providers.
  Claudius **does** support all four of those providers (the account
  switcher forwards `CLAUDE_CODE_USE_BEDROCK`/`_VERTEX`/`_FOUNDRY`,
  see `lib/server/accounts-store.ts:547-549`), so this got the full
  audit rather than a generic skip. Claudius's only `systemPrompt`
  construction site (`lib/server/session.ts:2110-2118`) always emits
  the `{ type: "preset", preset: "claude_code", append }` *object*
  form, never an array of blocks — the bug only affected the array
  form, so it never manifested for Claudius on any provider,
  Bedrock/Vertex/Foundry/gateway included.
- `[skipped — behavioral improvement, no shape change]` A repeated
  `initialize` on a running process now gets a fresh
  `background_tasks_changed` snapshot. Claudius's existing consumer
  (`lib/client/use-session.ts`'s `liveBackgroundTaskIds` gate,
  `lib/client/task-status.ts`) already treats this message type
  generically and needs no change — this only makes an existing
  message arrive more reliably after a reconnect-style re-initialize,
  which Claudius doesn't itself trigger (see the 0.3.238 `hooks_applied`
  item below for why).

### 0.3.238

- `[shipped]` Added `is_backgrounded` and `spawn_depth` to
  `task_started` events (`is_backgrounded` also now on background Bash
  tasks). Wired end-to-end: `lib/server/session.ts` (`captureTaskState`
  seeds both from `task_started` instead of only from a later
  `task_updated` patch), `lib/shared/events.ts` (`TaskSnapshotEntry`),
  `lib/server/session-tasks-db.ts` + new migration `016_session_tasks_
  backgrounded_depth.sql` (both fields are now persisted — they were
  never written to `session_tasks` even pre-0.3.238, so the "backgrounded-
  from-birth task looks active forever" bug would have resurfaced on
  every idle-reap/restart reload), `lib/client/types.ts` (`TaskInfo.
  spawnDepth`), `lib/client/use-session.ts` (task_started reducer), and
  `components/panels/BackgroundTasksPanel.tsx` (new "L{n}" nesting
  badge for depth ≥ 2). See "New UI surfaces" below.
- `[skipped — audited, dead bucket by design]` `command_lifecycle`
  gained a `refused` terminal state (a cross-session peer message the
  receive-side policy declines). Claudius **does** have the relevant
  feature (`crossSessionInbound` receive policy,
  `lib/server/settings.ts:154-209`, forwarded in `session.ts:2261-2274`)
  so this got audited rather than generically skipped. `command_lifecycle`
  frames are an already-documented dead bucket: `shouldBufferEvent()`
  (`lib/server/session.ts:826-832`) explicitly excludes them because
  "they're not in the SDK's public `.d.ts` yet, and Claudius has no
  consumer for them" (a decision made in the 0.3.206 update). `refused`
  is just a new value inside that same still-unconsumed, still-undocumented
  frame type — nothing to wire up without a public shape to read.
- `[skipped — SDK-internal]` Added `suppressOriginalPrompt` to
  `UserPromptExpansionHookSpecificOutput`. `UserPromptExpansion` is one
  of the `HOOK_EVENTS` names Claudius lists as available for
  user-authored hook scripts (`lib/shared/hook-events.ts:11,72`), but
  Claudius doesn't implement a callback for it itself (unlike
  `PreToolUse`, which Claudius registers programmatically,
  `session.ts:2371-2378`) — the CLI, not Claudius, reads a user hook's
  `hookSpecificOutput` for this event. No call site.
- `[skipped — SDK-internal]` Fixed hook callbacks silently not
  re-applying after a repeated `initialize`; response now reports
  `hooks_applied`. Claudius opens one `query()` per `Session` and never
  manually issues a follow-up `initialize` control request itself —
  this fixes a multi-host/reconnect race in the CLI's own control
  protocol that Claudius's one-`query()`-per-process model doesn't
  exercise.
- `[skipped — SDK-internal]` Fixed `CLAUDE_CODE_ENABLE_PROMPT_
  SUGGESTION=true` not keeping `prompt_suggestion` on near (not over)
  the usage limit. Claudius already sets `promptSuggestions` (session.ts
  ~2212) and already consumes `prompt_suggestion` messages
  (`use-session.ts:3978`) generically — this is a correctness fix to a
  case we already handle, no shape/call-site change.
- `[skipped — no consumer]` Changed `vcs_state_changed` to emit one
  event per pushed branch. Grepped the full tree — Claudius has no
  `vcs_state_changed` consumer anywhere.

## Code changes

- `lib/server/session.ts` — `captureTaskState()`'s `task_started` case
  now seeds `isBackgrounded`/`spawnDepth` from the message itself
  (previously `isBackgrounded` only came from a later `task_updated`
  patch, which a task backgrounded from birth never sends).
- `lib/shared/events.ts` — `TaskSnapshotEntry.spawnDepth` (new field)
  and updated doc comment on `isBackgrounded` to describe the new
  `task_started`-seeded path.
- `lib/server/db-migrations/016_session_tasks_backgrounded_depth.sql`
  — new migration adding `is_backgrounded`/`spawn_depth` columns to
  `session_tasks` (neither was ever persisted before this bump).
- `lib/server/session-tasks-db.ts` — thread the two new columns
  through `saveSessionTask`/`listSessionTasks`/`rowToEntry` (0/1/null
  tri-state mapping for `is_backgrounded`).
- `lib/client/types.ts` — `TaskInfo.spawnDepth` (new field).
- `lib/client/use-session.ts` — `task_started` SSE reducer now reads
  `is_backgrounded`/`spawn_depth` off the raw message and seeds them
  on the new `TaskInfo` row.
- `components/panels/BackgroundTasksPanel.tsx` — new "L{n}" nesting
  badge (`data-testid="task-nesting-badge"`) on Tasks-rail rows with
  `spawnDepth >= 2`; depth-1 (the common top-level-spawn case) stays
  unbadged.
- `package.json` / `bun.lock` — SDK bump to `^0.3.241`.

## Risks / follow-ups

- `lib/shared/cost-pricing.ts`'s `costFromTokens` disk-replay cost
  fallback will under-estimate by ~10% for accounts on US data
  residency now that `total_cost_usd` folds in that multiplier
  server-side — see the 0.3.239 changelog item above. Judged
  acceptable (the fallback already documents itself as an
  approximation whose source of truth is the live field), but if a
  future release adds more residency-aware pricing tiers this gap is
  worth closing properly rather than accumulating drift.
- `lib/server/claude-code-changelog.ts` (a bundled, hand-curated
  snapshot of the upstream *Claude Code* CHANGELOG.md, distinct from
  the SDK changelog this run consumed) is stale relative to Claude
  Code 2.1.237–2.1.241 and appears to have zero importers anywhere in
  `app/`, `lib/`, or `components/` (grepped the whole tree) — it looks
  orphaned, possibly dead code from a removed `/release-notes` page.
  Not touched in this run: refreshing it requires the actual upstream
  bullet text, which wasn't part of the changelog block this run was
  given, and fabricating bullets is explicitly against this run's
  instructions. Worth a follow-up to either wire it back into a UI
  surface or delete it if it's genuinely dead.
- The new `session_tasks.is_backgrounded`/`spawn_depth` columns are
  additive nullable columns (migration 016) — existing rows read back
  as `undefined` for both, which is the correct "unknown, pre-0.3.238"
  semantics, not a false `false`/`0`.
