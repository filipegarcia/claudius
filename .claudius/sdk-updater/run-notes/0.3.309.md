# SDK update 0.3.306 → 0.3.309

## Summary

The 0.3.306 → 0.3.309 window is small: a `managedSettings` hook-key fix, a
per-user temp directory for the bun-embedded CLI (`extractFromBunfs()`),
a handful of additive optional type fields (`liveReply` on the `mcp_status`
control request, `Settings.sshHostCommands`, browser-SDK
`supportedDialogKinds`), `wakeup_source` / `scheduled_for` on the
`command_lifecycle` `started` frame, and three "parity with Claude Code"
bumps (2.1.307 – 2.1.309). Claudius does not use `managedSettings`, the
browser SDK, `extractFromBunfs()`, or the `mcp_status` request options, and the
`command_lifecycle` frames are already filtered from the replay buffer
regardless of their fields, so no product code needed to change. The package
bump (already committed) is the whole SDK-specific diff; the only headline risk
is that the stacked branch also carries unrelated cc-parity 2.1.307 work.

## SDK changelog highlights

- `extractFromBunfs()` extracts into per-user temp dir `claude-agent-sdk-<uid>` — [skipped — only runs when the SDK is bundled into a bun-compiled binary; Claudius runs under Node/Electron and resolves the CLI from `node_modules`; no call site]
- `extractFromBunfs()` reuses extracted file only when bytes match — [skipped — same as above, internal SDK behaviour]
- `wakeup_source` / `scheduled_for` on `command_lifecycle` `started` frame (capability `lifecycle_wakeup_source_v1`) — [skipped — `command_lifecycle` frames are already excluded from the replay buffer (`shouldBufferEvent`, `lib/server/session.ts`) and not rendered; the frames are forwarded verbatim so the new fields pass through harmlessly. No UI consumes which-wakeup-fired]
- `supportedDialogKinds` on browser SDK `query()` — [skipped — browser SDK (`browser-sdk`) is not imported anywhere in Claudius; server-side `query()` is used]
- Parity with Claude Code v2.1.307 / v2.1.308 / v2.1.309 — [skipped — no SDK API surface in the diff beyond the items below; v2.1.307 parity product work is carried separately by the stacked branch's earlier commits]

New declarations (type-surface block):

## Code changes

- No code changes required. The 0.3.306 → 0.3.309 window adds only optional fields and internal fixes in paths Claudius doesn't use.

The only product-relevant diff for this release is the dependency bump in `package.json` / `bun.lock` (committed as `chore(deps): bump claude-agent-sdk to 0.3.309`). Every changelog item and new declaration was audited against our call sites (see above) and none hits an API we invoke: no `managedSettings`, no browser SDK, no `extractFromBunfs`, no CCR `mcp_status` option. `command_lifecycle` frames already pass through untouched.

## New UI surfaces

- No new UI surfaces this release. None of the SDK changes are user-visible in Claudius; `docs/sdk-updates/0.3.309/` is intentionally empty.

## Tests

- No new tests required. No behaviour changed; existing vitest and Playwright suites are the regression check (see gate results in the run's final message).

## Risks / follow-ups

- This branch is stacked on the open cc-parity 2.1.307 PR, so `git diff main...HEAD` also contains that PR's voice-stop-notice and extra-ca-certs work — not part of this SDK bump.
- If a future release starts using `managedSettings` (e.g. enterprise lockdown), note the new value-filtering semantics: `disableAllHooks` binds as `allowManagedHooksOnly`, and `allowedHttpHookUrls` / `httpHookAllowedEnvVars` bind only as empty lists.
