## Summary

Claude Code 2.1.299 adds:
- `/usage` behaviour warnings;
- idle compaction (terminal only, with `idleCompaction` / `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`);
- bare `/model` / `/effort` / `/fast` pickers in agent view;
- the `CLAUDE_CODE_DISABLE_FILE_MENTIONS` env var;
- a large batch of mod-runtime hooks;
- more than 150 fixes across MCP, sandbox, Remote Control, cloud sessions, scheduling, skills, encodings and Windows.

Most of it is engine-side (A) or terminal/hosted-only (C). Claudius reimplements **13 items** (bucket B), all as extensions of existing screens; no new routes.

**New UI:**
- **Cost overlay:** a "What's contributing to your limits usage?" section, with the CLI's own copy and 10% threshold, read from the SDK's `behaviors` scan.
- **Composer:** a bare `/model`, `/effort` or `/fast` opens the session ModelPicker.
- **Skills page:** a "Not offered to Claude until renamed" badge for names the engine now ignores.
- **Files editor:** a read-only banner for non-UTF-8 files, which are no longer silently converted. UTF-8 BOM and UTF-16LE files now round-trip.
- **Composer:** a failed send puts the message back in the box with a hint.
- **Chat notice stack:** an "Auto mode is off" notice when the new model doesn't support auto mode.

**Fixes with no new UI:**
- DST-safe `/schedule` re-arm;
- an empty `.mcp.json` no longer breaks `/mcp`;
- plan-usage percentages clamped to 100%;
- a plain-string `enabledMcpjsonServers` is shown as a one-item list in Settings;
- the composer draft is kept on a quick session switch;
- a held-back permission prompt no longer steals the Enter meant for a draft;
- `/fork` toasts name why a worktree couldn't be created.

**Deferred:** reaping blank chats early. A reaped never-prompted session can't be reopened today (see Risks).

**Headline review questions:**
1. Is the Cost overlay the right home for the usage warnings? `/usage` in Claudius is the accounts page, which has no live session.
2. Is the composer-picker translation of the "agent view" `/model` / `/effort` / `/fast` entry right?
3. Are the Files editor's read-only rules right? A BOM-less file with NUL bytes now opens read-only.

## Implemented (bucket B)

- `[extend: /schedule]` **DST-safe re-arm.**
  - What it does: `nextFireAfter(cron, anchor, now)` in `lib/shared/cron.ts` steps cron-parser's iterator from the job's `lastRunAt` (if it is under 25h old) to the first slot after now. `Scheduler.arm()` (`lib/server/scheduler.ts`) uses it on boot, edit and re-arm.
  - Result: a fixed-hour job such as `30 1 * * *` no longer fires again in the repeated 01:xx hour, while wildcard-hour crons still fire through both copies, which is classic Vixie-cron behaviour.
  - Guards: slots within 1s of the anchor are skipped, because `arm()` fires up to 250ms early. A progress guard falls back to the old compute-from-now path if cron-parser stops advancing (30-minute DST zones such as Lord Howe).
  - Rejected alternative: "skip a candidate whose local wall-clock minute equals `lastRunAt`'s". It would also drop the legitimate 01:00 EST fire of hourly crons, leaving a 2-hour gap.
- `[extend: /mcp]` **Empty `.mcp.json`.** `readJson` (`lib/server/mcp.ts`) treats an empty or whitespace-only file as missing. Listing works, adding a server writes valid `{ mcpServers }`, and malformed non-empty JSON still errors.
  - Rejected alternative: per-scope parse warnings instead of a 500. That is wider than the entry; noted as a follow-up.
- `[extend: Settings catalog]` **Plain-string list settings, and the duplicate `idleCompaction` row.**
  - `stringListSettingValue` (`lib/shared/string-list-setting.ts`) shows a non-blank string such as `"enabledMcpjsonServers": "srv"` as a one-item list; saving normalises it to an array.
  - The `idleCompaction` row listed twice in `app/settings/page.tsx` is de-duplicated (kept under "Context & compaction").
  - New `tests/unit/settings-catalog-keys.test.ts` asserts that catalog keys are unique.
  - Rejected alternative: an inline "stored as a single string" note. The engine now accepts the string form, so just showing the value is enough.
- `[extend: Cost overlay (/cost)]` **"What's contributing to your limits usage?"**

New `GET /api/sessions/[id]/usage-behaviors`. `CostOverlay` gains a `sessionId` prop and a section that fetches when the overlay opens, with a Day/Week toggle; it is hidden when `behaviors` is null (non-subscribers).

  - Rejected alternatives:
    - `app/usage/page.tsx`: in Claudius it is the accounts page, with no live session query.

The event is cancelable; the SessionCard claims it with `preventDefault()` and opens its existing ModelPicker, which already holds the model list and the effort and fast rows.

- `[extend: chat notice stack + session server]` **Leave auto mode on a model that can't run it.**

- `[extend: composer]` **Draft survives a quick session switch.** `PromptInput` records the latest unsaved `{sessionId, text, images}` (`lib/client/pending-draft.ts`) and flushes it to the previous session's draft on switch or unmount, and with `keepalive` (60 KiB or less) on `pagehide`.
  - Rejected alternative: keying the composer per session, which would still lose the 500ms debounce window.
- `[extend: composer]` **Undelivered message stays in the box.**
  - `send()`/`enqueue()` (`lib/client/use-session.ts`) catch network and HTTP failures, roll back the optimistic bubble and return a `SendResult`.
  - Placement (`PromptInput`): if the box is empty, the text, images and paste ranges are restored. If the user has started typing, the message goes into a dedicated ↑ slot that Ctrl+C / double-Esc can't overwrite. If the user has switched sessions, it is merged into the origin session's draft.
  - The hint names the error: "Couldn't reach Claudius — your message is back in the box." for network failures, "Message not sent — …" otherwise.
  - Only the composer (`reportsFailureInline`) skips the network errors banner; fire-and-forget senders such as goal submit keep it.
  - Rejected alternatives: waiting for the POST before clearing the box (it eats keystrokes typed mid-send), and a toast (gone before the user sees why the text is still there).
- `[extend: PermissionPrompt]` **No focus steal from a mid-draft composer.** A `defaultToNo` prompt skips its mount-time Deny focus while `isTypingInField(document.activeElement)` (`lib/client/typing-focus.ts`). AskUserQuestion and MCP elicitation were checked and already ignore Enter typed in fields.
  - Rejected alternative: a 300–500ms Enter guard after mount, which is timing-based and still racy for slow typists.
- `[extend: Files browser + git FileEditor]` **Encoding-safe editing.**
  - Detection: `lib/shared/text-encoding.ts` sniffs BOMs, probes the first 8 KB for NUL bytes, and does a strict UTF-8 decode.
  - GET: `GET /api/workspaces/[id]/files` returns decoded text plus `encoding`, `editable` and `readOnlyReason`.
  - PUT: reads raw bytes (`req.text()` would strip the BOM). It re-encodes UTF-8+BOM and UTF-16LE+BOM files in their original encoding and refuses everything else with 415. A new inline `resolve` + `startsWith(base + sep)` guard sits right above the new `readFile` sink, as CLAUDE.md requires.
  - UI: both editors show an amber read-only banner and disable Save and ⌘S. `HighlightedEditor` blocks the code editor's own edit keys when read-only.
  - Rejected alternative: transcoding with iconv-lite. It adds a dependency, is still lossy, and can't tell cp1252, Shift-JIS and GBK apart; CC refuses rather than converts.
- `[extend: /fork toast]` **Why there's no worktree.** `createForkWorktree` (`lib/server/fork-worktrees.ts`) returns `{ ok:false, reason }`: "the repository has no commits yet", "this is a bare repository's root, which has no working tree", or the first `fatal:` line. The fork route passes it through, and `forkConfirmation` says "…: couldn't create a worktree (<reason>); it shares your checkout." The fork itself still succeeds.
  - Rejected alternative: failing the `/fork` outright, even though the fork is still useful.

## Risks / follow-ups

- **Design alternatives, per bucket-B item.** Each bullet under "Implemented" names its rejected shape. The ones most worth a reviewer's eye:
  - **Usage warnings live in the Cost overlay.** The maximal shape is a dedicated usage-insights screen, or making `/usage` open the overlay. I extended `/cost` because it already holds plan usage and has a live session to query.
  - **Bare `/model` / `/effort` / `/fast`.**
    - Conservative reading (shipped): a bare command in the composer opens the existing in-session picker.
    - Literal reading (not shipped): Claudius has no "agent view", so the analogue would be new "new sessions start with" effort and fast defaults on the workspace form (`SessionDefaults` has no effort/fast today, `lib/shared/session-defaults.ts`). A related latent issue was found and not fixed: `setEffort` persists the top-level `effortLevel`, but newer models read `modelSettings.<model>.effortLevel` (see `app/settings/page.tsx:1073`), so new sessions may not inherit effort on current models.
  - **Failed-send restore.**
    - Conservative (shipped): restore on failure.
    - Maximal: also disable Send while the stream is "reconnecting", as the CLI does. Not shipped: `streamStatus` goes to `reconnecting` 4s after any EventSource error, including the ends of finite mocked SSE bodies, so gating would disable Send across much of the e2e suite and on brief blips.
    - Only one failed message is kept for ↑ at a time.
    - Some fire-and-forget senders (goal submit, `/btw`-style native sends) roll back their bubble on failure and rely on the errors banner rather than restoring text.
  - **Files encoding.**
    - Conservative (shipped): refuse to save non-UTF-8/UTF-16LE files.
    - Maximal: transcode.
    - Behaviour change: a BOM-less file with a NUL byte in its first 8 KB now opens read-only ("looks binary"). This matches content search, but locks text fixtures or logs with embedded NULs. Relaxing it to "NUL *and* invalid UTF-8" would be a one-line change.
    - Content search still skips UTF-16LE files, and the git diff's left pane is untouched.
  - **Auto mode.**
    - A user who explicitly picks Auto on an unsupported model is coerced to Default without the notice; the pill just reverts.
    - ModeSelector still lists Auto for every model. Hiding it via `supportsAutoMode` (the way ModelPicker reads `supportsFastMode`) is the follow-up.
    - The model's display name comes from `supportedModels()`, which waits for the CLI's init handshake (capped at 3s).
  - **Skills.** Emoji names using VS16 or ZWJ (`❤️`, family emoji) are flagged as not offered. I verified this matches the 2.1.299 engine: its `Ar` set includes `\p{Cf}` and Default_Ignorable code points. There is no rename action; the badge says "until renamed" and the user renames on disk or deletes.
  - **`/fast` picker.** Until the picker has loaded the model list once, a bare `/fast` on a model without fast mode still opens a picker with no fast row. Pre-fetching was avoided because the models endpoint returns 503 until the session is live.
- **Deferred bucket-B item: blank-chat reaping.**
  - Needed first: a "pristine revive" in `getOrResumeSession` and in the resume branch of `POST /api/sessions`. When a resume id has a sessions-db row but no JSONL, rebuild with `{ id, cwd: row.cwd, model: row.model }` instead of `resume`, which needs a cross-workspace lookup of the row.
  - Then: add `hasEverPrompted` / `isPristine()` and a shorter reap delay (for example 5 minutes, env-overridable) for pristine, unsubscribed sessions.
  - Today, a session reaped by the 60-minute window or by a server restart before its first prompt already shows the same "No conversation found" or 404.
- **Idle compaction (C).**
  - Maximal shape, not built: a Claudius-side timer that sends `/compact` to a 200K+ session idle for about 54 minutes, mirroring `idleCompaction` / `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`.
  - Why not: the entry says "in the terminal", and the engine deliberately gates it off for SDK hosts. It also spends tokens on the user's behalf and interacts with the 60-minute reaper.
  - The existing `idleCompaction` catalog row (from SDK 0.3.292) only affects engines that honour it.
- **Shared `node_modules` was reset to the lockfile.** At the start of the run, the shared checkout's `node_modules` had SDK **0.3.299** (likely left by the sibling SDK-updater pipeline), while `bun.lock` pins **0.3.296**.
  - What happened: the repo's pre-commit hook (`node scripts/native-abi.mjs ensure node`) ran inside fresh agent worktrees, which had no `dist-electron/native-abi.json`. It ran `bun install --force better-sqlite3` through the symlinked shared `node_modules`. That reinstalled to the lockfile (SDK 0.3.296) and removed `better-sqlite3/build/Release`; node-gyp needs Python with distutils.
  - Impact: better-sqlite3 still loads from its bundled prebuilds, and every gate in this run ran after the reset, i.e. against the lockfile's 0.3.296, as CI does. An Electron-ABI rebuild (`electron:rebuild-native-for-electron`) will be needed before `electron:dev`.
  - Process note: the hook's forced reinstall from a worktree without the ABI lock is a footgun worth a guard in `scripts/native-abi.mjs`. I didn't touch it; it's outside this release's scope.
  - On the resumed run, `node_modules` had drifted again: SDK 0.3.299 (lock: 0.3.296) and next 16.3.6 (lock: 16.3.8). I re-synced it with `bun install --frozen-lockfile`, without `--force`; better-sqlite3 still loads. The final gates below ran against the lockfile.
