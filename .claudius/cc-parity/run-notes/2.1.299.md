## Summary

_(Draft — finalized after implementation.)_ Claude Code 2.1.299 adds `/usage` behaviour warnings, idle compaction (terminal only), bare `/model` / `/effort` / `/fast` pickers, a `CLAUDE_CODE_DISABLE_FILE_MENTIONS` env var, many mod-runtime hooks, and a long list of fixes. Claudius reimplements the items whose code it owns (see Implemented).

## Changelog classification

Audit method:
- Seven parallel read-only audits (scheduler, composer/queue, MCP, skills/agents, usage/models, compaction/mentions/files, worktrees/misc), each grepping the Claudius code path the entry touches. Bugs were reproduced in `/tmp` where possible (DST re-arm with `TZ=America/New_York`; an empty `.mcp.json` through `JSON.parse`; BOM / UTF-16LE / cp1252 round trips through the Files route; `git status -z` with names that begin or end with a space).
- The bundled 2.1.299 engine (`node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`, SDK 0.3.299) was grepped for:
  - the `/usage` behaviour table (headline and body copy, threshold `10`);
  - the idle-compaction gate (interactive / host-list entrypoints only);
  - the skill-name rule;
  - the auto-mode kick-out reason text (`"<model> doesn't support auto mode"`).

### Bucket B — reimplemented in Claudius

- `[B — reimplement in Claudius] Fixed scheduled tasks and loops firing again after every turn, or firing early, during the repeated hour when daylight saving time ends` — Claudius's own `/schedule` scheduler re-arms with `nextFireMs(cron)` from `Date.now()` (`lib/server/scheduler.ts:84`), with no anchor on the last fire. Reproduced with `TZ=America/New_York`: `30 1 * * *` fires at 01:30 EDT and is re-armed for 01:30 EST, so it fires twice. Fix: anchor on `lastRunAt`. (Session crons and `/loop` are engine timers; see A.)
- `[B — reimplement in Claudius] Fixed claude mcp list, claude doctor and /status reporting an empty .mcp.json as invalid` — Claudius reads `.mcp.json` itself. `readJson` (`lib/server/mcp.ts:101-110`) calls `JSON.parse("")`, which throws, so `GET /api/mcp` returns 500 and the whole `/mcp` page fails, user-scope servers included. Fix: treat an empty or whitespace-only file as missing.
- `[B — reimplement in Claudius] Fixed a settings file being ignored when enabledMcpjsonServers or disabledMcpjsonServers held a single server name as a plain string` — the engine applies these keys, but Claudius owns the Settings catalog editor. `app/settings/page.tsx:1730` (`Array.isArray(value) ? value : []`) shows a string value as an empty list while the row is badged "overridden". Fix: show a plain string as a one-item list.
- `[B — reimplement in Claudius] Added /usage warnings for max effort, workflows, always-on context and large tool results` — SDK 0.3.299's `usage_EXPERIMENTAL…({skipBehaviors:false})` already returns `behaviors.{day,week}.behaviors[]`. Claudius reads only the skills slice of it (`lib/server/session.ts:6014`) and never shows the behaviour warnings. Ship a "What's driving your usage" section using the CLI's own headline and body copy and its 10% threshold (taken from the bundled binary).
- `[B — reimplement in Claudius] Fixed /usage, the approaching-limit warning (terminal and VS Code) and the status line sometimes showing more than 100% used` — Claudius's plan-usage bars are clamped, but their text is not:
  - `PlanUsageCard.tsx` renders `${Math.round(w.pct)}% used`;
  - `CostOverlay.tsx` `fmtUtilization` rounds;
  - `SystemPill.tsx:461` rounds `utilization*100` and says "You've used 103%".
  Fix: clamp the display text and `aria-valuenow` to 0–100, keeping the raw value for tone logic.
- `[B — reimplement in Claudius] Added /effort and /fast in agent view to set what new sessions start with; a bare /model, /effort or /fast there now opens a picker` — a bare `/model` in Claudius only shows a "Pass a model id" toast (`ChatSurface.tsx:1768-1779`), and a bare `/effort` only toasts the current level. The browser idiom is the existing session ModelPicker, which already hosts the effort and fast rows. Ship: a bare `/model`, `/effort` or `/fast` opens that picker, following the `/advisor` → `claudius:open-advisor-picker` precedent. The "agent view / new-session defaults" half is recorded under Risks.
- `[B — reimplement in Claudius] Fixed SDK and headless sessions staying in auto mode after the host switched to a model that doesn't support auto mode` — Claudius is that host, and it owns `permissionMode` state. `setModel` (`lib/server/session.ts:5388+`) never checks `ModelInfo.supportsAutoMode`, and Claudius never mirrors the engine's kick-out, so ModeSelector keeps saying Auto, and `subscribe()` and resume re-send `auto`. Ship: on a model switch that leaves auto unsupported, move to `default` and broadcast `mode_changed`, with the engine's own reason text.
- `[B — reimplement in Claudius] Changed skill and command loading: one whose file or folder name has hidden, direction-changing or blank-like characters, < or > is no longer offered until renamed; such a name: is ignored` — Claudius lists and writes skills itself. `SKILL_DIR_NAME` (`lib/server/skills.ts:47`) accepts some names the engine now refuses (Hangul fillers, variation selectors, leading combining marks, over 256 characters). `skillMdName` (`lib/shared/skill-names.ts`) shows any frontmatter `name:` as an alias, including ones the engine now ignores. Ship:
  - refuse such names on write (PUT `/api/skills`);
  - badge listed folders "Not offered to Claude until renamed";
  - stop showing an ignored frontmatter `name:`.
  Claudius has no custom-command writer (commands are engine-listed), so skills are the only write path.
- `[B — reimplement in Claudius] [VSCode] Fixed an unsent prompt and its attachments being lost when switching to another session and back` — Claudius's composer persists drafts, but the debounced 500 ms PUT is cancelled by the effect cleanup when `sessionId` changes (`components/chat/PromptInput.tsx:659-678`), so edits or image attaches made just before a switch are lost. Fix: flush the pending draft on switch and on unmount.
- `[B — reimplement in Claudius] [Remote Control] Fixed Remote Control sessions whose computer can't be reached still appearing to send your messages; your text now stays in the box and Send is off until it reconnects` — Claudius has the same browser→server shape. `submit()` clears the textarea and deletes the server draft before the send's outcome is known (`PromptInput.tsx:918-938`), and a network failure in `use-session` `send()` is uncaught, so the optimistic bubble stays as if sent. Ship: on a failed send, remove the bubble and put the text and images back in the box. Send gating while the stream is reconnecting is shipped only if it doesn't flicker on connect; see Risks.
- `[B — reimplement in Claudius] Fixed Enter answering a question or permission prompt that had been held back while you typed an unsent message` — Claudius's `defaultToNo` PermissionPrompt focuses Deny unconditionally on mount (`components/chat/PermissionPrompt.tsx:96-97`), so a prompt that appears while the user is typing takes the Enter they meant for their draft. Fix: don't steal focus from a non-empty text field.
- `[B — reimplement in Claudius] Fixed Read garbling UTF-16LE files with a byte-order mark, and Write dropping byte-order marks or silently converting Windows-1252, Shift-JIS, GBK or UTF-16BE files to UTF-8 (now refused)` — the engine's Read/Write tools are A, but Claudius's own Files editor does its own read and write (`app/api/workspaces/[id]/files/route.ts:136,262-272`, `utf8` both ways). Reproduced: a UTF-8 BOM is dropped on save, UTF-16LE opens garbled and is saved as U+FFFD, and cp1252 `é` is saved as U+FFFD. Ship: preserve the BOM, round-trip UTF-16LE, and open other encodings read-only, refusing the save.
- `[B — reimplement in Claudius] Improved the error shown when a worktree cannot be created because its base commit does not resolve … ; Improved the error for creating a worktree at a bare-repository layout's root` — Claudius creates `/fork` worktrees itself (`lib/server/fork-worktrees.ts:86-94`) and swallows the git error. The toast then says the generic "shares your checkout", the copy meant for a non-git folder. Ship: name the reason ("the repository has no commits yet" / "bare repository root") in the fork toast.
- `[B — reimplement in Claudius] [VSCode] Fixed unused blank chats keeping a background Claude process running after starting a new conversation` — Claudius spawns the CLI eagerly on session create (`session.ts:3370`), and a blank, never-prompted session with no subscribers lingers for the full 60-minute reap window (`session-manager.ts:21`). Planned last, with a conservative grace period; deferred to Risks if navigating back to a reaped blank session can't recreate it cleanly.
