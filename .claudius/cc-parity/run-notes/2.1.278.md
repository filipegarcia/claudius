## Summary

2.1.278's entire non-bug-fix delta is two bullets, both describing the
same underlying change: Claude API/Enterprise/Bedrock/Vertex/Foundry/gateway
auto-mode permission-classifier invocations now default to running
server-side (no classifier-overhead billing), with `CLAUDE_CODE_AUTO_MODE_SERVER=0`
as an opt-out on the enterprise deployment paths and a warning on billed
fallback; and a companion `Auto mode server` row was added to the CLI's
`/status` output reflecting which mode a given session landed in. Both
are engine/billing-side: the classifier itself already runs entirely
server-side from Claudius's perspective (Claudius only ever sets the
`auto` permission mode and forwards tool-call context — see the existing
`autoMode` settings and the "classifier runs server-side, unaffected by
Claudius" comments already in `lib/server/settings.ts` and
`app/[workspaceId]/permissions/page.tsx`), and the installed SDK
(`@anthropic-ai/claude-agent-sdk@0.3.278`, confirmed via `sdk.d.ts`) exposes
no field anywhere (not on `SessionInfo`, not alongside the existing
`supportsAutoMode` model-capability flag, not on any SSE/result event)
indicating which mode the classifier ran in for a given call. **No
bucket-B items ship this release.** The headline risk to flag: the second
bullet is a real, user-visible CLI affordance Claudius does not yet have
data to reproduce faithfully — building a static "Auto mode: server-side"
row now, with no per-session signal behind it, would be the "phantom
implementation" failure mode this pipeline is built to avoid (an
always-true indicator that looks live but isn't). The natural integration
point if the SDK ever exposes this fact is `components/overlays/StatusOverlay.tsx`,
which already has cc-parity precedent for exactly this kind of addition
(the 2.1.275 "Account" row).

## Changelog classification

- `[A — already via SDK updater] Changed auto mode ... to default to the
  server-side classifier, which does not charge for classifier overhead
  (CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out on Bedrock, Vertex, Foundry and
  gateways); warns on billed fallback.` — Pure engine/API-side default and
  billing-routing change. Claudius never implements the auto-mode
  classifier itself; it only sets permission mode to `auto` and relays
  host-asserted context via the SDK (`sdk.d.ts`'s `'auto' - Use a model
  classifier to approve/deny permission prompts`). Where the classifier
  physically runs, and what it costs, is entirely a backend/API concern
  that changes underneath the existing `auto` mode with zero Claudius code
  changes required, exactly like a new default model or a new
  permission-mode implementation detail landing via the SDK/API. The
  `CLAUDE_CODE_AUTO_MODE_SERVER` opt-out is a narrow enterprise
  Bedrock/Vertex/Foundry/gateway deployment env var; Claudius's existing
  account model (`lib/shared/accounts.ts`) deliberately surfaces only the
  account-type toggle (e.g. `CLAUDE_CODE_USE_BEDROCK=1`) and not every
  granular CLI env var beneath it, so adding a settings toggle for this one
  would break that established convention for no user-facing benefit (any
  billed-fallback warning, if Claudius ever streams it, would surface via
  the SDK's own warning/event surface, not a bespoke Claudius setting).
- `[A — already via SDK updater] Added an "Auto mode server" row to
  /status showing whether this session's auto mode classifier runs on the
  server.` — CLI's `/status` row displays session-level data (classifier
  execution location) that only the engine/API can supply. Verified the
  installed SDK (`@anthropic-ai/claude-agent-sdk@0.3.278`) exposes no such
  field: grepped `sdk.d.ts` for `classifier`, `serverSide`, `AUTO_MODE`,
  `billedFallback` — the only match is the per-model `supportsAutoMode`
  capability flag (whether a model *supports* auto mode at all, not
  whether a given call's classifier ran server-side) and prose describing
  the `auto` permission mode itself. No `SessionInfo`, result message, or
  SSE event field carries this fact today. Claudius's own `/status`
  equivalent (`components/overlays/StatusOverlay.tsx`, wired from
  `lib/shared/slash-commands.ts`'s `status` command) already shows Session
  id / Account / Kind / State / Model / Permission mode / Working
  directory / Capabilities — all backed by real `SessionInfo` fields. There
  is no analogous field to back a new row today. This is SDK-updater
  territory the same way any other new streamed field is: if/when the SDK
  exposes classifier-location data (the natural extension of the existing
  `supportsAutoMode` capability shape), it lands in Claudius the same way
  the 2.1.275 cc-parity leg added the "Account" row to this same
  `StatusOverlay.tsx` — via a follow-up cc-parity or sdk-update leg, once
  there is real data to show. See Risks/follow-ups for the rejected
