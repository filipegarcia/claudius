## Summary

Claude Code 2.1.302 is mostly engine work, Claude Tag (Slack), cloud-routine and terminal fixes, plus an `Idle compaction` row in `/config` (Claudius already has it) and `CLAUDE_CODE_AUTO_MODE_MODEL` (engine env var). The 2.1.299–2.1.301 sections in the block were handled by earlier runs. Claudius reimplements **six bucket-B items**, all extending existing screens (no new routes):
- **Schedule page:** a "Last run didn't start" banner with the reason. Scheduled runs that died (no result, or Claudius quit mid-run) are recorded as failed instead of Completed or stuck "Live".
- **Chat:** a disconnected state for running subagent cards. After review it was widened to quiet the Activity rail and the other chat spinners while the stream is reconnecting.
- **Session start:** "connection lost" / "server error (5xx)" wording. With no tabs open, a failed "+ New session" now shows its error at all; before, it showed nothing.
- **Files preview route:** refuses pipes/devices and sources over 128 MB.
- **Markdown:** empty or opening code fences render as code blocks. This is an adjacent fix: the exact VS Code bug doesn't reproduce in Claudius.

A read-only skeptic pass (one per item) led to the boot-race, pid-ownership, stale-banner, inbox-wording, stale-error and rail-spinner fixes.

**Headline review questions:**
1. Is the disconnected state the right breadth? It now touches six chat/rail components, not just the subagent card.
2. Should missed-while-closed slots also count as "didn't start"? Not built.
3. Is the Markdown fix in scope as an adjacent fix?

## Risks / follow-ups

- **Schedule banner (shape).** Rejected the sidebar-chip shape (see Implemented). Conservative scope: only two skip reasons exist in Claudius (previous run in progress; folder missing). **Maximal shape not built:** recording slots missed while Claudius was closed (`nextFireAfter` silently steps past them, `lib/shared/cron.ts:115`) as "didn't start — Claudius wasn't running". That's arguably the closest Claudius analog to CC's "concurrent-session limit" reason, but it adds a new catch-up concept to the scheduler. Also not built: a "Run now to retry" CTA on the banner, and an immediate `{ skipped }` answer from the run-now route (the banner appears on the page's next refresh).
- **Dead runs as failed.** Rejected a new RunStatus (see Implemented). Recovery trusts `process.kill(pid, 0)`; a recycled pid could make an orphaned run look alive until that process exits. That's harmless: it stays "running" as before. Runs older than the newest 50 per job are not scanned.
- **Disconnected state.**
