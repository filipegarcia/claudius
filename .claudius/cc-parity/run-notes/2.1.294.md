# Claude Code parity 2.1.293 → 2.1.294

## Summary

Claude Code 2.1.294 has two changes, both about hook evaluation. First, `prompt` and `agent` hooks written as instructions ("Block commands that…") no longer let through what they should block. Second, `prompt` hooks on Stop / SubagentStop written as instructions ("Carry on if the build is broken") are judged better, so Claude is less likely to stop early. Both are engine-side. Claudius only writes `prompt`/`agent` handlers into `settings.json` (`lib/server/hooks.ts`, built by the form on `app/[workspaceId]/hooks/page.tsx`). The bundled Claude Code engine evaluates them; Claudius has no evaluator of its own. Both fixes therefore reach Claudius through the `@anthropic-ai/claude-agent-sdk` 0.3.294 bump already on this branch (`4ffb53d4`, parity with CC v2.1.294). Nothing in this release is bucket B, so there is no new code, UI, or test. The main thing to review is that "no Claudius copy of the bug" call. A related but older copy problem is noted below: the hooks-form placeholder misdescribes prompt hooks as "injected" text.

## Changelog classification

- `[skip — already shipped via SDK migration on this branch] Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block` — The engine evaluates hooks: it runs the prompt/agent handler and judges whether to allow or block. Claudius has no copy of that logic. `lib/server/hooks.ts` only reads and writes the `hooks` key of user/project/local `settings.json`. `app/[workspaceId]/hooks/page.tsx:406-416` only builds `{ type: "prompt", prompt, continueOnBlock?, once?, if? }` / `{ type: "agent", agent, … }` objects for those settings, and `lib/shared/hook-events.ts:169-170` is just the type. Claudius's own programmatic hooks (`lib/server/session.ts:3188-3310`) are JS callbacks on PreToolUse / PostToolUse / CwdChanged / PostModelSwitch, and none of them is model-judged. `lib/shared/advisor.ts:18` only mentions the SDK's prompt-hook doc examples; no judge runs there. The fixed evaluator ships in the CC v2.1.294 engine bundled with SDK 0.3.294 (commit `4ffb53d4`).
- `[skip — already shipped via SDK migration on this branch] Improved how prompt hooks on Stop and SubagentStop written as instructions (such as "Carry on if the build is broken") are judged, so Claude is less likely to stop early` — Same evaluator, engine-side. Claudius registers no Stop or SubagentStop hook of its own (the programmatic `hooks` map in `lib/server/session.ts:3188-3310` has none), and it doesn't decide whether a turn continues after a Stop hook fires. That decision lives inside the engine's agent loop, which Claudius gets through `query()`. User-configured Stop/SubagentStop prompt hooks written from the Claudius hooks page are evaluated by the bundled CC v2.1.294 engine (SDK 0.3.294, `4ffb53d4`).

## Implemented (bucket B)

- No bucket-B items in this release. Both changelog entries change how the Claude Code engine evaluates `prompt`/`agent` hook handlers, and Claudius never evaluates those handlers. It only persists them to `settings.json` through `lib/server/hooks.ts` and the `/[workspaceId]/hooks` form. The engine that judges them is bundled with `@anthropic-ai/claude-agent-sdk`, already bumped to 0.3.294 (parity with CC v2.1.294) on this branch, so Claudius users get both fixes with no host-side change.

## New UI surfaces

- No new UI surfaces this release. Neither entry adds or changes anything user-visible in Claude Code beyond better hook verdicts, and Claudius's hooks page already lets users author instruction-style `prompt`/`agent` handlers. Nothing new needs rendering.

## Tests

## Risks / follow-ups

- **Main design call: "Claudius has no copy of either bug."** I checked `lib/server/hooks.ts`, `app/[workspaceId]/hooks/page.tsx`, `lib/shared/hook-events.ts`, `lib/shared/advisor.ts` and the programmatic `hooks` map in `lib/server/session.ts:3188-3310`. None evaluates a `prompt`/`agent` handler or gates Stop/SubagentStop continuation. If Claudius later adds its own Stop gating (for example a browser-side "keep going" judge), these entries would need revisiting.
- **Rejected alternative (pre-existing copy issue, not shipped):** the Prompt textarea placeholder on `app/[workspaceId]/hooks/page.tsx` says "System-style instruction injected when this event fires". That's inaccurate: a prompt hook is a model-judged allow/block (or, on Stop/SubagentStop, continue/stop) decision over the hook input, not injected text. Instruction-style prompts like "Block commands that touch .env" now work reliably, so a follow-up could change the placeholder to an example like that. I didn't do it here. The copy was wrong before 2.1.294, isn't the bug this release fixed, and changing it would add a UI change (spec + screenshot) to a release with no product-side scope.
- **No live verification of the engine fix.** No gate exercises a prompt hook against a real model, so this run doesn't prove the improved judging end to end. A reviewer could spot-check by adding a PreToolUse prompt hook "Block commands that delete files" on the hooks page and asking the agent to `rm` a scratch file.
- **Pre-existing screenshot churn stashed, not committed.** The working tree started with about 130 modified PNGs under `docs/cc-parity/`, `docs/sdk-updates/` and `site/screenshots/`, plus untracked `docs/sdk-updates/0.3.{246,251,261,267,271}/` directories. These are regenerated output from earlier e2e runs, not this run's work. They're unrelated to 2.1.294, so instead of committing or deleting them I stashed them with `git stash push -u -m "pre-existing screenshot churn (cc-parity 2.1.294)"` to leave the tree clean.
