## Summary

2.1.269 is a small release for Claudius's purposes: most of the changelog is
bug fixes (several already folded into the combined SDK 0.3.269 bump on this
same branch — the prompt cache/permission-denials/background-subagent fixes
listed there correspond 1:1 to entries here), plus a large VSCode-extension
and Claude-Tag/Slack section that's out of scope for a browser app. Exactly
one bucket-B gap survived the audit: `/output-style [name]`, a discoverable
slash command to list and switch output styles. Claudius already modeled
`outputStyle` as a Settings-page dropdown, but a change there only took
effect on the *next* session start — nothing forwarded the pick to the
already-running SDK query, and nothing surfaced the SDK's live
`available_output_styles` (which can include plugin-provided custom styles).
This release adds the missing live-apply half (`Session.setOutputStyle` via
the SDK's `updateSettings('localSettings', …)`) and the slash command that
discovers it. Headline risk to flag for review: the "no args" listing is
delivered as a toast (matching `/theme`/`/color`'s existing shape), not a
picker overlay like `/model` — see Risks for the rejected picker-overlay
alternative and why a toast fits better here.

## Implemented (bucket B)

- `[extend: chat command surface] /output-style [name] — list and switch
  output styles` — added the discoverable slash command Claudius was
  missing, wired to the settings-catalog persistence and live-session-apply
  Claudius already had the other halves of. Files touched:
  - `lib/shared/output-styles.ts` (new) — shared static fallback list
    (`default`/`explanatory`/`concise`/`developer`), used by both the
    Settings page dropdown and the new route's sessionless fallback.
  - `lib/server/session.ts` — `Session.setOutputStyle()` (live-applies via
    `query.updateSettings('localSettings', { outputStyle })`, best-effort,
    then persists to the `user` settings scope) and `Session.outputStyles()`
    (forwards `query.initializationResult()`'s `output_style` /
    `available_output_styles`, same `{ok, data|error}` envelope as
    `supportedModels`/`supportedAgents`).
  - `app/api/sessions/[id]/output-style/route.ts` (new) — GET lists
    `{current, available}` (session-sourced when a live query exists,
    static fallback otherwise); PATCH switches, 400 on a blank body, 500
    with the underlying error on failure.
  - `lib/shared/slash-commands.ts` — new `output-style` entry
    (`category: "ui"`, `handler: "native"`, `argsHint: "[name]"`).
  - `components/chat/ChatSurface.tsx` — native handler: no args fetches and
    toasts `current` + `available`; an argument PATCHes directly and toasts
    the result (success or the server's error message).
  - `app/settings/page.tsx` — the existing `outputStyle` dropdown now
    sources its option list from the same shared `STATIC_OUTPUT_STYLES`
    constant instead of a locally-duplicated array.

  Rejected alternative: a `/model`-style picker overlay (dedicated
  `OutputStylePicker.tsx` component, popover UI). Rejected because
  output-style is a 4-way (or plugin-extended) enum switched by exact name,
  the same shape as `/theme` and `/color` — both of which already resolve
  through a toast-confirmed inline command rather than a modal/popover in
  this codebase. A picker overlay would be over-scoped for a same-shape
  feature and would introduce a new UI pattern for no shape-fit gain; see
  Risks for the fuller trade-off.

- The queued-message takeback item classified above needed no new code —
  Claudius's existing Remove/Edit affordances in `QueueIndicator.tsx` already
  deliver the described behavior. Nothing shipped for it this release.

## Risks / follow-ups

- **Toast vs. picker-overlay shape** (the /output-style rejected
  alternative): a `/model`-style popover with per-style descriptions would
  read richer, especially if the account/session ever exposes many
  plugin-provided custom styles where a toast list gets unwieldy. Went with
  the toast because it matches `/theme`/`/color`'s existing shape for a
  same-cardinality enum switch, and because today's static list is only 4
  items. If plugin-provided output styles become common, revisit — the
  `available_output_styles` field this release starts consuming already has
  everything a richer picker would need.
- **`/focus` spinner-tip naming collision** (classified `[skip — ambiguous,
  see Risks]` above): the conservative reading taken was "don't ship a tip
  that points at the wrong feature." The maximal reading — build a real
  "prompt + one-line summary + response" turn-focus view and either extend
  Claudius's existing `/focus` semantics to include it or introduce a
  differently-named command for it — is out of proportion for what upstream
  shipped as a one-line spinner-tip changelog entry; it would be inventing
  scope the changelog doesn't ask for. Flagging for a future release if
  upstream's `/focus` view concept gets its own dedicated changelog entry
  (not just a tip) worth auditing on its own.
- **Queued-message takeback keybinding** (classified already-shipped
  above): Claudius deliberately doesn't bind plain `Esc`/`ArrowUp` to
  queue-recall (`PromptInput.tsx`'s comment explains Cmd/Ctrl+ArrowUp is
  reserved for prompt-history recall instead). If strict keybinding parity
  with the upstream Esc/Up gesture is ever wanted, that's a small, isolated
  addendum — not a new feature — but it wasn't added here since the
  functional behavior (remove from queue, recall to composer) already
  exists via the click affordances and the existing keybinding conflicts
  with an established Claudius shortcut.
- No harness-scope issues encountered (no gate pointed into
  `scripts/sdk-update/` or `scripts/cc-parity/`).
