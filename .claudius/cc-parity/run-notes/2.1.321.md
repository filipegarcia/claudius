## Summary

2.1.321's headline is Claude Fable 5.2 (`claude-fable-5-2`) as the new default Fable. The engine side arrives with SDK 0.3.321. Claudius also hard-codes model identity in several places, which this run brings up to date:
- browser cost estimates and the bundled LiteLLM snapshot ($8/$40, $0.20 cache reads);
- the advisor pairing table (rank 10);
- the `fable` alias and probe-list labels;
- the model-unavailable bubble;
- usage-limit detection for the engine's new `<Model> requires usage credits.` sentence.

The picker's Fast toggle now names the model ("Fast mode (Fable 5.2)"). Its "Draws from usage credits" row note shows only while fast mode is on, using either the toggle or the engine-reported state. Without that, every Fable row would carry the note now that Fable is fast-capable.

Four changelog fixes had a copy of the same bug in Claudius's own code. Each was fixed there:
- Bamum U+16910 is refused in skill names.
- `/fork` reads a failed `git status` as unavailable, not clean.
- The permission card's MCP source badge shows hidden or look-alike characters.
- The workspace form and workspace page now say what an unset permission mode actually gives.

Everything else is engine-side (A), terminal-only (C) or a product Claudius doesn't host. One feature is deliberately not built: the VS Code auth-conflict warning. Its only signal is an `@internal` field.

## Risks / follow-ups

- **Not built — VS Code auth-conflict warning.** Its only signal to SDK hosts is the `@internal` `auth_conflict` field on the initialize response. Revisit if the SDK declares it.
- **Fable 5.1 workspace pins aren't migrated.** A workspace whose stored default is `claude-fable-5-1` keeps it. The engine migrates only `settings.json` and only for entitled accounts. The maximal shape would be an entitlement-checked rewrite of `WorkspaceDefaults.model` with a one-time marker; it was not built because Claudius can't see entitlement.
- **Advisor in Fable sessions (pre-existing, made more visible).** `ADVISOR_FABLE_VALUE` in the advisor picker still pins `claude-fable-5`. In a Fable 5.2 session every advisor row is flagged as rejected, and `session.ts` clears any advisor for fable executors. This was already true for 5.1. A follow-up should pin the advisor row to the current Fable, or offer Mythos 5.2 / Fable 5.2.
- **LiteLLM bare `fable`.** The bundled snapshot has no `fable` alias key, so a server-side lookup of the bare alias resolves via its canonical scan (Fable 5.1 pricing). The browser estimator prices it as 5.2.
- **The unset permission mode stays split** (Auto at workspace creation, Default at session start). The labels now say so; unifying them is a behaviour change.
- **`/model` "More models" row:** skipped as ambiguous (no `overflow` flag in `supportedModels()`).
- **Fork maxBuffer path:** counting an overflowed status as dirty has no unit test, because it needs a repo with tens of thousands of changed files.
- **Pre-existing, found during the audit, not fixed here:**
  - `McpElicitationPrompt` and the `/mcp` page render MCP server names unescaped (same class as the permission-badge fix).
  - The hooks editor's `mcp_tool` shape is `{tool, arguments}`, but the engine's is `{server, tool, input}`.
  - A `null` MCP server config can crash `lib/server/mcp.ts:74`.
  - `account-oauth` follows cross-origin redirects.
  - `useSdkCommands` can keep stale rows.
