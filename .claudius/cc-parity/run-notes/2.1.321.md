### 2.1.321 — fixes on surfaces Claudius owns

- `[B — reimplement in Claudius] Fixed skill and command names holding a Bamum letter that some fonts draw as blank: they are now refused`. The engine rule gained exactly one code point, U+16910; the rest of the Bamum blocks stay allowed. Claudius's copy of that rule, `BLANK_LIKE_RE` in `lib/shared/skill-names.ts` (2.1.299), lacked it, so the Skills page's `writeSkill` created such a folder and `listSkills` listed it as offered. The only skill/command writer is `writeSkill`; nothing in Claudius writes `.claude/commands`, and the DB writer is for agents. Fixed there and in `HIDDEN_NAME_CHAR_RE` (`invisible-unicode.ts`), so the refused name renders legibly.
- `[B — reimplement in Claudius] Fixed the git status given to Claude at session start reading as clean when git status failed; it now reads as unavailable`. The agent-facing part is engine-only: Claudius injects no git status (`system-prompt-append.ts` passes the `claude_code` preset plus appends). Claudius's git page and DiffOverlay already show a failed status as an error. But `/fork` had the same mistake:
  - `createForkWorktree` (`lib/server/fork-worktrees.ts`) started from `dirty = false` and swallowed a failed `git status`.
  - Reproduced with a corrupt index: `rev-parse HEAD` and `worktree add` still succeed, and `status` exits 128.
  - So the toast read as if every change had gone into the worktree. It now says the check was unavailable.
- `[A — already via SDK updater] Fixed the git status given to Claude at session start showing the first listed file as staged when its changes were not staged`. This was the engine trimming the status text. Claudius's only status parser (`getStatus` → `parsePorcelainV1Z`, `lib/server/git.ts`) reads `-z` output untrimmed. Checked in a scratch repo: ` M a.txt` first parses as unstaged. The `trim()` callers (`isDirty`, `createForkWorktree`) only test for emptiness.
- `[A — already via SDK updater] Fixed project skills, commands and agents staying missing after their folder was removed and came back mid-session` / `…disappearing from the menu in SDK and desktop sessions after Claude entered a worktree`. Claudius's slash menu comes entirely from SDK data (init `slash_commands`, `supportedCommands()`, `commands_changed`), merged by `mergeSuggestions`. Its own disk listers (`listSkills`, `listAgents`) re-read the folder on every GET, with no cache or watcher.
- `[skip — Remote Control product] Fixed /compact showing twice in Remote Control on web and mobile`. Claudius's picker can't duplicate it: `mergeSuggestions` claims every registry name before the SDK union, and `richByName` is a Map.

Claudius runs no MCP OAuth of its own; grepping lib and app finds no MCP token or refresh fetch, so discovery, token and refresh all happen in the engine.
