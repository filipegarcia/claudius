## Summary

2.1.222 is almost entirely a bug-fix release for Claude Code's own engine
(worktree-isolation enforcement, hook/permission tightening, connectivity and
proxy fixes, `/usage` MCP-attribution accuracy) plus three CLI/terminal-only
accessibility and Remote Control changes — none of that needs new Claudius
code, either because it lands automatically via the next SDK bump or because
it has no browser analogue. Auditing the five entries that looked like real
bucket-B candidates (raw-diff/textconv, ultraplan removal, MCP usage
attribution, subagent effort label, Remote Control settings-scope) turned up
exactly one real, shippable item: **git diff views could be fooled by a
repo-configured `.gitattributes` `textconv` driver into showing filtered
content instead of the real change** — the same class of bug upstream fixed
for `/diff` and file-edit diffs. Fixed by adding `--no-textconv` to every
raw-content `git diff` invocation in `lib/server/git.ts` (the Git tab's
unstaged/staged/untracked diffs, "Show Diff with Working Tree", and the
diff fed to the AI commit-message drafter). The other four candidates came
back negative on inspection (no Claudius surface exists to have the bug, or
Claudius's existing implementation already enforces the stricter rule) — see
the classification and Risks sections for the evidence trail. Headline risk
to flag for review: this is a correctness/security-adjacent fix to an
*existing* screen with no new UI, so there's nothing novel to sanity-check
UX-wise, but the `ultraplan` removal is a genuine ambiguity (Claudius's own
`/ultraplan` delegates entirely to the SDK backend, and it's not verifiable
from here whether that backend skill was also removed) — flagged rather than
acted on.

## Implemented (bucket B)

- `[extend: Git tab diff view]` Raw git-blob diffs (ignore `.gitattributes` textconv/diff drivers) — `lib/server/git.ts`: added `--no-textconv` to `getDiff()`'s `staged`/`worktree` branches, `diffNoIndex()` (shared by untracked-file diffs and `getDiffForCommit`'s new-file diffs), `diffBranchAgainstWorktree()`, and the tracked-path branch of `getDiffForCommit()` (the diff fed to the AI commit-message drafter). `gitShow()` needed no change — `git show <rev>:<path>` is already textconv-immune. Rejected alternative: a **new dedicated "raw diff" toggle/setting** the user could flip — rejected because there's no legitimate reason a diff view should ever show filtered content instead of the real change; this is a correctness fix to existing behavior, not a new user-facing choice, exactly mirroring how upstream shipped it (unconditional, not opt-in).
