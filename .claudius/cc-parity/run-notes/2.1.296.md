## Summary

Claude Code 2.1.296 is mostly fixes. The few additions are:
- `autoCompactWindow` for subagents;
- two env vars, `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` and `CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS`;
- Read `allow_large`;
- a `code` gateway policy key;
- a `/plugin` note for hooks left out because two plugins share a name.

Its fixes span hooks, MCP, plugins, mods, Bash/Edit permissions, Windows, VS Code, cloud, Slack and Code Review.

`autoCompactWindow` already shipped on this branch through the SDK updater. Most other entries are engine-side (A) or terminal/hosted-only (C).

Claudius reimplements five items (bucket B), all as extensions of existing surfaces:
- **Sonnet 5.5 pricing:** cache reads cost $0.10/MT in both of Claudius's own cost estimators.
- **"Not run" row:** a dim row, in the chat and the Activity rail, for tool calls auto mode couldn't check.
- **Reserved marketplace names:** the Plugins → Marketplaces form refuses names Claude Code reserves (`constructor`, `toString`, …).
- **Windows-path chat links:** `C:\…` and `file:///C:/…` links now open in the Files browser.
- **U+2028 fix:** Claudius's own transcript readers no longer drop records containing U+2028/U+2029. This is the same class of bug the engine fixed in its transcript GC.

Headline risks for review:
- The "Not run" row reads an `@internal` SDK field (`tool_result_meta`).
- It only shows on the live stream. Resumed or older history comes from `getSessionMessages`, which strips that field, so those rows are red again.
- The `/plugin` duplicate-name note was deliberately not rebuilt, because the engine doesn't expose which plugin's hooks it left out.

## Risks / follow-ups

- **"Not run" row: alternative shape.** I considered an amber/sky badge in the style of the existing Staged / "Continuing in background" badges, and went with a muted label plus a dimmed row to match the CLI's dim treatment. If reviewers prefer the pill idiom, it is a one-line change in `ToolCall.tsx`.
- **"Not run" row: limitations.**
  - `tool_result_meta` is `@internal`: it is absent from the public `sdk.d.ts`, but present in the bundled CLI's output schema. It is read with `typeof` guards and could move without notice.
  - The dim state only survives on the live stream and the same-process replay buffer. `getSessionMessages` (resume / scroll-up history) strips `tool_result_meta`, just as it already strips `tool_use_result` (so `staged`/`detached` have the same gap), so those rows show red again. The fix would be server-side JSONL enrichment covering all three flags.
  - An Agent/Workflow/`mcp_task` call that is not run can still read "failed", because `reconcileTasksOnToolResult` maps any `isError` to failed. This is rare: those tools seldom go through the classifier.
