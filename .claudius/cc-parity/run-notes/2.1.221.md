## Summary

2.1.221 is a small parity surface: most of the release is bug fixes plus
engine-internal behavior (sandbox credential masking, auto-mode permission
caching, Vertex tool search, fast-mode credit reporting, `/fork`'s new
worktree isolation) that lands automatically once the SDK updater bumps
`@anthropic-ai/claude-agent-sdk`. Two entries are genuine bucket-B work,
both extensions of existing Claudius surfaces rather than new screens:
the emoji shortcode autocomplete (2.1.217 parity) gained an alias table so
`:love:` resolves like `:heart:`, and `/status`'s new "session kind"
concept (interactive vs. a background job that's attached/unattended) is
reimplemented on the `/schedule` page, which is Claudius's closest analog
to a CC background job — a scheduler run now shows an "attached" or
"unattended" chip depending on whether a browser tab has its live stream
open. A third candidate — the Stats panel's cache-token breakdown — turned
out to already be fully implemented in Claudius's `CostOverlay`/
`ModelBreakdown` components from prior parity work, so no code changed
there. The headline risk to flag for review: the `/status` → Schedule-page
mapping is an interpretive leap (CC's "background job" and Claudius's
"scheduler run" aren't the same abstraction), so the reviewer should
double check that mapping reads as intuitive rather than forced — see
Risks below for the rejected alternative (extending `StatusOverlay`
instead).

## Implemented (bucket B)

- `[extend: /schedule] "/status" session-kind parity — attached/unattended chip on live scheduler runs` — added `Scheduler.isRunAttached()` (`lib/server/scheduler.ts`, mirrors the existing `isRunLive`), stamped onto in-flight runs by `app/api/schedule/[id]/runs/route.ts`, and rendered as an "attached"/"unattended" chip (with `Eye`/`EyeOff` icons) next to the "Live" badge in the runs list, plus a "Kind" stat row in the run-detail transcript — both in `app/[workspaceId]/schedule/page.tsx`. Rejected alternative: extending `StatusOverlay.tsx` (the native `/status` overlay) directly — rejected because every Claudius chat session viewed in the browser is trivially "interactive" (you're always attached if you can see the page), so the overlay would show a constant, uninformative value; the Schedule page's scheduler runs are Claudius's only surface with a genuine attached/unattended distinction.
- `[extend: chat composer] Emoji shortcode aliases (:love: → ❤️, plus thumbs_up/thumbs_down underscore aliases)` — added an `EMOJI_ALIASES` table to `lib/shared/emoji-shortcodes.ts` and threaded it through `filterEmojiShortcodes`/`lookupEmojiShortcode`; no component changes needed since `EmojiShortcodePicker.tsx`/`PromptInput.tsx` already consume those two functions. Rejected alternative: a full alias-editing settings UI — overkill for a small curated list; matches the existing file's own stated philosophy ("a curated subset... not an exhaustive dump... add to it as needed").
