### Bucket B — reimplemented in Claudius

- `[B — reimplement in Claudius] [Remote Control] Fixed the diff view in Remote Control sessions on claude.ai and the desktop app showing deleted and renamed files as modified`
  - **Where the bug is.** The `/diff` overlay badges a staged rename that was then edited (porcelain `RM`) as **M / Modified**. `lib/shared/diff-overlay.ts` `statusChar` prefers the worktree slot, and `components/overlays/DiffOverlay.tsx` never shows `oldPath`.
  - **What is already correct.** Deletes are fine. The Git page (`components/git/ChangesList.tsx`) already shows renames correctly.
  - **Fix.** Badge R/C from the index slot when the worktree slot only says "modified", and render `old → new`.
- `[B — reimplement in Claudius] [VSCode] Fixed ↑ then Enter on a recalled slash command running it without its arguments; the command and file menus no longer open over a recalled prompt until you edit it`
  - **Where the bug is.** `components/chat/PromptInput.tsx` `applyRecalledText()` (Cmd/Ctrl+↑/↓ history) and `restoreUndelivered()` (the 2.1.299 failed-send restore) both call `refreshPickerState()`, so the slash, `@`-file and `:emoji` menus open over the recalled text.
  - **Effect.** Enter then picks the highlighted item instead of sending: a recalled `/compact` becomes `/compact `, and a recalled `explain @lib/foo.ts` swaps in another file.
  - **What is not present.** The "drops its arguments" half doesn't occur in Claudius: the slash token must touch the caret.
  - **Fix.** Close the menus on recall; the first real edit reopens them.
- `[B — reimplement in Claudius] [VSCode] Fixed "Edit prompt" on a flagged message opening the file or command menu over the restored prompt; Enter now sends it as written`
  - **Claudius analog.** The refusal pill's **Edit & retry** (`components/chat/SystemPill.tsx` → `ChatSurface.tsx` `onEditAndRetry`) and the queued-message **Edit** lift both inject text with `mode:'replace'`. That path in `PromptInput.tsx` re-runs `refreshPickerState()`.
  - **Fix.** Mark these injections as `recalled` and close the menus. The `/model ` prefill and `?prefill=1` keep their current behaviour.
- `[B — reimplement in Claudius] [VSCode] Fixed fast mode staying on after usage credits ran out, which made each request be refused and re-sent; it now turns off until you turn it back on, with an error notice`
  - **Engine behaviour** (2.1.300 binary). On a credit-exhaustion overage rejection the engine emits a `system/notification` with `key:"fast-mode-overage-rejected"` and `color:"error"`, retries without fast for that request only, and leaves the persistent fast flag on. Only the interactive REPL's listener turns it off, which is why the upstream fix shipped in the VS Code host rather than the engine.
  - **Claudius.** It ignores the notice's `key`/`color`, so fast stays on.
  - **Fix.**
    - Server: on that notice, turn fast off (`lib/server/session.ts`).
    - Client: flip the ModelPicker toggle and FastBadge mirror without re-POSTing, and render the notice in the error tone.
- `[B — reimplement in Claudius] [VSCode] Fixed changes to VS Code's chat font size settings needing a window reload or being undone by a theme change; diffs and the plan preview now follow them too`
  - **Where the bug is.** Claudius has a chat text-size setting (`components/settings/ChatSizeSection.tsx`, `--chat-text`). The ExitPlanMode plan preview in the transcript (`components/chat/ToolCall.tsx`) and the plan approval overlay (`components/overlays/PlanOverlay.tsx`) hard-code `text-sm` and ignore it.
  - **Diffs.** Claudius renders no diffs inside the chat column, so that half has no Claudius surface.
  - **Fix.** The plan containers follow `--chat-text`.
- `[B — reimplement in Claudius] Fixed agent hooks ignoring their model: aliases like haiku now resolve, a subagent's model no longer overrides it, and an unavailable model falls back to the caller's instead of allowing the action`
  - **Where the bug is.** The Claudius Hooks editor (`app/[workspaceId]/hooks/page.tsx`, `lib/shared/hook-events.ts`) writes agent hooks as `{type:"agent", agent:"<name>"}`. The engine schema is `{type:"agent", prompt, model?}`.
  - **Effect.** Reproduced against the bundled 2.1.300 engine: every agent hook saved from Claudius is skipped with "Invalid agent hook (prompt: … received undefined)". There is also no `model` field to set at all.
  - **Fix.** Write the correct `prompt` + optional `model` shape, add the field, and flag legacy `agent:`-shaped entries as ignored by the engine.
- `[B — reimplement in Claudius] Changed local session transcripts to also record each API request's system prompt, tools and parameters, so a transcript you choose to share can reproduce a request exactly`
  - **New entries.** The 2.1.300 engine writes `api-request-shape`, `api-request-blob` and `api-request` lines into the JSONL, on by default.
  - **Where the bug is.** Claudius's session content search (`app/api/sessions/search/route.ts`) regex-scans the raw JSONL text. Reproduced: any word in the system prompt, the tool descriptions or the request params (`playwright`, `TodoWrite`, `max_tokens`) matches every session recorded since 2.1.300, and a real hit later in the file is masked.
  - **Fix.** Skip matches on `api-request*` lines.
- `[B — reimplement in Claudius] Changed exit to force-kill background commands still running 1.5 seconds after being asked to stop; in fullscreen mode they could previously be left running`
  - **Where the bug is.** Claudius owns the persistent shell for `!` bash mode (`lib/server/bash-mode.ts`). On session close, `dispose()` and the per-command timeout only send SIGTERM to the process group. Reproduced: a background job that traps TERM outlives the session.
  - **Fix.** Escalate to SIGKILL after 1.5 s, as the engine now does. Also apply it to `lib/server/shell.ts`'s timeout.
- `[B — reimplement in Claudius] Added cache_creation_5m_tokens and cache_creation_1h_tokens to the OpenTelemetry api_request event, splitting cache writes by lifetime`
  - **Interpretation.** The telemetry half is engine-side (A). Claudius's own Cost page (`lib/server/cost-aggregate.ts` → `lib/server/litellm-pricing.ts`) merges 5m and 1h cache writes and prices all of them at the 5m rate, while the engine's pricer splits them.
  - **Effect.** Reproduced: 1h writes are undercounted by 37.5%.
  - **Fix.** Price the 1h share at the 1h rate.
  - Interpretive call, see Risks.

### Bucket A — engine-side, arrives via the SDK updater

- `[A — already via SDK updater] Added /advisor on Claude Platform on AWS; no advisor runs until you pick one with /advisor, advisorModel or --advisor, and CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off`
  - **Engine.** Provider availability and the env kill switch are decided in the engine's advisor gate (`CLAUDE_CODE_DISABLE_ADVISOR_TOOL || …; provider === firstParty || anthropicAws`).
  - **Claudius.** `/advisor` is native and unconditional (`lib/shared/slash-commands.ts`, `lib/shared/advisor.ts`). Claudius only forwards `advisorModel` when set (`lib/server/session.ts`), never enables an advisor by default, and doesn't scrub the env var.
- `[A — already via SDK updater] Fixed /autocompact warning about high token usage when you choose a smaller auto-compact window`
  - **Engine.** The warning (`Overriding auto may result in high token usage…`) lives only in the engine's `/autocompact` command, which reaches Claudius through the SDK.
  - **Claudius.** It has no `/autocompact` of its own. Its Settings `autoCompactWindow` editor only warns outside the engine's accepted 100k–1M range (`lib/shared/auto-compact-window.ts`), so a smaller in-range window never warns.
- `[A — already via SDK updater] Fixed SessionEnd hooks sometimes not running when you exit while a background command is still running` — SessionEnd fires inside the engine. Claudius runs no settings hooks itself: `lib/server/hooks.ts` only edits config, and its programmatic hooks in `session.ts` are PreToolUse/PostToolUse/PostModelSwitch.
- `[A — already via SDK updater] Fixed the branch showing as ".invalid" and --worktree failing to reopen a worktree in repositories using git's reftable ref storage`
  - **Claudius.** It never reads `.git/HEAD` as a file; branch info comes from `git status -b`, `rev-parse` and `worktree list` (`lib/server/git.ts`, `worktrees.ts`).
  - **Reproduced.** In a reftable repo `getStatus()` and `listWorktrees()` return the real branch names. The sessions-list `gitBranch` is the engine's own stamp.
- `[A — already via SDK updater] Fixed --worktree sessions sometimes starting from the wrong commit when a tag or branch was named like a commit ID, and their starting git status naming a branch other than the new worktree's` — Claudius's only worktree creator (`lib/server/fork-worktrees.ts`) passes the literal `HEAD` after a `rev-parse --verify HEAD^{commit}`, never a SHA string. The starting git status is the engine's prompt snapshot.
- `[A — already via SDK updater] Fixed --worktree failing in a worktree of a bare repository when origin's default branch can't be fetched; the fallback base is now the current checkout's HEAD` — `fork-worktrees.ts` never fetches origin. Its base is already the current checkout's HEAD (`rev-parse --show-toplevel` of the source cwd).
- `[A — already via SDK updater] Fixed plugin WorktreeCreate and WorktreeRemove hooks not running when Claude Code starts with --worktree` — Claudius has no `--worktree` startup path and runs no settings hooks. `session.ts` deliberately registers no SDK WorktreeCreate/Remove callbacks.
- `[A — already via SDK updater] Fixed the diff view in Claude Desktop and Remote Control sessions not noticing a conflicted cherry-pick or revert in reftable repositories`
  - **Claudius.** Its git views don't check for `CHERRY_PICK_HEAD`/`REVERT_HEAD`/`MERGE_HEAD` files. Conflicts come from the index (`git diff --diff-filter=U`, porcelain `U` codes; `lib/server/git.ts`), which doesn't depend on the ref backend.
  - **Reproduced.** In a reftable repo a conflicted cherry-pick shows as `UU`.
- `[A — already via SDK updater] Fixed the first transcript entry written after resuming a session being lost when a crash had cut the transcript's last line short`
  - **Writes.** The engine owns transcript writes. Claudius's one append (`lib/server/workspace-relocate.ts` `appendRelocatedStamp`) already prefixes `\n` when the file doesn't end in one.
  - **Reads.** Claudius's readers skip torn lines (`session-resume.ts`, `cost-aggregate.ts`, `asset-ingest.ts`, `peer-source.ts`).
- `[A — already via SDK updater] Fixed /branch dropping messages, and claude purge skipping subfolder projects, when they contain a Unicode line or paragraph separator (U+2028, U+2029)` — Claudius forks through the SDK's `forkSession` (`lib/server/sessions-store.ts`). Its JSONL readers split on `\n` only (`lib/server/jsonl-lines.ts`, the 2.1.296 port; `buf.split("\n")` elsewhere). It has no purge.
- `[A — already via SDK updater] Changed hooks: updatedInput from PreToolUse and PermissionRequest hooks is now validated like Claude's own input` — Claudius's programmatic PreToolUse hook never returns `updatedInput` (`session.ts`). Its `updatedInput` values are `canUseTool` results, not hook output. User hooks run in the engine.
- `[A — already via SDK updater] Fixed a conversation failing on every turn with a 400 error when the API rejected an MCP tool's input schema` — this is handled in the engine's request builder. Claudius's in-process MCP tools (`createSdkMcpServer`, trivial zod schemas) aren't affected.
- `[A — already via SDK updater] Engine-internal fixes and changes with no Claudius copy`:
  - automatic tool search turning off mid-conversation;
  - `forceLoginOrgUUID` token retention;
  - `git_commit_id` in OTel `tool_result` with reftable;
  - the OpenTelemetry GenAI span attributes;
  - the `prompt.submit` telemetry and title fix;
  - agent hooks' model resolution in the engine (the Claudius-side editor bug is B above);
  - the scratchpad full-path note;

  - MCP tools/instructions after a post-compaction connect;
  - Claude polling a background command's output;
  - stale feature flags behind TLS-inspecting proxies;
  - deferred-tool re-search on resume;
  - the Claude 3 @-PDF note;
  - artifact update flow;
  - the `plugin-authoring` and `claude-api` bundled skill changes;
  - `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` ignoring CA/proxy vars (Claudius never sets it; see `2.1.222.md`/`2.1.251.md`);
