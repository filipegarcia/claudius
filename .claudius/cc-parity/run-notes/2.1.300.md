## Summary

Claude Code 2.1.300 adds:
- mod-runtime hooks and props (`virtualText`, `$.ui.view`, `prompt.change`, `agent.spawn` rewrites);
- OpenTelemetry fields (5m/1h cache-write split, GenAI span attributes);
- `/advisor` on Claude Platform on AWS;
- per-request transcript capture;
- a 1.5 s force-kill of background commands on exit;
- validated hook `updatedInput`;
- a long tail of fixes across worktrees and reftable repos, resume/compaction, cloud sessions, Remote Control, VS Code, Slack and Code Review.

Most of it is engine-side (A) or terminal/IDE/hosted-only (C). Claudius reimplements **eight items** (bucket B), all as extensions of existing screens or server fixes; no new routes.

**Visible changes (each with an in-context screenshot):**
- **`/diff` overlay:** an edited staged rename now reads **R** with `old → new` instead of "Modified".
- **Composer:** the slash, `@`-file and `:emoji` menus stay closed over a prompt that comes back into the box, so Enter sends it as written. This covers Cmd/Ctrl+↑ history, the failed-send restore, **Edit & retry** on a refusal and the queued-message **Edit** lift.
- **Fast mode:** it turns **off** when the engine reports that usage credits ran out. The server turns it off; the ModelPicker toggle and fast badge follow, and the notice shows in red.
- **Plan previews:** the transcript's ExitPlanMode row and the plan approval overlay follow **Settings → Chat size**.
- **Hooks editor:** agent hooks are saved in the engine's `{prompt, model?, timeout?}` shape, with a **Model** field. The old `{agent: name}` shape, which the engine silently skipped, is badged "won't run — no prompt".

**Server-only fixes:**
- Session content search skips the new `api-request*` transcript records, which made any system-prompt word match every session.
- `!` bash mode SIGKILLs a process group still alive 1.5 s after SIGTERM.
- The Cost page prices 1-hour cache writes at the 1h rate (2× input), which it had undercounted by 37.5%.

**Headline review questions:**
1. Is the composer translation right? It closes menus on four restore paths; only history recall and "Edit prompt" are named upstream.
2. Is reading the OTel cache-split entry as a Claudius Cost-page pricing fix in scope? It now diverges from ccusage on purpose.
3. Is the hooks-editor schema fix the right shape for an entry that is nominally engine-side?

### Bucket B — reimplemented in Claudius

- `[B — reimplement in Claudius] [Remote Control] Fixed the diff view in Remote Control sessions on claude.ai and the desktop app showing deleted and renamed files as modified`
  - **Where the bug is.** The `/diff` overlay badges a staged rename that was then edited (porcelain `RM`) as **M / Modified**. `lib/shared/diff-overlay.ts` `statusChar` prefers the worktree slot, and `components/overlays/DiffOverlay.tsx` never shows `oldPath`.
  - **What is already correct.** Deletes are fine. The Git page (`components/git/ChangesList.tsx`) already shows renames correctly.
  - **Fix.** Badge R/C from the index slot when the worktree slot only says "modified", and render `old → new`.
- `[B — reimplement in Claudius] [VSCode] Fixed ↑ then Enter on a recalled slash command running it without its arguments; the command and file menus no longer open over a recalled prompt until you edit it`
  - **Where the bug is.** `components/chat/PromptInput.tsx` `applyRecalledText()` (Cmd/Ctrl+↑/↓ history) and `restoreUndelivered()` (the 2.1.299 failed-send restore) both call `refreshPickerState()`, so the slash, `@`-file and `:emoji` menus open over the recalled text.
  - **Effect.** Enter then picks the highlighted item instead of sending: a recalled `/compact` becomes `/compact `, and a recalled `explain @lib/foo.ts` swaps in another file.
  - **What is not present.** The "drops its arguments" half doesn't occur in Claudius: the slash token must touch the caret.
  - **Fix.** Close the menus on recall; the first real edit reopens them.
- `[B — reimplement in Claudius] [VSCode] Fixed "Edit prompt" on a flagged message opening the file or command menu over the restored prompt; Enter now sends it as written`
  - **Claudius analog.** The refusal pill's **Edit & retry** (`components/chat/SystemPill.tsx` → `ChatSurface.tsx` `onEditAndRetry`) and the queued-message **Edit** lift both inject text with `mode:'replace'`. That path in `PromptInput.tsx` re-runs `refreshPickerState()`.
  - **Fix.** Mark these injections as `recalled` and close the menus. The `/model ` prefill and `?prefill=1` keep their current behaviour.
- `[B — reimplement in Claudius] [VSCode] Fixed fast mode staying on after usage credits ran out, which made each request be refused and re-sent; it now turns off until you turn it back on, with an error notice`
  - **Engine behaviour** (2.1.300 binary). On a credit-exhaustion overage rejection the engine emits a `system/notification` with `key:"fast-mode-overage-rejected"` and `color:"error"`, retries without fast for that request only, and leaves the persistent fast flag on. Only the interactive REPL's listener turns it off, which is why the upstream fix shipped in the VS Code host rather than the engine.
  - **Claudius.** It ignores the notice's `key`/`color`, so fast stays on.
  - **Fix.**
    - Server: on that notice, turn fast off (`lib/server/session.ts`).
    - Client: flip the ModelPicker toggle and FastBadge mirror without re-POSTing, and render the notice in the error tone.
- `[B — reimplement in Claudius] [VSCode] Fixed changes to VS Code's chat font size settings needing a window reload or being undone by a theme change; diffs and the plan preview now follow them too`
  - **Where the bug is.** Claudius has a chat text-size setting (`components/settings/ChatSizeSection.tsx`, `--chat-text`). The ExitPlanMode plan preview in the transcript (`components/chat/ToolCall.tsx`) and the plan approval overlay (`components/overlays/PlanOverlay.tsx`) hard-code `text-sm` and ignore it.
  - **Diffs.** Claudius renders no diffs inside the chat column, so that half has no Claudius surface.
  - **Fix.** The plan containers follow `--chat-text`.
- `[B — reimplement in Claudius] Fixed agent hooks ignoring their model: aliases like haiku now resolve, a subagent's model no longer overrides it, and an unavailable model falls back to the caller's instead of allowing the action`
  - **Where the bug is.** The Claudius Hooks editor (`app/[workspaceId]/hooks/page.tsx`, `lib/shared/hook-events.ts`) writes agent hooks as `{type:"agent", agent:"<name>"}`. The engine schema is `{type:"agent", prompt, model?}`.
  - **Effect.** Reproduced against the bundled 2.1.300 engine: every agent hook saved from Claudius is skipped with "Invalid agent hook (prompt: … received undefined)". There is also no `model` field to set at all.
  - **Fix.** Write the correct `prompt` + optional `model` shape, add the field, and flag legacy `agent:`-shaped entries as ignored by the engine.
- `[B — reimplement in Claudius] Changed local session transcripts to also record each API request's system prompt, tools and parameters, so a transcript you choose to share can reproduce a request exactly`
  - **New entries.** The 2.1.300 engine writes `api-request-shape`, `api-request-blob` and `api-request` lines into the JSONL, on by default.
  - **Where the bug is.** Claudius's session content search (`app/api/sessions/search/route.ts`) regex-scans the raw JSONL text. Reproduced: any word in the system prompt, the tool descriptions or the request params (`playwright`, `TodoWrite`, `max_tokens`) matches every session recorded since 2.1.300, and a real hit later in the file is masked.
  - **Fix.** Skip matches on `api-request*` lines.
- `[B — reimplement in Claudius] Changed exit to force-kill background commands still running 1.5 seconds after being asked to stop; in fullscreen mode they could previously be left running`
  - **Where the bug is.** Claudius owns the persistent shell for `!` bash mode (`lib/server/bash-mode.ts`). On session close, `dispose()` and the per-command timeout only send SIGTERM to the process group. Reproduced: a background job that traps TERM outlives the session.
  - **Fix.** Escalate to SIGKILL after 1.5 s, as the engine now does. Also apply it to `lib/server/shell.ts`'s timeout.
- `[B — reimplement in Claudius] Added cache_creation_5m_tokens and cache_creation_1h_tokens to the OpenTelemetry api_request event, splitting cache writes by lifetime`
  - **Interpretation.** The telemetry half is engine-side (A). Claudius's own Cost page (`lib/server/cost-aggregate.ts` → `lib/server/litellm-pricing.ts`) merges 5m and 1h cache writes and prices all of them at the 5m rate, while the engine's pricer splits them.
  - **Effect.** Reproduced: 1h writes are undercounted by 37.5%.
  - **Fix.** Price the 1h share at the 1h rate.
  - Interpretive call, see Risks.

## Risks / follow-ups

**Design calls to confirm (one alternative per bucket-B item):**
- **Composer.** Upstream names only history recall (↑) and "Edit prompt" on a flagged message. Claudius also closes menus on the failed-send restore and the queued-message Edit lift, since both put back a prompt the user already wrote.
  - Conservative shape: history recall + Edit & retry only.
  - Maximal shape (shipped): all four restore paths. The draft seed, `?prefill`, the `/model ` prefill, append injections and the Cmd/Ctrl+↓ walk back to a live draft keep reopening menus.
  - Behaviour change: a restored bare `/comp` + Enter now sends `/comp` as written, which gives Claudius's "Unknown command" toast, instead of completing to `/compact `.
- **Cost 1h pricing** is an interpretation. The changelog entry is OpenTelemetry-only (A); the Claudius Cost page undercounting 1h cache writes is the analog.
  - The Cost page now **diverges from ccusage on purpose**, and its methodology note says so.
  - The engine falls back to the 5m rate for catalog models with no 1h price; Claudius always applies 2×. Every Anthropic catalog entry checked lists 1h = 2× input.
  - Follow-up: the live per-session cost estimates (`lib/server/session.ts` resumed-session baseline, `lib/client/use-session.ts` mid-turn estimate) still pass `cacheWrite1h: 0`, so they can read lower than the Cost page for the same transcript.
- **Hooks editor.** The engine fix ("aliases resolve, a subagent's model no longer overrides it") arrives via the SDK. The Claudius part is that its editor wrote a shape the engine rejects and had no `model` field.
  - Alternative considered: only adding a Model field. Rejected, because those hooks would still be skipped at load.
  - **Same bug class, not fixed:** `mcp_tool` hooks are still written as `{tool, arguments}`, while the engine schema wants `{server, tool, input}`, so they are probably skipped at load the same way. Worth a follow-up with the same legacy-badge treatment.
  - Command/http timeouts saved under the old "ms" label (e.g. `5000`) now display as `timeout=5000s` with no warning; a hint for implausibly large values could help.
- **Diff overlay.** The badge is fixed, but the diff **body** of a rename is still a modify diff (`RM`) or probably a whole-file add (pure staged `R `), because `/git/diff` only takes the new path. The Git page has the same behaviour. Fixing it means threading `oldPath` through the diff route.
- **Fast mode** is session-scoped, like effort and ultracode in Claudius. A user with `fastMode: true` in settings.json still starts each new session with fast on and pays one refused-and-resent request before it turns off again.
- **Bash mode.** The escalation covers session close and per-command timeouts, not server or Electron shutdown: nothing disposes bash sessions on process exit. This gap predates the change; noted in `lib/server/process-group.ts`.
- **Plan preview.** The SendFeedback "drafted report" preview in the same expander still uses a fixed `text-sm`. That's outside the entry.

**Ambiguous items:** none marked `[skip — ambiguous]`. The Artifact-tool, `/tasks` and breadcrumb entries were classified C after confirming Claudius has no such surface.

**Environment notes:**
- **Shared node_modules.** The three server-only fixes were implemented by agents in isolated git worktrees with a symlinked `node_modules`. Their first `git commit` ran the repo's pre-commit hook (`scripts/native-abi.mjs ensure node`), which found no ABI lock in the worktree and ran `bun install --force better-sqlite3` against the shared `node_modules`. That left better-sqlite3 13.0.3 (the lock pins 12.11.1) with its build wiped, and it changed `next`.
  - I restored with `bun install --frozen-lockfile`: better-sqlite3 is back at 12.11.1 (built) and next at 16.3.8.
  - That also put `@anthropic-ai/claude-agent-sdk` back to the lockfile's **0.3.296**. An unlocked **0.3.300** had been in the shared `node_modules` when the run started, presumably from the sibling SDK updater.
  - The engine-side evidence in this file (binary greps) was taken from the 0.3.300 / Claude Code 2.1.300 binary before that reset.
  - Future runs that use worktree agents should write `dist-electron/native-abi.json` in each worktree first. That is in the harness, which I didn't touch.
- No harness (`scripts/cc-parity/`, `scripts/sdk-update/`) failures were seen.
