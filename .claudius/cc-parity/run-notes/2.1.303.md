### 2.1.303

## Risks / follow-ups

- **Engine CA warnings are not shown in Claudius.**
  - The new deny-list warnings go to the engine's stderr (`console.error`). Claudius passes no `stderr` callback to `query()` (`git grep stderr -- lib/server` finds only the bash-mode, git and customization helpers).
  - So a user whose corporate `NODE_EXTRA_CA_CERTS` bundle is now partly or fully ignored will see the SDK's TLS or connection error in chat without the reason.
  - Possible follow-up: capture engine stderr through `Options.stderr` and show the known CA-warning lines as a session notice.
  - Not built here. Doing it would mean inventing a surface the changelog doesn't describe, and every other stderr line would need filtering.
- **The disambiguation method can't see logic-only fixes.** The string diff only shows changed user-facing text and identifiers. Any 2.1.303 fix that changed code paths without new strings is invisible to it. Those fixes live in the bundled binary, so they reach Claudius through the SDK bump, and the gate suite is the only check that nothing regressed.
- **Claudius's own Node server still trusts all of `NODE_EXTRA_CA_CERTS`.** The deny list applies only to the engine process. Claudius's own outbound fetches (model-list probe, pricing, PR status) use Node's normal handling of the same variable.
  - Rejected alternative: mirror the deny list in Claudius. Its contents are an undocumented set of SHA-256 hashes inside the engine, so copying them would be invented scope that goes stale without notice.
- **No bucket-B shape to review.** Nothing was built, so there is no extend-vs-new-screen call for the reviewer to check this release. The rejected maximal reading, treating "Bug fixes and reliability improvements" as permission to hunt for Claudius-side analogues of arbitrary engine fixes, is not backed by the changelog or the binary diff.
