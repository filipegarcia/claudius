## Summary

2.1.247 is a small release for Claudius's purposes: most of its substance is
either engine-internal (model-fallback chains, sandbox/hook robustness,
plugin-marketplace hardening — all Bucket A, inherited automatically once
`@anthropic-ai/claude-agent-sdk` catches up) or genuinely CLI/cloud-only
(terminal keyboard-layout fixes, Claude Code's own web/desktop/mobile "cloud
sessions", enterprise managed-settings gateway login). Three items are real
product surface for a browser app and are reimplemented here: (1) the new
`SendFeedback` tool + `feedbackDrafts` setting gets a settings-page row
(config passthrough, same shape as `keybindingFlavor`) and a dedicated
"Feedback draft" transcript card instead of a raw JSON tool dump; (2) the
Bash-permission-prompt auto-mode tip gets a real one-click "Yes, and switch
to auto mode" affordance on `PermissionPrompt`, wired to the pre-existing
Auto mode + `disableAutoMode` escape hatch; (3) cross-session peer messages
now collapse to a one-line preview by default with click-to-expand, matching
the changelog's `Message from @<sender>: <first line>` copy. The headline
risk to flag for review: the `SendFeedback` tool's input schema isn't part
of the SDK's public type surface (only the `feedbackDrafts` setting is
documented in `sdk.d.ts`), so the "drafted report" text extraction in
`ToolCall.tsx` defensively probes a few plausible field names
(`report`/`feedback`/`description`/`summary`/`text`) rather than binding to
a confirmed shape — worth re-checking against a real drafted-feedback tool
call once one is observed in the wild.

## Implemented (bucket B)

- `[extend: Settings page] feedbackDrafts setting` — added a
  `feedbackDrafts` ("notify"/"quiet"/"off") enum row to the existing
  Settings catalog (Storage & sessions section, next to the sibling
  `feedbackSurveyRate`), plus a dedicated "Feedback draft" rendering for
  the `SendFeedback` tool call in the transcript instead of the generic
  JSON-dump card every other tool gets. Files: `lib/server/settings.ts`,
  `app/settings/page.tsx`, `components/chat/ToolCall.tsx`,
  `lib/shared/feedback-draft.ts` (new — the drafted-text extraction
  helper). Rejected alternative: a bespoke "review queue" overlay
  (independent of the transcript) listing all pending drafts with
  Send/Dismiss actions — rejected because the tool's actual queueing
  semantics (is a draft held server-side pending an explicit "send" action,
  or does invoking the tool already forward it and "queued" just means
  Anthropic-side batching?) aren't documented anywhere in the SDK's public
  types or the fetched docs page, and guessing at a stateful queue/send
  flow risked building the wrong contract entirely. The shipped shape
  (readable transcript card + settings toggle) is correct regardless of
  which reading turns out true.
- `[extend: chat permission modal] Bash permission auto-mode tip` — added
  a tip row + one-click "Yes, and switch to auto mode" action to
  `PermissionPrompt.tsx`, shown only for `Bash` tool requests when Auto
  mode is available (respects the pre-existing `disableAutoMode` escape
  hatch and doesn't show when already in Auto mode). Files:
  `components/chat/PermissionPrompt.tsx`, `components/chat/ChatSurface.tsx`.
  Rejected alternative: a persistent "switch to Auto" banner shown
  globally after N Bash approvals — rejected as a bigger, noisier surface
  than the CLI's own scoped, per-prompt nudge; the permission modal is
  exactly where the CLI places it and exactly where a Claudius user is
  already looking when the tip is relevant.
- `[extend: chat transcript] Peer message collapse-by-default` — inbound
  peer-authored turns now render as a one-line `Message from <sender>:
  <first line>` clickable row, expanding to the full body on click (mirrors
  the pre-existing `BashIOBlock` collapse/expand convention in the same
  file). Files: `components/chat/UserMessage.tsx`,
  `lib/shared/peer-message-preview.ts` (new — the preview-string helper).
  Rejected alternative: a global `Ctrl+O`-style keybinding to expand the
  *last* peer message (matching the CLI literally) — rejected because
  Claudius's keybinding system (`lib/server/keybindings.ts`) is scoped to
  session-wide actions, not "the most recent of possibly many collapsed
  rows in a scrollable transcript"; a per-row click affordance is the
  correct browser-app translation and is already Claudius's own convention
  for this exact kind of collapse (see `BashIOBlock`).

## Risks / follow-ups

- **SendFeedback input schema is guessed, not confirmed.** `ToolCall.tsx`'s
  `extractFeedbackDraftText` probes `report`/`feedback`/`description`/
  `summary`/`text` in that order and falls back to the generic JSON dump if
  none match. If the real tool uses a different field name, the card will
  silently fall back to the pre-existing generic rendering (safe failure
  mode) but won't show the friendly text. Re-check against a real drafted
  report once the SDK exposes typed tool schemas or one is observed live.
- **feedbackDrafts is config-passthrough only, not forwarded per-session.**
  Same treatment as `keybindingFlavor`/`syncClaudeAiPlugins`/
  `promptCacheTtl`: written to `~/.claude/settings.json` and read directly
  by the engine, not threaded through `session.ts`'s inline `settings`
  block. This matches the documented precedent for global, non-per-turn
  engine settings, but differs from `crossSessionInbound`'s explicit
  per-session forwarding — if `feedbackDrafts` turns out to need per-session
  override behavior (unclear from the one-line SDK doc comment), that
  forwarding would need to be added.
- **spinnerTipsOverride's `tipsFile`/`priority`/`cooldownSessions` — conservative vs. maximal.**
  Conservative (shipped): no new work, since Claudius's independent tips
  system has no "organization tips file" concept and no per-tip numeric
  priority (only array order). Maximal (not built): add a
  `spinnerTipsOverride`-shaped settings field Claudius reads server-side to
  seed additional entries into `DEFAULT_TIPS`, with `cooldownSessions`
  mapped onto the existing dismiss-weighting mechanism. Rejected because
  it would be new scope invented on top of an ambiguous, thin changelog
  entry ("organizations can rotate their own tips") that has no confirmed
  Claudius user demand — flagging here rather than building it speculatively.
- **Terminal-hyperlink hardening (network/automounter paths, invisible chars) has no Claudius equivalent to fix, but raises an adjacent question**: should Claudius's own `Markdown.tsx` ever refuse to render a `file://`/UNC-style link as clickable? Out of scope for this pass (the changelog entry is specifically about OSC-8 terminal escape sequences), but worth a dedicated look if this is a live concern for Claudius's link rendering.
- None of the `[A — already via SDK updater]` items above needed a
  Claudius-side call-site change (verified by grep for their related
  settings/behavior — see the classification's per-item notes); they're
  listed individually rather than elided as pure bug fixes because several
  reveal engine-default assumptions (auto-compact threshold, sandbox
  cleanup, plugin marketplace parsing) worth a human's awareness even
  without action.
