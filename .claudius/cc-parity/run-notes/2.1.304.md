## Summary

_(Draft. Finalized after implementation.)_ Claude Code 2.1.304 is a large release, but most of it is engine-internal, terminal UI, mods (the CLI's TUI extension system, which Claudius has no copy of), VSCode, cloud, Claude Tag or Code Review work. Two entries land on surfaces Claudius owns. (1) The compaction summary now carries the names of the tools called earlier. The engine writes them into the summary text as a `<tools-used-before-summary>` tag, and Claudius's own "show summary" view would show that tag raw. (2) The `CLAUDE_CODE_AUTO_COMPACT_WINDOW` fix makes `200k` / `1M` suffixes work and warns on ignored or out-of-range values. Claudius's own Settings editor for the same window silently dropped `200k`. Both are bucket B and extend existing screens. The cold-resume quota warning was not built, because the engine shows it only in its interactive terminal UI.

### New features

- `[A — already via SDK updater] Added /auto-mode-setup …` — an engine slash command. Claudius's picker merges SDK-only commands from `supportedCommands()` with their descriptions (`lib/shared/slash-commands.ts:434`, `components/chat/SlashCommandPicker.tsx:20`), so it shows up and is forwarded with no registry entry.
- `[A — already via SDK updater] Added /claude-api managed-agents-secure` — an argument of the engine's bundled `claude-api` skill, which Claudius forwards (`lib/shared/slash-commands.ts:259`, `handler: "sdk"`).
- `[B — reimplement in Claudius] Added the names of the tools called earlier to the compaction summary in the transcript view (Ctrl+O)`
  - **What the engine does.** It writes `<tools-used-before-summary>Bash, Edit, Read</tools-used-before-summary>` into the compact-summary text (the tag is always present, and empty when no tools ran). Only the TUI rewrites it to "Tools called before this summary: …".
  - **The Claudius copy.** Claudius has its own copy of this view, the `CompactBoundaryDivider` "show summary" block (`components/chat/SystemPill.tsx:312-359`). It renders `entry.compactSummary` verbatim, so after the bump it would show the raw tag.
  - **What we built.** We parse the tag at render time and show a "Tools called before this summary" line.
- `[skip — ambiguous, see Risks] Added a warning on Pro and Max plans when resuming an inactive conversation would use a noticeable share of your 5-hour usage limit …`
  - **The engine shows it only in the terminal.** The engine's dialog (`cold_resume_quota`, title "Resume this conversation?") is raised only from the interactive REPL's `SessionController`. It is never emitted over the SDK: `sdk.d.ts` has no such dialog kind, and nothing on the stream-json side calls it.
  - **Claudius can't compute the figure.** The "about P% of your 5-hour limit" number comes from server-side GrowthBook credit tables (`tengu_amber_tally`) that an SDK host can't read.
  - Building a banner with invented thresholds would be inventing the feature. See Risks.
- `[A — already via SDK updater] Added a transcript line when a plugin that runs first skips one of your mod's hooks`; `decider: "person"` in a mod's `tool.check`; `e.isReadOnly` on `tool.check` — mods are the engine's extension runtime. Claudius has no mod runtime or mod UI (grep for `tool.check|decider|isReadOnly|settings.read` over `app/ components/ lib/` is empty), and the SDK types define no mod surface.

### Fixes on surfaces Claudius reimplements (each checked)

- `[B — reimplement in Claudius] Fixed CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k silently setting a 100K window: … accepts k and M suffixes … warns when a value is out of range or ignored`
  - **The bug in Claudius's copy.** Claudius's own editor for this window is the `autoCompactWindow` field on `/settings`: `AutoCompactWindowCatalogField` in `app/settings/page.tsx` plus `lib/shared/auto-compact-window.ts`. Its top-level input was `type="number"`, so `200k` couldn't be typed. Its per-model parser returned "ignore" for `200k` and said nothing.
  - **What we built.** Both inputs now accept `k`/`M`, and each input shows an "ignored" or "out of range" warning.
- `[A — already via SDK updater] Fixed Write results and rejected edits showing a file outside the working directory as ../../…`
  - Claudius's tool-card header renders the raw absolute `file_path` (`components/chat/ToolCall.tsx:162,245-263` via `lib/client/ide.ts:88-100`).
  - `toWorkspaceRelative` (`lib/client/file-paths.ts:88-114`) returns null for anything outside the workspace or containing `..`.
  - Claudius never writes `../../` itself. The result text and rejected-edit message are engine strings shown verbatim.
- `[A — already via SDK updater] Fixed /effort status, /effort ultracode and the prompt's effort indicator showing a guessed effort level when CLAUDE_CODE_EFFORT_LEVEL is auto or unset`
  - Claudius never reads `CLAUDE_CODE_EFFORT_LEVEL` and adds no default of its own: `use-session.ts:1475-1486` seeds `effort: "auto"`, `appliedEffort: undefined`.
  - The displayed applied level comes from the engine's `getSettings().applied.effort` (`lib/server/session.ts:5862-5883`, `lib/shared/effort-flags.ts:96-103`), so the engine fix flows through. The `null` path already renders "auto".
- `[A — already via SDK updater] Improved /usage to say when a rate limit on usage data ends instead of "try again in a moment"`
  - Claudius never shows that text. On a usage-fetch failure it broadcasts a payload-less `plan_usage_unavailable` (`lib/server/session.ts:9300-9323`, `lib/shared/events.ts:1142-1160`).
  - It then shows the last-known bars with an "as of HH:MM" note (`components/overlays/CostOverlay.tsx:214-221`, `components/chat/PlanUsageCard.tsx:279-289`).
  - The SDK exposes no retry-after for the usage endpoint. See Risks.
- `[A — already via SDK updater] Fixed self-paced /loop wakeups scheduled at the 1-hour maximum firing just after the cache expired`
  - The engine owns the wakeup timer. Claudius only observes `ScheduleWakeup` tool calls (`lib/server/session.ts:5453-5506`) and keeps the process alive while a loop is armed (`lib/server/loop-keepalive.ts:7-42`).

- `[A — already via SDK updater] Fixed a skill's once hook also removing another skill's identical hook`, and `Changed skill hooks: … at most 1,024 hooks and 16,384 matcher characters per session` — Claudius has no hook registry. `lib/server/hooks.ts` only edits settings.json hook groups, and `lib/server/skills.ts` has no hook code.
