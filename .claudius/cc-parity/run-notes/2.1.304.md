## Summary

Claude Code 2.1.304 is a large release, but most of it is engine-internal, terminal UI, mods (the CLI's TUI extension system, which Claudius has no copy of), VSCode, cloud, Claude Tag or Code Review work. All of that reaches Claudius through the 0.3.304 SDK bump already on this branch, or doesn't apply to a browser app. Two entries land on surfaces Claudius owns, and both ship as bucket B, extending existing screens.

1. **Compaction summary.** The compaction summary now names the tools called earlier. The 2.1.304 engine writes them into the summary text as a `<tools-used-before-summary>` tag, which only the terminal rewrites for display. Claudius's own copy of that view, the compaction divider's "show summary" block, would have shown the raw tag. It now shows a "Tools called before this summary:" line with one chip per tool.
2. **`autoCompactWindow`.** The `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` fix (accept `k`/`M` suffixes, warn when a value is out of range or ignored) is mirrored in Claudius's own `autoCompactWindow` editor on /settings. That editor used to silently drop `200k`.

The cold-resume quota warning was **not** built. The engine raises it only from its interactive terminal UI, and the percentage depends on server-side credit tables an SDK host can't read. See Risks. **Headline review question:** is the "ignored / stays N" warning wording on the Settings field the right shape? It came out of an adversarial review round, described under Risks.

## Implemented (bucket B)

- `[extend: chat → compaction divider "show summary" block]` **Tools called before the summary** (CC 2.1.304 "Added the names of the tools called earlier to the compaction summary in the transcript view (Ctrl+O)").
  - `lib/shared/compact-summary-tools.ts` (new) splits the engine's `<tools-used-before-summary>` tag out of the summary text with a fixed regex literal. The names are de-duplicated, an empty tag is dropped, and older tag-free text passes through unchanged.
  - `components/chat/SystemPill.tsx` `CompactBoundaryDivider` renders "Tools called before this summary:" with one `<code>` chip per tool (Wrench icon, `compact-summary-tools`) at the top of the expanded summary (`compact-summary-body`), followed by the summary without the tag.
  - Parsing happens at render time, so the live path (`use-session.ts:3723-3746`) and the resumed/paged path (`use-session.ts:6884-6924`) are both covered by one change.
  - Rejected alternative: computing the names client-side from the messages above the boundary. A resumed session doesn't load those messages (the 2.1.301 path), and the engine already carries names forward across repeated compactions, so parsing the tag it sends is both smaller and correct.
- `[extend: /settings → Context & compaction → autoCompactWindow]` **`k`/`M` suffixes and "ignored" / "out of range" warnings** (CC 2.1.304 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` fix).
  - `lib/shared/auto-compact-window.ts`: `parseAutoCompactWindowInput` accepts `200k` / `1M` / `0.5m` (any case). Its `allowAuto: false` option is for the top-level key, which the SDK types as `number` only (`sdk.d.ts:79`). The new `autoCompactWindowInputWarning` returns `"ignored" | "out-of-range" | null`.
  - `app/settings/page.tsx`:
    - The top-level input changes from `type="number"` (which couldn't take `200k`) to text with a raw-text buffer.
    - Per-model rows move into `PerModelAutoCompactRow`, with their own warning.
    - A new `AutoCompactWindowWarning` says the value was ignored and names the value the form still holds ("the window stays 200,000"), and also flags that value if it is out of range.
    - A non-number already in settings.json is now shown with an "ignored" warning instead of an empty "(default)" box.
    - The field is keyed by scope/refetch (`activeKey`, the page's existing convention for `OtherEditor`), so typed text can't carry across scopes.
  - Rejected alternative: parsing the `CLAUDE_CODE_AUTO_COMPACT_WINDOW` env var in Claudius, e.g. validating it in the Environment editor. Claudius doesn't read that variable; the engine does, and the engine fix ships with the SDK bump. The surface Claudius owns is its settings editor for the same window.

## Risks / follow-ups

- **Compaction tools line, alternative shape.** A separate collapsible "Tools used" list, or a chip in the divider row itself, is visible without expanding. Not picked: CLI parity places it inside the Ctrl+O summary view, and the divider row is already dense (label, stats, the 2.1.301 transcript-path line).
- **Compaction tools line, MCP names** like `mcp__github__create_issue` are shown raw. Claudius has no shared MCP-name prettifier to reuse.
- **`autoCompactWindow`, alternative shape.** Keep `type="number"` and add a separate "accepts 200k" hint. Rejected: a number input can't hold `200k` at all, which is the bug being mirrored.
- **`autoCompactWindow`, adversarial review round.** One UX and one correctness skeptic per bucket-B item. Both compaction skeptics passed it. Both autocompact skeptics refuted the first version, and both findings were fixed:
  - (a) The "ignored, the saved value is unchanged" text was false when typing key by key, because each prefix that parses (e.g. `200` in `200g`) is committed to the draft. The warning now names the held value and flags it if out of range.
  - (b) Typed text and warnings could carry across a scope switch or refetch. The field is now keyed by `activeKey`, and the rows re-seed when their value changes from outside the input.
  - Still a design question for the reviewer: committing every parsable prefix is the field's pre-existing behaviour, kept for consistency with the rest of the catalog. A commit-on-blur shape would avoid transient values like `2` but would differ from every other catalog field.
- **`[skip — ambiguous]` Cold-resume quota warning.** Upstream: the 2.1.304 changelog entry, plus the bundled engine binary (`cold_resume_quota` dialog kind, `SessionController.maybePromptStaleResume`, the `tengu_amber_tally` GrowthBook config). The SDK `.d.ts` has no such dialog kind, and the stream-json path never raises it. Options for a follow-up:
  - (1) A qualitative banner above the composer on resume: a Pro/Max plan, idle longer than the prompt-cache TTL, and context ≥ ~100k tokens. Actions: "Resume" and "Start new conversation" (reusing /clear). This is the maximal shape. It would invent thresholds and wording, and couldn't state the "P% of your 5-hour limit" figure or the engine's look-up pointer.
  - (2) Wire `onUserDialog` + `supportedDialogKinds: ["cold_resume_quota"]` once a future SDK exposes the dialog on the headless path. Then the engine supplies the percentage and the pointer. **Re-check at each SDK bump.**
- **`/usage` rate-limit end time.** The SDK's usage response has no retry-after for the usage endpoint itself, so Claudius keeps its "as of HH:MM" stale note. If a later SDK adds the field, show "rate limited until …" in `plan-usage-stale-note`.
- **Pre-existing, not in scope.** When the engine sets `foreignArtifactContent`, it puts an `<artifact-content-authored-by-others/>` line *before* the "This session is being continued…" preamble. That defeats the `startsWith(COMPACT_SUMMARY_PREFIX)` checks in `lib/shared/user-prompt.ts:42` and `lib/client/sdk-message-filters.ts:145` on the live path when `isCompactSummary` isn't set. This is rare (Artifact-content sessions only) and worth a separate fix.
- **Claudius has no notes field on AskUserQuestion options.** The SDK supports `annotations[q].notes`, and `lib/shared/events.ts:672` only writes `preview`. This is a separate feature gap, not the 2.1.304 terminal-truncation fix.
