**[VSCode] entries — Claudius has a browser chat surface of its own, so each one was checked**
- `[B — reimplement in Claudius] [VSCode] Added a notice on the microphone button when voice dictation stops by itself, saying why and that the text so far is kept` — Claudius reimplements voice dictation (`lib/client/useVoice.ts`, `lib/server/voice-stream.ts`, the composer mic in `components/chat/PromptInput.tsx:2144`). When the upstream closes without the user pressing stop, the `close` handler (`useVoice.ts`) just calls `cleanup()`: the red mic quietly goes back to grey with no explanation, which is the same bug. Fix: track user-initiated stops, show a visible notice anchored to the mic that says why it stopped and that the text is kept, and clear it on the next start.
- `[B — reimplement in Claudius] [VSCode] Fixed dictation failing behind a TLS-inspecting proxy when NODE_EXTRA_CA_CERTS is set only in ~/.claude/settings.json` — Claudius opens its own upstream WebSocket to `api.anthropic.com` from the Next.js Node process (`lib/server/voice-stream.ts` `openUpstream`). Node reads `NODE_EXTRA_CA_CERTS` only from the real process environment at startup, and nothing in Claudius applies a settings `env` block to its own process (`rg 'NODE_EXTRA_CA_CERTS|\bca:' lib/server` finds nothing). So a CA set only in `~/.claude/settings.json` never reaches the dictation socket. Same bug. Fix: read the CA file named in user settings `env` and pass it, together with the default roots, as `ca` on the socket.
- `[skip — ambiguous, see Risks] [VSCode] …it now also follows CLAUDE_CODE_CERT_STORE / Changed voice dictation and the extension's requests to filter their trusted certificates as the CLI does` — the docs don't say what values `CLAUDE_CODE_CERT_STORE` takes or what "filter as the CLI does" means, so building either would be guesswork.
- `[A — already via SDK updater] [VSCode] Fixed a long prompt expanded with Show more covering the whole chat panel (cap at 40%, scroll)` — Claudius's pinned (sticky) prompt is already capped and scrolls: `max-h-[20vh] overflow-y-auto` (`components/chat/MessageList.tsx:625`). It has no "Show more" expander that could cover the panel, so Claudius doesn't have this bug.
- `[skip — ambiguous, see Risks] [VSCode] Fixed part of a list item / table cell with LaTeX math pasting as a new list or table in rich text editors` — Claudius renders math with the same stack, rehype-katex `output: "htmlAndMathml"` in Chromium (`components/chat/Markdown.tsx:437`), and has no copy handler of its own.
