# Claude Code parity 2.1.306 → 2.1.307

## Summary

Claude Code 2.1.307 is mostly engine, cloud, runner and VSCode fixes. It adds two features: a `/claude-api api-version` bundled skill and a `claude_code.safety_event` OTel event. Both are engine-side and reach Claudius through the SDK. The SDK migration already on this branch (0.3.306 → 0.3.307) shipped no product code, and none of its items matches a CC changelog entry, so nothing here is tagged "already shipped via SDK migration". Two entries are bucket B because Claudius has its own copy of the same code: the voice-dictation client and proxy (`lib/client/useVoice.ts`, `lib/server/voice-stream.ts`). (1) **Dictation self-stop notice.** When dictation ends without the user pressing stop (upstream close, the proxy's idle reaper, or a 410 on a chunk upload), the composer mic turns amber and the composer footer shows a `role="status"` line. The line says why dictation stopped and that the text so far is kept. A stop the user pressed shows nothing. (2) **Settings-only `NODE_EXTRA_CA_CERTS` for dictation.** The dictation WebSocket now trusts a CA bundle named only in the `~/.claude/settings.json` `env` block, so dictation works behind TLS-inspecting proxies. The headline review risk is the notice's shape and copy. Claudius has no client-side 15 s / 2 min caps, so the notice explains whatever stop actually happened instead of claiming those limits. Adding the caps is recorded below as the maximal alternative.

## Implemented (bucket B)

- `[extend: chat composer]` **Notice when voice dictation stops by itself.** `useVoice` now records whether the user pressed stop. Every end-of-session path goes through `endOnItsOwn()`: the SSE `close` frame, a chunk-upload `410` for the *current* session, and a new `close` frame (`selfStopCloseFrame()`) that the proxy's idle reaper sends with `reason: "idle-timeout"`. When the user didn't press stop, `endOnItsOwn()` sets a `notice`; `describeVoiceSelfStop()` turns the code and reason into one sentence that always ends "The text so far is kept." The composer footer shows it as a `role="status"` line in the same priority chain as the existing send-failed notice. It ranks after the send-failed and the short-lived invisible-Unicode notices, so a paste warning is never masked, and it uses the same idiom: amber text, a `MicOff` glyph and an inline `· dismiss` like the keyword hints' `· ignore`. The mic turns amber, carries the same text in its `title`, and points `aria-describedby` at the line. The notice clears on the next dictation start, on dismiss, and on submit. Two latent races on this path are also fixed. A close that landed while `getUserMedia` / `addModule` was pending used to attach a live mic after teardown. A straggler 410 from a previous session could tear down a new one. Files: `lib/shared/voice-stop-notice.ts` (new), `lib/client/useVoice.ts`, `components/chat/PromptInput.tsx`, `lib/server/voice-stream.ts`. Rejected alternative: a global toast, i.e. the `showToast` used by `/clear`. It isn't anchored to the mic, it disappears before the user looks back at the draft, and toasts in Claudius are for confirming the user's own actions, not for explaining something that happened behind their back.
- `[extend: chat composer — dictation proxy]` **Dictation trusts a `NODE_EXTRA_CA_CERTS` set only in `~/.claude/settings.json`.** New `resolveExtraCaCerts()` returns `undefined` when the real process env already sets it, because Node loaded it at startup and passing `ca` would *replace* the default store. Otherwise it reads `env.NODE_EXTRA_CA_CERTS` from **user-scope** settings only, so a checked-in project file can't add trust anchors for a socket that carries the OAuth token. It returns the bundled roots plus that PEM, which `openUpstream` passes as `ca` to the `ws` socket. A missing or unreadable file, non-PEM content, or malformed settings falls back to default trust, so behaviour is unchanged. Under the Bun runtime the native WebSocket has no `ca` option, so the proxy logs a warning instead. Files: `lib/server/extra-ca-certs.ts` (new), `lib/server/voice-stream.ts`. Rejected alternative: copying every settings `env` key into `process.env` at boot. That has a wide blast radius (every child process and fetch inherits project-unvetted env), and Node ignores a late `NODE_EXTRA_CA_CERTS` anyway, so it wouldn't fix this.

## Risks / follow-ups

- **Voice notice — conservative vs. maximal shape.** Conservative (shipped): explain whatever self-stop actually happens in Claudius (upstream close with its code/reason, the proxy's 30 s idle reaper, a 410). Maximal (not shipped): also add VSCode's client-side caps, stopping after 15 s without recognized speech or after 2 minutes, with matching copy. The changelog entry adds the *notice*; the caps are described as existing VSCode behaviour, and I couldn't confirm whether the shared voice backend already enforces them: the engine ships as a native binary in the SDK package, and `browser-sdk.js` has no voice code. Adding caps would change how long Claudius dictation runs, so it was left for the reviewer to decide.
- **Voice notice — alternative shape considered:** a global toast (see Implemented) or a popover bubble on the mic itself. The popover was rejected because the composer has no popover idiom for status, and the footer status slot is where Claudius already explains why a draft is in a given state (send-failed restore, invisible-Unicode strip).
- **Voice notice copy:** an upstream close reason is echoed verbatim (control characters stripped, capped at 120 chars, rendered as React text). If the backend's reasons turn out to be internal codes, map them to friendlier copy in `describeVoiceSelfStop`.
- **Extra CA — alternative considered:** applying the whole user-settings `env` block to Claudius's own process (rejected; see Implemented). Also considered and rejected: honouring project/local scope. A repo-controlled file must not add trust anchors for the OAuth-bearing socket.
- **Extra CA — Bun runtime:** the Bun branch of `openUpstream` can't take `ca`, so it only warns. `next dev` and packaged builds run on Node and are covered.
- **`[skip — ambiguous]` `CLAUDE_CODE_CERT_STORE` / "filter trusted certificates as the CLI does"** (VSCode dictation, extension requests, runner cert file): the changelog doesn't say what values `CLAUDE_CODE_CERT_STORE` takes or what the filter is, so building either would be guesswork. Follow up when the CC docs (`https://docs.anthropic.com/en/docs/claude-code/`, network-config page) document the variable.
- **`[skip — ambiguous]` LaTeX copy into rich-text editors:** Claudius renders math with the same stack (rehype-katex `htmlAndMathml` in Chromium, `components/chat/Markdown.tsx:437`). It has no custom copy handler, so it may have the same clipboard behaviour. Not probed this run. Follow-up: a Playwright probe that selects part of an `<li>` containing inline math and inspects `text/html` on the clipboard for a wrapping `<li>`/`<ul>`. If it's there, add an `onCopy` handler that strips block ancestors from partial selections.
- **`[skip — ambiguous]` GitHub MCP write-tool form closing without creating anything:** Claudius renders MCP elicitation forms itself (`lib/shared/elicitation.ts`). The entry is specific to the desktop Code tab and gives no root cause. Worth a manual check with a directly configured GitHub MCP server.

The voice skeptic found that the persistent notice masked the 4 s invisible-Unicode paste warning (fixed by re-ranking it), that the idle-timeout frame wasn't tied to the renderer's parser (fixed with `selfStopCloseFrame` and a contract test), and that the spec header repeated VSCode's 15 s / 2 min wording (fixed). The CA skeptic confirmed the replace-not-augment `ca` semantics, the real-env short-circuit and the user-scope restriction. It flagged the Bun branch, which now logs a warning.
