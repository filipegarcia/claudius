# Claude Code parity 2.1.310 → 2.1.314

## Summary

The range is 2.1.310 → 2.1.314. 2.1.311 and 2.1.312 were classified and shipped in their own runs (#325, #328); their classification is carried over below. Most of Claude Code 2.1.314 is engine, terminal, IDE, cloud, gateway and Slack work, and it reaches Claudius through the SDK 0.3.314 bump on this branch or has no Claudius surface. The one new setting, `permissions.blockWritesOutsideWorkingDirectories`, was already shipped by the SDK updater (`88705b11`).

Seven 2.1.314 fixes describe bugs that also lived in Claudius's own code. All are mirrored by extending existing screens; there are no new routes.

**Visible changes:**
1. **Refused permission-mode switch.** The composer's mode pill now shows the mode actually in use, and a notice says the switch was refused. Before, it stayed on the refused pick.
2. **Delete and rename failures on the Sessions pages.** A failed delete or rename now shows the reason inline instead of failing silently.
3. **Paste on the AskUserQuestion card.** A paste while an option has focus now lands in "Other". On the reopened (modal) question, a dropped file lands in Other instead of navigating the window away.

**Invisible fixes:**
4. **Deleted sessions stay deleted.** They no longer come back as title-only stubs.
5. **Git refreshes leave the index alone.** The git panel's polling and the diff overlay's refreshes no longer take `.git/index.lock`.
6. **Dotted gateway model ids are priced right.** `claude-opus-5.5` is priced as Opus 5.5, not Opus 5.
7. **Letter shortcuts on non-Latin layouts.** Ctrl+C, Cmd/Ctrl+F/G/S and the others now work under Russian, Greek and Hebrew layouts.

An adversarial review, with one skeptic per change, found real bugs in four of the five reviews; all are fixed in `4d333692`, `cf95a29a`, `8d8a214c` and `ebf4a5f1`. The worst were: delete swallowing a stale-dir "not found" and wiping the title, saved tabs resurrecting a deleted session, AltGr characters triggering Ctrl shortcuts, and two quick refused mode switches landing on a refused mode.

**Headline review risks:**
- **Delete now refuses (409) to delete a busy chat**, where before it would have killed it.
- **The mode-refusal rollback trusts the SDK's error text** to tell an engine refusal from a closed transport.
- **"Session group changes fail silently"** is mirrored onto delete/rename, because Claudius has no session groups.

## Risks / follow-ups

- **Mode refusal: refusal vs transport.** The rollback relies on the SDK's error text to tell an engine refusal from "can't reach the engine" (`isTransportClosedError`: "Query closed before response", "Transport is not ready", …). A new SDK transport message would read as a refusal. The worst case is a wrong "refused" notice, and the next turn's `init` puts the pill right.
- **Mode refusal: alternative shape.** The maximal shape also syncs the server's mode from the engine's `system:init` / `status` `permissionMode`, which covers the Remote Control entry's "wrong mode until you typed". It isn't done because an `init` from a turn already in flight can overwrite a switch the user just made. Today the only drift Claudius can cause, a refused switch, is fixed. Engine-initiated drift still corrects at the next turn's `init` on the client (`use-session.ts:4202`).
- **Mode refusal: rejected alternative.** A new SSE event so every tab shows the notice. Every tab's pill already reverts; only the asking tab is told why.
- **Session delete: behaviour change.** Deleting a chat that's mid-turn or waiting on a prompt now returns 409 ("still working … then delete again"), shown inline. Before, it would have killed the live session; move-sessions already follows the same rule.
- **Session delete: rejected alternative.** Filtering leftover index rows out of `/api/sessions/all`. It would hide legitimately renamed-before-first-message sessions (2.1.309).
- **Session delete: interpretation of the groups entry.** "Session group changes that cannot be saved … failing silently" is mirrored on delete/rename because Claudius has no session groups. The conservative reading would skip it as VS Code only. The maximal reading would add session groups, which the changelog doesn't support.
- **Question paste/drop.** Image pastes and drops on the card are ignored; there is no image slot in an answer. On the inline card, files still go to the composer.
  - Rejected alternative: routing inline-card drops into Other as well. That needs stopping PromptInput's native chat-area drop listener, which runs before React's handler. Deferred as the maximal shape.
- **Git.** With optional locks off, `git status` never refreshes the stat cache. On a very large repo with many stat-dirty files, the 4 s poll re-hashes them each time; VS Code makes the same trade.
  - Rejected alternative: retrying on `index.lock` errors. The failing command is the agent's, not Claudius's, so a retry on our side doesn't help it.
- **Pricing.** The bundled LiteLLM snapshot still has no `claude-opus-4-8` key, so dashed *and* dotted Opus 4.8 fall back to the first Opus entry in the LiteLLM path when the network refresh hasn't run. That predates this run and isn't dot-specific. OpenRouter-style `claude-3.7-sonnet` (version before family) is left alone; it resolves to Sonnet pricing, which is right for those models.
  - Rejected alternative: a blanket `.` → `-` rewrite. It would corrupt `claude-2.1`, `claude-instant-1.2` and the `us.anthropic.` prefixes.
- **Shortcuts.** Claudius's dictation has no keyboard shortcut, so the mirrored fix covers the same bug class on its other letter shortcuts.
  - Rejected alternative: adding a Ctrl+D dictation shortcut. That is a new feature, not this fix.
- **Skipped, see classification.** "Blocked calls reading as if they ran in a collapsed tool group": Claudius has no collapsed group, and blocked calls render as red errors. The wider shape would dim deny-rule / hook / classifier blocks as "Not run". It isn't done because the 2.1.296 run deliberately dims only `automode-unavailable`, matching the CLI.
- **Environment.** `AGENTS.md` is rewritten by `next dev` on each run (a heading-level change). It is committed so the tree stays clean, as its own header suggests. The full e2e run regenerates unrelated screenshots under `docs/` and `site/`; those are reverted, not committed.
- **Pre-existing e2e flake.** In `tool-call-answer-pill.spec.ts`, a click on `/dev/tool-call-preview` could land before hydration and be lost. It is hardened as described under Tests. Other specs that click SSR'd dev-preview pages straight after `toBeVisible()` may race the same way under full-suite load; none failed in this run.
