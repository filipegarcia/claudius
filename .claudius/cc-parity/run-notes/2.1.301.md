## Summary

Claude Code 2.1.301 is mostly engine, terminal, mod-runtime and hosted-runner work: a retry-watchdog cap, OTel `tool_decision` fields, vim `%`, mod `Input.rows`, model-switch summarization, and a long tail of CLI fixes. These are A or C. Claudius reimplements **eight items** (bucket B). All of them extend existing screens; there are no new routes.

**Visible changes (each with an in-context screenshot):**
- **LaTeX math in Claude's responses** (from the VS Code entry). `$$` / `\[…\]` blocks and `$…$` / `\(…\)` inline math are typeset with KaTeX in assistant text, subagent output, plans and the transcript viewer. Prices, shell variables, code and the user's own prompts stay literal.
- **"Get more usage"** for Pro/Max on the usage-limit panel and the rejected rate-limit pill, beside the existing upgrade links.
- **Permission prompt says when a hook asked**, showing the hook's reason. Partial mirror: the SDK doesn't forward the plugin/skill name yet.
- **Binary files** (.xlsm/.parquet/.epub/.heic…) show a placeholder in the Files page and the /git editor instead of garbled text.
- **A search that can't read its folder says "Search failed"** instead of "No files match." This covers Files search, Find in folder and the @-mention picker.
- **Resumed session's compaction row** names the transcript file that holds the earlier messages.
- **Crash-loop guard:** a conversation whose load never finished (it crashed or froze the page) isn't reopened on the next reload. The tab opens a fresh session with an "Open anyway" notice, and the error page gains "Open a new session".

**Render-only fix:** `Markdown` and subagent trail rows are memoized, so a streaming delta no longer re-parses every unchanged block. A tool_result no longer rebuilds untouched trail rows.

**Provenance of this PR.** An earlier 2.1.301 run built this work on `cc-parity/2.1.301-detached-from-sdk-0.3.301`. That run ended before its full e2e pass, and the orchestrator committed its leftover PNGs as `wip`.
- This run cherry-picked those 13 commits onto `sdk-update/0.3.301` (above `adce2aa9`). There were no conflicts, `bun.lock` stayed on SDK 0.3.301, and the three math packages are locked.
- A fresh read-only audit (6 agents) re-derived the classification and agreed with it.
- A skeptic pass (7 agents, one per item) then found real bugs, fixed in three `(CC 2.1.301 review)` commits:
  - the compaction-row path was wiped by the stream route's trailing `ready`, so it never showed outside the mocks;
  - the crash-loop marker was never cleared after the skipped session opened fine;
  - known-binary files over 2 MB skipped the placeholder;
  - a hook ask with no reason showed nothing;
  - five math pre-pass edge cases.

**Headline review questions:**
1. Is the crash-loop guard's heuristic right? A load counts as finished when the resumed session's replay renders. A deleted session id, or a reload mid-load in the same tab, also trips the notice.
2. Is the math delimiter pre-pass conservative enough? It uses a Pandoc-style `$` rule. It never promotes `${…}`/`$(…)`. It needs a real TeX hint (a backslash command, `^`, `_`, braces, `=`, or an operator next to a letter) inside `\[ \]`/`\( \)`, so `\[1\]` citations stay literal.
3. The "Get more usage" URL (`claude.ai/settings/usage`) is inferred from the CLI's limit message, because the VS Code extension's copy isn't in the engine binary.

### Bucket B — reimplemented in Claudius

- `[B — reimplement in Claudius] [VSCode] Added LaTeX math rendering in Claude's responses, including $$ and multi-line \[ … \] blocks and inline $…$ and \(…\) math`
  - **Claudius analog.** Claudius is a GUI chat panel like the VS Code one. `components/chat/Markdown.tsx` runs `react-markdown` + `remark-gfm` only, so TeX shows as raw source.
  - **Plan.** Add `remark-math` + `rehype-katex` (KaTeX) behind an opt-in `math` prop on `Markdown`. Turn it on for Claude's output (assistant text, subagent output, plan previews, transcript viewer assistant rows); leave it off for user prompts, since the entry says "Claude's responses".
  - **Normalizer.** A pure normalizer rewrites `\[…\]`, `\(…\)` and Pandoc-rule `$…$` to the `$$` forms remark-math parses with `singleDollarTextMath: false`, skipping code fences and inline code, so `$5 and $10` stays prose.
- `[B — reimplement in Claudius] Improved rendering performance while a long-running subagent works: its progress trail now updates incrementally instead of being reprocessed in full on every render`
  - **Where the bug is.** Each streaming delta builds a new `subagentMessages` map. That re-renders every `AssistantMessage` → `TaskBlock` → `SubMessage`, and every `<Markdown>` re-parses because nothing is memoized (`MessageList.tsx:644`, `TaskBlock.tsx:195-224`, `Markdown.tsx`).
  - **Fix.** `memo` the `Markdown` component (its props are a string plus booleans) and `SubMessage`, so only the changed message re-parses. This also matters more once KaTeX makes each parse more expensive.
- `[B — reimplement in Claudius] [VSCode] Added a "Get more usage" link to the usage-limit banner for Pro and Max plans`
  - **Where the gap is.** `components/chat/RateLimitHitPanel.tsx` and the `rejected` branch of `RateLimitPill` (`SystemPill.tsx`) give Pro/Max only "Upgrade your plan / Upgrade to Team plan". A Max user is told to upgrade to the plan they already have.
  - **CLI reference.** The CLI's own limit message offers "/upgrade or /usage-credits" with `claude.ai/settings/usage?from=cc_cli_limit_message`.
  - **Plan.** Add a "Get more usage" link to `claude.ai/settings/usage` for `subscriptionType` pro/max on both hard-limit surfaces. Keep the existing upgrade links.
- `[B — reimplement in Claudius] [VSCode] Fixed a conversation that crashes or freezes the panel being reopened on every reload`
  - **Where the bug is.** On boot, `lib/client/use-session.ts` resumes `?session=` or the saved active tab unconditionally. A render crash goes to `app/global-error.tsx`, whose only action is `window.location.reload()`, so the crash loops.
  - **Plan.** Add a per-session boot marker in tab-scoped `sessionStorage`, cleared once the session's replay arrives. If the marker is still set at the next boot, open a fresh session instead and show a notice with "Open anyway". Also add an "Open a new session" action to `global-error.tsx`.
- `[B — reimplement in Claudius] Fixed the permission prompt for a plugin or skill hook's ask decision not showing which plugin or skill the hook comes from`
  - **This is a partial mirror.** Claudius drops `decisionReason` entirely (`session.ts` `permission_request` builder → `PermissionPrompt.tsx`), so a hook's ask shows nothing about the hook.
  - **What the SDK provides.** `sdk.mjs` 0.3.301 forwards `decisionReason` and `decisionReasonType` (`'hook'`). It does not forward the CLI's `decision_reason_hook_source` (`plugin:<name>`/`skill:<name>`).
  - **Plan.** Forward the reason and type, and render "Asked by a hook: <reason>" (ANSI-stripped) on the prompt. The plugin/skill name itself is blocked on the SDK; see Risks.
- `[B — reimplement in Claudius] Fixed Grep and Glob reporting no matches when the search program failed unexpectedly before returning any results; they now return an error saying the search failed`
  - **Claudius analog.** Workspace file search and content search walk folders in Node (`app/api/workspaces/[id]/files/route.ts` `searchFiles` / `searchFileContents`), and so does the @-mention picker (`lib/server/fs-list.ts`).
  - **Where the bug is.** All of them `catch { continue; }` on `readdir`. When the starting folder itself can't be read, the response is a 200 with `matches: []` / `entries: []`, which reads as "no matches".
  - **Plan.** Throw when the root folder is unreadable and map that to 403/500 with "search failed", the way `listDir` already does.
- `[B — reimplement in Claudius] Fixed the Read tool reading binary files such as .xlsm, .parquet, .epub and .heic as text`
  - **Claudius analog.** The workspace file viewer and the git `FileEditor`.
  - **Where the bug is.** `lib/shared/text-encoding.ts` detects binary by sniffing for a NUL byte, but the files route still sends `decodePreview(bytes, "binary")` (a lossy UTF-8 decode), so both viewers show garbled read-only text.
  - **Plan.** The route sends no content plus `binary: true`. Both viewers show a "Binary file — not shown" placeholder. A small binary-extension list catches tiny files that have no NUL byte.
- `[B — reimplement in Claudius] Fixed the compaction row in a resumed session offering ctrl+o for history that is not loaded; it now says where the earlier messages are saved, and also shows in fullscreen`
  - **What already works.** `CompactBoundaryDivider` (`SystemPill.tsx`) never offers to expand history that isn't loaded; its "show summary" toggle only appears when a summary was loaded.
  - **The gap.** In a resumed session the pre-compaction messages are not replayed (the `getSessionMessages` chain stops at the boundary), and the row doesn't say where they are.
  - **Plan.** On replayed boundaries, name the transcript JSONL path the server already resolves (`lib/server/session-resume.ts`). The fullscreen half doesn't apply: Claudius has no fullscreen split.

## Risks / follow-ups

- **LaTeX math.**
  - *Rejected shape:* a Settings toggle (see Implemented).
  - *Conservative vs maximal:* the conservative shape uses a Pandoc-style `$` rule, a TeX-character gate on `\[ \]`/`\(\)`, and leaves code untouched. The maximal shape is remark-math's default `singleDollarTextMath: true`, which would typeset `$5 and $10`.
  - *Known gaps after review:*
    - `$HOME/${NAME}` is still promoted, because the first `$` is a plain variable that passes the Pandoc rule.
    - TeX that starts with a brace or paren (`$(a+b)^2$`) now stays literal and needs `\(…\)`.
    - Indented code inside a blockquote, or after a list closed without a blank line, isn't detected.
    - A streaming unclosed display `$$` shows in the muted error colour until it closes.
  - *Load cost:* KaTeX CSS is imported at the root layout, about 24 KB on every route.
- **Subagent trail memo.**
  - *Rejected shape:* paragraph chunking or rAF-batched deltas.
  - *Remaining cost:*
    - `AssistantMessage` still re-renders on each delta, because its props are fresh object literals. Only the Markdown parse and unchanged trail rows are skipped.
    - The main-transcript tool_result `setMessages` still rebuilds every message. That is reconciliation only; Markdown stays memoized.
- **Get more usage.**
  - *Rejected shape:* also adding it to the approaching-limit pill.
