## Summary

Claude Code 2.1.326 is a very large release: about 330 entries. Most are permission/sandbox hardening, terminal-renderer and dialog polish, sign-in, MCP, Remote Control/cloud and VS Code work. All of it reaches Claudius through the bundled engine (SDK 0.3.326 already lands on this branch) or has no browser equivalent. A read-only audit of every entry on a surface Claudius draws itself found 13 places where Claudius has its own copy of the bug or gap, and this run fixes all 13, each on the existing screen. In the transcript: Windows paths keep the backslash before `.claude`/`_build`; your own prompts keep the asterisks in `2*3*4` and `src/**/*.ts`; the restore-files dialog says "Code changes unknown" instead of offering a restore that does nothing, and Esc closes it; a usage-limit message drops its upgrade hint once the limit has reset; a hook that stops Claude is amber and a failed hook shows its reason; a stopped or failed subagent's last tool call stops "running". In slash commands: `/clear --help` and friends show usage instead of running, `/help <command>` opens on that command, `/goal clear` clears the goal, and `/copy` stops claiming copies that didn't happen. On other pages, `/permissions` and `/add-dir` saves that can't be written name the file instead of looking saved, `/memory` warns about read-only files and keeps a failed save's draft, and the Sessions search (what `/resume` opens) looks through older pages before saying "No sessions match". In the composer, ↑ after Esc Esc brings back pasted text and images intact. Ten more confirmed Claudius gaps are recorded as `[skip — ambiguous]` with evidence, because each needs a reviewer call: a new dependency, a new theme mode, guessing at code blocks in prompts, or SDK signals Claudius doesn't have. Headline review question: is "Interrupted · agent stopped" (rather than "Not run") on a stopped subagent's unfinished tool row the right wording? Also, the user-prompt asterisk heuristic deliberately keeps letter-only `a*b*c` as emphasis; is that the right line?

## Risks / follow-ups

Review calls on what shipped:
- Stopped-agent rows: "Interrupted · agent stopped/failed" is a new amber state, chosen over the existing "Not run" because a stopped Bash call may already have run. Completed agents are deliberately left alone: a completed agent with an unanswered inner call is rare, and claiming "interrupted" there would over-assert.
- User-prompt asterisks: the rule only escapes runs between non-space characters next to `/`, a digit pair, or `.`+alphanumeric (globs, `2*3*4`, `*.ts`). Letter-only `a*b*c` still italicises, as CommonMark says. If reviewers want prompts closer to the CLI's raw text, the alternative is plain-text prompts (rejected above).
- Windows paths: paths that contain spaces (`C:\Program Files\.x`) and the leading `\\` of a UNC path aren't handled; both are documented in `lib/shared/lone-backslash.ts`.
- `/memory` writable check is `fs.access(W_OK)`, which can be wrong for ACLs or network mounts. That's why it's a warning and not a disabled Save.
- Sessions search auto-loads up to 1000 sessions per query (5 requests of 200) before offering "Search older". On a very large history that is still a client-side search; a server-side title search is the follow-up if it's slow.
- Hook reason preview: three lines when collapsed. A noisy hook still adds three lines per failure.
- Rate-limit panel: after a reset only the CTA rows go; the panel keeps its red "You've hit your 5-hour limit" header, as history. Toning it down is an optional follow-up.
- `/permissions` tool-prompt half: the "at a main-conversation tool prompt" part of that entry is engine-side. Claudius passes always-allow choices to the SDK as `updatedPermissions` and never writes them itself, so the engine's warning applies.

Ambiguous entries (`[skip — ambiguous]` above), each confirmed present in Claudius:
- Pasted code/diff in prompts: fixing it means guessing which free text is code (fencing indented or `+`/`-` runs). A wrong guess would break ordinary bulleted prompts.
- CJK bold with punctuation: needs `remark-cjk-friendly`, a new dependency.
- Empty-prompt failure hint: Claudius has no "last turn failed" state; `sendFailed` only means an undelivered POST.
- `/status` disabled-features row / "Unknown command" reasons: Claudius gets no provider or env-gate data from the SDK.
- Auto theme default: Claudius has no system theme mode; adding one is a feature, not a default flip.
- Recap after usage-credit replies: `sdk.d.ts` doesn't pin down which field means "billed to credits".
- Malformed `plugin.json` note: the engine's plugin.json verdicts aren't exposed; Claudius only reads marketplace entries.
- `/usage` bar order: Claudius's plan bars live in `/cost`, which keeps cost first, as upstream does.
- Subagent plan card: `PendingPlan` has no `agentId` (open since the 2.1.325 notes).
- Tool rows waiting on permission show the running timer: needs pending-permission ids threaded through `MessageList` → `AssistantMessage` → `ToolCall`. It's a good next-run candidate.

Follow-ups outside this changelog:
- Claudius's own `/mcp` and `/settings` pages show a bare `HTTP 500` for a broken `.mcp.json` or settings file (`lib/server/mcp.ts:101`), with no line/column. That is the same gap the engine fixed for itself.
- The 6 existing lint warnings (for example `react-hooks/set-state-in-effect` in `lib/client/use-session.ts`) are untouched.

Harness and environment notes:
- `bun run test:e2e` sometimes fails before any test runs. `next dev` 16.4.3 prints a "known security vulnerability / upgrade" notice and exits with code 1 the first time, and Playwright's `webServer` reports "was not able to start". That happened twice this run; re-running the same command started normally. The notice is the dev server's own output; nothing in this run changed or upgraded Next. Upgrading Next is a separate decision for a maintainer. The harness could pre-warm or retry the web server once.
- Shared `node_modules` incident: worktree agents' pre-commit hook (`scripts/native-abi.mjs ensure node`) ran through the symlinked `node_modules` and force-installed `better-sqlite3` 13.2.0 over the lockfile's 12.11.1. The node-gyp rebuild then failed: Python 3.14 has no `distutils`. It was restored with `bun install --frozen-lockfile`, and 12.11.1 loads again. Running `ensure` from a worktree whose `node_modules` is a symlink rewrites the main checkout's native modules, which is worth guarding in the hook or the harness.
