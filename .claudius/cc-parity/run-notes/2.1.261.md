## Summary

2.1.261 is a small point release. Most of its substantive entries are
engine-side (auto mode classifier heuristics, `/model` picker friendly
names, the `rm -rf` safety prompt, Vertex startup, `/context` token
counting) and already arrive verbatim through the SDK updater — several
of the CLI-config ones (`bashOutputMaxChars`/`taskOutputMaxChars`,
`keybindingFlavor` deprecation) were in fact shipped moments ago on
this same branch by the combined SDK 0.3.261 migration (see
`.claudius/sdk-updater/run-notes/0.3.261.md`), so this pass explicitly
does not redo that work. The rest is VS Code-extension-only or
CLI/terminal-only chrome with no browser-app equivalent. The one real
bucket-B item is `/skill-doctor` — Claudius already renders a
per-session context-usage breakdown (`/context`, `ContextOverlay.tsx`)
built directly on the SDK's `getContextUsage()` response, which already
carried a per-skill token-cost field (`skills.skillFrontmatter`) the
overlay simply wasn't displaying yet. This release adds that "Skills"
section (sorted priciest-first) and a `/skill-doctor` slash command that
opens the same overlay. The headline risk to flag for review: Claudius
ships only the "cost" half of `/skill-doctor`, not the "unused" half —
the SDK's context-usage response has no per-skill invocation flag, and
the `Skill` tool's input isn't a typed, documented shape in the bundled
`.d.ts` files, so pattern-matching the transcript to guess "was this
skill invoked" risked shipping a wrong, misleading "unused" badge (worse
than omitting it). See Risks/follow-ups for the full reasoning and the
deferred maximal shape.

## Risks / follow-ups

- **`/skill-doctor`'s "unused" half was deferred, not implemented.** Claude Code's upstream feature has two halves: "what a skill costs" and "which skills go unused." Claudius ships only the first. The SDK's `SDKControlGetContextUsageResponse.skills` field (verified in `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`) carries `skillFrontmatter: {name, source, tokens}[]` — cost data, no invocation/usage flag. Detecting "used this session" would require scanning the session transcript for `Skill`-tool invocations, but the `Skill` tool's input shape isn't declared anywhere in the SDK's bundled `.d.ts` files (confirmed: no `SkillToolInput`/equivalent type in `sdk-tools.d.ts`, and no existing Claudius code special-cases a `"Skill"`-named tool call). A docs lookup (`code.claude.com/docs/en/skills`, `code.claude.com/docs/en/commands`) didn't cover the mechanism either — the commands page describes `/doctor` finding "unused skills, MCP servers, and plugins versus their context cost" but not how. Guessing the tool-input field to pattern-match the transcript risked a wrong "unused" badge, which is actively harmful here (it would tell a user to prune a skill that was, in fact, in use) — worse than not shipping the signal at all. Conservative shape shipped: cost-only, sorted so the most prunable candidates (high cost) surface first even without a usage flag. Maximal shape (rejected for now): full unused+cost parity, once the invocation-tracking mechanism can be confirmed (e.g. by instrumenting a real session with a skill call and inspecting the actual `tool_use` payload, or a future SDK release typing it). Worth a dedicated follow-up pass rather than guessing here.
- **`[extend: /context overlay]` vs. a new `/skill-doctor`-only surface** — see the rejected-alternative note under Implemented above; recorded here too since it's the main design call a reviewer should sanity-check.
- **"Organization policy" `/status`/`claude doctor` line and the two managed-settings/gateway entries** were classified not-applicable rather than ambiguous — Claudius has no managed-settings/enterprise-policy distribution mechanism at all (confirmed via `lib/server/claude-code-changelog.ts`'s standing note on `forceLoginOrgUUID` and related enterprise pins never being reimplemented), so there's no existing surface to extend and no reasonable conservative default to build. Flagging in case a future release adds an actual per-user equivalent worth revisiting.
- None identified beyond the above.
