## Summary

Between 2.1.234 and 2.1.237 upstream shipped one genuinely new setting
(`spellcheck` for the prompt input, 2.1.235), a built-in "Concise" output
style (2.1.237 — Claudius already exposes this, see below), an
`ANTHROPIC_DEFAULT_MODEL` env var and several sandbox/auto-mode/SendMessage
engine refinements (2.1.236, all SDK-internal), and a long tail of
terminal-rendering and VSCode-extension bug fixes that don't translate to a
browser app. Exactly one bucket-B item ships this release: a `spellcheck`
toggle on the chat composer, mirroring the CLI's new setting with a
browser-native default (native `spellCheck` attribute, on by default,
since Claudius's textarea already gets free browser spellcheck — unlike a
terminal). Alongside it, auditing the "slash-command typo" bug fix
surfaced a matching, independently-introduced footgun in Claudius's own
`SlashCommandPicker` (fuzzy-match Enter could silently autocomplete to an
unrelated, weakly-matched command); that's fixed too since it's the same
UX contract the upstream entry describes, just in Claudius's own
implementation. Headline risk to flag: the `spellcheck` default (on) is a
deliberate divergence from the CLI's default (off) — see Risks.

## Implemented (bucket B)

- `[extend: Settings → Chat] Prompt-input spellcheck toggle` — added `spellcheck?: boolean` to `ClaudeSettings` (`lib/server/settings.ts`), a `useSpellcheckEnabled` client hook (`lib/client/useSpellcheckEnabled.ts`) mirroring the existing `useEmojiCompletionEnabled` pattern (user-scope, browser-only preference, absent = enabled), wired into the composer's `<textarea spellCheck={...}>` in `components/chat/PromptInput.tsx`, and a toggle row in `app/settings/page.tsx`'s Chat section (`sChat` search guard + `KNOWN_KEYS`). Rejected alternative: a new dedicated "Composer" settings screen — overkill, this is a one-row toggle that's a direct sibling of `emojiCompletionEnabled`/`promptSuggestionEnabled` already in the Chat card.
- `[extend: chat composer] SlashCommandPicker Enter-confidence gate` — `lib/shared/slash-commands.ts` gains an exported `isConfidentSlashMatch(cmd, filter)` helper (prefix-of-name or exact/prefix alias match); `components/chat/SlashCommandPicker.tsx`'s Enter handler now requires it before auto-completing, so a typo with only a weak subsequence fuzzy match no longer silently rewrites the composer to an unrelated command. Tab (explicit "insert top suggestion") is unchanged. Rejected alternative: showing an inline "no matching command" error message — bigger surface change than the upstream fix warrants; falling through to normal textarea Enter behavior (no silent rewrite) already satisfies the "don't silently run the wrong thing" contract.

## Risks / follow-ups

- **spellcheck default.** Upstream ships `spellcheck` opt-in (default off), because terminals have no native spellcheck. Claudius's `<textarea>` already gets free browser-native spellcheck with no code at all, so defaulting the new toggle to **on** preserves existing (pre-release) behavior; defaulting to off would be a silent UX regression for every current user. Conservative-vs-maximal: the "maximal"/CLI-literal reading would default to off; we picked the reading that matches Claudius's actual current behavior instead and documented the divergence here.
- **`/model` picker highlight-newest-only tweak** — classified `[C]` as a CLI terminal-rendering nuance. The rejected bucket-B alternative: teach Claudius's `ModelPicker.tsx` to badge the newest model too. Didn't build it because "newest model" metadata isn't something Claudius currently tracks (no model-release-date source), and the changelog entry is thin enough that inventing that metadata would be scope creep beyond what's documented.
- **`/usage` usage-credits spend row** — marked `[skip — ambiguous]`. Tried to disambiguate via `code.claude.com/docs/en/settings` and `account-profile.ts`; the org type/rate-limit-tier fields Claudius already fetches from `api/oauth/profile` don't include a credits balance, and there's no documented public endpoint for it. A future pass should check whether the Anthropic Console Admin API (org-scoped OAuth) is worth integrating for this specifically.
- **SlashCommandPicker fix scope** — this is Claudius's own bug, found by analogy while auditing the upstream entry, not a ported CLI code change (the two pickers share no code). Flagging in case a reviewer wants it split into its own non-parity PR instead of riding along here.
- Otherwise: no bucket-B item was deferred outright; both shipped this release.
