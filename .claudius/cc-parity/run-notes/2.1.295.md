# Claude Code parity 2.1.294 → 2.1.295

## Summary

Claude Code 2.1.295 is a large release, mostly fixes. It adds `onFailure: "block"` for command/HTTP hooks, OSC 7501 terminal status, `/copy` quoted text, plugin-settings load warnings, many Claude apps gateway options, and mod APIs. It also fixes engine issues in MCP, Bash, Read/Edit, plugins, mods, `/loop`, VS Code, cloud and Slack. Claudius reimplements nine items (bucket B), all as extensions of existing screens:

- **Hooks editor:** an `onFailure` block toggle and badge.
- **Plugins page:** a warning when a settings file doesn't load, refusal of marketplace names no plugin can be installed under, and plugin options named `constructor` reading correctly.
- **Settings `advisorModel`:** opens on "No advisor" when the saved Fable advisor isn't available.
- **Chat composer:** a queued message lifted back into the composer is kept in prompt history.
- **Chat transcript:** fork/rewind from the trailing-text bubble targets the real record, and fork failures show a toast.
- **Rate-limit pill:** says whether extra usage is on.
- **Scheduled-loop chips:** a working stop for self-paced `/loop`.

The rest is engine-side and arrives with the SDK bump, or is terminal, gateway, mod or cloud only. Headline risks for review:
- The `onFailure` toggle only works once the 2.1.295 engine is bundled. This branch still pins SDK 0.3.294 / CLI 2.1.294, which ignores the key.
- Several "Fixed …" entries were mapped onto Claudius's own versions of the bug, not the CLI's exact symptom: queue lift, fork id, and loop stop.

## Changelog classification

Audit method: six parallel read-only audits grepped the Claudius surface each entry touches; the bundled CLI (`node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`, 2.1.294) was searched for the hook-handler schema and the reserved marketplace-name set.

## Risks / follow-ups

- **onFailure needs the 2.1.295 engine.**
  - This branch pins SDK 0.3.294 / CLI 2.1.294. Its hook schema is a plain zod object (checked in the bundled binary), so `onFailure` is stripped and a failing hook still lets the action through. The tooltip says 2.1.295+ is needed.
  - Don't release this before the 0.3.295 bump, and confirm the bumped CLI's schema accepts the key.
  - Alternative considered: gating the toggle on the detected engine version. Rejected, because the SDK pipeline bump is the next commit on this stack.
- **Session advisor picker left as is (conservative reading).**
  - The `/advisor` command opens the session ModelPicker. The session model route always appends a `fable` alias row (`app/api/sessions/[id]/model/route.ts`, `ALWAYS_SHOWN_ALIASES`, kept because entitlement can lag), so that picker can't tell real Fable access from the augmented row. Only the Settings field, which has a trustworthy `source: "session"` signal, got the fix.
  - Maximal shape: tag augmented rows and run ModelPicker through `advisorPickerState` too. Risk: hiding Fable from entitled users whose `supportedModels()` omits it.
- **Marketplace names.** Reserved names come from the bundled 2.1.294 CLI. A later CLI may add more, so the copied set can drift.
  - Alternative considered: no reserved-name check, only the charset rule. Rejected, because the CLI refuses those names at load, so the add would "succeed" uselessly.
- **Plugin settings that don't load.**
  - Conservative shape: refuse and explain, never overwrite. Maximal shape: an in-page "open/fix this file" editor. Rejected as a new surface the changelog doesn't ask for.
  - The banner shows the parser's position but not the file content (it is sanitised so secrets don't reach the browser).
- **Queue lift history** is kept in memory per session and lost on reload. Every replace-mode injection (/model prefill, Edit & retry, queue Edit) now writes the single cleared-draft slot, which can overwrite a draft stashed earlier by Ctrl+C or double-Esc. Behaviour change beyond the changelog: the first Cmd/Ctrl+↑ now skips the newest history entry when the composer already holds exactly that text (sent prompts included), so it recalls the one before.
  - Alternative considered: recording only lifts that were later overwritten. Rejected because PromptInput would have to report overwrites back to ChatSurface.
- **Fork / trailing bubble.** Interpretation: the VS Code entry's "panel's own status lines" maps to Claudius's synthetic `:trailing` bubble, the one user-row id the reducer invents.
  - Pending optimistic bubbles now hide Rewind and Restore files (they have no record yet).
  - Alternative considered: hiding Rewind on trailing bubbles. Rejected, because the bubble does map to a real record.
- **Plugin options named constructor.** Alternative considered: making `readPluginOptions` return a null-prototype map. Rejected because it changes a shared helper's return type and every lookup would still need care. The write path (`setPluginOption`) only touches own keys, so it was left alone.
- **Rate-limit extra usage.** Off-signals win over on-signals when they conflict, and `rateLimitType: "overage"` pills get no line, since "keep going on extra usage" would be wrong there.
  - Alternative considered: also changing the rejected-state copy. Left as is.
- **Self-paced loop stop.** Interpretation: the CLI's "Esc / ← background" path has no Claudius equivalent. The Claudius-owned gap was that self-paced loops couldn't be stopped at all from the rail or /schedule. Stopping asks the agent to call `ScheduleWakeup` with `stop: true`, so it needs a turn; the chip shows "cancelling…" until the stop arrives.
  - Alternative considered: removing the wakeup locally without the agent. Rejected, because the engine would still fire it.
- **Found, not in scope:**
  - Recovered (history-less) subagent tasks show `local_agent`/`Agent` instead of the custom agent name (`lib/client/use-session.ts`, `subagent_type: entry.taskType ?? "Agent"`). The data is captured (`TaskSnapshotEntry.subagentType`) but not filled at `task_started`. This was noticed while checking the `worker` entry (classified A) and is worth its own fix.
  - After `disableAutoMode` is saved, a new session's mode picker showed "Bypass" instead of "Default" in e2e. This happens at baseline too.
- **E2E environment.** `tests/e2e/cc-parity-2.1.207-disable-auto-mode.spec.ts` times out on this machine's Node 26.8.2 with Playwright 1.59.1, at baseline (`3a5be0f3`) too:
  - Playwright stalls merging `trace.zip` after the test body has passed.
  - It passes with `--trace off`, and passes with tracing on under Node 22 (which CI uses).
  - It isn't caused by this branch. Pinning Node 22/24 for local e2e or upgrading Playwright would fix it.
