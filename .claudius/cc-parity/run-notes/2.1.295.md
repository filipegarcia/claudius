### Bucket B — reimplemented in Claudius

- `[B — reimplement in Claudius] Added onFailure: "block" for command and HTTP hooks` — Claudius's Hooks editor builds command/http handlers from a fixed field set (`app/[workspaceId]/hooks/page.tsx` AddHookForm; type `lib/shared/hook-events.ts:167`) with no `onFailure`, so a Claudius user could never set it. Plan: a "block on failure" toggle next to the existing async/once toggles, plus an `onFailure=block` badge on the handler list. The 2.1.294 CLI's hook schema is a non-strict zod object (unknown keys stripped, not rejected), so writing the key on this branch is harmless until the engine that honours it lands.
- `[B — reimplement in Claudius] Added a warning to claude plugin install/enable/disable/marketplace add when the settings file they write to does not load` — Claudius writes `enabledPlugins` / `extraKnownMarketplaces` itself (`lib/server/plugins.ts` via `writeSettings`). A malformed settings file today makes `GET /api/plugins` 500 (no per-scope catch in `listAll`) and a toggle on it silently does nothing (`app/plugins/page.tsx` discards the result). Plan: per-scope "settings file doesn't load" banner + inline toggle error; never overwrite the file.
- `[B — reimplement in Claudius] Fixed claude plugin marketplace add reporting success for a marketplace whose name no plugin can be installed under; such an add is now refused` — Claudius's "Extra known marketplaces" add form (`lib/shared/marketplace-settings.ts:189` `addExtraMarketplace`) only checks the name is non-empty. Plan: refuse names that fail the plugin-ref name rule (`NAME_RE`, `lib/shared/plugin-ref-lint.ts:27` — spaces, `@`, leading punctuation) and the CLI's reserved official names for a non-`anthropics/` source (set copied from the bundled CLI).
- `[B — reimplement in Claudius] Fixed plugin options named constructor or prototype always reading as their default` — Claudius's plugin options form reads `o.name in values ? values[o.name] : o.default` (`app/plugins/page.tsx:720`) on a plain object, so `constructor` (and `toString`, `valueOf`…) resolves to `Object.prototype` members. Plan: own-property lookup helper in `lib/shared/plugin-config.ts`.
- `[B — reimplement in Claudius] Fixed the /advisor dialog showing a checkmark on a saved advisor model that is no longer available; it now opens on "No advisor"` — Claudius's Settings `advisorModel` field force-adds and checks the Fable row whenever the saved advisor is Fable, even when the live session's `supportedModels()` says the account has no Fable (`app/settings/page.tsx:2407`). Plan: when the probe is authoritative (`source: "session"`) and has no Fable, open on "No advisor" with a note naming the unavailable saved model. Session ModelPicker left alone — see Risks.
- `[B — reimplement in Claudius] Fixed a queued message being lost when pulled back into the prompt with ↑ or Esc just after ←: prompt history now keeps it` — Claudius's queue "Edit" (`components/chat/QueueIndicator.tsx` → `liftQueued`, `components/chat/ChatSurface.tsx:1057`) deletes the queued row and replaces the composer draft; prompt history is built only from sent messages (`ChatSurface.tsx:1951`), so lifting a second item loses the first. Plan: lifted texts join the composer's prompt history.
- `[B — reimplement in Claudius] [VSCode] Fixed "Fork conversation from here" and Rewind's conversation restore failing with "Message not found in session" after … one of the panel's own status lines` — Claudius's reducer mints a synthetic `${uuid}:trailing` id for the trailing-text bubble (`lib/client/use-session.ts:3743`, `:6742`) and the bubble's "Rewind here" / rewind-files buttons send that id to `forkSession`, which can't find it; the failure is only `console`-logged (`ChatSurface.tsx:1124`). Plan: send the real record uuid and toast fork failures.
- `[B — reimplement in Claudius] Improved headless rate_limit_event usage-limit warnings to say whether the account has extra usage turned on` — Claudius writes its own copy for `rate_limit_event` (`components/chat/SystemPill.tsx` RateLimitPill) and only mentions extra usage on `rejected`. Plan: an "Extra usage is on/off" line on `allowed_warning` from the structured `overageStatus` / `isUsingOverage` / `overageInUse` / `overageDisabledReason` fields.
- `[B — reimplement in Claudius] Fixed Esc not stopping a self-paced /loop moved to the background with ←; cancelling a pending wakeup now shows a notice` — Claudius has no working stop for self-paced (ScheduleWakeup) loops: the chip's cancel is cron-only (`components/panels/widgets/ScheduledLoops.tsx:107`, `ChatSurface.tsx:1049`, `app/[workspaceId]/schedule/page.tsx:917`) and the cancel route always asks for `CronDelete` (`app/api/schedule/session-loops/cancel/route.ts:87`). Plan: offer cancel on wakeup loops, ask the agent for `ScheduleWakeup` `stop: true` (present in `sdk-tools.d.ts:2933`), and show the chip as cancelled.
