## Summary

Claude Code 2.1.239–2.1.245 is mostly bug fixes plus CLI/TUI/VSCode/Remote-Control
polish. Three product-surface features don't flow through the SDK and are worth
reimplementing in Claudius this cycle: a **Loops breakdown** on the Cost page
(per-loop run count / total tokens / tokens-per-run / last-run, mirroring CC's
`/usage` addition), a **curated `/model` picker** (`modelPicker` setting), and an
**org-contracted pricing override** (`modelPricing` setting) for the Cost page.
Two settings CC shipped this window (`promptCacheTtl`/`subagentPromptCacheTtl`)
were already implemented in a prior SDK-diff cycle (5509eb7) — no new work needed.
Headline risk: the Loops breakdown groups ticks **by session**, not by individual
`/loop` invocation, because Claudius's `scheduledLoops` map has no stable
per-invocation id across a chained wake-up (see Risks). The `modelPricing`
override is scoped to the Cost page only — Claudius's status line reconciles to
the SDK's own authoritative `total_cost_usd` seconds after each turn, so an org
override there would be fighting (and losing to) that authoritative value.

## Risks / follow-ups

- **Loops breakdown groups by session, not by `/loop` invocation.** Claudius has no stable id for an individual dynamic-loop chain (each `ScheduleWakeup` tick gets a fresh `tool_use_id`; only the owning session is stable). Conservative shape shipped: one breakdown row per session. Maximal shape would need a stable per-invocation loop id, which the SDK doesn't currently surface — worth revisiting if/when it does.
- **`modelPricing` scoped to the Cost page**, not the StatusLine's live `$` tile — see the rejected-alternative note above. If a reviewer wants the mid-turn estimate to reflect org pricing too, that's a follow-up (needs threading the setting to the client via the settings bundle).
- **Subagent model/effort in `/tasks`** and the **managed-settings "Skipped sources" line** and the **claude.ai-managed `/mcp`/`/plugins` marker** were all marked `[skip — ambiguous]` for lack of a data source or analogous Claudius concept — see classification section above for the specific commit/doc evidence checked for each.
- **Console keyless sign-in** (`/login`) was skipped rather than guessed at — Claudius's existing OAuth flow in `lib/server/account-oauth.ts` uses verified constants lifted from the leaked CLI source; the Console flow's constants aren't in that source and weren't independently verified, so implementing it risked a broken, hard-to-debug auth path shipped silently.
- Loop-tick token attribution uses the *main-loop-only, per-turn* `usage` field on the SDK's `result` message (excludes subagent/sidechain tokens, per its own doc comment) — this undercounts a loop tick's true cost if the tick spawned subagents. Documented as the conservative reading; the maximal reading (sum `modelUsage`, which is cumulative and includes subagents) would need diffing consecutive cumulative snapshots, which is more failure-prone to get right in one pass.
- The `modelPicker` Settings e2e spec caught a real bug during development: `ModelPickerCatalogField`'s `commit()` originally gated persistence on `entries.length > 0` only, so picking "Replace built-in lineup" before adding any rows was silently discarded (the next commit — adding a row — started from an empty draft again, losing the mode pick). Fixed by also persisting when `mode === "replace"`. Left as a note here rather than silently fixed-and-forgotten because it's exactly the kind of plausible-but-wrong shape the adversarial-verification step in this pipeline exists to catch — worth a second look from a human reviewer to confirm the fix (spread-from-props-each-commit, no local draft state) is the right long-term shape for this component, vs. switching to `useState`-backed local draft state if more fields get added later.
