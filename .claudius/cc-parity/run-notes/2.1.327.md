## Summary

Claude Code 2.1.327 is another large release, about 190 entries. Most of it is permission and sandbox hardening, terminal renderer and dialog polish, cloud/Remote Control/runner fixes, artifacts, mods and VS Code. All of that reaches Claudius through the bundled engine or has no browser equivalent. A read-only audit (six parallel agents, one per surface cluster) checked every entry that lands on a surface Claudius draws itself. It found 12 places where Claudius has its own copy of the bug or gap, and this run fixes all 12, each on a screen Claudius already has (no new routes).

What changed for the user:
- **Chat transcript**
  - A reopened chat whose session file is missing part of its history now says so at the top.
  - A subagent's card no longer shows raw `<task-notification>` XML after its background task finishes.
  - The restore-files dialog now reports a real restore that failed, instead of saying "Nothing restored".
  - Cmd/Ctrl+F now finds text inside Edit and Write cards: it opens the matching card and closes it again afterwards.
  - Esc on a permission prompt that just appeared now denies it, unless you were typing.
- **`/settings` (what `/config` opens)**
  - A save that fails now says so and names the file, and the same applies to the Skills toggle and Auto mode.
  - A row now notes when a higher-precedence settings file wins.
  - The `attributionProject` help now covers gateway billing groups.
- **`/status` and `/doctor`** now report agent and skill files whose frontmatter even the engine can't parse, plus `keybindings.json` errors.
- **`/mcp`**
  - Adding a server to a flat `.mcp.json` is now refused (it used to be quietly reshaped).
  - A server the running session didn't load now gets a hint saying what to do.
- **Spending limits** no longer show "Saved." after a refused save.

Headline review risks:
- whether `/status` → `/doctor` is the right home for the "broken files" list;
- whether opening Edit/Write cards from search, with their bodies now shown as labelled text blocks, is the right shape;
- the resume-gap detector's false-positive margin. It was checked against 99 real transcripts with 0 hits, but none of them had compactions or forks.

## Risks / follow-ups

- **Resume gap (alternative rejected: a broad "any orphan parent in the file" rule).**
  - The detector uses the CLI 2.1.327 rule (`yZt`/`_Zt` in the bundled binary): it looks only at the root of the chain `getSessionMessages` returned.
  - Run read-only over 99 real `~/.claude/projects` JSONLs, it found 0 hits. That sample had no compactions, sidechains or forks, so those shapes rest on the vitest fixtures alone.
  - A false "missing or damaged" warning on a healthy session is the failure to watch for.
  - The paged notice relies on the in-memory `Session`, which is always present while the chat stream is attached.
- **Search into edits (alternative rejected: searching raw tool input without DOM ranges, which gives a count you can't step to).**
  - Edit/Write/NotebookEdit cards now show their file text as labelled pre-wrapped blocks even when you're not searching. That reads better than escaped JSON, but it is a visible change to those cards.
  - The labels are raw keys (`old_string`, `new_string`).
  - For Edit, the leftover JSON is just `file_path`.
  - MultiEdit renders two blocks per edit, so a large one can be tall.
  - Known limits: an Edit card inside a collapsed subagent card opens but stays hidden, and a match below the fold of a tall block isn't scrolled into view inside that block.
- **`/status` → `/doctor` (alternatives rejected: listing the problems inside the `/status` overlay, or a new route).**
  - Conservative shape: only what Claudius parses itself (agent and skill frontmatter, `keybindings.json`).
  - Maximal shape (upstream): also command and output-style files, sandbox availability, ignored permission settings and hook matchers that never match. Those need engine knowledge Claudius doesn't have.
  - `parseFrontmatter` now uses the engine's fallback, so agents whose descriptions contain `: ` show their description on the Agents and Skills pages where they used to show none.
  - `docs/cc-parity/2.1.275/status-account.png` (an older run's screenshot) no longer matches the live overlay, which now has a Problems row.
- **`/config` override note (alternative rejected: a merged "Effective" view).**
  - Managed settings are ignored because Claudius doesn't read them.
  - The skip list (`USER_SCOPE_WINS_SETTING_KEYS`) has to stay in sync with `lib/server/session.ts`'s user-scope reads. The two point at each other in comments, but nothing enforces it.
  - On a catalog row, the old "overridden" badge (meaning "set in this file") can now sit next to "… takes precedence". The badge predates this change, but renaming it would remove the double reading.
- **`/mcp` (alternatives rejected: rewriting a flat file automatically; pushing a new server into the live session).**
  - The approval pointer for project servers is hedged ("If it still doesn't load…"), because I didn't confirm that the headless engine holds back unapproved `.mcp.json` servers.
  - A flat `.mcp.json` still lists no servers on `/mcp` until you try to add one. Showing the shape problem up front is a possible follow-up.
- **Subagent task notifications (alternative rejected: a muted "Background task finished" row in the trail).** The top-level transcript drops these notifications silently and the card already shows completion, so the trail does the same.
- **Restore-files failure (alternative rejected: checking each file on the client after the rewind).** The SDK gives no per-file result for partial failures, so only the all-failed case (`canRewind:false`) is reported. Partial failures still reach only the engine's telemetry.
- **`attributionProject`.** Copy-only change to the existing row's help text; the engine reads the setting. Rejected alternative: validating the value's format in Claudius, which would guess at gateway rules.
- **Settings save errors (alternative rejected: a toast).** `MessageList.tsx`'s "Cancel auto-continue" PUT is still best-effort and silent. The failure messages pass the raw errno text through.
- **Esc grace (alternative rejected: removing the grace, which would regress 2.1.318).** If a prompt appears within 1s of your last keystroke in a field (for example, the Enter that sent the message), an Esc in its first 400ms is still held back, on purpose.
- **Spending limits (alternative rejected: snapping the inputs back to the saved values on failure, which throws away the user's edits).** This is Claudius's own local spending cap, the browser counterpart of the CLI's account spend-limit menu (that menu is engine-side). When the cap override fails, the banner's Continue now does nothing visible. Surfacing that failure is a follow-up.
- **`[skip — ambiguous]` rows: confirmed Claudius-side gaps, deferred:**
  - **`CLAUDE_CONFIG_DIR`.** Claudius writes user-scope settings to a hard-coded `~/.claude` (`lib/server/settings.ts` `pathFor('user')`), and the account-profile mirroring uses the same path (`lib/server/accounts-store.ts` `realClaudeDir()`). So with `CLAUDE_CONFIG_DIR` set, `/statusline` and other user settings land in a file the engine doesn't read. This has been pending since 2.1.257 (see that run's notes). The fix touches profile mirroring and deserves its own PR.

The nearest analogue: deleting a `/fork` session leaves its worktree and `claudius/fork-*` branch on disk with no notice (`app/api/sessions/file/[id]/route.ts`, `lib/server/fork-worktrees.ts`). That would be new scope.
