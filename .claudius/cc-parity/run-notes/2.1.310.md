## Changelog classification

Context for the classification: the CLI binary bundled with SDK 0.3.310 (`node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`), the public `sdk.d.ts`, and a grep of the matching Claudius code path for each fix. The SDK migration on this branch (`58014f87`, `95cfab3d`) only bumped the dependency. None of its items overlap a CC changelog entry, so no line here needs the "already shipped via SDK migration" tag.

- `[A — already via SDK updater] Added the Monitor tool and plugin monitors on Bedrock, Vertex, and Foundry, and when telemetry or nonessential traffic is disabled; long foreground sleeps are now blocked there too`: tool availability is decided inside the engine. Claudius has no provider gate of its own on Monitor; its only Monitor list is `RESTRICTED_MODE_DISALLOWED_TOOLS` in `lib/server/session.ts`, which is unrelated. `ToolCall` already renders Monitor like any other tool call.
- `[A — already via SDK updater] Fixed requests failing behind some gateways and compatible servers that reject the effort-2025-11-24 beta value or mid-conversation system messages; Claude Code now retries without them`: the retry lives in the engine's API client. Claudius makes no Messages API calls of its own: `rg "anthropic-beta|@anthropic-ai/sdk" lib app` is empty, and the only direct `api.anthropic.com` uses are the OAuth profile and voice WebSocket.
- `[A — already via SDK updater] Fixed background cleanup deleting some recent files, such as pasted images, when cleanupPeriodDays is set to a very large value`: the sweep runs in the engine. Claudius only passes `cleanupPeriodDays` through from the Settings page (`app/settings/page.tsx`). Its own pasted-image store (`lib/server/asset-store.ts`) has no age-based sweep; `deleteAsset` runs only on explicit delete.
- `[A — already via SDK updater] Fixed compaction after a "Prompt is too long" error keeping too much of a conversation with dense text`: compaction happens in the engine. Claudius has no trimming or retry logic of its own; the only `Prompt is too long` match is a cost-aggregation comment in `lib/server/cost-aggregate.ts`.
- `[B — reimplement in Claudius] Fixed file read permission prompts not showing where a symbolic link leads`: the engine computes `symlinkTarget` for its own terminal card and prints "This will read X (outside working directory) via a symlink" or "Symlink target: X" (seen in the bundled CLI's `buildFilePermissionDescriptor`). That field is not part of the `canUseTool` options in `sdk.d.ts`, so it never reaches the host. Claudius renders its own card (`components/chat/PermissionPrompt.tsx`) from `title`, `description` and the tool input, which is collapsed by default, so a Read of a symlink shows only the link path. Claudius gets the same bug and needs its own fix: resolve the link on the server and show the target on the card.
- `[C — CLI/terminal only] Fixed a question's auto-continue timeout firing the moment the external editor closed after a long edit`: the external editor (Ctrl+G to `$EDITOR`) exists only in the terminal. Claudius's AskUserQuestion form (`components/chat/AskUserQuestionPrompt.tsx`) has no auto-continue timeout and no external editor (`rg -i "timeout|countdown" components/chat/AskUserQuestionPrompt.tsx` is empty).
- `[A — already via SDK updater] Windows: Fixed PreToolUse and PermissionRequest hooks letting a tool call through when Git Bash is missing and the hook's command is only quoted strings`: the engine runs the hooks. Claudius's `lib/server/hooks.ts` only edits settings.json and never starts a hook command (no `spawn`/`execFile`).
- `[A — already via SDK updater] Improved auto mode's prompt before the first read outside the working directories: it now says when blocking those reads makes shell commands ask for permission`: the engine writes this text and Claudius shows it through the `title`/`description` it forwards (`PermissionPrompt.tsx`). Claudius has no copy of the prompt (`rg -i "outside the working" components lib` is empty).
- `[A — already via SDK updater] Improved memory use of non-interactive sessions (-p, Agent SDK) during compaction when the transcript file is very large`: engine-internal. Claudius gets it with the SDK bump.
- `[C — CLI/terminal only] Improved a mod's Image to draw inside tmux with allow-passthrough and focus-events on, in kitty, Ghostty, and iTerm2 3.5+`: a terminal graphics protocol inside the CLI mod runtime. Not applicable in a browser.
- `[A — already via SDK updater] Linux: Improved /sandbox and the sandbox startup warning to name Ubuntu's AppArmor restriction on user namespaces`: `/sandbox` is an SDK-passthrough command (`handler: "sdk"` in `lib/shared/slash-commands.ts`), and the engine emits the startup warning. Claudius's own sandbox copy is the "Linux only (bubblewrap)" hint on the workspace toggle (`components/workspaces/WorkspaceForm.tsx`), which says nothing about why bubblewrap failed. The engine's new message is what users will see.
- `[A — already via SDK updater] Changed the error for an MCP tool call that times out in a non-interactive session while the server's elicitation is unanswered`: the engine produces the error text. Claudius's `onElicitation` (`lib/server/session.ts`) keeps the elicitation open with no timeout of its own until the user answers or the turn is aborted, so it has no separate copy of this message.
- `[skip — VS Code extension only] [VSCode] Fixed pressing Enter on the plan review card's "Send feedback and keep planning" button approving the plan`: Claudius's plan card (`components/overlays/PlanOverlay.tsx`) has no feedback button and no global Enter-to-accept. Its buttons are plain `onClick` (Enter on the focused "Reject & iterate" rejects), and the only keyboard accept is Cmd/Ctrl+Enter inside the edit textarea. The bug isn't present.
- `[skip — VS Code extension only] [VSCode] Fixed the panel showing "Something went wrong" after "Switch branch & continue" on a cloud session`: Claudius has no cloud-session history or Web tab.
- `[skip — cloud product, not in Claudius] [Cloud sessions] ×7 (Enterprise custom-role permissions, Choose file for setup script, dialog error fixes for environment saves and routine token actions, setup-script output box, admin confirmation, row-based environment dialog)`: these are claude.ai cloud-environment and admin surfaces. Claudius runs locally and has no cloud environments, routines API tokens or Enterprise roles.
- `[skip — Slack product, not in Claudius] [Claude Tag] ×3 (formatted ! commands, admin page load error, spend limits filter while loading)`: Claude Tag is a Slack integration. Claudius has no Claude Tag surface.

## Implemented (bucket B)

- `[extend: chat permission modal]` Symlink target on file-read permission prompts (plan). `canUseTool` on the server checks whether a `Read` call's `file_path` is a symlink (`lstat`, resolved against the session cwd). If it is, the server `realpath`s it and attaches `symlinkTarget` and `symlinkOutsideCwd` to the `permission_request` event. `PermissionPrompt.tsx` shows a warning row using Claude Code's wording. Rejected alternative: putting the target only in the collapsed tool-input JSON, which is the same hidden state the upstream fix removed.
