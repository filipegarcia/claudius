## Changelog classification

- `[A — already via SDK updater] Fixed read-only git commands in Bash
  unexpectedly asking for permission after a session had been running
  for a while (regression in 2.1.269)` — Claudius's `canUseTool`
  callback (`lib/server/session.ts:3059-3213`) is a generic dispatcher
  that special-cases only `mcp__claudius_goal__*`, `ExitPlanMode`, and
  `AskUserQuestion` by tool name, plus a web-search/subagent budget cap;
  for every other tool, including `Bash`, it forwards straight to the
  generic `permission_request` flow and never itself parses a command
  string to decide whether it's "read-only" (no `isReadOnlyBash`, no
  `git status`/`git log`/`git diff` allowlist logic anywhere in
  `lib/server`, `lib/shared`, or `lib/client`). `canUseTool` is only
  invoked when the SDK has already decided a prompt is needed
  (session.ts:2600-2607) — the read-only-bash fast path, its 2.1.269
  regression, and its 2.1.270 fix all live entirely inside
  `@anthropic-ai/claude-agent-sdk`. The SDK bump that carries this fix
  (`0.3.267` → `0.3.270`) is already committed on this same branch
  (`8378b36`), so no Claudius-side change is needed or possible here.

No other non-bug-fix entries exist in this changelog window — this is
a single-entry, bug-fix-only release.
