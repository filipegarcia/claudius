## Summary

Claude Code 2.1.285 (vs 2.1.284) is dominated by engine/CLI fixes (fork subagents inheriting plan/dontAsk mode, Artifact tool safety, `set_model` window refresh, MCP toggling mid-session, background Bash timeouts, `ping` stream events during non-streaming fallback), CLI-only work (`claude --desktop`, `claude plugin configure`, `claude mcp list/get`, `/ultrareview` upload hardening, Windows/WSL fixes) and VS Code / cloud / Claude Tag / Code Review surface changes that have no Claudius equivalent. Nearly everything Claudius could inherit flows through the SDK updater (bucket A). No bucket-B items were shipped this release; the headline risk is that the `/tasks` "System tasks" grouping and `CLAUDE_CODE_DISABLE_WEB_FETCH` were judged not to justify a speculative build (see Risks).

## Risks / follow-ups

- `/tasks` "System tasks" grouping: considered `[extend: tasks/agents pane]` adding a collapsed "System tasks" row; rejected because the SDK task events carry no reliable marker distinguishing Claude Code's own background work, so grouping would be guesswork. Revisit if the SDK adds such a field.
- `CLAUDE_CODE_DISABLE_WEB_FETCH`: considered `[extend: Settings panel]` toggle; rejected as a hidden-flag-style duplicate of existing per-session env / disallowed-tools controls (users can already disallow WebFetch). Revisit if users ask for a first-class switch.
- Auto-memory guard in `/memory`: maximal shape would block enabling auto-memory from background/tool-started Claudius sessions; conservative shape (chosen) is to do nothing since Claudius's memory settings are not reachable from those contexts.
