# Claude Code parity 2.1.307 → 2.1.309

## Summary

Claude Code 2.1.308 is a single "bug fixes and reliability" line. 2.1.309 is a large fix release covering sandbox, permissions, worktrees, skills, VSCode, cloud, Claude Tag and Code Review. It adds no new user-facing feature beyond a few changed behaviours. Most entries are engine-side and reach Claudius through the SDK bump already on this branch (0.3.306 → 0.3.309; that migration shipped no product code, so nothing is tagged "already shipped via SDK migration").

Five entries are bucket B because Claudius owns the same code path, and all five shipped:
1. **Empty "Untitled" sessions no longer fill history.** An abandoned new tab no longer appears on `/sessions` or in the picker.
2. **A rename now beats a generated name after a reload or resume.** The non-live rename path writes the sessions index. A live rename also goes to the running engine (`rename_session`, source "host"). A rename made before the first turn is re-mirrored to the JSONL.
3. **Dictation certificate failures say what to do.** They point at `NODE_EXTRA_CA_CERTS` in the composer footer and in the server log. The same hint covers Claudius's own sign-in and profile requests.
4. **The feedback banner shows the server's refusal reason** (e.g. "Your organization does not accept feedback.") next to the existing "Open an issue" link. The engine answers a refusal as a resolved `{feedback_id: null, unavailable_reason}`, which Claudius used to report as "sent".
5. **Bypass permissions denies a dangerous `rm`/`rmdir` at once with a rewrite hint**, like Desktop and VS Code, instead of parking an Allow/Deny card that stalls an unattended session.

Headline review risks:
- the bypass-mode auto-deny is new host policy that matches the engine's reason text;
- the feedback fix depends on an undocumented SDK response shape, verified against the bundled engine.

## Implemented (bucket B)

- `[extend: sessions history — /sessions page + session picker]` **Hide never-used sessions.** `/api/sessions/all` now leaves out a DB-only index row that has no title and whose session isn't live (`isHistoryWorthyDbRow`). The filter runs before the recency sort and `limit`, so empty rows no longer use up the picker's 25 slots. Renamed-before-first-turn rows (the reason the fan-out exists) and the user's currently-open empty tab stay listed. The workspace "move N sessions?" preview counts the same way, so it agrees with history. Files: `lib/shared/session-history.ts` (new), `app/api/sessions/all/route.ts`, `lib/server/workspace-relocate.ts`, `app/api/workspaces/[id]/move-sessions/route.ts`, `app/[workspaceId]/sessions/page.tsx` (adds a `session-row` test id). Rejected alternatives:
  - Deferring the index upsert until the first turn, or deleting the row on reap. That row also carries the goal, the account pin and pre-first-turn renames.
  - Filtering on the client. The server's `limit` would already be spent on empty rows.
- `[extend: session rename]` **A rename wins over a generated name after a reload or resume.**
  - The non-live branch of `/api/sessions/rename` now updates the sessions-index title via `retitleIndexedSession`. That function only touches DBs of known workspaces and never creates a DB or a row. Before, every reader kept preferring a stale, often engine-generated, index title.
  - `Session.rename` also tells the running engine through the SDK Query's `renameSession` (`rename_session`, source "host", which the CLI "counts as a user rename"). It is feature-detected and bounded at 5 s.
  - A name that reached neither the engine nor the JSONL is re-sent at the next turn boundary (`pendingTitleMirror`). It is seeded on a fresh start too, so a pre-first-turn rename from an earlier boot isn't lost.
  - The route trims once and returns 400 for a blank title on both paths.

  Files: `app/api/sessions/rename/route.ts`, `lib/server/sessions-db.ts`, `lib/server/session.ts`. Rejected alternatives:
  - Making the JSONL `customTitle` win over the index title. That breaks renames made before the JSONL exists.
  - Letting `upsertSession` overwrite titles. That lets a resumed session's generated `aiTitle` clobber user renames.
- `[extend: chat composer — mic / footer status]` **Actionable certificate-failure hint for dictation.**
  - The proxy (`openUpstream` error path) recognises CA-trust failures by OpenSSL/Node code, by message for Bun, and through `err.cause`. Expired or wrong-host certificates are excluded.
  - It logs `[voice:…] upstream error: … — <hint> It can be set in the environment or in the env block of ~/.claude/settings.json.` and sends the short hint in the SSE error frame.
  - `useVoice` shows the hint in the composer footer status slot shared with the 2.1.307 self-stop notice: amber mic, `role="status"`, hover title.
  - Any upstream error now tears the hook down. The mic used to stay red and locked on a dead session id.
  - Claudius's own HTTPS requests to Anthropic, the "extension's own requests" half of the entry, get the same treatment. The account token exchange throws "Sign-in couldn't reach Anthropic. … Start Claudius with NODE_EXTRA_CA_CERTS set to the proxy's CA bundle.", and the profile fetch shows that note instead of "fetch failed".

  Files: `lib/shared/tls-cert-hint.ts` (new), `lib/server/voice-stream.ts`, `lib/client/useVoice.ts`, `components/chat/PromptInput.tsx`, `lib/server/account-oauth.ts`, `lib/server/account-profile.ts`. Rejected alternative: log-only, the literal upstream shape. Claudius users rarely see the Next/Electron server log, so the mic's own status line is where the advice has to be.
- `[extend: chat — feedback banner]` **Feedback shows the server's reason.** `Session.submitFeedback` reads what the SDK resolves with (`interpretFeedbackResponse`):
  - `feedback_id` → sent.
  - `unavailable_reason` → not sent, with that reason. It is sanitised and capped by code point, and a trailing CLI "Report issues at …" is dropped.
  - `failure_reason` only, or a thrown transport error → not sent, no reason.

  The route returns `reason`, and the banner's fail state reads "Saved locally — not sent: <reason> To report a bug: Open an issue". Without a reason, the old connectivity copy stays. Error responses' machine codes (the 409's `session-unavailable`) are never shown. Files: `lib/shared/feedback-refusal.ts` (new), `lib/server/session.ts`, `app/api/feedback/route.ts`, `lib/client/use-session.ts`, `lib/client/types.ts`, `components/chat/FeedbackBanner.tsx`. Rejected alternative: probing org policy up front and hiding the survey. There's no SDK API for that, and it would guess at engine policy.
- `[extend: permission flow — canUseTool]` **Bypass mode auto-denies a dangerous rm/rmdir.** When the session is in `bypassPermissions`, the ask is a `safetyCheck`/`subcommandResults` whose reason is one of the engine's "Dangerous rm/rmdir operation …" checks, and no user ask rule forced it (`matchedAskRule`), Claudius answers `deny` at once. The message is the engine's reason plus "Denied automatically because this session runs in Bypass permissions mode… Rewrite the command so it removes only literal paths inside the project, or leave the removal for the user to run." No card is parked. The engine renders the denial as the tool's error in the existing tool row. Files: `lib/shared/dangerous-rm-deny.ts` (new), `lib/server/session.ts`. Rejected alternatives:
  - Setting a Desktop entrypoint so the engine behaves like Desktop. That impersonates a host and leaks into other entrypoint-gated logic.
  - Re-parsing the Bash command in Claudius. That duplicates the engine's classifier.

## Risks / follow-ups

- **Dangerous-rm auto-deny: conservative vs. maximal shape.** Shipped: deny only in `bypassPermissions`, only for the engine's dangerous-rm/rmdir safety checks (matched on its "Dangerous rm(dir) operation" wording, since there is no reason code for it), and never when a user ask rule forced the prompt. Maximal: auto-deny every `safetyCheck` in bypass mode, as the SDK typings suggest a host *may*. I didn't do that because the changelog names rm/rmdir only. Risk: if the engine rewords its reason, the match silently stops and the old card comes back, a fail-safe direction. Known limitation: the decision uses the session's mode. `ctx` doesn't carry a subagent's own `permissionMode`, so a bypass subagent under a non-bypass parent still gets the card. Alternative considered: a toast or notice when Claudius auto-denies. Rejected because the denial is already visible as the tool's error in the transcript, and other host-side auto-denies (the tool-budget cap) also surface only there.
- **Feedback: relies on an undocumented response shape.** The `submit_feedback` result (`feedback_id`, `unavailable_reason`, `failure_reason`) is marked `@internal` in the engine. Unknown shapes fall back to "sent", the old behaviour. Alternative shape considered: a separate "policy refused" banner variant with different styling. Rejected because the existing amber fail banner with its "Open an issue" link already is "where to report a bug".
- **Dictation hint: conservative vs. maximal.** Conservative: a server-log warning only, the literal upstream shape. Shipped: the log plus the composer's footer status slot, the 2.1.307 notice slot, now also documented as carrying connect-failure guidance. Maximal, not shipped: a Settings field for the CA bundle path. Claudius already honours a user-settings `env.NODE_EXTRA_CA_CERTS` for dictation (2.1.307), so a new field would duplicate it. Claudius's own sign-in and profile requests only honour a `NODE_EXTRA_CA_CERTS` present at process start, which is why their copy says "Start Claudius with…".
- **History filter: alternative shape considered.** Deleting abandoned rows on reap (rejected; see Implemented). Residual edge, found in adversarial review and not fixed: `ChatSurface`'s foreign-tab persist guard keeps any open tab that has no row in `session.sessions`. A reaped, empty, *foreign-workspace* session reached through a stale `?session=` URL can therefore be saved into the wrong workspace's tab strip. The same hole already existed for sessions outside the picker's top-25 slice. Fix idea: remember each id's last-known cwd in a ref instead of relying on the current listing.
- **Rename: alternative considered.** Showing the Claudius index title in `PeerMessageHeader` instead of the engine's registry name. Rejected because the engine owns that name, and the `rename_session` call now feeds it. The 5 s bound on the in-engine rename means a wedged control channel delays the rename response by up to 5 s, then falls back to the JSONL path. Checked in the bundled engine: the `rename_session` handler only answers success or error, so it emits nothing that Claudius would render and has no title event that could race the `session_title` broadcast. In a context with no rename callback registered, it answers "rename_session is not supported in this context". `renameInEngine` then returns false and the JSONL write plus the pending re-mirror carry the name, as before. Whether SDK-mode sessions register that callback wasn't verified against a live engine.
- **`[skip — ambiguous]` LaTeX paste in VSCode:** same open question as 2.1.307. Claudius renders math with rehype-katex (`components/chat/Markdown.tsx`) and has no copy handler, so a Playwright clipboard probe would settle whether a fix is needed.
