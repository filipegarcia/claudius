# Claude Code parity 2.1.307 → 2.1.309

## Summary

_(Draft — finalized after implementation.)_ Claude Code 2.1.308 is "bug fixes and reliability"; 2.1.309 is a large fix release (sandbox, permissions, worktrees, skills, VSCode, cloud, Claude Tag, Code Review) with no new user-facing features beyond a few changed defaults. Five entries are bucket B because Claudius owns the same code path: rename persistence, empty sessions in history, the dictation certificate hint, the feedback refusal reason, and the bypass-mode dangerous-rm auto-deny.

## Changelog classification

Context sources: the changelog text; a five-way read-only audit of the matching Claudius code paths (cited per line); `strings` over the bundled engine binary (`node_modules/@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`) for the dangerous-rm reason strings. The SDK migration on this branch (0.3.306 → 0.3.309, `.claudius/sdk-updater/run-notes/0.3.309.md`, commits `bfd49910` / `46a01b05`) shipped only the dependency bump and no product code, and none of its items (`managedSettings` filtering, `extractFromBunfs`, `liveReply`, `sshHostCommands`, `command_lifecycle` wakeup fields, `supportedDialogKinds`) matches a CC changelog entry — so no entry below is tagged `[skip — already shipped via SDK migration on this branch]`. 2.1.308 has a single "Bug fixes and reliability improvements" line: `[A — already via SDK updater]`, nothing to mirror.

**Bucket B — Claudius owns the surface and has the same bug**
- `[B — reimplement in Claudius] Fixed sessions renamed with /rename appearing to other sessions under a generated name after a window reload or a non-interactive --resume` — Claudius's non-live rename path (`app/api/sessions/rename/route.ts:24`, → `sessions-store.rename` → SDK `renameSession` only) never writes the per-project DB title, yet every reader prefers the DB title (`resolveSessionTitle`, `/api/sessions/all` `claudiusTitle`, `use-session.ts` tab merge). A session whose row was seeded with a generated (`aiTitle`) title on resume (`session.ts` `upsertSession`) keeps showing that generated name after a reload. Separately, a live rename made before the first turn swallows the SDK `renameSession` failure (`session.ts` `rename()`), so the JSONL — what the CLI and other sessions read — never gets the name. Fix: write the DB title on the non-live path, and re-mirror a pending rename to the JSONL at the next turn boundary.
- `[B — reimplement in Claudius] [VSCode] Fixed Session history filling up with empty "Untitled" sessions each time you start a new session without sending a message` — `Session.start()` upserts a DB row immediately (`session.ts` `upsertSession`) and `/api/sessions/all` (`app/api/sessions/all/route.ts:24-38`) synthesizes a history entry for every DB-only row, untitled or not. Each abandoned new tab / `/clear` shows up as "(untitled)" on `/sessions` and in the session picker and eats its 25-slot recency window. Fix: skip DB-only rows with no title and no live session.
- `[B — reimplement in Claudius] [VSCode] Added a log warning that says what to do when dictation or the extension's own requests fail certificate verification, such as behind a TLS-inspecting proxy` — Claudius proxies dictation itself (`lib/server/voice-stream.ts` `openUpstream`). A TLS trust failure logs only `upstream error: <message>` (`voice-stream.ts:362`) and the mic shows "Voice: unable to verify the first certificate" with no hint about `NODE_EXTRA_CA_CERTS`. Fix: a pure `tlsCertFailureHint()` used in the server log and in the SSE error payload the mic already shows.
- `[B — reimplement in Claudius] Fixed feedback saying "try again later" when your organization does not accept feedback; it now shows the server's reason and where to report a bug` — Claudius's session-quality survey (`components/chat/FeedbackBanner.tsx`, `app/api/feedback/route.ts`) forwards via `query.submitFeedback`, but `Session.submitFeedback` (`session.ts:6016-6022`) swallows the rejection, so the banner always says "couldn't reach Anthropic". Fix: carry the refusal reason through the route and show it in the banner next to the existing "Open an issue" link.
- `[B — reimplement in Claudius] Changed the dangerous rm and rmdir prompt in bypass permissions mode in the Desktop app and VS Code to deny the command at once with a rewrite hint, so unattended sessions keep going` — this is host policy, not engine: the engine raises dangerous rm/rmdir as a `safetyCheck` ask that bypass mode cannot auto-allow ("…This requires explicit approval and cannot be auto-allowed by permission rules.", engine binary strings), and the SDK typings say `decisionReasonType` is there so "SDK hosts make policy (e.g. auto-deny safetyCheck)". Claudius is a Desktop-like SDK host and its `canUseTool` (`lib/server/session.ts` ~3745) parks a normal Allow/Deny card even in `bypassPermissions`, so an unattended bypass session stalls. Fix: in bypass mode, deny a dangerous-rm safety-check ask at once with the engine's reason plus a rewrite hint.
