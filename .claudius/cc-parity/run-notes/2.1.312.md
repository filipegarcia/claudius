# Claude Code parity 2.1.310 → 2.1.312

## Summary

The range is 2.1.310 → 2.1.312. The 2.1.311 entries were already classified and shipped in the 2.1.311 run (#325); their classification is carried over below. Claude Code 2.1.312 is mostly engine, terminal, VS Code, cloud and Slack work. It either reaches Claudius through the SDK 0.3.312 bump already on this branch, or has no Claudius surface.

Four 2.1.312 entries land on surfaces Claudius owns. Each is mirrored by extending an existing screen:

1. **Queue hint names the send-now key.** The composer's queue hint now reads "Ctrl+Enter to send now", and a click does what Ctrl+Enter does.
2. **Cleared draft stays cleared.** A restored draft cleared with Ctrl+C or double-Esc no longer comes back on the next launch. This was a real bug in Claudius's own draft persistence.
3. **Mid-task effort note.** The effort pill and the `/effort` toast say a mid-task change "may wait for your next message". The note clears at the next request, on a switch back, or when the turn ends.
4. **Scheduled-job effort.** Scheduled jobs get an optional Effort level beside Model, mirroring the cloud-routine model picker.

An adversarial UX-fit pass, with one skeptic per item, confirmed the shapes. It found one real bug, fixed in `5cebcacc`: the toast and the pill decided "waits" from different baselines. It also found a few edge cases, all fixed in the same commit.

**Headline review risk:** the queue hint's click now sends **every** queued message into the running turn, as Ctrl+Enter does, where it used to send only the first. That matches "as its key does", but it changes behaviour (see Risks).

**Environment note for the gates:** this machine's Homebrew `node` is now v26 (ABI 147). `better-sqlite3` was last built in June for ABI 127, which failed 24 vitest files until `npm rebuild better-sqlite3`. No tracked file changed.

## Risks / follow-ups

**Design calls on the shipped bucket-B items** (each also names its rejected alternative under Implemented):

- **Queue hint now sends all, not the first.** A user with several queued messages who clicks the footer link sends all of them into the running turn, as Ctrl+Enter does. Running tools move to the background.
  - Conservative shape (not shipped): keep the first-only click and only add the key name. But then the hint names a key whose action differs from the click, which is what CC's entry fixes.
  - Maximal shape (not shipped): also move the hint under the queue strip and drop the strip's own "Send all now". That leaves two controls that do the same thing a few pixels apart (the header "Send all now" and the footer hint), which a skeptic flagged as low severity.
  - Reviewer call: hide one of them, or label both the same way.
- **The effort note is client-side and approximate.**
  - **What it tracks:** Claudius can't see the effort each request is sent with. It keeps the level in force at the first mid-turn pick, and clears the note on the first main-thread `message_start` after `effort_applied`, a switch back, or turn end.
  - **Known limits:**
    - A reconnect mid-turn drops the note, because `replay_done` resets pending.
    - An "auto" pick shows the note until it resolves.
    - On an engine without `getSettings` (no `effort_applied`), the note stays until turn end.
    - `needs_input` (a pending prompt) counts as not running, so the note clears while a permission is open.
  - **Maximal shape:** have the server stamp each `message_start` with the effort it was sent with, once the SDK exposes per-request effort.
- **Schedule effort applies to create only.** Claudius has no edit form for existing jobs, so the "edit a routine" half of the entry is reachable only through `PATCH /api/schedule/[id]`, which now accepts `effort`. Building a job edit dialog is a separate feature.
  - Option labels are raw level ids ("xhigh"). They match the settings page, but the chat ModelPicker says "Very High".
  - The select also doesn't apply the user's `maxEffortLevel` cap; the engine clamps anyway.
- **Cleared draft.** `submit()` has the same narrow DELETE-vs-in-flight-PUT ordering window that `clearInput` had. `clearInput` now closes it with a trailing PUT of the empty draft; `submit()` was left as-is (pre-existing).

**Skipped or deferred entries:**

- **`[skip — plausible]` Resending an unchanged message after a failed send running twice.**
  - Claudius gives a resend a new uuid (`lib/client/use-session.ts:5600`), and the input route doesn't dedupe by uuid (`app/api/sessions/[id]/input/route.ts:37`).
  - A double run needs the first POST to land while its response is lost. That is rare on localhost, where a rejected fetch almost always means the request never arrived.
  - Maximal shape: the client reuses the uuid for an unchanged resend after a `network` failure, and the server drops a uuid it has already dispatched or queued.
- **Hook timeout under 1 s counts as 1 s.** The engine applies this. Claudius's Hooks page still accepts `0.5` (`app/[workspaceId]/hooks/page.tsx:742-750`, `min={0}`). A hint, or `min={1}`, would make the editor reflect it. Not done, because the changelog wording is about prompt/agent hooks while that field also serves command hooks.
