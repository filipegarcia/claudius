## Summary

2.1.268 is mostly enterprise gateway administration, VSCode extension,
Claude Code on the web, Claude in Slack ("Claude Tag"), and GitHub Code
Review bot work — none of which has a Claudius surface. Two real
bucket-B items shipped this release, both extending screens Claudius
already has: (1) the MCP "needs-auth" startup notice now announces each
server once per needs-auth episode instead of re-nagging on every
session launch, persisted per-server in the per-cwd SQLite DB; (2)
Claudius now sets `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` so the todo/task
tool surface (TodoWrite/TaskCreate/TaskGet/TaskUpdate/TaskList) stays
registered on Claudius's own default/top-picker model, `claude-sonnet-5`,
which sits exactly at the SDK's new model-tier cutoff. The headline risk
to flag for review: item (2) is a **correctness fix for a previously
shipped parity item** (2.1.233) that turned out to be a no-op in
production — see "## Risks / follow-ups" for the full story. The MCP
item's shape (`[extend: session chrome + /mcp]`) is a design call the
reviewer should confirm; the alternative considered and rejected is
recorded below.

## Risks / follow-ups

- **The todo-tools item is a correctness fix for a previously-shipped parity item, not just a new feature.** `2.1.233.md` classified this exact upstream mechanism `[A — already via SDK updater]` and shipped `allowedTools: TODO_TASK_TOOL_NAMES` as belt-and-suspenders. Verified against the compiled SDK binary (`@anthropic-ai/claude-agent-sdk-darwin-arm64/claude`, the `isEnabled()` gate on each Task* tool) that `allowedTools`/`tools` are never consulted by the gate — only model tier, `CLAUDE_CODE_ENABLE_TODO_TOOLS`, and an internal remote flag are. That means the todos rail has likely been silently broken on Claudius's own default model (`claude-sonnet-5`) since whenever the SDK's 0.3.233-equivalent tool-gating actually shipped, with no error surfaced to any user. Flagging for review rather than just fixing quietly: worth deciding whether this warrants a changelog/release note of its own, separate from the routine cc-parity summary.
- **`buildQueryEnv` changes behavior when no account profile is active.** Previously Claudius omitted `Options.env` entirely in that case (native `process.env` inheritance by the SDK's own subprocess spawn). It now always passes an explicit `env` object (a spread copy of `process.env` plus the new var), because `Options.env` replaces the subprocess env wholesale when set and there's no way to inject a single var without supplying the rest. Functionally equivalent for the normal case, but if any caller relied on a live mutation of `process.env` *after* `start()` propagating to the already-spawned subprocess, that no longer applies (an explicit copy was taken at spawn time) — flagging in case this interacts with anything else that mutates `process.env` mid-session.
- **MCP needs-auth flag is scoped per-cwd, not per-workspace-root.** `openDb(cwd)` uses the session's cwd verbatim (no walk-up to a project root) — same limitation `loop_ticks` and other per-cwd tables already have. A session started in a subdirectory of a workspace gets a different `.claudius.db` and could re-announce a server already announced from the workspace root. Consistent with existing Claudius convention, not a regression introduced here; not fixed in this release.
- **Plugin `install()` doesn't auto-refresh the list on success** (`lib/client/usePlugins.ts`) — the UI explicitly tells the user to click Refresh. Discovered while auditing the `/plugin` reload-not-needed changelog entry (which is actually about the CLI's interactive menu and doesn't describe this gap). A one-line fix (`await refresh()` after a successful `install()`), left as a follow-up rather than folded into this release since it's unrelated to any specific 2.1.268 entry.
- **Plugin `error_count` from `reload_plugins` is dropped on the floor** (`app/api/plugins/route.ts:26` only destructures `d.plugins`). Not part of any 2.1.268 entry's scope (the changelog's `errorDetails`/`noteDetails` addition is CLI-`--json`-only and doesn't exist in the SDK's `reload_plugins` response Claudius consumes), but adjacent enough to note as a possible future bucket-B item if per-plugin error surfacing becomes a real ask.
- **`--skip-gates=e2e` was passed on this run's actual orchestrator invocation**, while the pipeline instructions' Definition of Done demands e2e. Ran the new e2e spec directly anyway (`bunx playwright test tests/e2e/cc-parity-2.1.268-mcp-needs-auth-badge.spec.ts --project=chromium`) since this release does ship a UI change — it passed. Did not run the full e2e suite as part of this note (see the PR gate log for whether the orchestrator's own `--skip-gates=e2e` suppressed it there too).
- A rendering artifact was found in this run's own input: the "Fixed the conversation summary produced by /compact and auto-compact mangling text that contained `#` sequences" changelog entry, as delivered in this prompt, had the entire prompt template nested inside it verbatim — almost certainly a `renderPrompt()` substitution bug in `scripts/cc-parity/orchestrate.ts`. Not fixed (that directory is off-limits per the hard constraints); flagging so the harness owner can look at `renderPrompt()`'s placeholder substitution.
