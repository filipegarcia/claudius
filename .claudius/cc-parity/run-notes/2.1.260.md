## Summary

Claude Code 2.1.258→2.1.260 is a mostly engine/enterprise-gateway
release (Bedrock, OIDC, Claude-apps-gateway policy fields, VSCode
extension polish) plus a handful of terminal-only affordances. Four
items are genuine product-surface gaps Claudius reimplements this
release: a native `/diff` panel (Claudius already has the git/diff
plumbing — `lib/server/git.ts`, `DiffViewer.tsx` — but no
slash-command-triggered surface for it), a text form of `/advisor`
(Claudius already has the full advisor model/settings/API stack, just
no chat-typed command parsing it), syntax-colored, foldable JSON
rendering for Workflow tool-call outcomes (`WorkflowBlock.tsx` currently
dumps raw `JSON.stringify` into a `<pre>`), and a new permission-rule
lint flagging trailing text after a rule's closing parenthesis (an
existing lint file + Permissions-page surface, extended with one more
check). Two other candidates that
looked bucket-B on first read turned out to be dead ends on inspection:
the `/cost` "likely cause of cache miss" diagnostic requires CLI-internal
state the Agent SDK never puts on the wire (shipping a locally-invented
heuristic and labeling it a diagnosis would be worse than not shipping,
and it would contradict an explicit existing design note in
`lib/shared/prompt-cache.ts`), and the fullscreen `ctrl+l`/`cmd+k`
clear-transcript shortcut collides with Claudius's existing
`nav.commandPalette` (Cmd+K) and has no non-reserved literal equivalent
(Cmd+L/Ctrl+L are browser-owned) — see Risks for both. Headline risk to
flag for review: the `/diff` panel is delivered as a full-screen overlay
(matching `CostOverlay.tsx`'s existing pattern) rather than a true
side-by-side "beside the conversation" split pane, since Claudius has
no beside-chat panel layout primitive today.

## Implemented (bucket B)

- `[extend: overlays]` Native `/diff` panel — flipped `/diff` from
  `handler: "sdk"` to a native command in
  `lib/shared/slash-commands.ts`, added a `runNative()` case in
  `components/chat/ChatSurface.tsx`, and built
  `components/overlays/DiffOverlay.tsx` (modeled on `CostOverlay.tsx`)
  that fetches `git/status` + `git/diff` for the active workspace and
  renders them through the existing `DiffViewer.tsx`. Rejected
  alternative: a true beside-chat split-pane layout — Claudius has no
  such layout primitive anywhere (every slash-command panel today is
  either a full overlay or a separate route), so introducing one purely
  for `/diff` would be a new, unproven layout pattern reviewed nowhere
  else in the app; the overlay reuses an established, already-reviewed
  pattern instead.
- `[extend: chat slash-command surface]` Text `/advisor` command —
  added native parsing for `/advisor`, `/advisor <model>`, and
  `/advisor off` (modeled on the existing `/effort` handler) that calls
  the existing `app/api/sessions/[id]/advisor/route.ts`. Rejected
  alternative: a new dedicated advisor slash-command settings screen —
  unnecessary, the UI (ModelPicker, AdvisorDisabledNoticePanel) and API
  already exist; the only gap was chat-typed command parsing.
- `[extend: WorkflowBlock]` Syntax-colored, foldable JSON rendering for
  Workflow tool-call args/script/outcome in
  `components/chat/WorkflowBlock.tsx`. Rejected alternative: pulling in
  a full syntax-highlighting dependency (e.g. `react-json-view`/`shiki`)
  — overkill for a small, already-parsed JSON value; a small inline
  tokenizer/highlighter keeps the bundle lean and matches the file's
  existing hand-rolled rendering style.
- `[extend: /permissions]` Trailing-text-after-`)` permission rule
  warning — added `lintTrailingGarbageRule` to the existing
  `lib/shared/permission-rule-lint.ts` (alongside the 2.1.210 and
  2.1.246 lints) and wired it into `app/[workspaceId]/permissions/page.tsx`
  with the same warning-icon-on-saved-rule + inline-warning-while-typing
  treatment those two already use. Rejected alternative: rejecting the
  rule outright (upstream's own behavior) — Claudius has no
  settings-file load boundary to reject at (rules are typed directly
  into the page), so a non-blocking warning is the closest equivalent
  moment, matching the house style the other two lints already
  established.

## Risks / follow-ups

- `bun run test:e2e` (full chromium suite, 245 passed / 2 failed / 7
  skipped) had two pre-existing failures unrelated to this release:
  `cc-parity-2.1.257-add-dir-network-path.spec.ts` (UNC-path-rejection
  toast) and `notifications-multi-tab.spec.ts` (backgrounded-session-badge
  cross-tab sync, a 15s `expect.poll` timeout). Both pass cleanly when
  re-run in isolation (`npx playwright test
  tests/e2e/cc-parity-2.1.257-add-dir-network-path.spec.ts
  tests/e2e/notifications-multi-tab.spec.ts` → 6 passed, 1 skipped, 0
  failed) — timing-sensitive under full-suite parallel load, not a
  regression from the `/diff` / `/advisor` / Workflow-JSON changes (none
  of which touch add-dir validation, notifications, or tab sync). All
  three new specs plus every other cc-parity/sdk-update spec passed
  in the same full run.
- `/diff` overlay vs. true split pane: shipped the overlay shape
  (matches `CostOverlay.tsx`); a genuine beside-chat panel is a larger
  layout investment (needs a resizable split-pane primitive Claudius
  doesn't have) — worth a dedicated design pass if users want to keep
  chatting while watching the diff live, which the overlay doesn't
  support (it covers the chat while open).
- `/cost` "likely cause of cache miss": the maximal shape would be a
  locally-computed heuristic (hash the system prompt + tool list per
  turn server-side, compare to the previous turn, flag idle-gap vs. the
  cache TTL) entirely from data Claudius already has
  (`cacheReadInputTokens`/`cacheCreationInputTokens`,
  `lib/shared/prompt-cache.ts`). Deliberately not shipped: it would be
  a guess presented as a diagnosis, and it contradicts the explicit
  "we don't have a signal for this" design note already in
  `lib/shared/prompt-cache.ts`. Revisit only if the SDK ever puts a real
  cache-miss-reason field on the wire.
- Permission-rule ambiguous-escaping suggestion (e.g. `Edit(C:\dir\(name)\**)`
  where `\(` reads as an escaped parenthesis rather than a path
  separator): deliberately not attempted. The maximal shape would be a
  Windows-path-aware re-lexer in `permission-rule-lint.ts` that detects
  the specific `\(`-inside-a-path ambiguity and proposes an unambiguous
  respelling — meaningfully harder than the other three lints (it needs
  to understand path-vs-escape-sequence intent, not just count
  parens), and a wrong suggestion would be worse than none. Shipped
  `lintTrailingGarbageRule` defensively avoids misfiring on this shape
  (see its doc comment and the dedicated unit test) rather than
  attempting to fix it.
- `ctrl+l`/`cmd+k` clear-transcript: unimplementable as specified
  (`nav.commandPalette` owns Cmd+K; Cmd+L/Ctrl+L are browser-reserved).
  Considered inventing a substitute binding (e.g. Cmd+Shift+K) but
  rejected it — the changelog entry describes a specific key chord, not
  a feature request for "a clear-transcript action on some key"; picking
  an arbitrary replacement key would be inventing UX the entry doesn't
  ask for.
- `[skip — ambiguous]` items (background-session delete-message
  wording, `managedMcpServers`, GitLab MR badge): all documented above
  with the specific evidence checked (grep results, `git blame`,
  existing file contents). GitLab MR badge in particular —
  if Claudius ever builds a GitHub PR footer badge (wiring up the
  already-dangling `prUrlTemplate` setting), revisit GitLab MR
  recognition alongside it as one combined feature rather than two.
