### Fixes on surfaces Claudius owns

- `[B — reimplement in Claudius] Fixed a collapsed tool call looking as if it ran after you rejected it with a reason: it now shows "Not run · rejected"`. Claudius denies from its own PermissionPrompt ("Deny…" takes a reason), and its ToolCall card shows the result as a failed run: a red alert icon, an "error" header, and the reason in red. In the bundled engine, a host `canUseTool` deny is stamped `non_execution_kind: "permission-rule"`, the same as a settings deny rule, so the meta can't tell them apart. Claudius's server knows which tool-use ids the user denied. Shipped: the server stamps those results `user-rejected`, and the card renders them in the existing CC 2.1.296 "not run" style with "Not run · rejected".
- `[B — reimplement in Claudius] Fixed a setting saved in a running session undoing a hand edit made to settings.json moments earlier`.
  - Claudius's Settings page PUTs the whole draft it loaded with the page. `app/api/settings/full/route.ts` writes it without re-reading the file, so a hand edit or CLI edit made after the page loaded is undone.
  - `/permissions` sends the whole cached `allow`/`ask`/`deny` array, so a rule added by hand is dropped on the next add or remove.
  - Shipped: read-merge-write patches for both.
- `[B — reimplement in Claudius] Fixed marketplaces named npm, pip, uv, cargo, github or gh being refused as reserved names`. Claudius's `RESERVED_SOURCE_NAMES` (`lib/shared/plugin-ref-lint.ts`) still refuses them in the add-marketplace form and on the server. The engine's reserved map is now only `inline`, `builtin`, `skills-dir`, `synced` and `claude-plugin-test`.
- `[B — reimplement in Claudius] Fixed plugins with a version list in enabledPlugins staying off with no message`.
  - `sdk.d.ts` documents that a list of versions leaves a marketplace plugin off. Claudius's plugins page treats any truthy value as on: it shows a green scope badge and a checked "enabled here" box, while the engine leaves the plugin unloaded.
