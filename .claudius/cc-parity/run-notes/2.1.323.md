## Summary

2.1.323 is mostly an engine, permissions, Remote Control and cloud release. Most entries reach Claudius through the bundled engine (bucket A), or concern the terminal, Desktop or cloud. Nine entries have a copy of the same bug, or the same missing affordance, in Claudius's own code, and all nine shipped:

- an inline warning on `/permissions` for `Bash(PORT=* …)` allow rules;
- a "<Model> needs usage credits" limit panel, replacing a mislabelled plan-window panel;
- the unknown-model notice saying 1M, not 200K, unless `CLAUDE_CODE_DISABLE_1M_CONTEXT` is set;
- "Not run · rejected" for tool calls the user denied;

- plugin rows explaining a version-list `enabledPlugins` entry;

- `/fork` refusing a checkout whose `.git` holds links.

All are `[extend: …]` of existing screens; there is no new route.

## Implemented (bucket B)

- `[extend: /[workspaceId]/permissions]` **Bash env-variable wildcard warning.** `lintBashEnvWildcardRule` (`lib/shared/permission-rule-lint.ts`) mirrors the engine's start-up check:
  - it reads the rule unescaped, as the engine matches it;
  - it applies to allow rules only;
  - a leading `NAME=` / `NAME+=` assignment whose value holds an unescaped `*`, followed by a command, is flagged;
  - legacy `:*` prefix rules and shell operators are skipped.

  A saved rule gets an amber chip whose tooltip names the command. A typed draft shows the engine's sentence plus "The rule will still save as typed." The check wins over the older subcommand-wildcard chip, because it is the wider hole. Rejected alternative: refusing to save the rule. The engine only warns, and every other `/permissions` lint is non-blocking.

## Risks / follow-ups

- **"Not run · rejected" depends on the live stream.**
  - The rejected ids are held in memory, and the stamp is applied only in the live consume loop. When the chat is rebuilt from the JSONL (resume replay after a restart or an idle reap, the watcher resync, or scrolling up past the replay buffer via `/transcript`), a rejected call falls back to the pre-2.1.323 red "error" rendering. Persisting the ids per session (as `mergeSessionState` does for `priorPlan`) and re-stamping on those paths is the follow-up.
  - An AskUserQuestion cancel is not stamped, since it is arguably a dismissal rather than a rejection.
  - `TaskBlock`/`WorkflowBlock` still say "failed" for a denied Agent or workflow call, the same gap 2.1.296's `notRun` already has.
  - The engine-side stamping was read from the bundled binary. No live probe ran, because the OAuth session had expired in this headless run.
- **The settings merge works at top-level-key granularity.** If the user changes a key in `permissions` or `env` on the Settings page, the whole object is replaced, so a hand edit inside that same object made after the page loaded is still lost. `persistModelToUserSettings` and other single-key writers already read-merge-write, but they can recreate a settings file deleted meanwhile.
- **Credits panel.**
  - It has no Switch-model button, only the `/model` hint.
  - Whether usage credits turned on mid-session apply without restarting the session was not verified for credits-only models. `LongContextCreditsPanel` documents a restart for the 1M case.
  - The admin line depends on the live `rate_limit_event`'s `canUserPurchaseCredits`, so after a reload it is not shown.
- **Fork link check scope.** It is checked against what `worktree add -b` writes. Hooks, config includes and `objects/` alternates are not checked (`objects/` is hard-linked on purpose by `git clone /local/path`). If the engine's list grows, this mirror needs updating by hand.
- **`enabledPlugins` objects now read as off.** The SDK type allows an object value. The engine loads only `true`, and gives no reason for an object, so Claudius shows no note for one.
- **Recap gap (from the audit, not in 2.1.323's scope).** Claudius's own `/recap` reads the server's event buffer, which the SDK updater's superseded-message eviction doesn't touch. A recap could still include a superseded reply.
- **Symlinked project settings (display only).** Claudius's own settings readers (the `/settings`, `/permissions` and `/plugins` displays) still follow a symlinked `.claude/settings.json`. The engine fix covers what is enforced; the displays can show a file the engine now ignores.
- **Audit side effects.** The read-only audit agents ran e2e and rewrote many older screenshots, and also created untracked `docs/sdk-updates/0.3.2xx` folders. All were reverted. The full e2e gate run also rewrites older `docs/cc-parity/*` PNGs as a side effect of their specs; those were restored rather than committed.
- **Unborn repo.** The audit noted that `getDiffForCommit` fails in a repository with no commits. This predates 2.1.323 and is not changed here.
