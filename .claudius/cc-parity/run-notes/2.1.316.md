## Summary

Most of Claude Code 2.1.316 is engine, terminal, IDE, cloud, gateway and Slack work. It reaches Claudius through the SDK 0.3.316 bump on this branch, or has no Claudius surface. That bump shipped no product code, so nothing here overlaps it.

The new engine-side items are `CLAUDE_CODE_SUBAGENT_EFFORT`, `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`, auto-mode `$defaults` handling, Vertex/Bedrock model step-down and the shell-snapshot fixes. The xhigh `ultrathink` boost and rainbow stay unreachable for SDK hosts (`_e()` gate), the same ruling as 2.1.311–2.1.314.

Nine entries describe a feature or bug on a surface Claudius reimplements. All nine are mirrored by extending existing screens; there are no new routes.

**Visible changes:**
1. **Invisible characters.** A plain prompt with a zero-width character now sends cleaned on the first Enter, with a "Removed N hidden characters from your prompt" footer note. Before, every such prompt needed a second Send. Slash commands, bidi controls and prompts left empty once cleaned are still held for review.
2. **Opus 4.8 fast mode.** When the active model is Opus 4.8, the Model picker's Fast row warns that Opus 4.8 fast mode is deprecated and will be removed on Nov 30. Turning fast mode on shows the same warning in the amber fast-mode strip. The engine's own copy of the notice (from a typed `/fast on`) now also renders amber instead of red.
3. **`[1m]` models in the picker.** A model setting such as `opus[1m]` no longer hides the Effort row, the Ultracode chip and the Fast toggle.
4. **Unknown model after `/model`.** `/model <id>` with an id Claudius can't place warns that auto-compact will assume a 200k window, with a "set the window" docs link.
5. **"Catching up…"** shows in place of the brand-new-session splash while a session you switch back to is replaying its history. It shows "Disconnected — reconnecting…" while the stream is down.
6. **Certificate hints name the cause.** A CA missing its issuer now says so, instead of always blaming a proxy. The gateway / missing-intermediate case is added to the longer hints.

**Invisible fixes:**
7. **`CLAUDE_CODE_DISABLE_ULTRATHINK`** now turns off Claudius's own ultrathink reminder.
8. **Queued messages after Stop.** A message queued behind a turn you stopped is no longer answered unasked when the session's process is replaced (dead-process restart, account switch, idle reaper, server restart).
9. **Git refreshes on large repos.** The Git page poll and the `/diff` overlay no longer abort their own in-flight `git status`, and they space refreshes out when git is slow.

An adversarial review ran with one skeptic per change cluster. It found one blocker: the sticky unknown-model warning followed the user into the next session. It also found a dozen should-fixes. All are fixed in `a22896f6`, `df0d9f2e` and `64d27fde`; see Risks for what was deliberately left.

**Headline review risks:**
- **Recognizer shape.** The `/model` warning uses a heuristic, not the engine's catalog. It recognizes aliases, catalog rows, `modelOverrides`, and any id that *starts* with a Claude family token (any version).
- **Stop holds the queue.** After a Stop, held messages wait for a successful turn or an explicit Send now, and so does any message queued behind them, even across process replacement.
- **`ultrathink` duplication.** Claudius's own reminder may duplicate the engine's `ultrathink_effort` attachment. It is gated, not removed.

  - `useGitStatus` reschedules itself with `setTimeout` after each poll settles, waiting `nextGitPollDelayMs` = max(4 s, 3 × last duration), capped at 60 s.
  - Background ticks and returning to the tab skip while a request is in flight. `refresh()` after stage or commit still fires immediately.
  - DiffOverlay merges edit-driven refreshes that arrive during a fetch into one follow-up (`createCoalescedRunner`).
  - Files: `lib/client/git-poll.ts`, `lib/client/useGitStatus.ts`, `components/overlays/DiffOverlay.tsx`.
  - Commits: `c004da86`, `64d27fde`.
  - Rejected alternative: de-duplicating or caching concurrent `git status` calls on the server. The client aborts its own request every 4 s, so the Changes list would still never render on a slow repo. The "one fewer full-repository git command" half has no Claudius counterpart: a refresh already runs only one.

## Risks / follow-ups

- **Invisible characters, `!` bash mode.**
  - Conservative shape (shipped): a `!` command still strips and runs immediately (2.1.280 behaviour), so only the prompt path changed.
  - Maximal shape: hold `!` commands with stripped characters for review, as the engine does for every non-prompt mode ("commands still wait for review"). That is safer against Trojan-source commands, but it reverses a 2.1.280 decision and its spec.
  - Edge case: ` !ls` with a leading space plus an invisible character is held, but the second Send goes to the model as text, not to bash, because the raw value doesn't start with `!`.
  - Held prompts keep Claudius's existing toast wording, not the engine's "· review and press Enter to send" / "nothing left to send".
- **Opus 4.8 deprecation.**
  - Alternative considered: a transcript pill like other engine notifications. Rejected; the fast-mode strip is Claudius's surface for fast-mode transitions.
  - The removal date is the engine's flag default (`tengu_sunset_penguin_opus48` = 2026-11-30), hardcoded. A remote override wouldn't reach Claudius.
  - After Nov 30 the notice disappears and the engine returns the error itself.
- **`[1m]` matching.**
  - Alternative considered: the same tolerant lookup for untagged ids. Rejected because a pinned `claude-sonnet-5` would start checking the `sonnet` alias row.
  - The server-side `findModelInfo` (`lib/shared/permission-modes.ts`, used for the fast-capability diff and the auto-mode kick-out) is still exact-only, so those paths still miss `opus[1m]`. Follow-up: route it through `findModelEntry`.
- **`/model` unknown-model warning: the recognizer is a heuristic.**
  - An id counts as recognized if it is an alias, a `supportedModels()` row, a `modelOverrides` key or value, or starts (or follows `.`, `/`, `:` or `@`) with a Claude family token of any version.
  - Conservative shape (shipped): no false positives on new models.
  - Maximal shape: the engine's exact catalog, which would also warn on a too-new Claude id. It wasn't chosen because Claudius can't read that catalog through the SDK.
  - Consequence: a custom id like `claude-sonnet-4-finetune` gets no warning.
- **`/model` copy and gates.**
  - The copy deviates from the engine in two places: "Update Claude Code" became "Update Claudius" (the engine is bundled), and the raw docs URL became a "set the window" link.
  - `CLAUDE_CODE_MAX_CONTEXT_TOKENS` suppresses the warning for every id. The engine skips it only for custom/gateway ids.
  - Not covered by a client test: the once-per-id dedupe after an SSE reconnect, and clearing the notice when the model changes.
- **Certificate hints.**
  - Alternative considered: the engine's cause-first wording verbatim. Rejected because Claudius's callers only reach Anthropic.
  - None of these callers honours `ANTHROPIC_BASE_URL` (dictation uses `VOICE_STREAM_BASE_URL`, and sign-in and profile are hardcoded), so the gateway sentence is generic.
  - The engine has no `CERT_UNTRUSTED` case; Claudius maps it to `untrusted-ca`.
- **`CLAUDE_CODE_DISABLE_ULTRATHINK`.**
  - Possible duplication: transcripts from SDK hosts on this machine show the engine adding its own `ultrathink_effort` attachment for stdin prompts. If that also happens for Claudius sessions, Claudius's reminder is a duplicate and could be deleted, which would honour the env var for free.
  - Conservative shape (shipped): gate Claudius's reminder. Follow-up: one live Claudius turn with "ultrathink", then check its JSONL for both reminders.
  - Under an account profile, the engine reads user settings from the profile's `CLAUDE_CONFIG_DIR`, but Claudius reads `~/.claude/settings.json`. Managed/policy env blocks are not read. Both are documented in the field doc.
- **Queue held after Stop.**
  - After a Stop, a new message sent while held rows exist queues behind them. Nothing drains until a successful turn or Send now / send-all, the same as in a session that was never replaced. Users may read that as stuck.
  - Alternative considered: drain on the next enqueue. Rejected because it would answer the stopped-behind message first.
  - The other `flushQueueIfIdle()` callers (permission / ask / plan resolution) still pop a held head; they behave the same in-process.
  - Migration 026 got a comment-only edit in `64d27fde`. It was added in this run and has never been on `main`.
  - The commit message of `e734affe` says a fresh message releases the hold; `64d27fde` reverses that.
- **Git poll.**
  - Alternative considered: server-side kill of the git child via `req.signal`. Kept out; useful hardening, but it doesn't fix the starvation.
  - The factor (3×) and cap (60 s) are Claudius's own; the engine's values aren't visible in the bundle.
  - An explicit `refresh()` after stage or commit still aborts an in-flight background poll on purpose, because that poll's answer may predate the operation.
- **"Catching up…".**
  - Alternative considered: a skeleton transcript. Rejected because Claudius uses muted one-line placeholders elsewhere.
  - Switching to a still-empty brand-new tab shows "Catching up…" briefly before the splash.
  - A reload can still flash the splash before `createSession` runs, because the open-tabs lookup comes first.

  - The `[VSCode]` xhigh `ultrathink` boost and rainbow (`Eme()` needs `entrypoint === "claude-vscode"` or the `tengu_virtual_pancake` flag for non-interactive hosts).
  - `/code-review` findings card (`desktop_app`/`web_claude_ai` clients only).
