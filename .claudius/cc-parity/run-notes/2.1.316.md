**New features / changes**

- `[B — reimplement in Claudius] Added CLAUDE_CODE_DISABLE_ULTRATHINK, which turns the ultrathink keyword off`: Claudius injects its own "deeper reasoning" reminder (`ultrathinkReminderBody`, `lib/server/session.ts:304`, queued at `:4348`) and never looks at the env var, so setting it would turn the engine's reminder off but not Claudius's. Engine gate: `iPt(){return!process.env.CLAUDE_CODE_DISABLE_ULTRATHINK&&…}`, so any non-empty value disables. Mirror: gate the reminder on the session's effective env (query env + settings `env`).
- `[skip — not reachable from the SDK, see Risks] [VSCode] Changed ultrathink to run its turn at xhigh effort and show in a rainbow in the chat box, as in the terminal`: both the boost and the rainbow sit behind the engine's `Eme()` gate, `iPt() && (!_e() || u0t() && FC())`. For an SDK host `_e()` (non-interactive) is true, `u0t()` needs `entrypoint === "claude-vscode"` (or a desktop host) and `FC()` is the `tengu_virtual_pancake` flag (default off). Claudius is `sdk-ts`, so neither the boost nor the engine's rainbow applies to its turns; a Claudius chip saying "this turn runs at xhigh" would be false. Same ruling as the 2.1.311–2.1.314 notes.
- `[A — already via SDK updater] Added CLAUDE_CODE_SUBAGENT_EFFORT`: engine resolves subagent effort (`ePo`/`nRt` in the bundle). Claudius has no subagent-effort logic (the agents page only shows frontmatter `effort`, `app/[workspaceId]/agents/page.tsx:380`), and the env reaches the engine through `buildQueryEnv` (`lib/server/session.ts:840`) or settings `env`. The env editor is free-form, so there is no catalog to extend.
- `[A — already via SDK updater] Added CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`: engine system-CA loading. Claudius's own TLS (`lib/server/extra-ca-certs.ts`) uses Node's bundled `rootCertificates`, never the system store, so it has no cross-cert logic.
- `[B — reimplement in Claudius] Deprecated fast mode for Opus 4.8 as of October 30, 2026 …`: the removal and error are engine-side (A), but the notice the engine shows on turning fast mode on (`_Lr`: "Opus 4.8 fast mode is deprecated and will be removed on Nov 30", `color: "warning"`) fires only from the terminal `/fast` command and TUI picker. Claudius's Model picker toggles fast mode through `applyFlagSettings({ fastMode })` (`lib/server/session.ts:6177`), which never calls it. Mirror: the notice in the picker's fast-mode row and the fast-mode notice strip.
- `[skip — gateway product, not in Claudius] Added pooled group budgets` / `Added managed.policy_mode: layered` / `Added guardrail.input_tagging on Bedrock upstreams` / `Fixed the gateway not checking every model a request names against availableModels…` / `Fixed claude auth login refusing to run where managed settings require a gateway`: Claudius has no gateway.

**Fixes**

- `[B — reimplement in Claudius] Fixed prompts containing invisible characters needing a second Enter to send; plain prompts now send cleaned on the first Enter, and commands still wait for review`: Claudius's composer has its own copy of the review step. `PromptInput.submit()` (`components/chat/PromptInput.tsx:1043-1053`) puts back the cleaned text and returns whenever any character was removed. Engine rule (`xUo` in the bundle): hold only when the cleaned text is empty, has bidi controls, starts with `/` or `!`, or is an exit word; otherwise send cleaned and say so. Mirror for the prompt path.
- `[B — reimplement in Claudius] Self-hosted runner: Fixed a message sent while Claude was working being answered after a Stop, once the session's process had been replaced`: Claudius owns a persisted mid-turn queue (`queued_messages`, migration 014). Stop leaves it in place on purpose (`Session.interrupt`, `lib/server/session.ts:5257`), but a replaced Session drains it at the end of `start()` (`session.ts:3540-3547`). Process replacement happens on `restartIfDead` (also on stream connect, `lib/server/session-resume.ts:104`), account switch, idle reap and server restart. So after Stop plus a replacement, Claude answers the queued message unasked. Mirror: Stop marks the queue held; a fresh `start()` doesn't drain held rows.
- `[B — reimplement in Claudius] [VSCode] Fixed the missing Effort slider, Ultracode switch and model name when the model setting has the [1m] tag, such as opus[1m]`: Claudius's Model picker finds the active model by exact match (`components/panels/widgets/ModelPicker.tsx:304`). The engine's `supportedModels()` drops `[1m]` where it has no effect, so `opus[1m]` matches nothing, and the Effort row, Ultracode chip and Fast toggle disappear. The same exact match is in SessionCard's bare-`/fast` check (`SessionCard.tsx:209`). The model *name* is fine in Claudius (`prettyModelName` falls back to the raw id). Mirror: a `[1m]`-tolerant lookup.
- `[B — reimplement in Claudius] Fixed /model <id> not warning when the model isn't recognized by this version and auto-compact will assume a 200K context window`: Claudius handles `/model <id>` itself (`components/chat/ChatSurface.tsx:1800-1815` → `Session.setModel` → `query.setModel`). The engine's warning is only added by its terminal `/model` command, so Claudius's path never warns. Mirror: the engine's warning text on the existing chat-command model notice, but only for ids Claudius cannot place at all (see Risks for the recognizer).
- `[skip — VSCode only] [VSCode] Fixed a conversation coming back in Auto mode after a reload… "Yes, and manually approve edits"`: Claudius has no such approval option (one accept path, `components/overlays/PlanOverlay.tsx:100-104`) and keeps no permission mode across reloads except plan (`lib/server/session-resume.ts:72`).
