## Summary

2.1.273 is a fix-heavy release: of ~60 changelog entries, the large
majority are bug fixes (permission-checker edge cases, hook-timeout
scoring, transcript rendering) or belong to product surfaces Claudius
doesn't implement at all (VSCode extension, Windows UNC paths, Claude
Code on the web's cloud environments/routines, the Slack "Claude Tag"
bot, the GitHub Code Review App, the Artifact tool). Of the handful of
genuinely new engine/product behaviors, exactly one clears the bar for
Claudius to reimplement (bucket B): the CLI's new mid-session
notification for an MCP server that disconnects and whose automatic
reconnection gives up, pointing the user at `/mcp`. This release
extends the existing `/mcp` surface (and its CC 2.1.193/2.1.268
needs-auth-notice sibling) with a `mcp_disconnected_notice` SSE event
→ transcript info pill, following the exact same one-shot,
per-server-deduped pattern already in place for needs-auth. Headline
risk to flag for review: Claudius has no push signal for "the SDK's
own MCP auto-reconnect loop just gave up" (the SDK's `mcpServerStatus()`
is pull-based, and this branch's SDK 0.3.273 migration added no such
event) and no existing mid-session polling timer to hang a live
detector on, so this ships the conservative interpretation — a
`failed`-status check reused from the existing `system:init` check
points — rather than the maximal shape (a new live poller that fires
the instant a server flips from `connected` to `failed`). See "## Risks
/ follow-ups" for the full alternative-shape discussion. Nothing in
this release overlaps with the SDK migration that just landed on this
branch (0.3.272 → 0.3.273, `task_notification.reason: "worker_restart"`
plumbing) — no bucket-A item below needed the
`[skip — already shipped via SDK migration on this branch]` tag.

## Implemented (bucket B)

- `[extend: /mcp]` MCP disconnected / reconnect-gave-up notice. When a
  configured MCP server is observed in `failed` status at a `system:init`
  check, the server broadcasts a one-shot `mcp_disconnected_notice` SSE
  event (deduped per server, per episode, across sessions) and the client
  injects a `kind: "info"` transcript pill reading `MCP server is
  unavailable: <name> · open /mcp to check` — the exact sibling of the
  existing CC 2.1.193 needs-auth notice. Worded "unavailable"/"check"
  rather than "disconnected"/"reconnect": the underlying `failed` read is a
  single point-in-time status check that can't tell a mid-session drop
  apart from a server that never connected at all (see "## Risks /
  follow-ups"). Files touched:
  `lib/server/db-migrations/023_mcp_disconnected_notified.sql` (new table),
  `lib/server/mcp-disconnected-db.ts` (new, mirrors
  `mcp-needs-auth-db.ts`), `lib/shared/events.ts`
  (`McpDisconnectedNoticeEvent`), `lib/server/session.ts`
  (`noteMcpDisconnectedAtStartup()` + call site + replay-buffer exclusion),
  `lib/client/use-session.ts` (event handler → transcript pill).
  Rejected alternative: a new dedicated banner/toast component distinct
  from the transcript pill — rejected because Claudius already has this
  exact affordance (the needs-auth pill) for the sibling "something's wrong
  with an MCP server, go to /mcp" situation, and a second, visually
  different mechanism for a near-identical situation would be inconsistent
  UX for no benefit. A new screen was never in consideration — `/mcp`
  already exists and already owns per-server connection status.

## Risks / follow-ups

- **Headline gap — false positives, not just false negatives.** Because
  `noteMcpDisconnectedAtStartup()` reads `failed` at a single point in time
  (`system:init`) rather than watching a `connected` → `failed`
  transition, it cannot distinguish "dropped mid-session and gave up
  reconnecting" (upstream's actual trigger) from "never connected in the
  first place" — a misconfigured command, a dead URL, a typo — which is
  the far more common way a server shows up `failed` at a fresh session
  start. Shipping the literal upstream wording ("disconnected" /
  "reconnect") would be actively misleading for that common case, so the
  pill and event doc comments were deliberately worded "unavailable" /
  "check" instead — accurate for both causes, at the cost of being less
  specific than upstream's copy. A secondary, smaller gap from the same
  point-in-time-check limitation: a server that disconnects and recovers
  entirely between two `system:init` checks (e.g. a long-running session
  that never resumes) won't be announced at all. Flagging both for a human
  to weigh — the wording softening in particular is a judgment call a
  reviewer may want to revisit.
- **Conservative vs. maximal shape for the detector itself.** Conservative
  (shipped): reuse the existing `system:init` check points, as above.
  Maximal (not shipped): a genuine mid-session live detector — either a new
  polling timer inside `Session` that periodically calls
  `mcpServerStatus()` while a session is actively streaming and diffs
  against the previously-observed status per server (which *would* let the
  copy safely say "disconnected"/"reconnect"), or subscribing to a
  push-based disconnect signal from the SDK's MCP transport if one exists.
  Not built because (a) `session.ts` has no existing periodic timer to
  attach to today — introducing one purely for this notice is a materially
  bigger change than the feature warrants, and (b) the SDK's
  `mcpServerStatus()` is confirmed pull-based with no push-style disconnect
  event (checked against the 0.3.273 SDK run notes on this branch, which
  added no such type).
- Classification note (see classification section): the upstream "say how
  to re-authenticate" MCP sign-in-expiry error-message improvement is
  tagged `[C — CLI/terminal only]` rather than a variant bucket-B tag,
  since only the four tags the prompt defines are valid for the gate's
  bucket-B-claim-vs-diff check. It doesn't require new Claudius work
  because the existing needs-auth pill already produces the same outcome;
  worth a second look only if upstream's wording diverges meaningfully from
  Claudius's own copy in a future release.
- `.claudius/sdk-updater/run-notes/0.3.273.md` shows as modified in the
  working tree but was NOT touched by this cc-parity pass — it's the
  sibling SDK-migration stage's own file, already dirty on arrival in this
  combined-mode run (this review runs layered onto `sdk-update/0.3.273`
  per the prompt's combined-mode preamble). Left alone deliberately; not
  part of this diff.
- **Rejected UI shape for the shipped item**: a standalone dismissible
  banner (like `TokenExpiringPanel`) instead of a transcript pill. Rejected
  because the direct precedent for "an MCP server has a problem, go to
  /mcp" (the needs-auth notice) is a transcript pill, not a banner —
  matching it keeps the two nearly-identical situations visually
  consistent instead of introducing a second UI pattern for one feature.
