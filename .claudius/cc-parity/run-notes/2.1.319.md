## Summary

Claude Code 2.1.318 and 2.1.319 are mostly engine, terminal, gateway, cloud, runner and VSCode work. That work reaches Claudius through the SDK 0.3.319 bump already on this branch. Fourteen entries (twelve bucket-B items, two of which cover two entries each) describe a bug or feature that lives in Claudius's own code, and all of them are mirrored here:

- **Two new surfaces on existing screens:**
  - an "Earlier in this session" group of finished subagents in the Activity rail, with Open and Message;
  - an account-scope "Deny instead of prompting" toggle on /permissions.
- **Two new states of existing UI:**
  - a warning toast when `/rename` couldn't save to the transcript;
  - a "sign-in ends in about N days" banner driven by the new `credential_expires_at`.
- **Fixes in Claudius-owned code:**
  - git revision lists ending in `--`;
  - atomic, serialized writes to MCP and keybindings files;
  - the feedback survey latched off after a refusal and limited to first-party sign-ins;
  - the idle reaper sparing sessions with live background agents after `/clear`;
  - clean subagent hand-back reports;
  - a guard against pathological `$$` math;
  - a 400 ms Escape guard on permission and MCP prompts;
  - the thinking-replay recovery no longer draining the queue out of order.

There are no new routes. Two entries were skipped as ambiguous (see Risks).

- **`$$` math guard** `[extend: Markdown renderer]`.
  - `hasPathologicalDollarRuns` (`lib/shared/math-delimiters.ts`) does one linear scan and counts runs of 3 or more `$`.
  - Above 16 runs, `Markdown.tsx` renders that message without remark-math or rehype-katex. Measured: 1,008 ms → 31 ms on an 80 KB reply.
  - *Rejected:* debouncing the streaming render; it only spreads the same super-linear cost out and still freezes on the final render.
- **Permission and elicitation prompt Escape guard** `[extend: PermissionPrompt / McpElicitationPrompt]`. Escape is ignored for 400 ms after a prompt appears (`lib/client/prompt-arm.ts`, keyed on `requestId`).
  - *Rejected:* listening only while the prompt is focused; that breaks the existing Escape-from-anywhere deny, which users rely on.
- **Thinking-replay recovery queue order** `[extend: session queue]`.
  - `flushQueueIfIdle` waits while `thinkingReplayRecoveryScheduled`, so the next queued message goes to the rebuilt session after the re-sent prompt.
  - `noteThinkingRecoverySuccess` runs only on non-error results, so the 3-attempt cap holds.
  - *Rejected:* re-queuing the failed prompt at the head of the SQLite queue; recovery already re-sends it in place, and doing both would send it twice.

## Risks / follow-ups

- **Model picker "More models" (skipped, ambiguous).** The engine groups older models with a catalog `overflow` flag that the SDK's `supportedModels()` drops. Claudius could guess with a hard-coded family list, but that would go stale with every model release and clash with its existing "More models" row, which holds probed pinned ids. Follow-up: build it once `ModelInfo` carries the flag.
- **VSCode "Claude service links as text" (skipped, ambiguous).** The extension's matcher isn't in the CLI bundle. A broad `claude.ai`/`anthropic.com` block would also disable docs links, so it wasn't guessed.
- **Cleared-from banner count not built.** "Background tasks that keep running after /clear disappearing" was classified A (a cloud list). A "N still running there" count on `ClearedFromBanner` would be a nice addition but isn't needed for parity.
- **MCP config lock is in-process only.** A CLI `claude mcp add` running at the same moment as a Claudius save can still race; the engine's lock has the same limit. Atomic rename means the loser's change is lost but the file is never left half-written.
- **Reaper exemption is bounded at 4 h of task silence.** A legitimately silent agent running longer than that can still be reaped. The bound is deliberate, so one hung agent can't pin a process.
- **Expired claude.ai login keeps the generic banner copy.** `auth-failed-detector.ts` still matches the new "Failed to authenticate" text, but doesn't say "your sign-in reached its time limit". Follow-up if the engine's wording settles.
- **Sign-in-ends nudge fires once per session.** Several sessions open at once each show it once. That matches the access-token nudge, but could be de-duplicated across sessions.
- **Harness bug, not edited:** `scripts/cc-parity/orchestrate.ts:715` runs `git diff <sha> HEAD` without `--`, the same ambiguous-revision bug fixed here in `lib/server`. A repo with a top-level file named after the sha or `HEAD` breaks it. Reported, not changed, because harness files are off-limits for this run.
