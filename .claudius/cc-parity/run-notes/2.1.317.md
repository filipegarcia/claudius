## Summary

Claude Code 2.1.317 is almost entirely engine, terminal, cloud, gateway, self-hosted-runner, VSCode and Slack work. It reaches Claudius through the SDK 0.3.317 bump on this branch, or has no Claudius surface.

Several entries that look like Claudius work turned out to be engine-side:
- **Email-address check and "don't ask again" for mod tool calls.** The engine signals both through fields Claudius already forwards and renders (`decision_reason`, `suppress_always_allow_rule`).
- **Region-block 403.** It no longer reads as an auth failure, so Claudius's own sign-in nudge stays quiet with no code change. A unit test locks that in.
- **`/loop` missing field.** Claudius never required `noop`.
- **Fork fixes.** Claudius calls the SDK's `forkSession`.

One entry is a bug in Claudius's own code (bucket B), and it is fixed with no UI change:
- **A permission-mode switch survives the idle reaper and an app update or restart.** An SDK host's mode switch never reaches the engine's transcript. Claudius's revive read the mode only from the transcript, so "switch to Plan, close the tab" came back in the workspace default after a reap or restart, able to edit files.
- Claudius now records each committed switch in the session's state bag. A revive uses the newer of that record and the transcript's last prompt stamp.
- The 2.1.292 rule that only plan carries over is unchanged.

An adversarial review ran two skeptics. Both independently found the same defect in the first version: undated CLI-written stamps were ordered wrongly on sessions also used from `claude --resume`. That is fixed in `865330af`, which also adds a seq guard for a plan-accept race and makes `mergeSessionState` atomic.

**Headline review risk:** is the "undated stamp → plan wins" tiebreak the right call for sessions shared with the terminal CLI? It can keep such a session in plan after the user left plan in the terminal; it can never widen permissions.

## Implemented (bucket B)

- `[extend: session revive (no UI change)]` **A permission-mode change survives the idle reaper and an app update or restart.**
  - **Recording.** `Session` records `{ permissionMode, permissionModeAt }` in the session's state bag (`mergeSessionState`) whenever it commits a mode:
    - in `applyPermissionMode`, only after the engine accepts the switch. A refused switch returns before the write, and a switch raced by plan acceptance is skipped (same `seq` guard as the rollback);
    - in `resolvePlan`'s direct `acceptEdits` write, in the same merge as `priorPlan`.
  - **Reading.** `resumePermissionMode`, used by `POST /api/sessions {resume}` (boot reload and tab-switch wake) and `getOrResumeSession`, works from two records for a session that isn't live:
    - the transcript's last stamp with its timestamp (`lastRecordedPermissionModeAt`);
    - the persisted record (`persistedPermissionMode`).
  - **Choosing.** `pickRecordedPermissionMode` picks one:
    - dated: the newer wins, and the transcript wins a tie;
    - undated (only the terminal CLI writes undated `permission-mode` lines): plan wins if either side says plan.
  - The 2.1.292 rule is unchanged: only plan carries over, and every other mode falls back to the workspace default.
  - **Hardening.** `mergeSessionState` now reads and writes synchronously on one handle, so concurrent fire-and-forget merges can't drop each other's keys.
  - Files: `lib/shared/permission-mode-record.ts` (new), `lib/server/session-resume.ts`, `lib/server/session.ts`, `lib/server/sessions-db.ts`.
  - Commits: `eb795527`, `865330af`.
  - Rejected alternatives:
    - **Carry every mode across a revive** (restore acceptEdits, bypass or auto too). That widens what a revived session may do, against the deliberate 2.1.292 plan-only policy.
    - **Append a synthetic `{type:"permission-mode"}` line to the engine's JSONL on each switch.** That makes Claudius a second writer on a file the engine owns and re-stamps.
    - **Add a "restored Plan mode" notice to the session chrome.** Rejected because the mode pill already shows the restored mode, and Claudius shows no notice for the existing 2.1.292 carry-over either.

## Risks / follow-ups

- **Sessions shared with the terminal CLI (undated stamps).**
  - Conservative shape (shipped): when the transcript's last stamp is an undated, CLI-written `permission-mode` line, Claudius can't order it against its own record, so plan wins if either side says plan.
  - Consequence: a session where the user left plan in `claude --resume`, after an earlier Claudius switch to plan, comes back in plan in Claudius. It never comes back with wider permissions.
  - Maximal shape: order undated lines by the JSONL's mtime. Rejected, because later engine writes (titles, metadata) bump mtime and would make a stale CLI mode look newest.
  - Both review skeptics flagged the first version's ordering here (it took the last prompt's timestamp). That is fixed in `865330af` and covered by `session also used from the terminal CLI…`.
- **Engine-side reading this rests on.** The bug assumes the engine never writes `permission-mode` lines for SDK hosts.
  - Evidence: in the 0.3.317 bundle the only writer is the metadata re-append from `currentSessionPermissionMode`, and that field's setter is called from the TUI only. None of the 96 `sdk-ts` transcripts on this machine has such a line; a reviewer scan of about 1500 local transcripts found them only with `entrypoint=cli`.
  - If a later engine starts writing dated mode lines for SDK hosts, the newest-wins comparison still does the right thing.
- **Not tracked: engine-initiated mode changes.** EnterPlanMode by the model, or a `setMode` the engine applies itself, don't go through `applyPermissionMode`. That was already true before this change. Such a change is recorded only by the next prompt stamp, so a reap right after it reverts to the previous record.
