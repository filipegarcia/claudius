## Summary

Claude Code 2.1.271 is mostly engine-side: sandboxed `allowed_domains` for
Bash/PowerShell/Monitor, auto-mode classifier changes, Artifact-tool
improvements, dynamic-workflow pause/resize, and MCP tool-search fixes all
land automatically via the SDK updater, and `omitClaudeMd` was already
shipped end-to-end on this same combined-mode branch by the `sdk-update/
0.3.271` cycle (commit `041c35f`, verified via `git show --stat` per this
pipeline's own gate-gap history of phantom-implementation claims). Two
real bucket-B items shipped this release, both extensions of screens
Claudius already has: the `modelPricing` multiplier now supports markup up
to 10x for internal chargeback rates (extends the Settings catalog field
from CC 2.1.243), and `StatusLine` swaps its "Working" label to "Deep in
thought" after 45s of continuous turn time (extends the CC 2.1.246 elapsed-
time ticker). Both went through an adversarial UX-fit review pass, which
caught a real bug in the first draft — silently clamping the pricing-
multiplier input in place would have misrepresented a value a *managed*
settings.json set directly outside the UI (the field would show a clamped
10 while an admin's file actually says 25) — since fixed to show the raw
value with an "Effective: 10x" warning instead. The headline risk for
review is the deliberately conservative scope on the "long thinking"
status: only the time-based "deep in thought" swap shipped; the
hook-running-feedback + Esc-cancel half of the same changelog entry and the
gateway-specific desktop-app spinner tip were judged out of scope for this
release (see Risks).

## Risks / follow-ups

- **modelPricing multiplier — design iteration worth flagging explicitly.** The first implementation clamped the input value in place (typing 25 silently became 10) to mirror the server-side ceiling. An adversarial review agent correctly refuted this: `modelPricing` is a *managed* setting an admin can write directly into `settings.json` outside Claudius's UI entirely, so silently rewriting an already-set value on render would show 10 in the UI while a config file says 25 — a real "what did I actually configure" bug, not a nitpick. Fixed by committing the raw value and showing an inline "Effective: Nx" (or "ignored" for ≤0) warning instead, matching this file's `JsonRow`/`OtherEditor` red-error-pill convention for out-of-range input rather than inventing a new pattern. The maximal alternative — reject/refuse the keystroke entirely like `statusLine.refreshInterval`'s revert-on-invalid handler — was considered and rejected: a managed setting's value must always be *visible and editable* even when out of range (a refusing input can't display a value it refuses to accept), so "show it with a warning" fits this specific field better than "revert it."
- **"Deep in thought" — conservative scope, two things deferred.** The upstream entry has three sub-parts: (1) "deep in thought" after 45s — shipped; (2) "picking the thought back up" recovering from the output-token limit — judged already close enough to intent via the existing `api-retry.ts` `max_output_tokens` → `SpinnerTip` preemption (an accurate status replaces the generic tip while stalled on the same condition), so no code changed; the maximal alternative was adding bespoke "picking the thought back up" copy for exactly that retry reason, rejected as a copy-only change not worth a separate diff given the existing UX already communicates the same state; (3) hook-running feedback (SessionStart/UserPromptSubmit/PreToolUse/SessionEnd + elapsed time) and Esc-cancel during a SessionStart-hook wait — deferred entirely. Claudius has no server-side hook-execution timing/instrumentation today; building this needs a new SSE event type threaded through every hook registration site in `lib/server/session.ts` plus Esc-cancel wiring, which is a distinct, larger unit of work than this release's other two items combined. The maximal shape (build it now) was rejected in favor of the conservative shape (skip and flag) specifically because rushing new server-side hook instrumentation without its own design/review pass risks the "plausible but wrong shape" failure mode this pipeline is supposed to guard against.
- **Gateway desktop-app spinner tip — skipped as scope-inventing.** "Added a spinner tip pointing Bedrock/Vertex/Foundry/LLM gateway users to the Claude desktop app" is Anthropic's own cross-sell from the CLI to a different native app. Claudius has no equivalent "you're in the browser, try our Electron build" nudge today, and the changelog entry's actual scope (Anthropic's distribution funnel) doesn't support inventing one from scratch. Maximal alternative considered: add a `lib/shared/tips.ts` entry that nudges Electron when running in the browser (or vice versa) — rejected because nothing in this changelog entry actually asks for that, and Claudius's Electron build isn't a "different app" in the way Claude Code's terminal-vs-desktop split is; it would be net-new scope, not parity.
- **`allowed_domains` sandboxing (Bucket A) — one item worth a human's eyes once the SDK bump lands.** Classified engine-side since Bash/PowerShell/Monitor execution happens entirely inside the CLI binary the SDK spawns. Worth a quick sanity check on the next SDK-update cycle that Claudius's own permission-prompt UI (which reviews tool calls before they run) doesn't need to surface the newly-scoped `allowed_domains` list somewhere — flagging here rather than guessing at UI scope now, since the SDK's exact event/type shape for this isn't known yet.
- Housekeeping (not a code risk): 14 `docs/cc-parity/*/*.png` files were already dirty in the working tree before this run (re-screenshotted by unrelated historical cc-parity Playwright specs whenever the full e2e suite runs) and were deliberately left uncommitted/unstaged — same for `docs/cc-parity/2.1.246/turn-duration.png`, re-dirtied by re-running that spec during this session's verification pass. None of these reflect an intentional change; a future run should consider whether those specs need tighter screenshot-diffing tolerance so they stop drifting on every run.
